Atkārtojuma tests: 3.4 Kļūdu apstrāde un validācija

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Kad izpildās except bloks?

except ir drošības tīkls: ja try blokā kļūdas nav, tas tiek izlaists. Atkārto: 3.4 — Teorija: Izņēmumu apstrāde ↗

2. Lietotājs ievada abc. Kas notiek? 
try:
    likme = float(input("Ievadi likmi: "))
except ValueError:
    print("Kļūda! Ievadi skaitli.")

float("abc") rada ValueError, bet except ValueError to noķer un izdrukā tavu paziņojumu. Vēlreiz jautāt programma sāk tikai tad, ja bloks ir while ciklā. Atkārto: 3.4 — 1. uzdevums — Noķer ValueError ar try/except ↗

3. Kāpēc šajā kodā break atrodas try blokā, aiz konvertācijas? 
while True:
    try:
        likme = float(input("Ievadi likmi: "))
        break
    except ValueError:
        print("Kļūda! Ievadi skaitli.")

Ja float() rada kļūdu, Python uzreiz pārlec uz except, un break netiek sasniegts. Tāpēc cikls jautā vēlreiz, līdz ievade ir derīga. Atkārto: 3.4 — 2. uzdevums — Uzbūvē drošu ievadi ciklā ↗

4. Lietotājs ievada -5. Vai except ValueError to noķer?

except noķer tikai to, ko nevar pārvērst skaitlī. Skaitlis -5 ir tehniski derīgs, bet bezjēdzīgs likmei, tāpēc vajag atsevišķu if pārbaudi. Atkārto: 3.4 — 3. uzdevums — Pievieno vērtību validāciju ↗

5. Programmā ir gan try/except, gan pārbaude if likme <= 0:. Kuru ievadi tā pieņem?

abc noraida except, bet 0 un -5 noraida if pārbaude. Paliek tikai pozitīvs skaitlis 2.5. Atkārto: 3.4 — 3. uzdevums — Pievieno vērtību validāciju ↗
