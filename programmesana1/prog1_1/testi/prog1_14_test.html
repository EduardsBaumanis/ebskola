Atkārtojuma tests: 1.3 Koda sinhronizācija (Desktop)

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Tu sāc jaunu stundu. Ko dari GitHub Desktop, pirms atver VS Code?

Fetch origin pārbauda, vai GitHub ir jaunumi, un Pull origin tos saņem. Tad izvēlies Repository → Open in Visual Studio Code. Klonē tikai vienu reizi katrā datorā. Atkārto: 1.3 — Stundas beigās ↗

2. Tu nospiedi Commit to main, bet GitHub vietnē jaunā faila nav. Ko aizmirsi?

Commit saglabā versiju tikai tavā datorā. Uz GitHub to nosūta Push origin. Atkārto: 1.3 — 2. uzdevums — Fiksē un nosūti uz GitHub ↗

3. Kādā secībā jārīkojas, lai izmaiņa nonāktu GitHub?

Vispirms saglabā failu VS Code, tad GitHub Desktop saglabā versiju datorā (Commit) un beigās nosūti to uz GitHub (Push). Atkārto: 1.3 — Teorija: kā kods nokļūst no datora uz GitHub ↗

4. GitHub Desktop rāda šīs atšķirības failā 13.py. Ko tās nozīmē? 
-print("Mans pirmais commit!")
+print("Sveiki no VS Code!")

Rinda ar mīnusu (sarkana) ir izdzēsta, rinda ar plusu (zaļa) ir pievienota. Kopā tas nozīmē, ka rinda ir nomainīta. Atkārto: 1.3 — 3. uzdevums — Izlasi atšķirības un salīdzini commit ziņas ↗

5. Kura commit ziņa ir labākā?

Laba commit ziņa pasaka, kas mainīts, tāpēc cilnē History to var saprast, neatverot failu. Atkārto: 1.3 — 3. uzdevums — Izlasi atšķirības un salīdzini commit ziņas ↗
