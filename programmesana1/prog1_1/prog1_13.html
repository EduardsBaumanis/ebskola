1. tēma / 1.3

1.3 Koda sinhronizācija (Desktop)

Sasniedzamais rezultāts: Šajā stundā tu pārnesīsi savu GitHub krātuvi uz datoru, nosūtīsi pirmās izmaiņas atpakaļ uz GitHub un iemācīsies ceļu, pa kuru turpmāk sāksi katru stundu: GitHub Desktop → VS Code.

SR 2.4.9. Lieto versiju pārvaldības sistēmas (Git).

Teorija: kā kods nokļūst no datora uz GitHub

Tava krātuve pagaidām atrodas tikai GitHub vietnē. Lai tajā strādātu, tev vajag tās kopiju datorā. Pēc tam katru izmaiņu uz GitHub nosūti divos soļos: vispirms saglabā to kā versiju datorā, tad nosūti uz GitHub. To visu dara programma GitHub Desktop, tāpēc komandas nav jāraksta.

  • Klonēšana (Clone): krātuves kopijas lejupielāde no GitHub uz datoru. To dara vienu reizi katrā datorā.
  • Fiksēšana (Commit): izmaiņu saglabāšana kā jauna versija ar īsu aprakstu. Versija paliek tikai tavā datorā.
  • Nosūtīšana (Push): datorā saglabāto versiju nosūtīšana uz GitHub. Tikai pēc tās izmaiņas redz skolotājs.
  • Atšķirības (Diff): skats, kurā izdzēstā rinda ir sarkana ar mīnusu, bet pievienotā rinda ir zaļa ar plusu.

Ceļš, pa kuru iet katra izmaiņa:

VS Code             GitHub Desktop             GitHub (internets)
raksti kodu    →    Commit to main        →    Push origin
Ctrl+S              (versija datorā)           (versija GitHub)

Tā GitHub Desktop parāda vienas rindas nomaiņu:

-print("Mans pirmais commit!")
+print("Sveiki no VS Code!")
Pašpārbaude: vai Commit jau nosūta izmaiņas uz GitHub?

Nē. Commit saglabā versiju tikai tavā datorā. Lai tā nonāktu GitHub, jānospiež Push origin.

Pirms sāc

Pārbaudi, vai tev ir viss no iepriekšējām stundām:

  • datorā ir uzstādīts VS Code un Python (1.1 stunda);
  • uz darbvirsmas ir mape python_darbi ar failiem 11.py un 12.py;
  • GitHub vietnē ir tava krātuve programmesana-pamatkurss (1.2 stunda);
  • programma GitHub Desktop ir uzstādīta, un tu tajā esi pierakstījies ar savu GitHub kontu (1.2 stunda).

1. uzdevums -

Klonē krātuvi un atver to VS Code

Beigās tava krātuve būs mape tavā datorā, un tā būs atvērta VS Code.

  1. Atver klonēšanas logu: programmas GitHub Desktop augšējā izvēlnē izvēlies File → Clone repository (klonēt krātuvi).
  2. Izvēlies krātuvi: cilnē GitHub.com sarakstā noklikšķini uz rindas, kas beidzas ar /programmesana-pamatkurss.
  3. Sāc klonēšanu: lauku Local path (vieta datorā) atstāj, kā ir, un nospied zilo pogu Clone. Pagaidi, līdz logs aizveras.
  4. Atver krātuvi VS Code: augšējā izvēlnē izvēlies Repository → Open in Visual Studio Code. Atveras VS Code ar tavu krātuvi.
  5. Apstiprini mapi: ja VS Code jautā Do you trust the authors of the files in this folder?, nospied Yes, I trust the authors (jā, uzticos). Tā ir tava paša mape.
  6. Atver krātuves mapi sistēmā Windows: atgriezies GitHub Desktop un izvēlies Repository → Show in Explorer (parādīt mapi). Atveras logs ar krātuves mapi, un tajā ir fails README.md.
  7. Nokopē vecos failus: atver uz darbvirsmas mapi python_darbi, iezīmē failus 11.py un 12.py un nospied Ctrl+C.
  8. Ielīmē tos krātuvē: pārslēdzies uz krātuves mapes logu, noklikšķini tukšā vietā un nospied Ctrl+V.

Gatavs, kad: VS Code kreisajā pusē redzi 11.py, 12.py un README.md, bet GitHub Desktop kreisajā pusē zem Changes (izmaiņas) ir 11.py un 12.py.

Iestrēgi?
  • 2. solis: sarakstā nav tavas krātuves. GitHub Desktop nav pierakstīts ar tavu kontu. Izvēlies File → Options → Accounts un nospied Sign in. Ja krātuves nav arī GitHub vietnē, izveido to pēc 1.2 stundas 2. uzdevuma.
  • 4. solis: izvēlnē nav rindas ar Visual Studio Code vai nekas neatveras. Izvēlies File → Options → Integrations, laukā External editor izvēlies Visual Studio Code un nospied Save. Tad atkārto 4. soli.
  • 7. solis: neatrodi 11.py vai 12.py. Izlaid 7. un 8. soli. Trūkstošo failu izveido no jauna VS Code tāpat kā 2. uzdevuma 1. solī; failā 11.py ieraksti print("Sveika, pasaule!").
  • Strādā pie cita datora? Krātuve jāklonē vienu reizi katrā datorā. Atkārto 1.–4. soli.

2. uzdevums -

Izveido 13.py, fiksē un nosūti uz GitHub

Beigās tavi trīs faili būs redzami GitHub vietnē.

  1. Izveido failu: VS Code kreisajā pusē ar peles labo pogu noklikšķini tukšā vietā zem failu saraksta, izvēlies New File (jauns fails), ieraksti nosaukumu 13.py un nospied Enter.
  2. Ieraksti šo rindu un saglabā ar Ctrl+S: 
    print("Mans pirmais commit!")
  3. Palaid programmu ar Run pogu (trijstūris VS Code augšējā labajā stūrī). Terminālī jāparādās: 
    Mans pirmais commit!
  4. Apskati izmaiņas: pārslēdzies uz GitHub Desktop. Kreisajā pusē zem Changes tagad ir trīs faili: 11.py, 12.py un 13.py. Katram priekšā ir ķeksītis.
  5. Apraksti izmaiņu: kreisajā apakšējā stūrī laukā Summary (kopsavilkums) ieraksti Pievieno 11.py, 12.py un 13.py.
  6. Fiksē: nospied zilo pogu Commit to main. Failu saraksts kļūst tukšs, jo versija ir saglabāta datorā.
  7. Nosūti uz GitHub: augšējā joslā nospied Push origin (nosūtīt).
  8. Pārbaudi pārlūkā: izvēlies Repository → View on GitHub. Atveras tava krātuve GitHub vietnē.

Gatavs, kad: GitHub vietnē failu sarakstā redzi 11.py, 12.py un 13.py, un blakus tiem ir tava ziņa Pievieno 11.py, 12.py un 13.py.

Iestrēgi?
  • 3. solis: nav Run pogas vai parādās kļūda par Python. VS Code apakšējā joslā labajā pusē jābūt Python versijas numuram. Ja tā nav, nospied Ctrl+Shift+P, ieraksti Python: Select Interpreter un izvēlies Python no saraksta (1.1 stunda).
  • 4. solis: GitHub Desktop nerāda 13.py. Fails nav saglabāts. Ja VS Code pie faila nosaukuma ir balts aplītis, nospied Ctrl+S.
  • 6. solis: poga Commit to main ir pelēka. Lauks Summary ir tukšs vai nevienam failam nav ķeksīša.
  • 8. solis: GitHub vietnē jauno failu nav. Ir izdarīts Commit, bet nav izdarīts Push. Atgriezies GitHub Desktop un nospied Push origin.

3. uzdevums -

Izlasi atšķirības un salīdzini divas commit ziņas

Beigās tu pratīsi nolasīt, kura rinda ir mainīta, un zināsi, kāpēc commit ziņai jābūt skaidrai.

  1. Nomaini tekstu: VS Code failā 13.py pārraksti rindu tā, kā redzams šeit, un saglabā ar Ctrl+S: 
    print("Sveiki no VS Code!")
  2. Izlasi atšķirības: GitHub Desktop zem Changes noklikšķini uz 13.py. Labajā pusē jāredz sarkana rinda ar mīnusu (vecā) un zaļa rinda ar plusu (jaunā): 
    -print("Mans pirmais commit!")
+print("Sveiki no VS Code!")
  3. Fiksē ar apzināti neskaidru ziņu: laukā Summary ieraksti izmainas un nospied Commit to main.
  4. Pievieno otru rindu faila 13.py beigās un saglabā ar Ctrl+S: 
    print("Šis ir mans otrais labojums.")
  5. Fiksē ar skaidru ziņu: laukā Summary ieraksti Pievieno otru sveiciena rindu un nospied Commit to main.
  6. Nosūti abas versijas: nospied Push origin.
  7. Salīdzini abas ziņas: GitHub Desktop kreisajā pusē atver cilni History (vēsture). Noklikšķini uz izmainas, pēc tam uz Pievieno otru sveiciena rindu. Tikai viena no tām pasaka, kas mainīts, neatverot failu.
  8. Pieraksti secinājumu piezīmēs. Fails README.md turpmāk būs tava piezīmju klade: katrā stundā tajā pierakstīsi secinājumus, un skolotājs tos redzēs GitHub. VS Code atver README.md, faila beigās pievieno šīs rindas, pabeidz abus teikumus un saglabā ar Ctrl+S: 
    ## Piezīmes

### 1.3 Koda sinhronizācija

Commit ziņai jābūt konkrētai, jo

Pēc Commit vēl jānospiež Push origin, jo

Gatavs, kad: cilnē History augšējās divas rindas ir Pievieno otru sveiciena rindu un izmainas, un failā README.md zem virsraksta ### 1.3 Koda sinhronizācija ir divi pabeigti teikumi.

Iestrēgi?
  • 2. solis: labajā pusē nav sarkanās un zaļās rindas. Fails 13.py nav saglabāts (nospied Ctrl+S) vai kreisajā pusē nav noklikšķināts uz 13.py.
  • 6. solis: uz pogas Push origin ir skaitlis 2. Tā tam jābūt: datorā gaida divas versijas, un viens klikšķis nosūta abas.
  • 7. solis: neredzi cilni History. Tā atrodas GitHub Desktop kreisajā pusē blakus cilnei Changes.
  • 8. solis: virsraksts GitHub vietnē neizskatās kā virsraksts. Aiz zīmēm ## un ### jābūt atstarpei, un katram virsrakstam jābūt savā rindā.
Papildu uzdevums - Izmēģini Pull

Ja pamatdarbs ir gatavs, izmēģini pretējo virzienu: saņem izmaiņu no GitHub uz datoru.

  1. Atver krātuvi pārlūkā: GitHub Desktop izvēlies Repository → View on GitHub.
  2. Izveido failu GitHub vietnē: nospied Add file → Create new file (izveidot jaunu failu), nosauc to sveiciens.txt un lielajā laukā ieraksti vienu teikumu.
  3. Saglabā to: nospied zaļo pogu Commit changes un atvērtajā logā vēlreiz Commit changes.
  4. Pārbaudi, vai GitHub ir jaunumi: GitHub Desktop augšējā joslā nospied Fetch origin. Poga pārvēršas par Pull origin (saņemt izmaiņas).
  5. Saņem izmaiņu: nospied Pull origin.

Gatavs, kad: fails sveiciens.txt, ko izveidoji pārlūkā, ir redzams VS Code kreisajā pusē.

Stundas beigās

Piezīmes failā README.md vēl ir tikai tavā datorā. Nosūti arī tās.

  1. Saglabā visus failus: VS Code izvēlies File → Save All.
  2. Apskati izmaiņas: pārslēdzies uz GitHub Desktop. Zem Changes jābūt failam README.md.
  3. Apraksti un fiksē: laukā Summary ieraksti Pievieno 1.3 piezīmes un nospied Commit to main.
  4. Nosūti: nospied Push origin.

Gatavs, kad: GitHub Desktop raksta No local changes (nav nenosūtītu izmaiņu), un augšējā joslā ir poga Fetch origin, nevis Push origin.

Turpmāk katru stundu sāc tā

  1. Atver GitHub Desktop un pārbaudi, vai augšā kreisajā stūrī pie Current repository ir programmesana-pamatkurss.
  2. Nospied Fetch origin. Ja poga pārvēršas par Pull origin, nospied arī to.
  3. Izvēlies Repository → Open in Visual Studio Code.

Katru stundu beidz tāpat kā šo: Summary, Commit to main, Push origin.
