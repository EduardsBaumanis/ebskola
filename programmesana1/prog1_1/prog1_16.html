1.6 Noslēguma pārbaudes darbs - Darba vide un kodu pārvaldība

Stundas uzdevums: Patstāvīgi izveidot, dokumentēt un publicēt nelielu Python projektu, izmantojot tikai 1. tēmā apgūto VS Code, GitHub Desktop, Markdown, `.gitignore` un ergonomikas saturu.

SR 2.4.8. Dokumentē kodu un ievēro noformēšanas vadlīnijas SR 2.4.9. Versiju pārvaldība ar Git SR 2.4.12. Programmēšanas vides sagatavošana SR 3.1.1. Ergonomika un droša darba vide

70 min plāns: Ievads un kritēriju pārruna (~10 min) · 1. uzdevums (~15 min) - izveido projekta struktūru un .gitignore · 2. uzdevums (~25 min) - uzraksti programmu un README · 3. uzdevums (~20 min) - publicē GitHub un pārbaudi pēc kritērijiem. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: šis ir pārbaudes darbs. Jaunas Python konstrukcijas nav vajadzīgas - vērtē to, ko apguvi 1.1-1.5 stundās. Atver savu krātuvi un burtnīcu ar pierakstiem.

Teorija: pārbaudes darbā vērtē procesu, ne tikai failus

Šajā darbā nav jāizmanto jaunas Python konstrukcijas. Vērtēts tiek tas, vai tu proti sakārtot projektu, pasargāt nevajadzīgus failus ar .gitignore, dokumentēt darbu README failā un publicēt izmaiņas GitHub krātuvē ar saprotamu vēsturi.

# PD1 darba vide
Autors: **Vārds Uzvārds**

## Palaišana
python sveiciens.py

## Ergonomika
- Monitors acu līmenī.
- Regulāri atpūtinu acis.
- Sēžu ar taisnu muguru.
Šis README izmanto tikai iepriekš apgūtos Markdown virsrakstus, treknrakstu un sarakstus.

70 min plāns: projekta struktūra ~20 min, programma un README ~25 min, GitHub publicēšana ~25 min.

Praktiskie uzdevumi

1. uzdevums - Izveido projekta struktūru un .gitignore

Beigās tavā krātuvē būs sakārtota mapju struktūra un aizsargāti personīgie faili.

  1. Izveido krātuvē jaunu mapi pd1.
  2. Izveido tajā apakšmapi kods.
  3. Izveido failu .gitignore, ja tā vēl nav.
  4. Ieraksti tajā rindas __pycache__/ un piezimes.txt.
  5. Izveido failu piezimes.txt un pārbaudi, ka GitHub Desktop to nerāda.

Gatavs, kad: GitHub Desktop rāda mapi pd1, bet nerāda piezimes.txt.

2. uzdevums - Uzraksti programmu un README

Beigās tavs projekts sastāvēs no strādājošas programmas un tās apraksta.

  1. Izveido mapē pd1/kods failu sveiciens.py.
  2. Uzraksti programmu, kas izdrukā tavu vārdu un kursa nosaukumu divās rindās.
  3. Palaid to un pārliecinies, ka nav kļūdu.
  4. Izveido mapē pd1 failu README.md.
  5. Ieraksti tajā virsrakstu, autoru treknrakstā un sadaļu ## Palaišana.
  6. Pievieno sadaļu ## Ergonomika ar trim domuzīmju punktiem.

Gatavs, kad: programma izdrukā divas rindas bez kļūdām, un README ir vismaz divas ## sadaļas.

3. uzdevums - Publicē GitHub un pārbaudi pēc kritērijiem

Beigās tavs darbs būs redzams internetā un gatavs iesniegšanai.

  1. Veic commit ar skaidru ziņu, piemēram Pievieno PD1 darbu.
  2. Nospied Push origin.
  3. Atver krātuvi pārlūkā un pārbaudi, ka mape pd1 ir redzama.
  4. Pārbaudi, ka piezimes.txt GitHub nav nonācis.
  5. Pārbaudi, ka README sākumlapā izskatās sakārtots, nevis kā viena rinda.
  6. Nokopē savas krātuves saiti un iesniedz to skolotājam.
  7. Pieraksti vienu secinājumu: kurš solis šajā darbā bija grūtākais.

Gatavs, kad: skolotājam iesniegtā saite atveras un tajā redzama mape pd1 ar kodu un README.

Papildu uzdevums - Sakārto commit vēsturi

Ja pamatdarbs ir gatavs, padari savu izmaiņu vēsturi saprotamu citiem.

  1. Atver GitHub krātuves sadaļu Commits.
  2. Atrodi commit ziņu, kas neko nepasaka, piemēram update.
  3. Izdari jaunu nelielu izmaiņu un uzraksti tai teicamu ziņu.
  4. Salīdzini abas ziņas sarakstā.
  5. Pieraksti savu likumu, kā rakstīsi commit ziņas turpmāk.

Gatavs, kad: vēsturē ir vismaz viena ziņa, pēc kuras var saprast izmaiņu, to neatverot.

Biežākās kļūdas (un kā tās labot)

  • `slepenais.txt` tomēr parādās GitHub Desktop: pārbaudi, vai `.gitignore` atrodas projekta saknē un vai faila nosaukums sakrīt precīzi.
  • README nerenderējas kā formatēts teksts: pārbaudi, vai faila nosaukums ir README.md, nevis README.txt.
  • GitHub redz vecu versiju: pēc commit vēl jānospiež Push origin.
  • Iesniegta lokālā adrese: E-klasē jāiesniedz saite, kas sākas ar https://github.com/.

Vērtēšanas kritēriji (SLA)

Kritēriji Sācis apgūt (1-3) Turpina apgūt (4-6) Apguvis (7-8) Apguvis padziļināti (9-10)
Struktūra un ignorēšana Faili nav sakārtoti atbilstoši mapēm vai .gitignore nedarbojas. Struktūra ir izveidota, bet slepenais.txt ir netīšām publicēts internetā. Precīza mapju struktūra; .gitignore veiksmīgi bloķē lieko failu. Nevainojama resursu pārvaldība un izpratne par ceļiem un failu paplašinājumiem.
Versiju kontrole (Desktop) Izmaiņas netiek fiksētas (nav Commit) vai nav nosūtītas uz mākoni. Veikts Commit, bet ziņojums ir tukšs, nesaprotams vai fails nav augšupielādēts (Push). Kods ir augšupielādēts; izmantots skaidrs un aprakstošs Commit ziņojums. Nevainojama sinhronizācijas rīku lietošana, pārliecinoties par izmaiņām pirms fiksēšanas.
Dokumentācija (Markdown) README faila nav vai tas rakstīts kā parasts teksts bez formāta. README ir nepilnīgs; nav izmantots Markdown virsrakstiem vai sarakstiem. README satur visas prasītās sadaļas, pareizi pielietojot `#`, `**` un `-` Markdown elementus. Izsmeltinoša dokumentācija, kas ir vizuāli pievilcīga un demonstrē dziļu izpratni par ergonomiku.
Koda izpilde un Iesniegšana Python fails nedarbojas vai nav iesniegta saite E-klasē. Kods darbojas ar kļūdām; iesniegta neprecīza saite (piem., lokālā C: diska adrese). Kods izpildās bez kļūdām; iesniegta korekta GitHub pārlūka saite uz PD1 mapi. Kods ir papildināts ar komentāriem; process veikts patstāvīgi bez aizķeršanās.
