10.3 Datu modelis un UI plūsma

Sasniedzamais rezultāts: Izveidot "rentgena uzņēmumu" savai programmai. Pirms ķeries pie koda, Tev ir precīzi jāzina, kādi dati Tev būs nepieciešami un kā spēlētājs pārvietosies starp spēles ekrāniem. Projektēsim datu struktūras un vizualizēsim spēles gaitu.

SR 2.4.5. Programmatūras projektējums

Stundas mērķi:

  • Atpazīt būtības (entities) un to atribūtus "Krustiņi un nullītes" spēles kontekstā.
  • Izveidot vienkāršu ER (Entity-Relationship) diagrammu datu glabāšanai.
  • Projektēt UI (lietotāja saskarnes) plūsmas diagrammu (Wireflow).

Teorija: ER diagrammas un UI plūsma

Sākt testu →

  • ER diagramma (Entity-Relationship): Shēma, kas parāda, kādi objekti (būtības) eksistē sistēmā un kā tie ir saistīti.
    • Būtība (Entity): Galvenais objekts (piem., Spēlētājs, Spēle).
    • Atribūts (Attribute): Objekta īpašība (piem., spēlētāja zīme X vai O, spēles laukums).
    • Saite (Relationship): Kā tie ir saistīti (piem., Spēlētājs piedalās Spēlē).
  • UI plūsma (User Interface Flow): Diagramma, kas parāda spēlētāja ceļu.
    • Katrs ekrāns ir taisnstūris.
    • Izvēles ir bultas, kas ved uz nākamo taisnstūri.
    • Šī shēma palīdz ieraudzīt "strupceļus", kur spēlētājs varētu iesprūst.
  • Rīki: Profesionāļi izmanto Draw.io vai Lucidchart, bet programmētāji bieži lieto arī vienkāršas teksta diagrammas tieši kodā.
# ER diagrammas pārvēršana datu modelī
spele = {
    "id": 1,
    "speletaji": ["X", "O"],
    "laukums": [["", "", ""], ["", "", ""], ["", "", ""]],
    "pasreizejais_gajiens": "X",
    "uzvaretajs": None
}

Pirms sāc

  1. Atver GitHub Desktop un pārbaudi, vai augšā kreisajā stūrī pie Current repository (pašreizējā krātuve) ir programmesana-pamatkurss.
  2. Nospied Fetch origin (pārbaudīt jaunumus). Ja poga pārvēršas par Pull origin (saņemt izmaiņas), nospied arī to.
  3. Izvēlies Repository → Open in Visual Studio Code. Atveras VS Code ar tavu krātuvi.
  4. Atrodi mapi tema10 VS Code kreisajā pusē — šīs stundas faili būs tajā. Ja tādas mapes vēl nav, ar peles labo pogu noklikšķini tukšā vietā zem failu saraksta, izvēlies New Folder (jauna mape) un nosauc to tema10.
  5. Izveido failu: ar peles labo pogu noklikšķini uz mapes tema10, izvēlies New File (jauns fails) un nosauc to 103.md.
  6. Atver diagrammu rīku: pārlūkā atver app.diagrams.net un izvēlies Create New Diagram (jauna diagramma) → Blank Diagram (tukša diagramma).

Kad diagramma ir gatava, saglabā to kā attēlu: diagrams.net izvēlies File → Export as → PNG un saglabā mapē tema10 — ER diagrammu kā 103_er.png, UI plūsmu kā 103_plusma.png. Tā tās nonāks krātuvē, un 10.6 stundā tās būs vajadzīgas.

Praktiskie uzdevumi

1. uzdevums -

Uzzīmē ER diagrammu ar divām būtībām

Beigās tu redzēsi, kādi dati tavā spēlē vispār pastāv.

  1. Uzzīmē taisnstūri ar nosaukumu Spēlētājs.
  2. Pieraksti tajā vismaz trīs atribūtus, piemēram vards, zime, uzvaras.
  3. Uzzīmē otru taisnstūri ar nosaukumu Spēle.
  4. Pieraksti tajā atribūtus id, laukums un pasreizejais_gajiens.
  5. Novelc līniju starp abiem un uzraksti uz tās saiti piedalās.
  6. Atzīmē katrai būtībai, kurš atribūts ir unikālā atslēga.

Gatavs, kad: diagrammā ir divas būtības ar atribūtiem, viena saite starp tām un atzīmētas atslēgas.

2. uzdevums -

Uzzīmē UI plūsmu

Beigās tu redzēsi visu ceļu no spēles sākuma līdz beigām.

  1. Uzzīmē ekrānu Sākums kā taisnstūri.
  2. Uzzīmē ekrānus Spēle un Rezultāts.
  3. Novelc bultas, kas rāda, kā spēlētājs pārvietojas starp ekrāniem.
  4. Pieraksti uz katras bultas darbību, piemēram nospiež Sākt.
  5. Pievieno vismaz vienu bultu atpakaļ, piemēram Spēlēt vēlreiz.
  6. Pārbaudi, vai no katra ekrāna var tikt prom.

Gatavs, kad: no katra ekrāna izejošas vismaz viena bulta, un neviens ekrāns nav strupceļš.

3. uzdevums -

Pārbaudi, vai plūsma sasaucas ar datiem

Beigās tu pamanīsi datus, ko neviens ekrāns nerāda.

  1. Noliec abas diagrammas blakus.
  2. Atzīmē katram ER atribūtam, kurā ekrānā tas parādās.
  3. Atrodi atribūtu, kas nav redzams nevienā ekrānā.
  4. Izlem, vai to izdzēst vai pievienot kādam ekrānam.
  5. Atrodi ekrānu, kas rāda datus, kuru ER diagrammā nav.
  6. Papildini ER diagrammu ar trūkstošo atribūtu.
  7. Pieraksti failā 103.md vienu secinājumu: kāpēc abas diagrammas jāzīmē kopā.

Gatavs, kad: katram ER atribūtam ir norādīts ekrāns, un neviens ekrāns neprasa datus, kuru diagrammā nav.

Papildu uzdevums - Pievieno trešo būtību

Ja pamatdarbs ir gatavs, paplašini modeli ar gājieniem.

  1. Uzzīmē būtību Gājiens ar atribūtiem zime, rinda un kolonna.
  2. Novelc saiti starp Spēle un Gājiens.
  3. Pieraksti uz saites, cik gājienu var būt vienā spēlē.
  4. Pievieno UI plūsmā ekrānu Gājienu vēsture.
  5. Savieno to ar ekrānu Spēle abos virzienos.

Gatavs, kad: modelī ir trīs būtības, un gājienu vēstures ekrānu var gan atvērt, gan pamest.
