10.4 Testēšana ar unittest

Sasniedzamais rezultāts: Šajā stundā tu uzrakstīsi funkciju, kas atrod krustiņu un nullīšu uzvarētāju, un automātiskus testus, kas ar vienu klikšķi pārbauda, vai tā atbilst akceptēšanas kritērijiem.

SR 2.4.6. Izstrāde un testēšana pēc specifikācijas

Teorija: akceptēšanas kritērijs kļūst par testu

Sākt testu →

10.2 stundā tu rakstīji akceptēšanas kritērijus — teikumus, uz kuriem var atbildēt ar jā vai nē. Tos var pārbaudīt ar roku, pēc katra labojuma izspēlējot spēli no jauna. Ātrāk un drošāk ir likt to darīt datoram.

  • Automātisks tests (unit test): neliela funkcija, kas izsauc tavu funkciju ar iepriekš zināmiem datiem un pārbauda, vai atbilde ir tāda, kādu gaidi.
  • unittest: Python iebūvēta bibliotēka testu rakstīšanai un palaišanai.
  • Pārbaude self.assertEqual(a, b): tests izdodas, ja a ir vienāds ar b. Ja nav, tests neizdodas, un terminālī redzi abas vērtības.

Tā kritērijs kļūst par testu:

Akceptēšanas kritērijsTests
Ja augšējā rindā ir trīs X, uzvar X.Laukums ar X X X augšējā rindā → uzvaretajs(laukums) jāatgriež "X".
Ja laukums ir tukšs, uzvarētāja nav.Tukšs laukums → jāatgriež None.

Mazākais tests izskatās tā:

import unittest


def dubulto(x):
    return x * 2


class TestDubulto(unittest.TestCase):

    def test_divi(self):
        self.assertEqual(dubulto(2), 4)


unittest.main()

Palaižot to, terminālī parādās:

.
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK

Katrs punkts . ir viens izdevies tests. Rindu class …(unittest.TestCase): un vārdu self pagaidām raksti tieši tā — klases apgūsi 14. tēmā. Katra testa nosaukumam jāsākas ar test_, citādi unittest to neatradīs.

Pašpārbaude: ko nozīmē rinda OK testu beigās?

Visi testi izdevās: katrā assertEqual funkcijas atbilde sakrita ar gaidīto vērtību.

Pirms sāc

  1. Atver GitHub Desktop un pārbaudi, vai augšā kreisajā stūrī pie Current repository (pašreizējā krātuve) ir programmesana-pamatkurss.
  2. Nospied Fetch origin (pārbaudīt jaunumus). Ja poga pārvēršas par Pull origin (saņemt izmaiņas), nospied arī to.
  3. Izvēlies Repository → Open in Visual Studio Code. Atveras VS Code ar tavu krātuvi.
  4. Atrodi mapi tema10 VS Code kreisajā pusē — šīs stundas faili būs tajā. Ja tādas mapes vēl nav, ar peles labo pogu noklikšķini tukšā vietā zem failu saraksta, izvēlies New Folder (jauna mape) un nosauc to tema10.

Šajā stundā izmantosi 10.3 stundas laukuma modeli: laukums ir saraksts ar trim rindām, katrā rindā trīs rūtiņas, tukša rūtiņa ir "" (10.3 stunda). Bibliotēka unittest ir iebūvēta Python, tā nav jāinstalē.

1. uzdevums -

Uzraksti uzvarētāja funkciju un pirmo testu

Beigās viens klikšķis pārbaudīs, vai funkcija atrod uzvarētāju augšējā rindā.

  1. Izveido failu: ar peles labo pogu noklikšķini uz mapes tema10, izvēlies New File (jauns fails) un nosauc to spele_104.py. Nosaukums nesākas ar ciparu, jo šo failu importēsi.
  2. Ieraksti funkciju un saglabā ar Ctrl+S. Tā pārbauda visas astoņas uzvaras līnijas: trīs rindas, trīs kolonnas un divas diagonāles. 
    def uzvaretajs(laukums):
    """Atgriež "X" vai "O", ja kāds ir uzvarējis, citādi None."""
    # 1) trīs rindas
    for rinda in laukums:
        if rinda[0] != "" and rinda[0] == rinda[1] and rinda[1] == rinda[2]:
            return rinda[0]
    # 2) trīs kolonnas
    for k in range(3):
        if laukums[0][k] != "" and laukums[0][k] == laukums[1][k] and laukums[1][k] == laukums[2][k]:
            return laukums[0][k]
    # 3) divas diagonāles
    if laukums[1][1] != "" and laukums[0][0] == laukums[1][1] and laukums[1][1] == laukums[2][2]:
        return laukums[1][1]
    if laukums[1][1] != "" and laukums[0][2] == laukums[1][1] and laukums[1][1] == laukums[2][0]:
        return laukums[1][1]
    return None
  3. Izveido otru failu tajā pašā mapē tema10 un nosauc to test_104.py.
  4. Ieraksti pirmo testu un saglabā ar Ctrl+S: 
    import unittest
from spele_104 import uzvaretajs


class TestUzvaretajs(unittest.TestCase):

    def test_x_augseja_rinda(self):
        laukums = [["X", "X", "X"],
                   ["O", "O", ""],
                   ["", "", ""]]
        self.assertEqual(uzvaretajs(laukums), "X")


unittest.main()
  5. Palaid testu: pārliecinies, ka atvērts ir fails test_104.py, un nospied zaļo Run pogu. Terminālī jāparādās: 
    .
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK

Gatavs, kad: terminālī ir rinda Ran 1 test un zem tās OK.

Iestrēgi?
  • 5. solis: ModuleNotFoundError: No module named 'spele_104'. Abiem failiem jābūt vienā mapē tema10, un nosaukumam jābūt tieši spele_104.py.
  • 5. solis: Ran 0 tests un NO TESTS RAN. Testa funkcijas nosaukums nesākas ar test_.
  • 5. solis: NameError: name 'assertEqual' is not defined. Pirms assertEqual trūkst self..
  • 5. solis: terminālī nekas nemainās vai palaižas cits fails. Run poga palaiž to failu, kas pašlaik atvērts. Pārslēdzies uz cilni test_104.py.

2. uzdevums -

Pārvērs kritērijus testos

Beigās vēl trīs testi pārbaudīs kolonnu, diagonāli un tukšu laukumu.

  1. Izlasi kritērijus, kurus pārvērtīsi testos: 
    1. Ja kreisajā kolonnā ir trīs O, uzvar O.
2. Ja diagonālē no kreisā augšējā stūra ir trīs X, uzvar X.
3. Ja laukums ir tukšs, uzvarētāja nav (None).
  2. Pievieno trīs testus: failā test_104.py zem pirmā testa, bet virs rindas unittest.main(), ieraksti šo kodu. Rindām def jābūt ar tādu pašu atkāpi kā pirmajam testam. 
        def test_o_kolonna(self):
        laukums = [["O", "X", ""],
                   ["O", "X", ""],
                   ["O", "", "X"]]
        self.assertEqual(uzvaretajs(laukums), ___)

    def test_x_diagonale(self):
        laukums = [[___, "O", ""],
                   ["O", ___, ""],
                   ["", "", ___]]
        self.assertEqual(uzvaretajs(laukums), "X")

    def test_tukss_laukums(self):
        laukums = [["", "", ""],
                   ["", "", ""],
                   ["", "", ""]]
        self.assertEqual(uzvaretajs(laukums), ___)
  3. Aizpildi ___ vietas: pirmajā testā ieraksti, kuram jāuzvar; otrajā ieliec "X" trīs vietās, lai tie būtu diagonālē; trešajā ieraksti, ko funkcija atgriež, ja uzvarētāja nav. Saglabā ar Ctrl+S.
  4. Palaid test_104.py. Terminālī jāparādās četri punkti: 
    ....
----------------------------------------------------------------------
Ran 4 tests in 0.000s

OK
  5. Pieraksti secinājumu. Atver README.md, faila beigās pievieno virsrakstu ### 10.4 Testēšana ar unittest un zem tā pabeidz teikumu: Akceptēšanas kritērijs kļūst par testu, kad …

Gatavs, kad: terminālī ir ...., Ran 4 tests un OK.

Iestrēgi?
  • 3. solis: pirmajā testā "O"; otrajā "X" visās trīs vietās; trešajā None — bez pēdiņām.
  • 4. solis: AssertionError: None != 'None'. Tu uzrakstīji "None" pēdiņās. Tas ir teksts, bet funkcija atgriež None bez pēdiņām.
  • 4. solis: AssertionError: None != 'X' pie test_x_diagonale. Kāds no trim "X" nav diagonālē: tiem jābūt rindā 1 vietā 1, rindā 2 vietā 2 un rindā 3 vietā 3.
  • 4. solis: joprojām Ran 1 test. Jaunie testi nav klases iekšā: rindām def vajag 4 atstarpju atkāpi, un tām jābūt virs unittest.main().

3. uzdevums -

Salauz funkciju un pievieno savu testu

Beigās tu redzēsi, kā tests pats atrod kļūdu, un būsi uzrakstījis piekto testu.

  1. Salauz funkciju: failā spele_104.py zem komentāra # 3) divas diagonāles ieliec # priekšā četrām rindām, lai beigas izskatītos tā, un saglabā:

Iestrēgi?
  • 2. solis: joprojām OK. Fails spele_104.py nav saglabāts, vai # ielikts ne tajās rindās. Pārbaudi, vai pie faila nosaukuma nav balta aplīša.
  • 2. solis: IndentationError. Tu ieliki # rindām ar if, bet ne rindām ar return. Komentē visas četras rindas.
  • 5. solis: tests izskatās tā:

                   ["X", "O", "O"],
                   ["O", "X", "X"]]

  • 6. solis: Ran 4 tests. Jaunā testa nosaukums nesākas ar test_, vai tas nav klases iekšā ar 4 atstarpju atkāpi.

Stundas beigās

  1. Saglabā visus failus: VS Code izvēlies File → Save All.
  2. Apskati izmaiņas: pārslēdzies uz GitHub Desktop. Zem Changes (izmaiņas) jābūt tema10/spele_104.py, tema10/test_104.py un README.md.
  3. Apraksti un fiksē: laukā Summary (kopsavilkums) ieraksti Pievieno 10.4 uzvaretaja funkciju un testus un nospied Commit to main.
  4. Nosūti: nospied Push origin (nosūtīt uz GitHub).

Gatavs, kad: GitHub vietnē mapē tema10 redzami faili spele_104.py un test_104.py.

Papildu uzdevums - Pārbaudi pārējās uzvaras līnijas

Ja pamatdarbs ir gatavs, pievieno testus līnijām, kuras vēl neviens tests nepārbauda.

  1. Pievieno klasē testu test_o_otra_diagonale, kurā O stāv no labā augšējā līdz kreisajam apakšējam stūrim:

 ["X", "O", ""],

  2. Pievieno testu test_x_apakseja_rinda ar laukumu, kurā apakšējā rindā ir trīs X.
