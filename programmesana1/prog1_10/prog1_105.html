10.5 Sasniedzamie rezultāti un resursu plānošana

Sasniedzamais rezultāts: Izveidot reālistisku "ceļa karti" (Roadmap) sava projekta īstenošanai. Programmēšanā laiks ir visdārgākais resurss, tāpēc apgūsi, kā sadalīt lielu projektu mazos, izpildāmos soļos un precīzi definēt, kas nepieciešams katra posma pabeigšanai.

SR 2.4.3. Individuāla izstrāde pa posmiem

Stundas mērķi:

  • Definēt izmērāmus starprezultātus (Milestones) "Krustiņi un nullītes" spēles izstrādei.
  • Identificēt nepieciešamos tehniskos un informatīvos resursus (bibliotēkas, dokumentāciju).
  • Izveidot laika grafiku, prioritizējot kritiskās funkcijas.

Teorija: Resursi un "Definition of Done"

Sākt testu →

  • Resursu veidi IT projektā:
    • Tehniskie: Python vide, bibliotēkas (unittest, random), VS Code paplašinājumi.
    • Informatīvie: Oficiālā dokumentācija, algoritmu špikeri, iepriekšējo tēmu koda paraugi.
    • Cilvēkresursi: Tavs un klasesbiedru laiks (īpaši testēšanas fāzē).
  • Starprezultāti (Milestones): Kontrolpunkti projektā, kas palīdz sekot progresam (piemēram: "Funkcija uzvaretajs() atrod uzvarētāju visās 8 līnijās").
  • Pabeigta darba definīcija (DoD): Skaidri kritēriji, kad funkcija skaitās gatava (piemēram: "Kods ir PEP 8 saderīgs, funkcijām ir docstring, un visi testi failā test_104.py iziet — terminālī redzams OK").

Pirms sāc

  1. Atver GitHub Desktop un pārbaudi, vai augšā kreisajā stūrī pie Current repository (pašreizējā krātuve) ir programmesana-pamatkurss.
  2. Nospied Fetch origin (pārbaudīt jaunumus). Ja poga pārvēršas par Pull origin (saņemt izmaiņas), nospied arī to.
  3. Izvēlies Repository → Open in Visual Studio Code. Atveras VS Code ar tavu krātuvi.
  4. Atrodi mapi tema10 VS Code kreisajā pusē — šīs stundas faili būs tajā. Ja tādas mapes vēl nav, ar peles labo pogu noklikšķini tukšā vietā zem failu saraksta, izvēlies New Folder (jauna mape) un nosauc to tema10.

Praktiskie uzdevumi

1. uzdevums -

Nospraud trīs starprezultātus

Beigās tavs projekts būs sadalīts pārbaudāmos posmos.

  1. Izveido failu 105.md ar sadaļu ## Starprezultāti.
  2. Pieraksti trīs posmus, piemēram datu ielāde, spēles cikls, izvade.
  3. Uzraksti katram posmam vienu teikumu, kas nozīmē pabeigts.
  4. Pārbaudi, vai katru var pārbaudīt ar jā vai nē.
  5. Sakārto posmus tādā secībā, kādā tos var izpildīt.
  6. Atzīmē, kurš posms ir atkarīgs no iepriekšējā.

Gatavs, kad: katram no trim posmiem ir pārbaudāma pabeigtības definīcija, un secība ir izpildāma.

2. uzdevums -

Veic resursu auditu

Beigās tu zināsi, kā tev pietrūkst, pirms darbs apstājas.

  1. Pievieno sadaļu ## Resursi ar trim apakšpunktiem.
  2. Uzskaiti tehniskos resursus: Python versija, bibliotēkas, redaktors.
  3. Uzskaiti informatīvos resursus: dokumentācija, iepriekšējo tēmu paraugi.
  4. Uzskaiti cilvēkresursus: cik stundu nedēļā tu vari veltīt.
  5. Atzīmē ar zvaigznīti tos, kuru tev pašlaik NAV.
  6. Pieraksti katram trūkstošajam, kā to iegūsi.

Gatavs, kad: sarakstā ir vismaz viens atzīmēts trūkstošs resurss ar plānu, kā to dabūt.

3. uzdevums -

Uzraksti laika grafiku un riskus

Beigās tu zināsi, kas var noiet greizi un ko tad darīsi.

  1. Pievieno sadaļu ## Grafiks ar datumiem katram posmam.
  2. Pieraksti katram posmam, cik stundu tas prasīs.
  3. Saskaiti kopējo stundu skaitu un salīdzini ar pieejamo laiku.
  4. Pievieno sadaļu ## Riski ar trim riskiem.
  5. Uzraksti katram riskam vienu rīcības plānu.
  6. Atzīmē bīstamāko risku.
  7. Pieraksti vienu secinājumu: vai plāns iekļaujas pieejamajā laikā.

Gatavs, kad: kopējais stundu skaits nepārsniedz tavu pieejamo laiku, un katram riskam ir plāns B.

Papildu uzdevums - Uzraksti Definition of Done

Ja pamatdarbs ir gatavs, definē, ko nozīmē 'gatavs' visam projektam.

  1. Pievieno sadaļu ## Definition of Done.
  2. Uzraksti piecus kritērijus ar rūtiņām - [ ].
  3. Iekļauj kritēriju - [ ] Visi testi failā test_104.py iziet (OK) un vienu kritēriju par dokumentāciju.
  4. Pārbaudi, vai neviens kritērijs nav viedokļa jautājums.
  5. Salīdzini tos ar 10.2 stundas akceptēšanas kritērijiem.

Gatavs, kad: visi pieci kritēriji ir pārbaudāmi ar jā vai nē un nepārklājas savā starpā.

Koda piemērs

# Krustiņi un nullītes - izstrādes ceļa karte
## Starprezultāti
1. Laukums un gājieni (4 h) - gatavs, kad divi spēlētāji pēc kārtas ieliek X un O.
2. Uzvarētāja pārbaude (3 h) - gatavs, kad visi testi failā test_104.py iziet (OK).
3. Spēles cikls (3 h) - gatavs, kad spēle beidzas ar uzvaru vai neizšķirtu.

## Riski un risinājumi
- Nepareiza ievade (burti, aizņemta rūtiņa) -> pārbaude ar try/except un if.
- Uzvaras pārbaude nepamana diagonāli -> tests test_x_diagonale to atklāj.

## Definition of Done
- [ ] Visi testi failā test_104.py iziet (OK)
- [ ] README apraksta, kā palaist spēli un testus
