Atkārtojuma tests: 11.5 Interaktivitāte pārlūkprogrammā

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Kāpēc ar parastu mainīgo klikski = 0 skaitlis nepieaug pāri 1?

Katrs klikšķis palaiž visu failu no augšas. Rinda klikski = 0 izpildās katru reizi, tāpēc iepriekšējā vērtība pazūd. Atkārto: 11.5 — 1. uzdevums — Saglabā skaitītāju ar session_state ↗

2. Ko dara šis kods? 
if "klikski" not in st.session_state:
    st.session_state.klikski = 0

st.session_state saglabājas starp pārlādēm. Pārbaude not in nodrošina, ka 0 tiek ielikts tikai tad, kad vērtības vēl nav. Atkārto: 11.5 — Teorija: session_state un interaktivitāte ↗

3. Lietotājs nospiež pogu piecas reizes. Ko lapa rāda? 
if "klikski" not in st.session_state:
    st.session_state.klikski = 0
if st.button("Klikšķini mani"):
    st.session_state.klikski += 1
st.write(f"Klikšķi: {st.session_state.klikski}")

Vērtība glabājas session_state, tāpēc katrs klikšķis pieskaita 1 iepriekšējai vērtībai: 0 → 5. Atkārto: 11.5 — 1. uzdevums — Saglabā skaitītāju ar session_state ↗

4. Ko dara clear_on_submit=True rindā with st.form("forma", clear_on_submit=True):?

Pēc pogas nospiešanas ievades lauks kļūst tukšs, un var uzreiz rakstīt nākamo uzdevumu. Atkārto: 11.5 — 2. uzdevums — Uzbūvē To-Do sarakstu ar formu ↗

5. Kāpēc katrai dzēšanas pogai sarakstā vajag savu key?

Visām dzēšanas pogām ir vienāds uzraksts. Unikāls key, piemēram ar uzdevuma numuru, ļauj tās atšķirt. Atkārto: 11.5 — 3. uzdevums — Pievieno dzēšanu un notīrīšanu ↗
