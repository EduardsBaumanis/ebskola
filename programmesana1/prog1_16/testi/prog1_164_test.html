Atkārtojuma tests: 16.3 REST API izstrāde

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Kuru HTTP metodi REST API izmanto, lai izveidotu jaunu ierakstu?

GET lasa, POST izveido, PUT un PATCH atjaunina, DELETE dzēš. Atkārto: 16.3 — Teorija: REST principi ↗

2. Klients atsūtīja rezultātu bez vārda. Kādu statusa kodu jāatgriež serverim?

400 (Bad Request) nozīmē, ka klients atsūtīja nederīgus datus. Atbildē jāpaskaidro, kas nav kārtībā. Atkārto: 16.3 — 2. uzdevums — Pievieno validāciju un pareizus statusa kodus ↗

3. Kurš pieprasījums pēc REST principiem dzēš spēlētāju ar id 42?

URL nosauc resursu (/api/speletaji/42), bet metode — darbību (DELETE). Atkārto: 16.3 — Teorija: REST principi ↗

4. Serverī ir request.args.get("limit", 100, type=int). Ko tas atgriež, ja atver /api/rezultati?limit=abc?

type=int mēģina pārvērst vērtību skaitlī. Ja tas neizdodas, tiek atgriezta noklusējuma vērtība, un serveris nesalūzt. Atkārto: 16.3 — 3. uzdevums — Pievieno filtrēšanu un kārtošanu ↗

5. Ko izdrukā šis kods, kas sagatavo TOP sarakstu? 
rezultati = [{"vards": "Anna", "punkti": 120},
             {"vards": "Jānis", "punkti": 95},
             {"vards": "Eva", "punkti": 145}]
limit = 2
top = sorted(rezultati, key=lambda r: r["punkti"], reverse=True)[:limit]
for r in top:
    print(r["vards"])

Sakārto pēc punktiem no lielākā (reverse=True) un paņem pirmos limit = 2 ierakstus. Atkārto: 16.3 — 3. uzdevums — Pievieno filtrēšanu un kārtošanu ↗
