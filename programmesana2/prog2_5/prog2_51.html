5.1 File I/O (failu ievade un izvade) Godot vidē

Sasniedzamais rezultāts: Apgūt FileAccess (failu piekļuve) class (klasi) un Godot failu sistēmu.

SR 2.4.17. Failu un ārējās krātuves SR 2.4.4. Iegūst un apstrādā datus

Teorija: failu ievade un izvade (File I/O) ar FileAccess

Virtuālie ceļi res:// un user:// Godot vidē

Lai programma darbotos vienādi dažādās operētājsistēmās (Linux, Windows, macOS vai mobilajās ierīcēs), Godot neizmanto konkrēta datora cietos diska ceļus (piemēram, C:\...), bet divus virtuālos prefiksus. To atšķirību var salīdzināt ar tipogrāfijā iespiestu mācību grāmatu un personīgo pierakstu kladi:

  • res:// (resources — projekta resursi): norāda uz projekta mapi izstrādes laikā. Kad lietotni eksportē gatavā izpildfailā, šie resursi tiek iepakoti vienotā tikai lasāmā (read-only) arhīvā, tāpēc programmas darbības laikā res:// mapē rakstīt jaunus datus nedrīkst.
  • user:// (lokālā lietotāja krātuve): norāda uz operētājsistēmas piešķirtu mapi konkrētā lietotāja profilā, kurā lietotnei ir pilnas tiesības gan lasīt, gan rakstīt failus (Godot redaktorā šai mapei atbilst izvēlne Project -> Open User Data Folder):
// Nemainīgie projekta resursi (pēc eksportēšanas — tikai lasāmi):
string veidnesCels = "res://Dati/noklusejums.txt";

// Lietotāja datu mape (atļauta gan lasīšana, gan rakstīšana):
string lietotajaFails = "user://piezimes.txt";

// Ja atkļūdošanai vajag redzēt pilno ceļu operētājsistēmā:
GD.Print(ProjectSettings.GlobalizePath("user://"));

Teksta un bināro datu rakstīšana un nolasīšana (FileAccess)

Failu apstrādei Godot piedāvā klasi FileAccess, ko atver ar FileAccess.Open(cels, rezims), norādot režīmu ModeFlags.Write (rakstīšanai — izveido jaunu vai pārraksta esošu failu) vai ModeFlags.Read (lasīšanai). C# priekšraksts using (līdzīgi kā Python with open(...)) nodrošina, ka bloka beigās fails tiek automātiski aizvērts un saglabāts diskā:

using Godot;

// Rakstīšana lietotāja datu mapē
using FileAccess fails = FileAccess.Open("user://ieraksti.txt", FileAccess.ModeFlags.Write);
if (fails != null)
{
    fails.StoreLine("Pirmā rinda (UTF-8)");
    fails.StoreString("Turpinājums");
}

// Droša nolasīšana, vispirms pārbaudot faila esamību
if (FileAccess.FileExists("user://ieraksti.txt"))
{
    using FileAccess lasit = FileAccess.Open("user://ieraksti.txt", FileAccess.ModeFlags.Read);
    if (lasit != null)
    {
        string vissTeksts = lasit.GetAsText(); // Vai pa rindām ar GetLine(), kamēr !lasit.EofReached()
    }
}

Pirms lasīšanas vienmēr pārbauda FileAccess.FileExists(...) un fails != null, lai pirmajā programmas palaišanas reizē trūkstošs fails neizraisītu kļūdu (līdzīgi kā apstrādājot FileNotFoundError). Bez teksta metodēm (StoreString, StoreLine, GetAsText, GetLine) pieejamas arī binārās metodes, piemēram, Store32(...) un Get32() 32 bitu veseliem skaitļiem. Rakstot vairākas vērtības binārā plūsmā, tās tiek noliktas baitos cita aiz citas bez nosaukumiem — kā numurētas kastes šaurā koridorā, tāpēc nolasīšana jāveic tieši tādā pašā secībā un ar tādiem pašiem tipiem kā rakstot:

string cels = "user://dati.bin";
using (FileAccess bin = FileAccess.Open(cels, FileAccess.ModeFlags.Write))
{
    if (bin != null)
    {
        bin.Store32((uint)2026); // 1. ieraksta gadu
        bin.Store32((uint)150);  // 2. ieraksta apjomu
    }
}

if (!FileAccess.FileExists(cels)) return; // Droša izeja, ja faila vēl nav
using FileAccess lasitBin = FileAccess.Open(cels, FileAccess.ModeFlags.Read);
if (lasitBin != null)
{
    int gads = (int)lasitBin.Get32();   // 1. nolasa gadu (2026)
    int apjoms = (int)lasitBin.Get32(); // 2. nolasa apjomu (150)
}

1. uzdevums

Ieraksti un nolasi teksta failu mapē user://

Kur strādāt: 1) Izveido jaunu Godot 4 .NET (C#) projektu ProceduralMaze ar mapēm Scenes/ un Scripts/.
2) Mapē Scenes/ izveido scēnu Scenes/FileDemo.tscn (Node sakne FileDemo) un piesaisti tai jaunu skriptu Scripts/FileDemo.cs.
3) Programmas darbības laikā dati tiks ierakstīti failā user://save.txt.

Pirmajā solī izveidosim 5. tēmas Godot projektu un ierakstīsim pirmo teksta failu operētājsistēmas lietotāja datu mapē user://.

  1. Atver Godot 4 (.NET versiju), izveido jaunu projektu ProceduralMaze un FileSystem panelī izveido divas mapes: Scenes/ un Scripts/.
  2. Izveido jaunu scēnu (Scene → New Scene → Other Node → Node), pārsauc saknes mezglu par FileDemo un saglabā scēnu kā Scenes/FileDemo.tscn.
  3. Piesaisti FileDemo mezglam jaunu C# skriptu Scripts/FileDemo.cs un tā metodē _Ready() ieraksti teksta saglabāšanas un nolasīšanas kodu: 
    using Godot;

public partial class FileDemo : Node
{
    private const string TextPath = "user://save.txt";

    public override void _Ready()
    {
        // 1. Ierakstām tekstu failā user://save.txt
        using (FileAccess writeFile = FileAccess.Open(TextPath, FileAccess.ModeFlags.Write))
        {
            if (writeFile != null)
            {
                writeFile.StoreString("Sveiks, fails! Šis teksts glabājas diskā.");
            }
        }

        // 2. Nolasām tekstu atpakaļ no faila
        using (FileAccess readFile = FileAccess.Open(TextPath, FileAccess.ModeFlags.Read))
        {
            if (readFile != null)
            {
                string content = readFile.GetAsText();
                GD.Print("[FileDemo] Nolasītais teksts: ", content);
            }
        }

        GD.Print("[FileDemo] Pilnais ceļš diskā: ", ProjectSettings.GlobalizePath("user://"));
    }
}
  4. Nospied Build (āmura ikonu augšējā labajā stūrī) un palaid scēnu ar F5 (izvēloties Scenes/FileDemo.tscn kā galveno scēnu).
  5. Pārbaudi Output paneli un atver Project → Open User Data Folder: pārliecinies, ka atvērtajā datora mapē ir parādījies fails save.txt, un atver to jebkurā teksta redaktorā.

Gatavs, kad: Output panelī izdrukājas Sveiks, fails! Šis teksts glabājas diskā. un fails save.txt ir redzams Open User Data Folder mapē.

2. uzdevums

Saglabā un ielādē spēles rezultātu ar SaveManager

Kur strādāt: 1) Mapē Scripts/ izveido jaunu C# failu Scripts/SaveManager.cs (klase ar metodēm SaveScore un LoadScore).
2) Esošajā failā Scripts/FileDemo.cs metodē _Ready() izsauc SaveScore(150) un LoadScore().

Izveidosim atsevišķu klasi SaveManager, kas saglabā 32 bitu veselu skaitli (spēles rezultātu) failā user://score.bin, un pārbaudīsim, ka rezultāts nepazūd arī pēc spēles aizvēršanas.

  1. Mapē Scripts/ izveido jaunu C# skriptu Scripts/SaveManager.cs un definē tajā metodes SaveScore(int score) un LoadScore(): 
    using Godot;

public partial class SaveManager : Node
{
    private const string ScorePath = "user://score.bin";

    public void SaveScore(int score)
    {
        using FileAccess file = FileAccess.Open(ScorePath, FileAccess.ModeFlags.Write);
        if (file != null)
        {
            file.Store32((uint)score);
            GD.Print($"[SaveManager] Rezultāts {score} saglabāts failā {ScorePath}");
        }
    }

    public int LoadScore()
    {
        using FileAccess file = FileAccess.Open(ScorePath, FileAccess.ModeFlags.Read);
        if (file != null)
        {
            int loaded = (int)file.Get32();
            GD.Print($"[SaveManager] Ielādēts rezultāts: {loaded}");
            return loaded;
        }
        return 0;
    }
}
  2. Atver failu Scripts/FileDemo.cs un metodē _Ready() izveido SaveManager eksemplāru, saglabā rezultātu 150 un uzreiz to nolasi: 
    SaveManager saveManager = new();
saveManager.SaveScore(150);
int score = saveManager.LoadScore();
GD.Print("[FileDemo] Pašreizējais rekords: ", score);
  3. Nospied Build un palaid scēnu (F5): pārliecinies, ka Output panelī parādās Rezultāts 150 saglabāts un Ielādēts rezultāts: 150.
  4. Pārbaudi pastāvīgumu starp sesijām: failā Scripts/FileDemo.cs aizkomentē rindu // saveManager.SaveScore(150);, nospied Build un palaid spēli no jauna (F5) — pārliecinies, ka LoadScore() no diska joprojām nolasa 150!

Gatavs, kad: arī ar aizkomentētu SaveScore(150) rindu jaunā spēles palaišanā no diska tiek nolasīts rezultāts 150.

3. uzdevums

Apstrādā trūkstošu failu bez kļūdas

Kur strādāt: 1) Atver lietotāja datu mapi (Project → Open User Data Folder) un izdzēs score.bin.
2) Failā Scripts/SaveManager.cs metodes LoadScore() sākumā pievieno FileAccess.FileExists(...) pārbaudi.
3) Atbildes uz jautājumiem pieraksti projekta saknes failā README.md.

Kad spēlētājs palaiž spēli pašā pirmajā reizē, saglabāšanas faila diskā vēl nav. Pārbaudīsim, kas notiek, ja mēģina lasīt neesošu failu, un pievienosim drošu pārbaudi.

  1. Atver Project → Open User Data Folder un izdzēs failu score.bin (pārliecinies, ka failā Scripts/FileDemo.cs rinda saveManager.SaveScore(150); joprojām ir aizkomentēta).
  2. Palaid spēli (F5) un apskati Godot apakšējo cilni Debugger → Errors: mēģinājums atvērt neesošu failu lasīšanai (`ModeFlags.Read`) atgriež null un reģistrē kļūdu.
  3. Atver failu Scripts/SaveManager.cs un metodes LoadScore() pašā sākumā pievieno FileAccess.FileExists(ScorePath) pārbaudi: 
    public int LoadScore()
{
    if (!FileAccess.FileExists(ScorePath))
    {
        GD.Print("[SaveManager] Saglabāšanas fails vēl neeksistē — atgriežam 0.");
        return 0;
    }

    using FileAccess file = FileAccess.Open(ScorePath, FileAccess.ModeFlags.Read);
    if (file != null)
    {
        int loaded = (int)file.Get32();
        GD.Print($"[SaveManager] Ielādēts rezultāts: {loaded}");
        return loaded;
    }
    return 0;
}
  4. Nospied Build un palaid spēli (F5) ar izdzēstu score.bin failu: pārliecinies, ka Debugger → Errors cilnē vairs nav nevienas kļūdas un Output panelī izdrukājas noklusējuma vērtība 0.
  5. Failā Scripts/FileDemo.cs atkomentē rindu saveManager.SaveScore(150);, lai saglabāšana atkal strādātu, un pārbaudi, ka rezultāts 150 tiek saglabāts un nolasīts.
  6. Projekta saknē izveido failu README.md un īsi pieraksti:
    • kāpēc spēlētāja progresu nedrīkst rakstīt mapē res://, bet jāraksta user://;
    • kā FileAccess.FileExists(...) pārbaude pasargā spēli pirmajā palaišanas reizē (līdzīgi kā FileNotFoundError apstrāde Python valodā).

Gatavs, kad: ar izdzēstu score.bin failu spēle bez kļūdām atgriež 0, bet pēc saglabāšanas atkal ielādē 150, un secinājumi ir pierakstīti README.md.

Papildu uzdevums — Saglabā vairākas vērtības binārā failā un pārbaudi secību

Kur strādāt: Papildini Scripts/SaveManager.cs ar metodēm SaveStats(int hp, int level, string playerName) un LoadStats(), un izsauc tās no Scripts/FileDemo.cs metodes _Ready().

Ja pamatdarbs ir gatavs, pārbaudi praksē, kāpēc binārajā failā nolasīšanas secībai ir precīzi jāsakrīt ar rakstīšanas secību.

  1. Failā Scripts/SaveManager.cs pievieno metodi SaveStats(int hp, int level, string name), kas failā user://stats.bin pēc kārtas ieraksta file.Store32((uint)hp);, file.Store32((uint)level); un file.StorePascalString(name);.
  2. Tajā pašā failā pievieno metodi LoadStats(), kas šīs trīs vērtības nolasa tieši tādā pašā secībā ar Get32(), Get32() un GetPascalString() un izdrukā konsolē.
  3. Pamēģini metodē LoadStats() apmainīt vietām hp un level nolasīšanu un pieraksti README.md, kas notiek ar nolasītajām vērtībām.

Gatavs, kad: visas trīs vērtības (hp, level, name) ielādējas pareizi un esi novērojis, kas notiek, sajaucot nolasīšanas secību.

Ko sagatavo

Stundas mērķis: Tava spēle saglabā tekstu un skaitlisku rezultātu user:// mapē, ielādē to pēc restarta un neizmet kļūdu, ja saglabāšanas faila vēl nav.

GitHub krātuvē jābūt:

  • Scēnai Scenes/FileDemo.tscn un skriptiem Scripts/SaveManager.cs un Scripts/FileDemo.cs.
  • Ekrānuzņēmumam ar Output paneli un atvērtu user:// mapi, kurā redzami izveidotie faili.
  • Failam README.md ar skaidrojumu, ar ko user:// atšķiras no res:// un kā darbojas FileAccess.FileExists(...) pārbaude.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • file is null (fails nav pieejams): Permission denied (piekļuve liegta) vai ceļš nepareizs.
  • Encoding errors (kodējuma kļūdas): UTF-8 ir noklusējuma, bet pārbaudi ar speciāliem simboliem.
  • res:// ir read-only (tikai lasāms): Production build (buildos) to nevar rakstīt - lieto user://.
