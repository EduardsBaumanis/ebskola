5.1 File I/O (failu ievade un izvade) Godot vidē

Stundas uzdevums: Apgūt FileAccess (failu piekļuve) class (klasi) un Godot failu sistēmu.

SR 2.4.17. Failu un ārējās krātuves SR 2.4.4. Iegūst un apstrādā datus

Teorija: failu ievade un izvade (File I/O) ar FileAccess

Virtuālie ceļi res:// un user:// Godot vidē

Lai programma darbotos vienādi dažādās operētājsistēmās (Linux, Windows, macOS vai mobilajās ierīcēs), Godot neizmanto konkrēta datora cietos diska ceļus (piemēram, C:\...), bet divus virtuālos prefiksus. To atšķirību var salīdzināt ar tipogrāfijā iespiestu mācību grāmatu un personīgo pierakstu kladi:

  • res:// (resources — projekta resursi): norāda uz projekta mapi izstrādes laikā. Kad lietotni eksportē gatavā izpildfailā, šie resursi tiek iepakoti vienotā tikai lasāmā (read-only) arhīvā, tāpēc programmas darbības laikā res:// mapē rakstīt jaunus datus nedrīkst.
  • user:// (lokālā lietotāja krātuve): norāda uz operētājsistēmas piešķirtu mapi konkrētā lietotāja profilā, kurā lietotnei ir pilnas tiesības gan lasīt, gan rakstīt failus (Godot redaktorā šai mapei atbilst izvēlne Project -> Open User Data Folder):
// Nemainīgie projekta resursi (pēc eksportēšanas — tikai lasāmi):
string veidnesCels = "res://Dati/noklusejums.txt";

// Lietotāja datu mape (atļauta gan lasīšana, gan rakstīšana):
string lietotajaFails = "user://piezimes.txt";

// Ja atkļūdošanai vajag redzēt pilno ceļu operētājsistēmā:
GD.Print(ProjectSettings.GlobalizePath("user://"));

Teksta un bināro datu rakstīšana un nolasīšana (FileAccess)

Failu apstrādei Godot piedāvā klasi FileAccess, ko atver ar FileAccess.Open(cels, rezims), norādot režīmu ModeFlags.Write (rakstīšanai — izveido jaunu vai pārraksta esošu failu) vai ModeFlags.Read (lasīšanai). C# priekšraksts using (līdzīgi kā Python with open(...)) nodrošina, ka bloka beigās fails tiek automātiski aizvērts un saglabāts diskā:

using Godot;

// Rakstīšana lietotāja datu mapē
using FileAccess fails = FileAccess.Open("user://ieraksti.txt", FileAccess.ModeFlags.Write);
if (fails != null)
{
    fails.StoreLine("Pirmā rinda (UTF-8)");
    fails.StoreString("Turpinājums");
}

// Droša nolasīšana, vispirms pārbaudot faila esamību
if (FileAccess.FileExists("user://ieraksti.txt"))
{
    using FileAccess lasit = FileAccess.Open("user://ieraksti.txt", FileAccess.ModeFlags.Read);
    if (lasit != null)
    {
        string vissTeksts = lasit.GetAsText(); // Vai pa rindām ar GetLine(), kamēr !lasit.EofReached()
    }
}

Pirms lasīšanas vienmēr pārbauda FileAccess.FileExists(...) un fails != null, lai pirmajā programmas palaišanas reizē trūkstošs fails neizraisītu kļūdu (līdzīgi kā apstrādājot FileNotFoundError). Bez teksta metodēm (StoreString, StoreLine, GetAsText, GetLine) pieejamas arī binārās metodes, piemēram, Store32(...) un Get32() 32 bitu veseliem skaitļiem. Rakstot vairākas vērtības binārā plūsmā, tās tiek noliktas baitos cita aiz citas bez nosaukumiem — kā numurētas kastes šaurā koridorā, tāpēc nolasīšana jāveic tieši tādā pašā secībā un ar tādiem pašiem tipiem kā rakstot:

string cels = "user://dati.bin";
using (FileAccess bin = FileAccess.Open(cels, FileAccess.ModeFlags.Write))
{
    if (bin != null)
    {
        bin.Store32((uint)2026); // 1. ieraksta gadu
        bin.Store32((uint)150);  // 2. ieraksta apjomu
    }
}

if (!FileAccess.FileExists(cels)) return; // Droša izeja, ja faila vēl nav
using FileAccess lasitBin = FileAccess.Open(cels, FileAccess.ModeFlags.Read);
if (lasitBin != null)
{
    int gads = (int)lasitBin.Get32();   // 1. nolasa gadu (2026)
    int apjoms = (int)lasitBin.Get32(); // 2. nolasa apjomu (150)
}

Kā šo izmantot projektā

Atceries: ar redzamu efektu redaktorā nepietiek. Paskaidro, kura C# class glabā stāvokli, kura method (metode) to maina un kā Godot node (mezgls) struktūra izmanto šo kodu.

Pārbaudi: C# kods pārbauda failu kļūdas, validē datus, izmanto versijas lauku un pamato time complexity (algoritmu sarežģītību).

Praktiskie uzdevumi

1. uzdevums -

Ieraksti un nolasi failu

Kur strādāt: Izveido Scripts/FileDemo.cs un piesaisti to Node saknei scēnā Scenes/FileDemo.tscn. Rakstīšanas un lasīšanas izmēģinājumu ievieto _Ready(); user://save.txt ir programmas izveidotais datu fails.

Beigās tava spēle pratīs saglabāt tekstu diskā.

  1. Pārliecinies, ka faila sākumā ir using Godot;.
  2. Atver failu ar using FileAccess f = FileAccess.Open("user://save.txt", FileAccess.ModeFlags.Write);.
  3. Pārbaudi if (f != null) pirms rakstīšanas.
  4. Ieraksti tekstu ar f.StoreString("Sveiks, fails!");.
  5. Atver failu no jauna režīmā Read un nolasi ar GetAsText().
  6. Izdrukā nolasīto tekstu.
  7. Atrodi failu diskā: Godot izvēlnē Project -> Open User Data Folder.
using FileAccess f = FileAccess.Open("user://save.txt", FileAccess.ModeFlags.Write);
if (f != null)
{
    f.StoreString("Sveiks, fails!");
}

using FileAccess rf = FileAccess.Open("user://save.txt", FileAccess.ModeFlags.Read);
if (rf != null)
{
    GD.Print(rf.GetAsText());
}

Gatavs, kad: Output panelī izdrukājas tas pats teksts, ko ierakstīji, un fails ir atrodams lietotāja dati mapē.

2. uzdevums -

Saglabā spēles rezultātu

Kur strādāt: Izveido Scripts/SaveManager.cs ar parastu SaveManager klasi un metodēm SaveScore() un LoadScore(). To izsaukumus raksti Scripts/FileDemo.cs metodē _Ready(), aizstājot 1. uzdevuma teksta izmēģinājumu. Otrajā palaišanā atstāj tikai ielādi, lai nepārrakstītu saglabāto rezultātu.

Beigās rezultāts saglabāsies arī pēc spēles aizvēršanas.

  1. Izveido class SaveManager ar method public void SaveScore(int score).
  2. Ieraksti failā rezultātu ar file.Store32((uint)score);.
  3. Uzraksti method public int LoadScore(), kas to nolasa ar (int)file.Get32().
  4. Izsauc saglabāšanu ar vērtību 150.
  5. Aizver spēli pilnībā un palaid no jauna.
  6. Izdrukā ielādēto rezultātu.
  7. Pieraksti, kāpēc user:// ir labāks par res:// saglabāšanai.
public void SaveScore(int score)
{
    using FileAccess file = FileAccess.Open("user://save.txt", FileAccess.ModeFlags.Write);
    if (file != null) file.Store32((uint)score);
}

Gatavs, kad: pēc spēles aizvēršanas un atvēršanas ielādētais rezultāts joprojām ir 150.

3. uzdevums -

Apstrādā trūkstošu failu

Kur strādāt: Faila esamības pārbaudi pievieno Scripts/SaveManager.cs metodes LoadScore() sākumā. Trūkstoša faila pārbaudei izdzēs user://save.txt, kuru atrodi ar Open User Data Folder.

Beigās pirmā spēles palaišana vairs neradīs kļūdu.

  1. Izdzēs saglabāto failu no lietotāja dati mapes.
  2. Palaid spēli un pieraksti, kas notiek ar LoadScore().
  3. Pievieno pārbaudi if (!FileAccess.FileExists("user://save.txt")).
  4. Atgriez tādā gadījumā noklusējuma vērtību 0.
  5. Palaid vēlreiz ar izdzēstu failu un pārbaudi rezultātu.
  6. Saglabā jaunu rezultātu un pārbaudi, ka tas ielādējas.
  7. Pieraksti, ar ko šī pārbaude līdzinās Python FileNotFoundError apstrādei.

Gatavs, kad: ar izdzēstu failu spēle rāda rezultātu 0 un neizmet kļūdu.

Papildu uzdevums - Saglabā vairākas vērtības

Kur strādāt: Datu rakstīšanu un lasīšanu papildini Scripts/SaveManager.cs; izmēģinājuma vērtības un izdrukas maini Scripts/FileDemo.cs metodē _Ready().

Ja pamatdarbs ir gatavs, saglabā visu spēlētāja stāvokli.

  1. Papildini saglabāšanu ar HP (dzīvības punkti), līmeni un spēlētāja vārdu.
  2. Ieraksti tos noteiktā secībā ar Store32 un StoreString.
  3. Nolasi tos TIEŠI tādā pašā secībā.
  4. Samaini apzināti divas nolasīšanas rindas vietām un palaid.
  5. Pieraksti, kāpēc secība ir tik svarīga.

Gatavs, kad: visas vērtības ielādējas pareizi, bet, samainot nolasīšanas secību, dati sajūk.

Ko sagatavo

Stundas mērķis: Tava spēle saglabā rezultātu failā user:// mapē, ielādē to pēc restarta un neizmet kļūdu, ja saglabāšanas faila vēl nav.

GitHub krātuvē jābūt:

  1. Fails SaveManager.cs.
  2. Divi ekrānuzņēmumi: rezultāts pēc saglabāšanas un tas pats rezultāts pēc spēles restarta.
  3. README.md: ar ko user:// atšķiras no res:// un kā tu apstrādāji trūkstošu failu.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Biežākās kļūdas

  • file is null (fails nav pieejams): Permission denied (piekļuve liegta) vai ceļš nepareizs.
  • Encoding errors (kodējuma kļūdas): UTF-8 ir noklusējuma, bet pārbaudi ar speciāliem simboliem.
  • res:// ir read-only (tikai lasāms): Production build (buildos) to nevar rakstīt - lieto user://.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

using Godot;

public partial class SaveSystem : Node
{
    public void SaveText(string filename, string content)
    {
        string path = "user://" + filename;
        using FileAccess file = FileAccess.Open(path, FileAccess.ModeFlags.Write);
        if (file != null)
        {
            file.StoreString(content);
            GD.Print("Saglabāts: ", path);
        }
        else
        {
            GD.PrintErr("Neizdevās atvērt: ", path);
        }
    }

    public string LoadText(string filename)
    {
        string path = "user://" + filename;
        if (!FileAccess.FileExists(path)) return "";

        using FileAccess file = FileAccess.Open(path, FileAccess.ModeFlags.Read);
        return file != null ? file.GetAsText() : "";
    }
}
