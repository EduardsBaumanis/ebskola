Teorija: Big O (lielā O notācija) un optimization (optimizācija)

Big O notation (lielā O notācija) apraksta, kā algorithm (algoritma) laiks pieaug ar data (datu) apjomu.

OAprakstsPiemērs
O(1)KonstantsDirect array access (tieša piekļuve masīva elementam)
O(log n)LogaritmisksBinary search (binārā meklēšana)
O(n)LineārsIteration (iterācija)
O(n log n)LinearitmisksQuicksort (ātrā kārtošana), Mergesort (kārtošana ar sapludināšanu)
O(n²)KvadrātisksNested loops (ligzdoti cikli)

// O(n) - lineārs
for (int i = 0; i < n; i++)
{
    GD.Print(arr[i]);
}

// O(n²) - kvadrātisks (slikti lielam n)
for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        if (arr[i] == arr[j]) { /* ... */ }
    }
}

// O(log n) - bināra meklēšana
int BinarySearch(List<int> arr, int target)
{
    int lo = 0;
    int hi = arr.Count - 1;
    while (lo <= hi)
    {
        int mid = (lo + hi) / 2;
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Praktiskie uzdevumi

1. uzdevums -

Izmēri divu algorithm (algoritmu) laiku

Beigās tu redzēsi, ka ligzdots loop (cikls) aug daudz straujāk.

  1. Uzraksti function (funkciju) ar vienu loop (ciklu) pār 1000 element (elementiem).
  2. Uzraksti otru function (funkciju) ar diviem ligzdotiem loop (cikliem) pār to pašu list (sarakstu).
  3. Izmēri abas ar ulong t0 = Time.GetTicksUsec(); pirms un pēc.
  4. Izdrukā abus laikus mikrosekundēs.
  5. Atkārto mērījumu ar 100 element (elementiem) un pieraksti abus rezultātus.
  6. Izrēķini, cik reižu pieauga katras function (funkcijas) laiks.
  7. Pieraksti, kura no tām ir O(n) un kura O(n kvadrātā).

Gatavs, kad: palielinot data (datus) 10 reizes, viena loop (cikla) laiks aug ~10 reizes, bet ligzdotā - ~100 reizes.

2. uzdevums -

Atrodi un salabo lēno vietu savā spēlē

Beigās tava spēle darbosies raitāk.

  1. Palaid savu spēli un atver Debugger (atkļūdotājs) -> Profiler (profilētājs).
  2. Nospied Start un spēlē 30 sekundes.
  3. Atrodi list (sarakstā) function (funkciju), kas aizņem visvairāk laika.
  4. Pieraksti tās nosaukumu un laiku.
  5. Atrodi code (kodā) vietu, kur tā tiek izsaukta katrā frame (kadrā) bez vajadzības.
  6. Pārvieto to ārpus loop (cikla) vai izsauc retāk.
  7. Būvē un palaid profiler (profileri) vēlreiz.

Gatavs, kad: profiler (profilerī) tavas izlabotās function (funkcijas) laiks ir manāmi mazāks nekā pirms labojuma.

3. uzdevums -

Pierādi uzlabojumu ar mērījumu

Beigās tev būs skaitļi, nevis sajūta.

  1. Pieraksti tabulā FPS (kadri sekundē) pirms labojuma un pēc tā.
  2. Pieraksti arī profiler (profilera) laiku abos gadījumos.
  3. Palaid spēli ar dubultu object (objektu) skaitu un atkārto mērījumu.
  4. Pieraksti, vai uzlabojums saglabājas arī ar lielāku slodzi.
  5. Izvēlies vēl vienu vietu, ko varētu uzlabot, un pieraksti to.
  6. Pieraksti, kāpēc nav vērts optimizēt code (kodu), kas izpildās reti.
  7. Veic commit (izmaiņu fiksējums) ar ziņu par veikto optimization (optimizāciju).

Gatavs, kad: tavā tabulā ir četri skaitļi, kas parāda uzlabojumu gan ar parasto, gan ar dubultu slodzi.

Biežākās kļūdas

  • Mēģini optimizēt bez profiling (profilēšanas): 'Premature optimization (optimizācija) is root (sakne) of all evil' - vienmēr profilē vispirms.
  • O(n²) paslēpts API (lietojumprogrammas saskarne): Some Godot function (funkcijas) iekšēji ir O(n) - find_child loop (cikls) = O(n²).
  • Cache invalidation (kešatmiņas atjaunināšana): Aizmirsis update cache (kešatmiņa) pēc data (datu) izmaiņas - bugs (kļūdas).

using Godot;
using System.Collections.Generic;

// Spatial hash priekš ātras kolīzijas
public class SpatialHash
{
    private const int CellSize = 64;
    private readonly Dictionary<long, List<Node2D>> grid = new();

    private long CellKey(int cx, int cy)
    {
        return ((long)cx << 32) | (uint)cy;
    }

    public void Rebuild(IEnumerable<Node2D> objects)
    {
        grid.Clear();
        foreach (Node2D obj in objects)
        {
            Vector2 pos = obj.Position;
            int cx = (int)(pos.X / CellSize);
            int cy = (int)(pos.Y / CellSize);
            long key = CellKey(cx, cy);
            if (!grid.ContainsKey(key)) grid[key] = new List<Node2D>();
            grid[key].Add(obj);
        }
    }

    public List<Node2D> GetNearby(Vector2 pos)
    {
        int cx = (int)(pos.X / CellSize);
        int cy = (int)(pos.Y / CellSize);
        List<Node2D> result = new();
        for (int dx = -1; dx <= 1; dx++)
        {
            for (int dy = -1; dy <= 1; dy++)
            {
                if (grid.TryGetValue(CellKey(cx + dx, cy + dy), out List<Node2D> cell))
                {
                    result.AddRange(cell);
                }
            }
        }
        return result;
    }
}
1000 object (objektu) kolīzijas pārbaude: bez optimization (optimizācijas) - 5 ms, ar spatial hash (jaucējvērtība) - 0.3 ms.
