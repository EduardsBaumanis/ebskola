Teorija: Save (saglabāt) system (sistēmas) architecture (arhitektūra)

Profesionāla save (saglabāt) system (sistēma) sastāv no vairākiem komponentiem:

  • SaveManager - galvenais koordinators.
  • Saveable interfeiss - visi saglabājami object (objekti) to implementē.
  • Save slots (saglabāšanas vieta) - vairāki save file (saglabāšanas faili) (slot1.json, slot2.json, ...).
  • Autosave (automātiskā saglabāšana) - automātiska save (saglabāšana) ik pa N minūtēm vai pie checkpoint.
using Godot;
using Godot.Collections;
using System.Collections.Generic;

public interface ISaveable
{
    Dictionary SaveState();
    void LoadState(Dictionary state);
}

public partial class SaveManager : Node
{
    private readonly List<ISaveable> saveables = new();

    public void RegisterSaveable(ISaveable saveable)
    {
        saveables.Add(saveable);
    }

    public void SaveToSlot(int slot) { }
    public void LoadFromSlot(int slot) { }
}

Praktiskie uzdevumi

1. uzdevums -

Izveido SaveManager ar save slot (saglabāšanas vietām)

Beigās spēlētājs varēs izvēlēties, kurā vietā saglabāt.

  1. Izveido class (klasi) SaveManager ar method (metodi) private string SlotPath(int slot).
  2. Atgriez tajā path (ceļu) user://slot1.json atbilstoši numuram.
  3. Uzraksti method (metodes) public void Save(int slot) un public bool Load(int slot).
  4. Saglabā dažādus data (datus) slotos 1 un 2.
  5. Ielādē save slot (saglabāšanas vietu) 1 un pārbaudi, ka data (dati) ir pareizie.
  6. Ielādē save slot (saglabāšanas vietu) 2 un salīdzini.
  7. Uzraksti method (metodi), kas pasaka, kuri sloti vispār eksistē.

Gatavs, kad: abi sloti glabā atšķirīgus data (datus), un method (metode) pareizi pasaka, kuri sloti ir aizpildīti.

2. uzdevums -

Liec object (objektiem) saglabāt sevi pašiem

Beigās katrs object (objekts) pats zinās, ko par sevi saglabāt.

  1. Izveido interfeisu public interface ISaveable ar divām method (metodēm).
  2. Pieteic tajā Dictionary SaveState();.
  3. Pieteic arī void LoadState(Dictionary state);.
  4. Liec spēlētāja class (klasei) implementēt ISaveable un abas method (metodes).
  5. Liec arī inventory (inventāra) class (klasei) to pašu.
  6. Savāc SaveManager visus ISaveable object (objektus) vienā list (sarakstā).
  7. Izsauc loop (ciklā) katram SaveState() un saliec rezultātus vienā Dictionary (vārdnīca).

Gatavs, kad: viens Save() izsaukums saglabā gan spēlētāju, gan inventory (inventāru), un SaveManager nezina to iekšējo uzbūvi.

3. uzdevums -

Pievieno autosave (automātiskā saglabāšana) un version (versiju)

Beigās spēle saglabāsies pati, un vecie file (faili) neradīs kļūdas.

  1. Pievieno saglabātajam Dictionary (vārdnīca) field (lauku) version ar value (vērtību) 1.
  2. Pārbaudi ielādējot, vai version (versija) sakrīt.
  3. Izdrukā brīdinājumu un lieto noklusējumus, ja version (versija) ir citāda.
  4. Pievieno Timer (taimeris) node (mezglu), kas ik pēc 60 sekundēm izsauc autosave (automātiskā saglabāšana).
  5. Saglabā autosave (automātiskā saglabāšana) atsevišķā save slot (saglabāšanas vietā), lai tas nepārrakstītu spēlētāja save slot (saglabāšanas vietu).
  6. Palaid spēli un pagaidi vienu autosave (automātiskā saglabāšana) loop (ciklu).
  7. Nomaini file (failā) version (versiju) uz 2 un pārbaudi brīdinājumu.

Gatavs, kad: autosave (automātiskā saglabāšana) file (fails) parādās pats, un ar nepareizu version (versiju) spēle brīdina, nevis avarē.

Papildu uzdevums - Parādi save slot (saglabāšanas vietu) menu (izvēlni)

Ja pamatdarbs ir gatavs, ļauj slotus izvēlēties uz screen (ekrāna).

  1. Izveido UI (lietotāja saskarne) ar trim button (pogām) - pa vienai katram slotam.
  2. Parādi pie katras, vai slots (saglabāšanas vietas) ir tukšs vai aizpildīts.
  3. Ielādē attiecīgo save slot (saglabāšanas vietu), nospiežot button (pogu).
  4. Pievieno button (pogu) slota dzēšanai.
  5. Pārbaudi, ka pēc dzēšanas slots (saglabāšanas vietas) rāda 'tukšs'.

Gatavs, kad: menu (izvēlnē) redzams katra slota statuss, un slotus var ielādēt un dzēst ar button (pogām).

Biežākās kļūdas

  • Save (saglabāt) file (fails) fragmented: Save (saglabāt) daļas atsevišķos file (failos) vs viens - izvēlies vienu pieeju.
  • Race condition (sacensības stāvoklis): Save (saglabāt) un load (ielādēt) notiek vienlaikus - lieto mutex (savstarpējās izslēgšanas slēdzene) vai sekvenciāli.

Code sample (koda piemērs) (paplašināts)

using Godot;
using Godot.Collections;
using System.Collections.Generic;

public partial class SaveManager : Node
{
    private readonly List<Node> saveables = new();
    private float autosaveTimer = 0.0f;

    public override void _Process(double delta)
    {
        autosaveTimer += (float)delta;
        if (autosaveTimer >= 300.0f)  // 5 min
        {
            SaveToSlot(0);  // 0 = autosave
            autosaveTimer = 0.0f;
        }
    }

    public void SaveToSlot(int slot)
    {
        Dictionary allData = new();
        foreach (Node node in saveables)
        {
            if (node.HasMethod("SaveState"))
            {
                allData[node.GetPath().ToString()] = node.Call("SaveState");
            }
        }
        allData["timestamp"] = Time.GetUnixTimeFromSystem();
        allData["version"] = 1;

        string path = $"user://save_{slot}.json";
        using FileAccess file = FileAccess.Open(path, FileAccess.ModeFlags.Write);
        file?.StoreString(Json.Stringify(allData, "  "));
    }
}
3 save slot (saglabāšanas vieta) ar metadata (metadatu) (level, time played, last save (saglabāt)), autosave (automātiskā saglabāšana) ik 5 min, korekta load (ielādēt).
