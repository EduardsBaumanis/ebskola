5.6 Noslēguma project (projekts): Procedural (procedurālais) klases labirints

Stundas uzdevums: Pilnvērtīga procedural (procedurālā) klases labirinta spēle ar procedural generation (procedurālā ģenerēšana), save (saglabāt) system (sistēmu) un meta-progress (kopējais progress).

SR 2.4.1. Problem decomposition (problēmu dekompozīcija) SR 2.4.16. Data structure (datu struktūras) SR 2.4.17. File I/O (failu ievade un izvade) SR 2.4.19. Algorithm (algoritmi)

80 min plāns: Ievads un kritēriju pārruna (~10 min) · 1. uzdevums (~20 min) - savieno labirintu ar spēlētāju · 2. uzdevums (~25 min) - pievieno savācamos un šķēršļus · 3. uzdevums (~20 min) - pievieno meta-progression (meta-progresu) un save (saglabāšanu) · Iesniegšana (~5 min).

Pirms sāc: šis ir 5. tēmas noslēguma project (projekts). Izmanto 5.4 labirinta ģeneratoru un 5.3 save (saglabāšanas) system (sistēmu). Sāc ar TRIM līmeņiem, nevis desmit.

Teorija: Spēles apraksts

Procedural (procedurālais) klases labirints: spēlētājs iziet cauri nejauši ģenerētiem labirintiem, savāc bonusa materiālus, risina šķēršļus, kļūdas gadījumā zaudē konkrētā mēģinājuma progresu (run), bet meta-progress (kopējais progress) (kopējie XP (pieredzes punkti), atklātās class (klases)) saglabājas.

Galvenās function (funkcijas):

  • Procedurāli ģenerēti 10 līmeņu labirinti.
  • 3 spēlētāja class (klases) ar dažādām spējām.
  • 50+ materiālu un šķēršļu type (tipi).
  • Fināla izaicinājums katram 5. līmenim.
  • Save/load (saglabāšana/ielāde) starp session (sesijām) (meta-progress (kopējais progress)).
  • Procedural (procedurāla) bonusa materiālu ģenerēšana.

Kā šo izmantot project (projektā)

Atceries: ar redzamu efektu editor (redaktorā) nepietiek. Paskaidro, kura C# class (klase) glabā state (stāvokli), kura method (metode) to maina un kā Godot node (mezgls) structure (struktūra) izmanto šo code (kodu).

Pārbaudi: C# code (kods) pārbauda file (failu) kļūdas, validē data (datus), izmanto version (versijas) field (lauku) un pamato time complexity (algoritmu sarežģītību).

Praktiskie uzdevumi

1. uzdevums -

Savieno labirintu ar spēlētāju

Beigās varēsi iziet uzģenerētu labirintu un nokļūt nākamajā.

  1. Ievelc savu 5.4 labirinta ģeneratoru jaunā project (projektā) vai scene (scēnā).
  2. Novieto spēlētāju labirinta sākumā un izeju tālākajā stūrī.
  3. Pievieno izejai Area2D (2D saskares zona), kas nosaka, ka līmenis pabeigts.
  4. Uzģenerē jaunu labirintu, kad spēlētājs sasniedz izeju.
  5. Pievieno līmeņa numura skaitītāju un parādi to screen (ekrānā).
  6. Izej trīs līmeņus pēc kārtas.
  7. Pārbaudi, ka katrs jaunais labirints ir citāds un izejams.

Gatavs, kad: izejot izeju, uzreiz sākas jauns, atšķirīgs labirints, un numurs screen (ekrānā) pieaug.

2. uzdevums -

Pievieno savācamos un šķēršļus

Beigās labirintā būs par ko cīnīties un no kā izvairīties.

  1. Izvieto labirintā nejaušās ejās vismaz piecus savācamos materiālus.
  2. Pievieno katram Area2D (2D saskares zona), kas palielina XP (pieredzes punkti) skaitītāju.
  3. Izvieto arī divus šķēršļus, kas atņem mēģinājumam dzīvību.
  4. Pārliecinies, ka object (objekti) nekad nerodas sienā.
  5. Pievieno HUD (spēles informācijas panelis) ar XP (pieredzes punkti), dzīvībām un līmeņa numuru.
  6. Izspēlē līmeni un savāc visus materiālus.
  7. Pārbaudi, ka pēc dzīvību zaudēšanas mēģinājums beidzas.

Gatavs, kad: visi savācamie ir sasniedzami, neviens nav iesprūdis sienā, un HUD (spēles informācijas panelis) rāda pareizus skaitļus.

3. uzdevums -

Pievieno meta-progression (meta-progresu) un save (saglabāšanu)

Beigās tavs progress saglabāsies arī pēc neveiksmīga mēģinājuma.

  1. Sadali data (datus) divās daļās: mēģinājuma data (dati) un pastāvīgie data (dati).
  2. Pievieno pastāvīgajiem data (datiem) kopējo XP (pieredzes punkti) un labāko sasniegto līmeni.
  3. Saglabā tos JSON (JavaScript objektu pieraksts) file (failā) ar 5.3 stundas SaveManager.
  4. Nomet pēc zaudējuma tikai mēģinājuma data (datus).
  5. Ielādē pastāvīgos data (datus), palaižot spēli no jauna.
  6. Izspēlē divus mēģinājumus un pārbaudi, ka kopējais XP (pieredzes punkti) summējas.
  7. Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi).

Gatavs, kad: pēc zaudējuma un spēles restart (restarta) kopējais XP (pieredzes punkti) saglabājas, bet mēģinājuma progress sākas no sākuma.

Papildu uzdevums - Pievieno spēlētāja class (klases)

Ja pamatdarbs ir gatavs, ļauj izvēlēties varoni ar savu spēju.

  1. Izveido base class (bāzes klasi) ar kopīgajām property (īpašībām).
  2. Izveido divas derived class (bērna klases) ar atšķirīgu ātrumu un dzīvību skaitu.
  3. Pievieno spēles sākumā menu (izvēlni) ar abām class (klasēm).
  4. Saglabā izvēlēto class (klasi) pastāvīgajos data (datos).
  5. Izspēlē mēģinājumu ar katru class (klasi) un salīdzini.

Gatavs, kad: abas class (klases) jūtas atšķirīgi, un izvēle saglabājas arī pēc spēles restart (restarta).

Ko sagatavo

Stundas mērķis: Tev ir izspēlējams procedural (procedurālais) labirints: katrs līmenis tiek uzģenerēts un pārbaudīts, ka ir izejams, labirintā ir savācamie un šķēršļi, un meta-progression (kopējais progress) saglabājas JSON (JavaScript objektu pieraksts) file (failā) arī pēc neveiksmīga mēģinājuma.

GitHub repository (krātuvē) jābūt:

  1. Viss project (projekts) ar C# script (skriptiem), scene (scēnām) un project (projekta) file (failiem).
  2. README.md ievietota video link (saite), kurā izej vismaz divus līmeņus un savāc materiālus.
  3. Saglabātā JSON (JavaScript objektu pieraksts) file (faila) paraugs ar meta-progression (meta-progresa) data (datiem).
  4. README.md: kuri data (dati) tavā spēlē ir mēģinājuma data (dati) un kuri pastāvīgie, un kāpēc.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub repository (krātuves) link (saiti); visiem prasītajiem file (failiem), README.md pierakstiem un pierādījumiem jābūt pašā repository (krātuvē).

Biežākās kļūdas

  • Save (saglabāt) un mēģinājuma beigas: Pārbaudi, ka delete (dzēst) save (saglabāt) file (fails) notiek tikai pēc run_end, ne pirms.
  • Performance (veiktspēja) ar 50+ šķēršļiem: Lieto spatial hash (jaucējvērtība) un pool (objektu krātuve) no 4. tēmas.
  • Procedural (procedurāls) balance: Pārāk daudz/maz bonusa materiālu - pielāgo varbūtības.

using Godot;

public partial class GameSession : Node
{
    private int currentLevel = 1;
    private Player player;
    private MazeGenerator generator = new();

    public void StartRun()
    {
        generator.Generate((int)Time.GetUnixTimeFromSystem());
        SpawnPlayer();
        SpawnObstacles();
        SpawnBonusItems();
    }

    public void OnRunFailed()
    {
        // Save meta-progress
        MetaProgress.Instance.AddRun(currentLevel, player.SolvedTasks);
        MetaProgress.Save();
        // Remove run save
        DirAccess.RemoveAbsolute("user://current_run.json");
        GetTree().ChangeSceneToFile("res://menu.tscn");
    }

    public void OnLevelComplete()
    {
        SaveRun();  // autosave
        currentLevel++;
        if (currentLevel > 10) OnGameWon();
        else StartNextLevel();
    }
}
