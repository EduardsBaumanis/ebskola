5.6 Noslēguma projekts: Procedural (procedurālais) klases labirints

Stundas uzdevums: Pilnvērtīga procedural klases labirinta spēle ar procedural generation (procedurālā ģenerēšana), saglabāt sistēmu un meta-progress (kopējais progress).

SR 2.4.1. Problēmu dekompozīcija SR 2.4.16. Data structure (datu struktūras) SR 2.4.17. File I/O (failu ievade un izvade) SR 2.4.19. Algoritmi

80 min plāns: Ievads un kritēriju pārruna (~10 min) · 1. uzdevums (~20 min) - savieno labirintu ar spēlētāju · 2. uzdevums (~25 min) - pievieno savācamos un šķēršļus · 3. uzdevums (~20 min) - pievieno meta-progression un saglabāšanu · Iesniegšana (~5 min).

Pirms sāc: šis ir 5. tēmas noslēguma projekts. Izmanto 5.4 labirinta ģeneratoru un 5.3 saglabāšanas sistēmu. Sāc ar TRIM līmeņiem, nevis desmit.

Failu ceļi: ceļi ir norādīti no tava Godot projekta mapes, kur atrodas project.godot; piemēram, Scripts/Player.cs Godot panelī ir res://Scripts/Player.cs. Ja norādītais fails jau ir izveidots, atver un papildini to.

Jaunus C# failus veido mapē Scripts, scēnas — norādītajā ceļā; trūkstošās mapes izveido. Ja tavā projektā skripts glabājas citur, rediģē esošo failu. using direktīvas raksti faila sākumā, laukus un metodes — klases iekšienē. Esošu _Ready() vai _PhysicsProcess() papildini, neveido otru tāda paša nosaukuma metodi.

Teorija: īslaicīgā un pastāvīgā stāvokļa nošķiršana procedurālās sistēmās

Īslaicīgie sesijas dati pret pastāvīgajiem datiem

Daudzposmu programmās datus pēc to dzīves cikla iedala divās kategorijās: īslaicīgajā jeb sesijas stāvoklī (transient / session state) un pastāvīgajā stāvoklī (persistent state). To var salīdzināt ar treniņu lietotni telefonā — viena skrējiena hronometrs un pašreizējais temps darbojas tikai konkrētā treniņa laikā un nākamajā reizē sākas no nulles, turpretim kopējais mēneša kilometru skaits un personīgais rekords tiek saglabāti profilā starp visām sesijām:

// Īslaicīgie sesijas dati — glabājas tikai operatīvajā atmiņā (RAM)
public class SesijasStavoklis
{
    public int PasreizejaisPosms = 1;
    public int SesijasPunkti = 0;
    public void Atiestatit() { PasreizejaisPosms = 1; SesijasPunkti = 0; }
}

// Pastāvīgie dati — tiek serializēti JSON failā mapē user://
public class PastavigaisProgress
{
    public int KopejiePunkti = 0;
    public int AugstakaisPosms = 1;
}

Nošķirot abas datu grupas atsevišķās C# klasēs, sesijas pārtraukšana vai restarts atiestata tikai SesijasStavoklis laukus, nejauši neizdzēšot ilgtermiņa uzkrājumu un neierakstot diskā pagaidu mainīgos.

Procedurālas vides posmu izpildes plūsma un datu saskaņotība

Apvienojot procedurālu režģa ģenerēšanu, dinamisku objektu izvietošanu un failu saglabāšanu vienā sistēmā, izpildi organizē stingrā secībā:

  • Ģenerēšana un sasniedzamības pārbaude: katra jauna posma sākumā algoritms izveido 2D datu režģi un ar apgabala aizpildīšanu (flood fill) pārliecinās, ka ceļš no sākumpunkta līdz izejas zonai ir nepārtraukts, pirms scēnā tiek izvietoti vizuālie mezgli.
  • Objektu izvietošana derīgajās koordinātās: papildu interaktīvās zonas (Area2D) nekad nenovieto aklā nejaušībā pa visu laukumu — vispirms savāc brīvo šūnu koordinātas (rezgis[x, y] == 0, izņemot sākuma un beigu punktu) sarakstā un izvēlas pozīcijas tikai no šīs kopas, lai objekti neiesprūstu sienās.
  • Droša pāreju un saglabāšanas secība: noslēdzot posmu vai sesiju, vispirms pieskaita rezultātus pastāvīgajam progresam un ieraksta pārbaudītu JSON failu mapē user://, un tikai pēc tam notīra vai pārbūvē nākamā posma scēnu.

Kā šo izmantot projektā

Atceries: ar redzamu efektu redaktorā nepietiek. Paskaidro, kura C# class glabā stāvokli, kura method (metode) to maina un kā Godot node (mezgls) struktūra izmanto šo kodu.

Pārbaudi: C# kods pārbauda failu kļūdas, validē datus, izmanto versijas lauku un pamato time complexity (algoritmu sarežģītību).

public class PersistenceCheckpoint
{
    public string Lesson = "5.6 Noslēguma projekts: Procedurālais klases labirints";
    public bool UsesCSharp = true;
    public bool HandlesMissingFile = true;
    public bool ValidatesData = true;
    public bool DocumentsComplexity = true;
}

Praktiskie uzdevumi

1. uzdevums -

Savieno labirintu ar spēlētāju

Kur strādāt: Saglabā spēles scēnu kā Scenes/MazeGame.tscn. Turpini Scripts/MazeGenerator.cs un Scripts/MazeDemo.cs no 5.4; pēdējā pievieno līmeņa maiņu un skaitītāju. Izejas Area2D piesaisti jaunam Scripts/Exit.cs, kas paziņo par līmeņa pabeigšanu.

Beigās varēsi iziet uzģenerētu labirintu un nokļūt nākamajā.

  1. Ievelc savu 5.4 labirinta ģeneratoru jaunā projektā vai scēnā.
  2. Novieto spēlētāju labirinta sākumā un izeju tālākajā stūrī.
  3. Pievieno izejai Area2D (2D saskares zona), kas nosaka, ka līmenis pabeigts.
  4. Uzģenerē jaunu labirintu, kad spēlētājs sasniedz izeju.
  5. Pievieno līmeņa numura skaitītāju un parādi to ekrānā.
  6. Izej trīs līmeņus pēc kārtas.
  7. Pārbaudi, ka katrs jaunais labirints ir citāds un izejams.

Gatavs, kad: izejot izeju, uzreiz sākas jauns, atšķirīgs labirints, un numurs ekrānā pieaug.

2. uzdevums -

Pievieno savācamos un šķēršļus

Kur strādāt: Izvietošanu un HUD atjaunošanu raksti Scripts/MazeDemo.cs. Izveido Scripts/Collectible.cs un Scripts/Hazard.cs attiecīgo Area2D mezglu apstrādei; XP un dzīvību maiņu pievieno Scripts/Player.cs. Mezglus izveido Scenes/MazeGame.tscn vai atsevišķās priekšmetu scēnās.

Beigās labirintā būs par ko cīnīties un no kā izvairīties.

  1. Izvieto labirintā nejaušās ejās vismaz piecus savācamos materiālus.
  2. Pievieno katram Area2D, kas palielina XP skaitītāju.
  3. Izvieto arī divus šķēršļus, kas atņem mēģinājumam dzīvību.
  4. Pārliecinies, ka objekti nekad nerodas sienā.
  5. Pievieno HUD (spēles informācijas panelis) ar XP, dzīvībām un līmeņa numuru.
  6. Izspēlē līmeni un savāc visus materiālus.
  7. Pārbaudi, ka pēc dzīvību zaudēšanas mēģinājums beidzas.

Gatavs, kad: visi savācamie ir sasniedzami, neviens nav iesprūdis sienā, un HUD rāda pareizus skaitļus.

3. uzdevums -

Pievieno meta-progression un saglabāšanu

Kur strādāt: Pastāvīgos datus glabā jaunā Scripts/ProgressData.cs klasē. JSON saglabāšanu papildini Scripts/SaveManager.cs; ielādi un mēģinājuma restartu izsauc Scripts/MazeDemo.cs, atiestatot Scripts/Player.cs mēģinājuma datus.

Beigās tavs progress saglabāsies arī pēc neveiksmīga mēģinājuma.

  1. Sadali datus divās daļās: mēģinājuma dati un pastāvīgie dati.
  2. Pievieno pastāvīgajiem datiem kopējo XP un labāko sasniegto līmeni.
  3. Saglabā tos JSON (JavaScript objektu pieraksts) failā ar 5.3 stundas SaveManager.
  4. Nomet pēc zaudējuma tikai mēģinājuma datus.
  5. Ielādē pastāvīgos datus, palaižot spēli no jauna.
  6. Izspēlē divus mēģinājumus un pārbaudi, ka kopējais XP summējas.
  7. Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi).

Pilna projekta pārskats pārbaudei (Procedural klases labirints): spēlētājs iziet cauri procedurāli ģenerētiem labirintu līmeņiem (sākot ar 3 līmeņiem pamatvariantā un paplašinot līdz 10 līmeņiem ar īpašu izaicinājumu ik 5. līmenī), pa ceļam savāc bonusa materiālus un apiet šķēršļus. Zaudējot dzīvības, konkrētā mēģinājuma (run) līmenis un mēģinājuma dati tiek atiestatīti, savukārt meta-progress (kopējie XP pieredzes punkti, labākais sasniegtais līmenis un papildu uzdevumā izvēlētās spēlētāja klases ar atšķirīgām spējām) saglabājas JSON failā starp sesijām.

Gatavs, kad: pēc zaudējuma un spēles restarta kopējais XP saglabājas, bet mēģinājuma progress sākas no sākuma.

Papildu uzdevums - Pievieno spēlētāja class

Kur strādāt: Kopīgo kodu turpini Scripts/Player.cs; atvasinātās klases izveido, piemēram, Scripts/FastPlayer.cs un Scripts/ToughPlayer.cs. Izvēlnes kodu raksti Scripts/CharacterMenu.cs, kas piesaistīts Scenes/CharacterMenu.tscn Control saknei; izvēli saglabā ar Scripts/ProgressData.cs un Scripts/SaveManager.cs.

Ja pamatdarbs ir gatavs, ļauj izvēlēties varoni ar savu spēju.

  1. Izveido base class (bāzes klasi) ar kopīgajām īpašībām.
  2. Izveido divas derived class (bērna klases) ar atšķirīgu ātrumu un dzīvību skaitu.
  3. Pievieno spēles sākumā izvēlni ar abām class.
  4. Saglabā izvēlēto class pastāvīgajos datos.
  5. Izspēlē mēģinājumu ar katru class un salīdzini.

Gatavs, kad: abas class jūtas atšķirīgi, un izvēle saglabājas arī pēc spēles restarta.

Ko sagatavo

Stundas mērķis: Tev ir izspēlējams procedural labirints: katrs līmenis tiek uzģenerēts un pārbaudīts, ka ir izejams, labirintā ir savācamie un šķēršļi, un meta-progression saglabājas JSON failā arī pēc neveiksmīga mēģinājuma.

GitHub krātuvē jābūt:

  1. Viss projekts ar C# skriptiem, scēnām un projekta failiem.
  2. README.md ievietota video saite, kurā izej vismaz divus līmeņus un savāc materiālus.
  3. Saglabātā JSON faila paraugs ar meta-progression datiem.
  4. README.md: kuri dati tavā spēlē ir mēģinājuma dati un kuri pastāvīgie, un kāpēc.

Kā iesniedz: Veic commit un push. Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Biežākās kļūdas

  • Save un mēģinājuma beigas: Pārbaudi, ka dzēst saglabāt fails notiek tikai pēc run_end, ne pirms.
  • Veiktspēja ar 50+ šķēršļiem: Lieto spatial hashing (telpisko jaukšanu) un pool (objektu krātuve) no 4. tēmas.
  • Procedural balance: Pārāk daudz/maz bonusa materiālu - pielāgo varbūtības.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

using Godot;

public partial class GameSession : Node
{
    private int currentLevel = 1;
    private Player player;
    private MazeGenerator generator = new();

    public void StartRun()
    {
        generator.Generate((int)Time.GetUnixTimeFromSystem());
        SpawnPlayer();
        SpawnObstacles();
        SpawnBonusItems();
    }

    public void OnRunFailed()
    {
        // Save meta-progress
        MetaProgress.Instance.AddRun(currentLevel, player.SolvedTasks);
        MetaProgress.Save();
        // Remove run save
        DirAccess.RemoveAbsolute("user://current_run.json");
        GetTree().ChangeSceneToFile("res://menu.tscn");
    }

    public void OnLevelComplete()
    {
        SaveRun();  // autosave
        currentLevel++;
        if (currentLevel > 10) OnGameWon();
        else StartNextLevel();
    }
}
