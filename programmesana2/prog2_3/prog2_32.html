Teorija: mantošana, metožu pārrakstīšana un polimorfisms

Mantošana (:) un bāzes konstruktors (base)

Ja programmā ir vairāki radniecīgi objektu veidi ar kopīgiem datiem un pamatdarbībām, koda kopēšana atsevišķos failos rada risku — katra kļūdas labošana būtu jāatkārto visās kopijās. Mantošana (inheritance) ļauj no vispārīgās jeb bāzes klases (base class) izveidot specializētu jeb atvasināto klasi (derived class). Pieraksts public class SkolenaBilete : Bilete izsaka attiecību „ir” — līdzīgi kā parasta sabiedriskā transporta e-biļete un skolēna biļete izmanto vienu un to pašu reģistrācijas sistēmu, atšķiroties tikai brauciena cenas aprēķinā.

Atvasinātās klases konstruktorā izsaukums : base(...) nodod sākuma datus bāzes klases konstruktoram (ja bāzes klasei nav konstruktora bez parametriem, bez : base(...) kods nebūvējas). Savukārt bāzes klases private lauki joprojām ir pieejami tikai pašai bāzes klasei — atvasinātā klase ar tiem strādā caur mantotajām publiskajām metodēm:

public class Bilete
{
    public string Ipashnieks;
    private int atlikums;

    public Bilete(string ipashnieks, int sakumaAtlikums)
    {
        Ipashnieks = ipashnieks;
        atlikums = sakumaAtlikums;
    }

    public virtual void AprekinatMaksu(int summa)
    {
        if (summa <= 0) return;
        atlikums -= summa;
        if (atlikums < 0) atlikums = 0;
    }

    public int GetAtlikums() { return atlikums; }
}

// Atvasinātā klase nodod sākuma datus bāzes konstruktoram:
public class DienasBilete : Bilete
{
    public DienasBilete(string ipashnieks) : base(ipashnieks, 100) { }
}

Metožu pārrakstīšana (virtual, override un base.Metode)

Lai atvasinātā klase varētu vienai mantotai darbībai noteikt citu aprēķina likumu, bāzes klasē šo metodi atzīmē ar atslēgvārdu virtual, bet atvasinātajā klasē raksta metodi ar precīzi tādu pašu nosaukumu, parametriem un atgriežamo tipu, pievienojot override:

using System;

public class SkolenaBilete : Bilete
{
    private int atlaide = 10;

    public SkolenaBilete(string ipashnieks) : base(ipashnieks, 150) { }

    public override void AprekinatMaksu(int summa)
    {
        if (summa <= 0) return;
        int samazinata = Math.Max(1, summa - atlaide);
        base.AprekinatMaksu(samazinata);
    }
}

Funkcija Math.Max(a, b) (no System bibliotēkas) atgriež lielāko no diviem skaitļiem, nodrošinot noteiktu zemāko robežu. Izsaukums base.AprekinatMaksu(...) izpilda kopīgo bāzes klases versiju — ja priekšā izlaistu base., metode bezgalīgi izsauktu pati sevi. Metodes, kuru darbība visiem paveidiem ir vienāda, pārrakstīt nevajag.

Polimorfisms un kopīgs objektu saraksts (List<T>)

Dinamiskajā sarakstā List<BazesTips> (pieslēdzot using System.Collections.Generic;) ar metodi Add(...) drīkst vienuviet ievietot gan pašas bāzes klases, gan jebkuras no tās atvasinātās klases objektus, jo katrs atvasinātais objekts vienlaikus pieder bāzes tipam.

Šķērsojot šādu sarakstu ar foreach ciklu un izsaucot virtual metodi, C# izpildes laikā automātiski izvēlas katra konkrētā objekta īsto override versiju — šo īpašību sauc par polimorfismu. Gluži kā viedtālrunī nospiežot vienu komandu „Nosūtīt” dažādu paziņojumu sarakstam, e-pasta, īsziņas un lietotnes ziņojums katrs tiek piegādāts pēc sava kanāla noteikumiem bez atsevišķām if pārbaudēm ciklā:

using System.Collections.Generic;

List<Bilete> biletes = new List<Bilete>();
biletes.Add(new Bilete("Kārlis", 100));  // Bāzes klases objekts
biletes.Add(new SkolenaBilete("Līga"));  // Atvasināts objekts (sāk ar 150)

foreach (Bilete b in biletes)
{
    b.AprekinatMaksu(20); // Katram izpildās tā tipam atbilstošā versija
    GD.Print(b.Ipashnieks, ": ", b.GetAtlikums()); // 80 un 140
}

2. uzdevums

Maini kapteiņa reakciju uz sodu

Kur strādāt: virtual pievieno Scripts/Participant.cs; stability lauku un override metodi — Scripts/Captain.cs. Sodu pārbaudes raksti Scripts/LessonDemo.cs metodē _Ready().

  1. Participant metodē ApplyPenalty pievieno virtual (public virtual void ApplyPenalty(int amount)). Captain pievieno stability lauku un override metodi pēc parauga zemāk (ievēro base.ApplyPenalty(reduced), lai pozitīvs sods vienmēr atņemtu vismaz 1 punktu un metode neizsauktu pati sevi).
  2. Pārbaudi atsevišķi sodu 20 (izvēle starp 1 un 10 → piemēro 10) un sodu 6 (izvēle starp 1 un -4 → piemēro 1). Katrā pārbaudē izveido jaunu kapteini, lai sākuma enerģija būtu 150.
  3. Izdrukā vērtību pirms un pēc soda. Paredzamie rezultāti: 140 un 149.
  4. Uz brīdi noņem virtual no Participant, pieraksti kļūdas iemeslu un pēc tam to atjauno.
using System;

public class Captain : Participant
{
    private int stability = 10;

    public Captain(string name) : base(name, 150) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        int reduced = Math.Max(1, amount - stability);
        base.ApplyPenalty(reduced);
    }
}

Gatavs, kad: kapteinis zaudē attiecīgi 10 un 1 punktu; enerģija nekļūst negatīva.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Participant.cs

public class Participant
{
    public string Name;
    public int Level = 1;
    private int energy;

    public Participant(string name, int energy)
    {
        Name = name;
        this.energy = energy;
        if (this.energy < 0) this.energy = 0;
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (amount < 0) return;
        energy -= amount;
        if (energy < 0) energy = 0;
    }

    public int GetEnergy()
    {
        return energy;
    }

    public bool IsActive()
    {
        return energy > 0;
    }
}

Captain.cs

using System;

public class Captain : Participant
{
    private int stability = 10;

    public Captain(string name) : base(name, 150) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        int reduced = Math.Max(1, amount - stability);
        base.ApplyPenalty(reduced);
    }
}

Presenter.cs

public class Presenter : Participant
{
    public Presenter(string name) : base(name, 80) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        base.ApplyPenalty(amount + 5);
    }
}

LessonDemo.cs

using Godot;
using System.Collections.Generic;

public partial class LessonDemo : Node
{
    public override void _Ready()
    {
        List<Participant> party = new List<Participant>();
        party.Add(new Participant("Ieva", 100));
        party.Add(new Captain("Anna"));
        party.Add(new Presenter("Jānis"));

        foreach (Participant p in party)
        {

            p.ApplyPenalty(20);

        }
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Participant.cs, Captain.cs, Presenter.cs un pārbaudes skripts.
  • Izdruka ar sākuma enerģiju un rezultātu pēc vienāda soda.
  • README: base un override skaidrojums saviem vārdiem; virtual noņemšanas pārbaude.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • override kļūda: Participant metodei jābūt virtual, un metodes nosaukumam, parametriem un atgriežamajam tipam abās klasēs jāsakrīt.
  • Math vai List nav atrasts: faila sākumā pievieno attiecīgi using System; vai using System.Collections.Generic;.
  • Metode izsauc sevi: pārbaudi, vai atvasinātā klase lieto base.ApplyPenalty(...).
