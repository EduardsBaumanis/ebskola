Pirms sāc: atver 3.1. projekta gala versiju. Šajā stundā Participant un tā lomas vēl ir parastas C# klases; pārbaudes vada LessonDemo mezgls.

Darba secība: izlasi skaidrojumu pie attiecīgā uzdevuma, paredzi piemēra rezultātu un tad pārbaudi to. Pēc C# izmaiņām saglabā failus, Godot nospied Build un palaid scēnu ar F6. Rezultātus skaties Output panelī.

Teorija ar piemēriem

1. Kādas darbības lomām ir kopīgas?

Koda nosaukumus lasi šādi: Participant — dalībnieks, Captain — kapteinis, Presenter — prezentētājs. Nosaukumi palīdz atpazīt katras klases lomu.

Visiem turnīra dalībniekiem ir vārds un enerģija. Visiem jāmāk saņemt sodu un pateikt, vai viņi vēl piedalās. Kapteinis arī ir dalībnieks, tikai viņam ir īpašs noteikums: pozitīvu sodu samazina par 10 punktiem, atstājot vismaz 1 punktu.

Mantošana ļauj jaunajai klasei izmantot kopīgo kodu no esošās klases. Participant saucam par bāzes klasi, bet Captain — par atvasināto klasi. Pieraksts Captain : Participant nozīmē “kapteinis ir dalībnieks”.

Ja kapteinis būtu atsevišķs nokopēts Participant fails, enerģijas pārbaudes kļūda būtu jālabo vairākās vietās. Ar mantošanu kopīgo enerģijas samazināšanu labojam Participant klasē.

2. Kā kapteinis iegūst sākuma datus?

public class Captain : Participant
{
    public Captain(string name) : base(name, 150)
    {
    }
}

Šo kodu liec Captain.cs. Izsaukums new Captain("Anna") nodod vārdu Captain konstruktoram. Daļa base(name, 150) tālāk izsauc Participant konstruktoru ar vārdu un enerģiju 150. Tāpēc jaunajam kapteinim jau darbojas GetEnergy() un IsActive().

Ja izdzēs : base(name, 150), C# mēģina izsaukt Participant konstruktoru bez argumentiem. Mūsu iepriekšējās stundas klasē tāda nav, tāpēc Build parāda kļūdu. Pēc izmēģinājuma atjauno šo koda daļu.

Privātais energy joprojām pieder Participant kodam: Captain nevar to tieši mainīt. Tas izmanto mantotās publiskās metodes.

3. Kā vienai darbībai piešķirt citu noteikumu?

Participant metodes sākumā pievieno virtual: public virtual void ApplyPenalty(int amount). Tas ļauj atvasinātajai klasei definēt savu šīs darbības versiju. Captain lieto to pašu nosaukumu un parametrus, bet raksta override.

using System;

public class Captain : Participant
{
    private int stability = 10;

    public Captain(string name) : base(name, 150) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        int reduced = Math.Max(1, amount - stability);
        base.ApplyPenalty(reduced);
    }
}

Math.Max(1, amount - stability) izvēlas lielāko no diviem skaitļiem. Ja sods ir 20, izvēle ir starp 1 un 10 — kapteinim piemēro 10. Ja sods ir 6, izvēle ir starp 1 un −4 — piemēro 1. Šajā simulatorā katrs pozitīvs sods patērē vismaz vienu enerģijas punktu.

base.ApplyPenalty(reduced) izsauc Participant versiju, kas samazina enerģiju un neļauj tai kļūt negatīvai. Rakstot tikai ApplyPenalty(reduced), metode izsauktu pati sevi atkal un atkal. Vārds base šeit ir būtisks.

4. Viena komanda var saturēt dažādas lomas

List<Participant> ir dalībnieku saraksts. Tajā drīkst ievietot arī Captain un Presenter, jo abi ir Participant. Add pievieno vienu dalībnieku, bet foreach paņem katru saraksta dalībnieku pēc kārtas.

List<Participant> party = new List<Participant>();
party.Add(new Captain("Anna"));
party.Add(new Presenter("Jānis"));

foreach (Participant p in party)
{
    p.ApplyPenalty(20);
    GD.Print(p.Name, ": ", p.GetEnergy());
}

Šīs rindas liec LessonDemo metodes _Ready() iekšienē; faila augšā vajag using System.Collections.Generic;. Mainīgais p katrā reizē norāda uz citu objektu. C# izvēlas šī objekta ApplyPenalty versiju: Annai — Captain, Jānim — Presenter.

Šo iespēju vienā vārdā sauc par polimorfismu. Svarīgākais ir rezultāts: ciklā rakstām vienu darbību, bet katra loma to izpilda pēc saviem noteikumiem.

Pašpārbaude: Vai kapteinim jāpārraksta arī GetEnergy()?

Nē. Ja nolasīšanas noteikums visām lomām ir vienāds, pietiek ar mantoto Participant metodi. Atšķirīgo uzvedību raksta tikai tur, kur tā ir vajadzīga.

Izveido kapteiņa lomu

Atbalsts: skaidrojums un piemērs.

  2. Failā Captain.cs izveido īso mantošanas piemēru. LessonDemo izveido kapteini un izdrukā vārdu, enerģiju un IsActive().
  3. Uz brīdi noņem base konstruktora izsaukumu un izpēti Build kļūdu. Atjauno izsaukumu.

Gatavs, kad: kapteinis sāk ar 150 punktiem un lieto mantotās metodes.

2. uzdevums

Maini kapteiņa reakciju uz sodu

Atbalsts: skaidrojums un piemērs.

  1. Participant metodē ApplyPenalty pievieno virtual. Captain pievieno stability lauku un override metodi no piemēra.
  2. Pārbaudi atsevišķi sodu 20 un sodu 6. Katrā pārbaudē izveido jaunu kapteini, lai sākuma enerģija būtu 150.
  3. Izdrukā vērtību pirms un pēc soda. Paredzamie rezultāti: 140 un 149.
  4. Uz brīdi noņem virtual, pieraksti kļūdas iemeslu un pēc tam to atjauno.

Gatavs, kad: kapteinis zaudē attiecīgi 10 un 1 punktu; enerģija nekļūst negatīva.

Papildu uzdevums — Pievieno TimeKeeper lomu

Izveido vēl vienu atvasināto klasi ar sākuma enerģiju 100. Tās ApplyPenalty pozitīvam sodam pieskaita 10 un izsauc bāzes metodi. Pievieno sarakstam: pēc soda 20 jāpaliek 70. Noslēguma projektā izmantosim arī šo lomu; tās piemērs būs dots.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Participant.cs

public class Participant
{
    public string Name;
    public int Level = 1;
    private int energy;

    public Participant(string name, int energy)
    {
        Name = name;
        this.energy = energy;
        if (this.energy < 0) this.energy = 0;
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (amount < 0) return;
        energy -= amount;
        if (energy < 0) energy = 0;
    }

    public int GetEnergy()
    {
        return energy;
    }

    public bool IsActive()
    {
        return energy > 0;
    }
}

Captain.cs

using System;

public class Captain : Participant
{
    private int stability = 10;

    public Captain(string name) : base(name, 150) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        int reduced = Math.Max(1, amount - stability);
        base.ApplyPenalty(reduced);
    }
}

Presenter.cs

public class Presenter : Participant
{
    public Presenter(string name) : base(name, 80) { }

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        base.ApplyPenalty(amount + 5);
    }
}

LessonDemo.cs

using Godot;
using System.Collections.Generic;

public partial class LessonDemo : Node
{
    public override void _Ready()
    {
        List<Participant> party = new List<Participant>();

        party.Add(new Captain("Anna"));

}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Participant.cs, Captain.cs, Presenter.cs un pārbaudes skripts.
  • Izdruka ar sākuma enerģiju un rezultātu pēc vienāda soda.
  • README: base un override skaidrojums saviem vārdiem; virtual noņemšanas pārbaude.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • override kļūda: Participant metodei jābūt virtual, un metodes nosaukumam, parametriem un atgriežamajam tipam abās klasēs jāsakrīt.
  • Math vai List nav atrasts: faila sākumā pievieno attiecīgi using System; vai using System.Collections.Generic;.
  • Metode izsauc sevi: pārbaudi, vai atvasinātā klase lieto base.ApplyPenalty(...).
