3.2 Mantošana C++ un Godot

Stundas uzdevums: Izveidot specializētas dalībnieku klases, izmantojot inheritance (mantošanu).

SR 2.4.18. OOP SR 2.4.15. Modulāras programmas

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - izveido bērna klasi · 2. uzdevums (~25 min) - pārraksti metodi ar override · 3. uzdevums (~20 min) - izsauc visas lomas vienā ciklā · Iesniegšana (~5 min).

Pirms sāc: atver savu Participant klasi no 3.1 stundas. Šodien no vienas klases taisīsi vairākas lomas, nekopējot kodu.

Teorija: Inheritance un virtuālas funkcijas

Mantošana ļauj bērna klasei pārmantot vecāka atribūtus un metodes, pievienojot vai pārrakstot.

class Participant { /* base klase */ };

class Captain : public Participant {
public:
    int stability;
    Captain(String n) : Participant(n, 150, 18, 12) {  // izsauc vecāku konstruktoru
        stability = 10;
    }
    // Pārraksta (override) vecāka metodi
    void apply_penalty(int amount) override {
        amount -= stability;  // stabilitāte samazina soda punktus
        Participant::apply_penalty(amount);
    }
};

class Presenter : public Participant {
public:
    int ideas;
    Presenter(String n) : Participant(n, 80, 25, 3), ideas(100) {}

    void present_bonus(Participant& target) {
        if (ideas >= 20) {
            ideas -= 20;
            target.apply_penalty(40);
        }
    }
};

virtual atslēgvārds ļauj izsaukt bērna metodi caur vecāka pointer (polimorfisms).

Kā šo izmantot projektā

Atceries: ar redzamu efektu editorā nepietiek. Paskaidro, kura C++ klase glabā stāvokli, kura metode to maina un kā Godot node struktūra izmanto šo kodu.

Praktiskie uzdevumi

1. uzdevums - Izveido bērna klasi

Beigās jaunā klase mantos visu no vecāku klases.

  1. Izveido failu captain.hpp.
  2. Ieraksti class Captain : public Participant {.
  3. Pievieno konstruktoru Captain(String n) : Participant(n, 150) {}.
  4. Pievieno privātu lauku int stability = 10;.
  5. Izveido objektu Captain c("Anna"); un izsauc tam is_active().
  6. Pieraksti, no kurienes šī metode radās, ja tu to Captain klasē nerakstīji.
  7. Izdzēs : Participant(n, 150) daļu, kompilē un izlasi kļūdu.

Gatavs, kad: bērna objektam strādā vecāka metodes, bet bez vecāka konstruktora izsaukuma kods nekompilējas.

2. uzdevums - Pārraksti metodi ar override

Beigās kapteinis sodu izturēs labāk nekā parasts dalībnieks.

  1. Pievieno vecāka klasē atslēgvārdu virtual pirms apply_penalty.
  2. Pievieno Captain klasē void apply_penalty(int amount) override;.
  3. Ieraksti tajā amount = std::max(1, amount - stability);.
  4. Izsauc pēc tam vecāka versiju ar Participant::apply_penalty(amount);.
  5. Izmēģini vienādu sodu abiem: parastam dalībniekam un kapteinim.
  6. Pieraksti, cik enerģijas katrs zaudēja.
  7. Izdzēs virtual vārdu, kompilē un pieraksti, kas mainās.

Gatavs, kad: ar vienādu sodu kapteinis zaudē mazāk enerģijas nekā parasts dalībnieks.

3. uzdevums - Izsauc visas lomas vienā ciklā

Beigās viens cikls apkalpos jebkuru lomu skaitu.

  1. Izveido vēl vienu bērna klasi Presenter ar citu enerģiju.
  2. Pārraksti arī tai apply_penalty savā veidā.
  3. Izveido std::vector<Participant*> party;.
  4. Pievieno tam pa vienam objektam no katras klases.
  5. Uzraksti ciklu, kas katram izsauc apply_penalty(20).
  6. Izdrukā pēc cikla katra vārdu un atlikušo enerģiju.
  7. Pieraksti, kāpēc cikls nezina, kura loma tam tiek padota.

Gatavs, kad: viens cikls apstrādā visas lomas, un katra zaudē atšķirīgu enerģijas daudzumu.

Papildu uzdevums - Pievieno trešo lomu

Ja pamatdarbs ir gatavs, paplašini hierarhiju.

  1. Izveido klasi TimeKeeper ar mazāku enerģiju, bet lielāku ātrumu.
  2. Pārraksti tai apply_penalty tā, lai tā zaudētu vairāk.
  3. Pievieno to sarakstam.
  4. Palaid ciklu vēlreiz un pārbaudi, vai kods bija jāmaina.
  5. Pieraksti, cik rindu bija jāpieraksta ciklā.

Gatavs, kad: trešā loma darbojas ciklā, un pašā ciklā nebija jāmaina neviena rinda.

Ko iesniedz skolotājam

Stundas mērķis: Tu proti izveidot bērna klasi ar public mantošanu, izsaukt vecāka konstruktoru, pārrakstīt metodi ar virtual un override un apstrādāt visas lomas vienā ciklā.

Iesniedzamais:

  1. Faili captain.hpp un presenter.hpp tavā GitHub krātuvē.
  2. Ekrānuzņēmums ar Output paneli, kurā redzams, ka pēc vienāda soda lomām palikusi atšķirīga enerģija.
  3. Burtnīcā: kas notiek, ja no vecāka metodes noņem virtual.

Kā iesniedz: Veic commit un push, tad iesniedz krātuves saiti un ekrānuzņēmumu skolotāja norādītajā vietā.

Biežākās kļūdas

  • Cannot call base constructor: Trūkst initializer list ar : Participant(...).
  • 'override' was not declared: C++11+ vajadzīgs (Godot prasa C++17).
  • Slicing problem: Pieliecot Participant objektu, ne Participant*, polimorfisms nedarbojas.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

class Captain : public Participant {
private:
    int stability;
public:
    Captain(String n) : Participant(n, 150, 18, 12), stability(10) {}

    void apply_penalty(int amount) override {
        amount = std::max(1, amount - stability);
        Participant::apply_penalty(amount);
    }
};

class Presenter : public Participant {
private:
    int ideas;
public:
    Presenter(String n) : Participant(n, 80, 25, 3), ideas(100) {}

    void present_bonus(Participant* target) {
        if (ideas >= 20) {
            ideas -= 20;
            UtilityFunctions::print(name, " izmanto prezentācijas bonusu pret ", target->get_name());
            target->apply_penalty(40);
        }
    }
