3.3 Signāli: paziņo par notikumu

Stundas uzdevums: Liec dalībniekam paziņot par izstāšanos un turnīra vadītājam šo paziņojumu saņemt.

SR 2.4.15. Modulāras programmas SR 2.4.18. Objektorientētā programmēšana

Pirms sāc: izmanto 3.2. lomu projektu. Šodien mainās veids, kā dalībnieku izveidojam, tāpēc vispirms izlasi pārejas soļus.

Darba secība: izlasi skaidrojumu pie attiecīgā uzdevuma, paredzi piemēra rezultātu un tad pārbaudi to. Pēc C# izmaiņām saglabā failus, Godot nospied Build un palaid scēnu ar F6. Rezultātus skaties Output panelī.

Failu ceļi: ceļi ir norādīti no tava Godot projekta mapes, kur atrodas project.godot; piemēram, Scripts/Player.cs Godot panelī ir res://Scripts/Player.cs. Ja norādītais fails jau ir izveidots, atver un papildini to.

Jaunus C# failus veido mapē Scripts, scēnas — norādītajā ceļā; trūkstošās mapes izveido. Ja tavā projektā skripts glabājas citur, rediģē esošo failu. using direktīvas raksti faila sākumā, laukus un metodes — klases iekšienē. Esošu _Ready() vai _PhysicsProcess() papildini, neveido otru tāda paša nosaukuma metodi.

Teorija ar piemēriem

1. Darbība un paziņojums nav viens un tas pats

ApplyPenalty(20) ir lūgums dalībniekam veikt darbību: samazināt enerģiju. Finished ir paziņojums, ka kaut kas jau noticis: dalībnieka enerģija sasniegusi nulli. Šādu paziņojumu Godot sauc par signālu.

Iedomājies finiša zvanu. Dalībnieks to nospiež, bet rezultātu pierakstītājs klausās. Vēlāk zvanu var klausīties arī ekrāna tablo. Dalībnieka kodā nav jāraksta katra klausītāja darbības.

Savienojums tomēr ir jāizveido: turnīra vadītājs atrod dalībnieku un pieslēdz savu metodi. Dalībniekam nav jāzina, kura klase saņem paziņojumu. Ja neviens nav pieslēdzies, signāls pats par sevi izdruku nerada.

2. Pāreja no parastas klases uz Godot mezglu

Līdz šim Participant veidojām ar new Participant("Anna", 100). Tagad gribam pievienot dalībnieku scēnai un lietot Godot signālus. Tāpēc Participant mantos no Node. Mezgls ir scēnas koka elements; tam var pievienot skriptu un pēc nosaukuma to atrast.

  1. Participant.cs sākumā pievieno using Godot; un klasē lieto public partial class Participant : Node. partial ļauj Godot pievienot ģenerēto kodu, piemēram, signāla nosaukumu.
  2. Iepriekšējo konstruktoru ar parametriem šajā versijā aizstāj ar metodi Setup(string name, int initialEnergy). Godot vispirms izveido mezglu bez argumentiem; pēc tam mūsu kods izsauc Setup ar sākuma datiem.
  3. Dalībnieka vārda lauku pārsauc par ParticipantName. Godot Node jau ir savs Name, kas apzīmē mezgla nosaukumu scēnas kokā.
  4. Arī Captain, Presenter un, ja izveidots, TimeKeeper deklarācijās pievieno partial un izņem vecos konstruktorus. To ApplyPenalty metodes saglabā. Pilnās savstarpēji saderīgās versijas ir zem uzdevumiem.

Turpmāk, veidojot mezglu kodā, raksti new Captain(), tad Setup("Anna", 150) un pievieno to scēnai ar AddChild. Šajā stundā dalībnieku mezglus izveidosi Godot redaktorā; Setup izsauks turnīra vadītājs.

Garajā pieteikuma rindā delegate apraksta paziņojuma datu formu. Šobrīd lieto doto pierakstu: nosaukumam jābeidzas ar EventHandler. Godot no tā izveido Finished un SignalName.Finished. Pēc izmaiņām vajag Build.

Saņēmēja metodei jāpieņem tādi paši dati — šeit viens string. Pieslēgšanas rindā raksta metodes nosaukumu bez iekavām, jo to neizsauc uzreiz: norāda, ko izsaukt vēlāk.

private void OnParticipantFinished(string participantName)
{
    GD.Print(participantName, " izstājās");
}

4. Kā nepieļaut atkārtotu izstāšanos?

Participant metodē pirms enerģijas maiņas pārbauda, vai dalībnieks vēl ir aktīvs. !IsActive() nozīmē “nav aktīvs”, || nozīmē “vai”, bet return tūlīt beidz metodes izpildi.

public virtual void ApplyPenalty(int amount)
{
    if (!IsActive() || amount <= 0) return;
    energy = Math.Max(0, energy - amount);
    if (energy == 0)
        EmitSignal(SignalName.Finished, ParticipantName);
}

5. Kā savienot abus skriptus?

Tournament (Node, skripts TournamentManager.cs)
├── Anna (Node, skripts Participant.cs)
└── Janis (Node, skripts Participant.cs)

Izveido jaunu scēnu Tournament.tscn ar šādu koku. Abiem bērna mezgliem pievieno vienu un to pašu Participant.cs. Saknes skripta _Ready() izmanto GetNode<Participant>("Anna"): tas meklē bērnu ar precīzu nosaukumu Anna un ļauj lietot Participant metodes.

Secība ir svarīga: atrod mezglus → iestata sākuma datus → pieslēdz signālus → piemēro sodus. Paziņojumus, kas notikuši pirms pieslēgšanas, vēlāk automātiski neatkārto.

anna.Finished -= OnParticipantFinished; noņem tieši šo klausītāju. Lai salīdzinātu, palaid scēnu no jauna un ievieto atvienošanu pēc pieslēgšanas, bet pirms soda. Jau izstājies dalībnieks mūsu piemērā otru signālu neraidīs.

Pašpārbaude: Vai pēc atvienošanas Annas enerģija vairs nemainās?

Enerģija joprojām mainās un signāls joprojām tiek raidīts. Tikai atvienotā saņēmēja metode vairs netiek izsaukta. Atvienošana nemaina pašu ApplyPenalty darbību.

1. uzdevums

Sagatavo dalībnieka paziņojumu

Kur strādāt: Atjauno Scripts/Participant.cs, Scripts/Captain.cs, Scripts/Presenter.cs un, ja izveidots, Scripts/TimeKeeper.cs. Finished signālu pievieno Participant klasē, tā nosūtīšanu — ApplyPenalty(); vecās pārbaudes izņem no Scripts/LessonDemo.cs metodes _Ready(). Izveido Scenes/Tournament.tscn.

Atbalsts: skaidrojums un piemērs.

  1. Pirms izmaiņām saglabā iepriekšējā projekta kopiju ārpus šī projekta mapes. Pēc pārejas apraksta atjauno Participant.cs un visas izveidotās lomas. LessonDemo.cs izņem tikai vecās izmēģinājuma rindas no _Ready() iekšienes, saglabājot pašu klasi un tukšu metodi. Jauno pārbaudi rakstīsi TournamentManager.cs. Godot būvē visus projekta C# failus, arī tos, kuri nav pievienoti palaistajai scēnai.
  2. Izveido Tournament scēnu ar Anna un Janis mezgliem.
  3. Pievieno Finished pieteikumu un nosūtīšanu brīdī, kad enerģija sasniedz nulli. Pirms soda pārbaudi IsActive().
  4. Nospied Build, atlasi dalībnieka mezglu un Signals sarakstā atrodi Finished signālu.

Gatavs, kad: projekts būvējas un dalībnieka signāls ir reģistrēts.

2. uzdevums

Saņem paziņojumu turnīra vadītājā

Kur strādāt: Izveido Scripts/TournamentManager.cs ar pilno piemēru un piesaisti to Scenes/Tournament.tscn saknei. Dalībnieku atrašanu, signālu pieslēgšanu un sodu izsaukumus raksti tā metodē _Ready().

Atbalsts: skaidrojums un piemērs.

  1. Saknei pievieno TournamentManager.cs no pilnā piemēra.
  2. Metodē _Ready atrod abus dalībniekus, izsauc Setup un ar += pieslēdz OnParticipantFinished.
  3. Palaid piemēru. Output jāparādās pa vienam izstāšanās paziņojumam Annai un Jānim.
  4. Annai piemēro vēl vienu sodu pēc izstāšanās un pārliecinies, ka trešā paziņojuma nav.

Gatavs, kad: enerģijas sasniegšana līdz nullei katram rada tieši vienu paziņojumu.

3. uzdevums

Atvieno vienu klausītāju un salīdzini

Kur strādāt: Atvienošanas rindu un enerģijas izdruku pievieno Scripts/TournamentManager.cs metodē _Ready(); secinājumus raksti README.md.

Atbalsts: skaidrojums un piemērs.

  1. Pirms sodu izsaukumiem pēc += pievieno Annas signāla atvienošanu ar -=.
  2. Palaid scēnu no jauna. Izdrukā arī Annas enerģiju: tai jābūt 0, bet izstāšanās teksts parādās tikai Jānim.
  3. Atjauno pieslēgumu. README salīdzini tiešu ApplyPenalty izsaukumu ar Finished paziņojumu.
  4. Paskaidro, kura klase atrod otru un kura tikai paziņo par notikumu.

Gatavs, kad: vari izskaidrot, kāpēc izdrukas trūkums nenozīmē, ka sods netika piemērots.

Papildu uzdevums — Paziņo arī par katru sodu

Kur strādāt: Signālu un zaudēto punktu aprēķinu pievieno Scripts/Participant.cs klasē un metodē ApplyPenalty(). Klausītāja metodi raksti Scripts/TournamentManager.cs klasē un pieslēdz to _Ready().

Pievieno PenaltyApplied signālu ar vienu int parametru. Pirms soda saglabā enerģiju, pēc soda aprēķini starpību un nosūti tieši zaudēto punktu skaitu. Piemēram, pie atlikušiem 5 punktiem sods 20 nozīmē faktiski zaudētus 5. Pieslēdz metodi, kas šo skaitli izdrukā.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Participant.cs

using Godot;
using System;

public partial class Participant : Node
{
    [Signal]
    public delegate void FinishedEventHandler(string participantName);

    public string ParticipantName = "Dalībnieks";
    private int energy = 100;

    public void Setup(string name, int initialEnergy)
    {
        ParticipantName = name;
        energy = Math.Max(0, initialEnergy);
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (!IsActive() || amount <= 0) return;
        energy = Math.Max(0, energy - amount);
        if (energy == 0)
            EmitSignal(SignalName.Finished, ParticipantName);
    }

    public int GetEnergy()
    {
        return energy;
    }

    public bool IsActive()
    {
        return energy > 0;
    }
}

Captain.cs

using System;

public partial class Captain : Participant
{
    private int stability = 10;

    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        base.ApplyPenalty(Math.Max(1, amount - stability));
    }
}

Presenter.cs

public partial class Presenter : Participant
{
    public override void ApplyPenalty(int amount)
    {
        if (amount <= 0) return;
        base.ApplyPenalty(amount + 5);
    }
}

TournamentManager.cs

using Godot;

public partial class TournamentManager : Node
{
    public override void _Ready()
    {
        Participant anna = GetNode<Participant>("Anna");
        Participant janis = GetNode<Participant>("Janis");
        anna.Setup("Anna", 30);
        janis.Setup("Jānis", 20);

        anna.Finished += OnParticipantFinished;
        janis.Finished += OnParticipantFinished;

        anna.ApplyPenalty(10);  // Paliek 20. Signāla vēl nav.
        anna.ApplyPenalty(20);  // Anna izstājas.
        anna.ApplyPenalty(5);   // Atkārtots paziņojums nerodas.
        janis.ApplyPenalty(20); // Jānis izstājas.
    }

    private void OnParticipantFinished(string participantName)
    {
        GD.Print(participantName, " izstājās");
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Saderīgi Participant, lomu un TournamentManager skripti; Tournament.tscn.
  • Izdrukas ar diviem paziņojumiem un ar vienu paziņojumu pēc atvienošanas.
  • README: kādā secībā pieslēdzi un raidīji signālu; ko maina -=.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Node not found: salīdzini GetNode ceļu ar scēnas koku. Anna un Janis jābūt saknes bērniem.
  • Nav Finished vai SignalName: pārbaudi [Signal], EventHandler galotni un partial; nospied Build.
  • Vecais konstruktors vairs neder: šīs stundas mezglus veido bez argumentiem un datus iestata ar Setup. Atjauno arī iepriekšējos pārbaudes skriptus.
  • Divi vienādi paziņojumi: pārbaudi, vai vienu metodi nepieslēdzi divreiz un vai ApplyPenalty ignorē jau neaktīvu dalībnieku.
