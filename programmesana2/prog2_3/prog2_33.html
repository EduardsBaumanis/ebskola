Teorija: notikumu signāli un Godot mezglu saziņa

Tiešs metodes izsaukums pret notikuma signālu (signal)

Tiešs metodes izsaukums ir komanda konkrētam objektam izpildīt darbību, savukārt signāls (signal) Godot vidē ir paziņojums, ka kāds būtisks notikums jau ir iestājies. To var salīdzināt ar dūmu detektoru vai skolas zvanu: zvans noskan noteiktā brīdī, bet tam nav jāzina, vai skaņu uztver tikai gaitenī esošie cilvēki, vai arī automātiska tablo un žurnāla sistēma.

Šāda pieeja mazina klašu savstarpējo atkarību: raidītāja kodā nav jāuzskaita katra klausītāja darbības. Savienojumu izveido vadošais skripts, kurš atrod vajadzīgo objektu un pieslēdz savu apstrādes metodi; ja neviens klausītājs nav pieslēdzies, signāls tiek izraidīts klusi un kļūdu nerada.

Godot mezgls (Node), partial un sākuma datu iestatīšana

Lai objekts varētu atrasties scēnas kokā, būt atrodams pēc nosaukuma ar GetNode<Tips>("Nosaukums") un izmantot pielāgotus Godot signālus, klasei jāpieslēdz using Godot; un jāmanto no Node ar atslēgvārdu partial (piemēram, public partial class Sensors : Node). Vārds partial ļauj Godot kompilācijas (Build) laikā pievienot automātiski ģenerēto signālu apraksta kodu.

Atšķirībā no parastām C# klasēm, scēnas mezglus Godot vienmēr izveido bez argumentiem, tāpēc konstruktoru ar parametriem aizstāj ar atsevišķu sākuma iestatīšanas metodi (piemēram, Setup(...)); ja mezglu veido kodā, to izveido ar new, pievieno kokam ar AddChild(...) un tad iestata datus. Tāpat jāņem vērā, ka Node klasē jau ir iebūvēta īpašība Name (mezgla identifikators scēnas kokā), tāpēc paša skripta teksta laukiem izvēlas citu, atšķirīgu nosaukumu:

using Godot;

public partial class Sensors : Node
{
    public string SensoraNosaukums = "Noklusējums"; // Nevis Node.Name
    private int limenis = 50;

    public void Setup(string nosaukums, int sakumaLimenis)
    {
        SensoraNosaukums = nosaukums;
        limenis = sakumaLimenis;
    }

    public bool IrAktivs() { return limenis > 0; }
}

// Vadības mezgla metodē _Ready() — esošs vai kodā veidots mezgls:
Sensors gaismas = GetNode<Sensors>("GaismasSensors");
gaismas.Setup("Gaitenis", 40);

Sensors dumu = new Sensors();
AddChild(dumu);            // Pievieno mezglu scēnas kokam
dumu.Setup("Virtuve", 25); // Iestata datus bez parametru konstruktora

RaidītEmitSignal(SignalName.RobezaSasniegta, dati);Raidītājs nosūta paziņojumu un argumentus visiem pašlaik pieslēgtajiem klausītājiem.

Signāli, kas izraidīti pirms pieslēgšanās, vēlāk automātiski neatkārtojas, tāpēc inicializācijā ievēro secību: atrast mezglus → iestatīt sākuma datus → pieslēgt signālus (+=) → veikt darbības. Atvienošana ar -= atslēdz konkrēto klausītāja metodi, bet nemaina paša raidītāja iekšējo stāvokli. Savukārt loģiska sākuma pārbaude (ar noliegumu ! - „ne” un savienojumu || - „vai”) ļauj priekšlaicīgi iziet ar return, lai robežas sasniegšanas signāls tiktu nosūtīts tikai vienu reizi:

// Raidītāja klasē Sensors - vienreizējs signāls pie nulles robežas:
public void SamazinatLimeni(int daudzums)
{
    if (!IrAktivs() || daudzums <= 0) return;
    limenis = Math.Max(0, limenis - daudzums);
    if (limenis == 0)
        EmitSignal(SignalName.RobezaSasniegta, SensoraNosaukums);
}

// Klausītāja klasē - secība metodē _Ready():
Sensors s = GetNode<Sensors>("GaismasSensors"); // 1. Atrod mezglu
s.Setup("Gaitenis", 30);                        // 2. Iestata datus
s.RobezaSasniegta += ApstradesMetode;           // 3. Pieslēdz signālu
s.SamazinatLimeni(30);                          // 4. Raida tieši 1 reizi
s.RobezaSasniegta -= ApstradesMetode;           // Atvieno klausītāju

Pārvērt dalībniekus par Godot mezgliem un sagatavo Finished signālu

Kur strādāt: Atjauno failus Scripts/Participant.cs, Scripts/Captain.cs, Scripts/Presenter.cs (un Scripts/TimeKeeper.cs, ja to izveidoji 3.2. stundā), kā arī iztīri Scripts/LessonDemo.cs metodi _Ready(). Izveido jaunu scēnu Scenes/Tournament.tscn.

Tournament (Node - piesaistīts Scripts/TournamentManager.cs 2. uzdevumā)
 ├── Anna (Node - piesaistīts Scripts/Participant.cs)

Atver failu Scripts/Participant.cs un pielāgo to Godot mezglam: pievieno augšgalā using Godot; un using System;, klases galveni nomaini uz public partial class Participant : Node, lauku Name pārdēvē par public string ParticipantName = "Dalībnieks"; (lai tas nepārklātos ar Node.Name), un konstruktoru aizstāj ar metodi public void Setup(string name, int initialEnergy).
  2. Pievieno turpat failā Scripts/Participant.cs signāla deklarāciju [Signal] public delegate void FinishedEventHandler(string participantName); un metodē ApplyPenalty(int amount) izsauc EmitSignal(SignalName.Finished, ParticipantName);, tiklīdz enerģija sasniedz 0 (skat. koda paraugu zemāk).
  3. Atver failus Scripts/Captain.cs un Scripts/Presenter.cs (un Scripts/TimeKeeper.cs, ja tāds ir): katrā pievieno atslēgvārdu partial (public partial class Captain : Participant) un izdzēs vecos konstruktorus ar : base(...), atstājot tikai ApplyPenalty metodes.
  4. Atver failu Scripts/LessonDemo.cs un izdzēs no _Ready() iekšienes 3.2. stundas testa rindas (atstājot tukšu public override void _Ready() { }), lai vecie konstruktora izsaukumi netraucētu projekta kompilēšanai.
  5. Izveido jaunu scēnu ar Node sakni Tournament, pievieno tai divus Node bērna mezglus ar precīziem nosaukumiem Anna un Janis, abiem bērniem piesaisti skriptu Scripts/Participant.cs un saglabā scēnu kā res://Scenes/Tournament.tscn.
  6. Nospied Build, Scene kokā atlasi mezglu Anna un labās puses cilnē Node -> Signals pārliecinies, ka sarakstā ir parādījies tavs signāls Finished(participantName: String).
// 1. Fails: Scripts/Participant.cs (pilna 3.3. stundas versija)
using Godot;
using System;

public partial class Participant : Node
{
    [Signal]
    public delegate void FinishedEventHandler(string participantName);

    public string ParticipantName = "Dalībnieks";
    private int energy = 100;

    public void Setup(string name, int initialEnergy)
    {
        ParticipantName = name;
        energy = Math.Max(0, initialEnergy);
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (!IsActive() || amount <= 0) return;
        energy = Math.Max(0, energy - amount);
        if (energy == 0)
            EmitSignal(SignalName.Finished, ParticipantName);
    }

    public int GetEnergy() { return energy; }
    public bool IsActive() { return energy > 0; }
}

Gatavs, kad: projekts būvējas bez kļūdām un dalībnieka mezglam cilnē Node -> Signals ir redzams signāls Finished.

Saņem izstāšanās paziņojumu skriptā Scripts/TournamentManager.cs

Kur strādāt: Izveido jaunu skriptu Scripts/TournamentManager.cs un piesaisti to scēnas Scenes/Tournament.tscn saknei Tournament. Mezglu atrašanu, Setup(), signālu pieslēgšanu (+=) un sodu izsaukumus raksti metodē _Ready().

  1. Izveido failu res://Scripts/TournamentManager.cs (public partial class TournamentManager : Node) un piesaisti to scēnas Scenes/Tournament.tscn saknes mezglam Tournament.
  2. Pievieno klasē TournamentManager klausītāja metodi private void OnParticipantFinished(string participantName), kas izdrukā GD.Print(participantName, " izstājās");.
  3. Atrodi metodē _Ready() abus bērna mezglus ar Participant anna = GetNode<Participant>("Anna"); un Participant janis = GetNode<Participant>("Janis"); un iestati sākuma datus: anna.Setup("Anna", 30); un janis.Setup("Jānis", 20);.
  4. Pieslēdz metodē _Ready() abiem dalībniekiem klausītāju pirms sodu piemērošanas: anna.Finished += OnParticipantFinished; un janis.Finished += OnParticipantFinished;.
  5. Izsauc pēc pieslēgšanas sodus: anna.ApplyPenalty(10);, anna.ApplyPenalty(20);, anna.ApplyPenalty(5); un janis.ApplyPenalty(20);.
  6. Nospied Build un palaid scēnu Scenes/Tournament.tscn ar F6 — salīdzini Output izdruku ar tabulu zemāk un pārliecinies, ka pēc trešā soda Annai (ApplyPenalty(5)) otrs izstāšanās paziņojums neparādās.
// Fails: Scripts/TournamentManager.cs
using Godot;

public partial class TournamentManager : Node
{
    public override void _Ready()
    {
        Participant anna = GetNode<Participant>("Anna");
        Participant janis = GetNode<Participant>("Janis");
        anna.Setup("Anna", 30);
        janis.Setup("Jānis", 20);

        anna.Finished += OnParticipantFinished;
        janis.Finished += OnParticipantFinished;

        anna.ApplyPenalty(10);  // Paliek 20. Signāla vēl nav.
        anna.ApplyPenalty(20);  // Sasniedz 0 -> Anna izstājas.
        anna.ApplyPenalty(5);   // Jau izstājusies -> otrs paziņojums nerodas.
        janis.ApplyPenalty(20); // Sasniedz 0 -> Jānis izstājas.
    }

    private void OnParticipantFinished(string participantName)
    {
        GD.Print(participantName, " izstājās");
    }
}

3. uzdevums

Atvieno klausītāju ar -= un salīdzini stāvokli ar paziņojumu

Kur strādāt: Atvienošanas rindu -= un enerģijas pārbaudes izdruku pievieno failā Scripts/TournamentManager.cs metodē _Ready(); secinājumus ieraksti failā README.md.

  1. Atver failu Scripts/TournamentManager.cs un metodē _Ready() tūlīt aiz += pieslēgšanas rindām (pirms sodu izsaukumiem) pievieno atvienošanas rindu: anna.Finished -= OnParticipantFinished;.
  2. Pievieno metodes _Ready() beigās kontroles izdruku GD.Print("Annas enerģija beigās: ", anna.GetEnergy());.
  3. Nospied Build un palaid scēnu Scenes/Tournament.tscn (F6): pārliecinies, ka Annas enerģija joprojām kļūst 0, taču izstāšanās paziņojumu Output panelī izdrukā tikai Jānis.
  4. Izdzēs pagaidu atvienošanas rindu anna.Finished -= OnParticipantFinished; un pārbaudi ar F6, ka atkal parādās abi paziņojumi.
  5. Pieraksti failā README.md: (a) kādā secībā jāizpilda Setup, += un ApplyPenalty; (b) kāpēc pēc -= atvienošanas Annas enerģija tik un tā samazinājās līdz 0; (c) kura klase šajā pārī pazīst otru un kura tikai izziņo notikumu.

Gatavs, kad: esi pārbaudījis -= darbību, atjaunojis abus signālu pieslēgumus un pierakstījis secinājumus README.md.

Papildu uzdevums - Paziņo arī par katru sodu ar signālu PenaltyApplied

Kur strādāt: Signālu PenaltyAppliedEventHandler un tā izsaukšanu pievieno failā Scripts/Participant.cs. Klausītāja metodi un += pieslēgumu pievieno failā Scripts/TournamentManager.cs.

Ja pamatdarbs ir gatavs, pievieno otru signālu, kas pēc katra soda paziņo faktiski zaudēto punktu skaitu.

  1. Pievieno failā Scripts/Participant.cs signālu [Signal] public delegate void PenaltyAppliedEventHandler(string participantName, int lostPoints);.
  2. Metodē ApplyPenalty(int amount) pirms atņemšanas saglabā int before = energy;, pēc atņemšanas aprēķini faktisko zudumu int lost = before - energy; un izsauc EmitSignal(SignalName.PenaltyApplied, ParticipantName, lost);.
  3. Pieslēdz failā Scripts/TournamentManager.cs šim signālam klausītāja metodi un pārbaudi, ka pie atlikušiem 5 punktiem un soda 20 signāls paziņo par faktiski zaudētiem 5 punktiem.

Gatavs, kad: katrs derīgs sods izraida PenaltyApplied ar faktiski zaudēto enerģijas daudzumu.

Ko sagatavo

Stundas mērķis: Dalībnieku klases ir pārvērstas par Godot Node mezgliem ar Setup() metodi un Finished signālu, ko scēnā Scenes/Tournament.tscn uztver un apstrādā Scripts/TournamentManager.cs.

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Saderīgus skriptus Scripts/Participant.cs, Scripts/Captain.cs, Scripts/Presenter.cs, Scripts/TournamentManager.cs un scēnu Scenes/Tournament.tscn.
  • Output izdrukas ar diviem izstāšanās paziņojumiem un ar vienu paziņojumu pēc -= atvienošanas pārbaudes.
  • README.md: skaidrojums par Setup → += → ApplyPenalty izpildes secību un to, ko maina -=.

Kā iesniedz: Saglabā failus, veic git commit un git push. Skolotāja norādītajā vietā iesniedz GitHub krātuves saiti.

Ja kaut kas nestrādā

  • Node not found: salīdzini GetNode ceļu ar scēnas koku. Anna un Janis jābūt saknes bērniem.
  • Nav Finished vai SignalName: pārbaudi [Signal], EventHandler galotni un partial; nospied Build.
  • Vecais konstruktors vairs neder: šīs stundas mezglus veido bez argumentiem un datus iestata ar Setup. Atjauno arī iepriekšējos pārbaudes skriptus.
  • Divi vienādi paziņojumi: pārbaudi, vai vienu metodi nepieslēdzi divreiz un vai ApplyPenalty ignorē jau neaktīvu dalībnieku.
