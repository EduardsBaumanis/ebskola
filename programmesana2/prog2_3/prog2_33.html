3.3 Signāli un objektu komunikācija

Stundas uzdevums: Apgūt Godot signal sistēmu objektu komunikācijai.

SR 2.4.15. Modulāras programmas SR 2.4.18. OOP

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - reģistrē un raidi signālu · 2. uzdevums (~25 min) - pieslēdzies signālam no cita objekta · 3. uzdevums (~20 min) - salīdzini signālu ar tiešu izsaukumu · Iesniegšana (~5 min).

Pirms sāc: atver savu projektu ar dalībnieku klasēm. Signāls ir kā paziņojums: viens objekts pasaka "tas notika", bet citi paši izlemj, vai klausīties.

Teorija: Godot signāli (Signals)

Godot signāli ir veids, kā objekti var sazināties bez tieša savienojuma. Viens objekts emit (raida) signālu, citi connect (pievienojas), lai uz to reaģētu.

// Klases definīcijā ar signal
class Participant : public Node {
    GDCLASS(Participant, Node)
protected:
    static void _bind_methods() {
        ClassDB::bind_method(...);
        // Reģistrē signal
        ADD_SIGNAL(MethodInfo("finished", PropertyInfo(Variant::STRING, "name")));
        ADD_SIGNAL(MethodInfo("penalty_applied", PropertyInfo(Variant::INT, "amount")));
    }

public:
    void apply_penalty(int amount) {
        energy -= amount;
        emit_signal("penalty_applied", amount);
        if (energy <= 0) emit_signal("finished", name);
    }
};

Citur kodā:

hero->connect("finished", Callable(this, "on_hero_finished"));

Kā šo izmantot projektā

Atceries: ar redzamu efektu editorā nepietiek. Paskaidro, kura C++ klase glabā stāvokli, kura metode to maina un kā Godot node struktūra izmanto šo kodu.

Pārbaudi: katrai būtiskai turnīra lomai ir C++ klase ar header/implementation dalījumu, konstruktoriem, metodēm, signāliem vai mantošanu.

Praktiskie uzdevumi

1. uzdevums - Reģistrē un raidi signālu

Beigās tavs objekts pratīs paziņot, ka tas beidzis darbu.

  1. Nomaini Participant tā, lai tā mantotu no Node un lietotu GDCLASS(Participant, Node).
  2. Pievieno _bind_methods metodē ADD_SIGNAL(MethodInfo("finished", PropertyInfo(Variant::STRING, "name")));.
  3. Uzraksti metodē apply_penalty pārbaudi, vai enerģija nokritusi līdz 0.
  4. Izsauc tajā emit_signal("finished", name);.
  5. Kompilē un pievieno objektu scēnai.
  6. Pārbaudi Godot editorā cilnē Node -> Signals, vai signāls finished tur ir redzams.
  7. Pieraksti, kas notiek, ja ADD_SIGNAL rindu izdzēš.

Gatavs, kad: Godot editora Signals sarakstā parādās tavs signāls finished.

2. uzdevums - Pieslēdzies signālam no cita objekta

Beigās cits objekts uzzinās par notikumu, tieši to nepārbaudot.

  1. Izveido C++ klasi TournamentManager, kas manto no Node.
  2. Pievieno tai metodi void on_participant_finished(String name);.
  3. Reģistrē to _bind_methods metodē ar ClassDB::bind_method.
  4. Savieno _ready metodē signālu ar participant->connect("finished", Callable(this, "on_participant_finished"));.
  5. Izdrukā apstrādātājā, kurš dalībnieks beidzis darbu.
  6. Kompilē un samazini dalībnieka enerģiju līdz nullei.
  7. Pārbaudi Output panelī, ka paziņojums pienāca.

Gatavs, kad: kad dalībnieka enerģija sasniedz 0, menedžeris izdrukā tā vārdu, lai gan pats to nepārbaudīja.

3. uzdevums - Salīdzini signālu ar tiešu izsaukumu

Beigās tu zināsi, kāpēc signāli ir ērtāki par tiešu saiti.

  1. Pievieno otru dalībnieku un pieslēdz arī to tam pašam signālam.
  2. Samazini abu enerģiju un pārbaudi, ka pienāk divi paziņojumi.
  3. Iedomājies variantu, kur Participant pats izsauktu menedžeri, un pieraksti, ko tad vajadzētu glabāt katrā dalībniekā.
  4. Pieraksti, kas notiktu ar šo variantu, ja menedžera scēnā nav.
  5. Atvieno vienu dalībnieku ar disconnect(...) un pārbaudi vēlreiz.
  6. Pieraksti, cik paziņojumu tagad pienāca.
  7. Pieraksti secinājumu: kurš objekts zina par kuru.

Gatavs, kad: abi dalībnieki raida signālu neatkarīgi, un atvienotais vairs neizraisa paziņojumu.

Papildu uzdevums - Pievieno signālam vairāk datu

Ja pamatdarbs ir gatavs, nodod signālā arī skaitli.

  1. Papildini ADD_SIGNAL ar otru parametru, piemēram atlikušo enerģiju.
  2. Nodod to emit_signal izsaukumā.
  3. Papildini apstrādātāja metodi ar otru parametru.
  4. Izdrukā abus datus.
  5. Pārbaudi, ka kompilators sūdzas, ja parametru skaits nesakrīt.

Gatavs, kad: signāls nodod gan vārdu, gan skaitli, un tie abi parādās izdrukā.

Ko iesniedz skolotājam

Stundas mērķis: Tu proti C++ klasē reģistrēt Godot signālu, to raidīt notikuma brīdī un pieslēgt tam citu objektu, un vari izskaidrot, kāpēc signāls ir ērtāks par tiešu izsaukumu.

Iesniedzamais:

  1. Faili ar ADD_SIGNAL, emit_signal un connect izsaukumiem GitHub krātuvē.
  2. Ekrānuzņēmums ar Godot Node -> Signals cilni, kurā redzams tavs signāls.
  3. Ekrānuzņēmums ar Output paneli, kurā redzami abu dalībnieku paziņojumi.
  4. README.md: viens teikums par to, kurš objekts par kuru zina, lietojot signālus.

Kā iesniedz: Veic commit un push, tad iesniedz krātuves saiti un abus ekrānuzņēmumus skolotāja norādītajā vietā.

Biežākās kļūdas

  • emit_signal nav efekta: Signal nav reģistrēts ar ADD_SIGNAL.
  • Callable error: Metode klasei nav reģistrēta ar bind_method.
  • Signal saņemts vairākkārt: Connect izsaukts vairākas reizes - pārbaudi is_connected.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

#include <godot_cpp/core/method_bind.hpp>

void Participant::_bind_methods() {
    ClassDB::bind_method(D_METHOD("apply_penalty", "amount"),
                         &Participant::apply_penalty);
    ADD_SIGNAL(MethodInfo("penalty_applied",
        PropertyInfo(Variant::INT, "amount")));
    ADD_SIGNAL(MethodInfo("finished",
        PropertyInfo(Variant::STRING, "name")));
}

void Participant::apply_penalty(int amount) {
    energy = std::max(0, energy - amount);
    emit_signal("penalty_applied", amount);
    if (energy == 0) {
        emit_signal("finished", name);
    }
}

// Game klasē
void Game::_ready() {
    Participant* anna = ...;
    anna->connect("penalty_applied", Callable(this, "on_penalty"));
    anna->connect("finished", Callable(this, "on_finished"));
}
