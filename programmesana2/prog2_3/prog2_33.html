3.3 Signal (signāli) un object communication (objektu komunikācija)

Stundas uzdevums: Apgūt Godot signal sistēmu object (objektu) komunikācijai.

SR 2.4.15. Modulāras programmas SR 2.4.18. OOP (objektorientētā programmēšana)

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - reģistrē un raidi signal · 2. uzdevums (~25 min) - pieslēdzies signal no cita object · 3. uzdevums (~20 min) - salīdzini signal ar tiešu izsaukumu · Iesniegšana (~5 min).

Pirms sāc: atver savu projektu ar dalībnieku class (klasēm). Signal ir kā paziņojums: viens object pasaka "tas notika", bet citi paši izlemj, vai klausīties.

Teorija: Godot Signals

Godot signal ir veids, kā object var sazināties bez tieša savienojuma. Viens object emit (raida) signal, citi connect (pievienojas), lai uz to reaģētu.

using Godot;
using System;

public partial class Participant : Node
{
    [Signal] public delegate void FinishedEventHandler(string name);
    [Signal] public delegate void PenaltyAppliedEventHandler(int amount);

    private int energy = 100;
    private string participantName = "Anna";

    public void ApplyPenalty(int amount)
    {
        energy -= amount;
        EmitSignal(SignalName.PenaltyApplied, amount);
        if (energy <= 0)
            EmitSignal(SignalName.Finished, participantName);
    }
}

Citur kodā:

hero.Finished += OnHeroFinished;

Praktiskie uzdevumi

1. uzdevums -

Reģistrē un raidi signal

Beigās tavs object pratīs paziņot, ka tas beidzis darbu.

  1. Nomaini Participant tā, lai tā mantotu no Node: public partial class Participant : Node.
  2. Pievieno class signal [Signal] public delegate void FinishedEventHandler(string name);.
  3. Uzraksti method ApplyPenalty pārbaudi, vai enerģija nokritusi līdz 0.
  4. Izsauc tajā EmitSignal(SignalName.Finished, Name);.
  5. Būvē projektu un pievieno object scēnai.
  6. Pārbaudi Godot redaktorā cilnē Node -> Signals, vai signal finished tur ir redzams.
  7. Pieraksti, kas notiek, ja [Signal] (signāla atribūts) rindu izdzēš.

Gatavs, kad: Godot redaktora Signals sarakstā parādās tavs signal finished.

2. uzdevums -

Pieslēdzies signal no cita object

Beigās cits object uzzinās par event (notikumu), tieši to nepārbaudot.

  1. Izveido C# class TournamentManager, kas manto no Node.
  2. Pievieno tai method private void OnParticipantFinished(string name).
  3. Paņem dalībnieku ar Participant participant = GetNode<Participant>("Participant");.
  4. Savieno _Ready() method signal ar participant.Finished += OnParticipantFinished;.
  5. Izdrukā handler (apstrādātājā), kurš dalībnieks beidzis darbu.
  6. Būvē un samazini dalībnieka enerģiju līdz nullei.
  7. Pārbaudi Output panelī, ka paziņojums pienāca.

Gatavs, kad: kad dalībnieka enerģija sasniedz 0, menedžeris izdrukā tā vārdu, lai gan pats to nepārbaudīja.

3. uzdevums -

Salīdzini signal ar tiešu izsaukumu

Beigās tu zināsi, kāpēc signal ir ērtāki par tiešu saiti.

  1. Pievieno otru dalībnieku un pieslēdz arī to tam pašam signal.
  2. Samazini abu enerģiju un pārbaudi, ka pienāk divi paziņojumi.
  3. Iedomājies variantu, kur Participant pats izsauktu menedžeri, un pieraksti, ko tad vajadzētu glabāt katrā dalībniekā.
  4. Pieraksti, kas notiktu ar šo variantu, ja menedžera scēnā nav.
  5. Atvieno vienu dalībnieku ar participant.Finished -= OnParticipantFinished; un pārbaudi vēlreiz.
  6. Pieraksti, cik paziņojumu tagad pienāca.
  7. Pieraksti secinājumu: kurš object zina par kuru.

Gatavs, kad: abi dalībnieki raida signal neatkarīgi, un atvienotais vairs neizraisa paziņojumu.

Papildu uzdevums - Pievieno signal vairāk datu

Ja pamatdarbs ir gatavs, nodod signal arī skaitli.

  1. Papildini signal delegate (deleģāts) ar otru parameter (parametru), piemēram atlikušo enerģiju.
  2. Nodod to EmitSignal izsaukumā.
  3. Papildini handler method ar otru parameter.
  4. Izdrukā abus datus.
  5. Pārbaudi, ka compiler (kompilators) sūdzas, ja parameter skaits nesakrīt.

Gatavs, kad: signal nodod gan vārdu, gan skaitli, un tie abi parādās izdrukā.

Ko sagatavo

Stundas mērķis: Tu proti C# class reģistrēt Godot signal, to raidīt event brīdī un pieslēgt tam citu object, un vari izskaidrot, kāpēc signal ir ērtāks par tiešu izsaukumu.

GitHub krātuvē jābūt:

  1. Faili ar [Signal], EmitSignal un += signal pieslēgumu.
  2. Ekrānuzņēmums ar Godot Node -> Signals cilni, kurā redzams tavs signal.
  3. Ekrānuzņēmums ar Output paneli, kurā redzami abu dalībnieku paziņojumi.
  4. README.md: viens teikums par to, kurš object par kuru zina, lietojot signal.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Biežākās kļūdas

  • EmitSignal nav efekta: signal nav pieteikts ar [Signal] vai netiek izsaukts pareizais SignalName.
  • Handler kļūda: handler parameter skaitam un type (tipiem) jāsakrīt ar signal delegate.
  • Signal saņemts vairākkārt: += izsaukts vairākas reizes - pieslēdz signal vienā vietā, parasti _Ready().

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

using Godot;
using System;

public partial class Participant : Node
{
    [Signal] public delegate void PenaltyAppliedEventHandler(int amount);
    [Signal] public delegate void FinishedEventHandler(string name);

    private int energy = 100;
    private string participantName = "Anna";

    public void ApplyPenalty(int amount)
    {
        energy = Math.Max(0, energy - amount);
        EmitSignal(SignalName.PenaltyApplied, amount);
        if (energy == 0)
            EmitSignal(SignalName.Finished, participantName);
    }
}

public partial class Game : Node
{
    public override void _Ready()
    {
        Participant anna = GetNode<Participant>("Anna");
        anna.PenaltyApplied += OnPenalty;
        anna.Finished += OnFinished;
    }

    private void OnPenalty(int amount) { }
    private void OnFinished(string name) { }
}
