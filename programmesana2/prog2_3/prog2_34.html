3.4 Klases un iestatījumi Godot redaktorā

Stundas uzdevums: Izveido šķēršļa klasi un iestati trīs dažādus šķēršļus Inspector panelī.

SR 2.4.7. UI (lietotāja saskarne) SR 2.4.18. Objektorientētā programmēšana

Pirms sāc: atver esošo Godot .NET projektu. Šodien pievienosi šķēršļu datus; 3.3. dalībnieku signālus saglabā.

Darba secība: izlasi skaidrojumu pie attiecīgā uzdevuma, paredzi piemēra rezultātu un tad pārbaudi to. Pēc C# izmaiņām saglabā failus, Godot nospied Build un palaid scēnu ar F6. Rezultātus skaties Output panelī.

Failu ceļi: ceļi ir norādīti no tava Godot projekta mapes, kur atrodas project.godot; piemēram, Scripts/Player.cs Godot panelī ir res://Scripts/Player.cs. Ja norādītais fails jau ir izveidots, atver un papildini to.

Jaunus C# failus veido mapē Scripts, scēnas — norādītajā ceļā; trūkstošās mapes izveido. Ja tavā projektā skripts glabājas citur, rediģē esošo failu. using direktīvas raksti faila sākumā, laukus un metodes — klases iekšienē. Esošu _Ready() vai _PhysicsProcess() papildini, neveido otru tāda paša nosaukuma metodi.

Teorija ar piemēriem

1. Viens apraksts, trīs dažādi šķēršļi

Turnīrā var gadīties rinda pie printera, pazust internets vai marķieris. Katram šķērslim vajag nosaukumu un soda lielumu. Nav vajadzīgs jauns skripts katram nosaukumam: izveidosim vienu Obstacle klasi un trīs tās mezglus ar dažādiem iestatījumiem.

Šajā turnīrā šķērslis ir notikums, kas samazina dalībnieka enerģiju. Tāpēc lietosim Node; kustība un sadursmju formas šim piemēram nav vajadzīgas. Lauku Penalty lasi kā “soda lielums”, piemēram, 20 enerģijas punkti.

2. Ko dara [GlobalClass] un [Export]?

PierakstsKo tas ļauj izdarītKo tas neveic
[GlobalClass] virs klasesAtrast Obstacle pēc nosaukuma Add Node logā.Neizveido šķērsli scēnā tavā vietā.
[Export] virs lauka vai īpašībasMainīt vērtību Inspector un saglabāt to kopā ar scēnu.Nepiemēro sodu automātiski. To vēlāk darīs kods.

Abas atzīmes lieto dažādiem mērķiem. Parasts public dod piekļuvi no cita C# koda, bet viens pats neparāda vērtību Inspector. Pēc atzīmju pievienošanas saglabā failu un nospied Build.

3. Īpašība izskatās kā vērtība, bet var to pārbaudīt

Lauks tieši glabā vērtību. Īpašība dod veidu, kā to nolasīt un iestatīt. Vienkāršā pierakstā get ļauj nolasīt, bet set — iestatīt. Šajā piemērā C# glabāšanas daļu izveido pats:

[Export]
public string ObstacleName { get; set; } = "Rinda pie printera";

Sodam vēlamies noteikumu: tam jābūt vismaz 1. Tāpēc vērtību glabāsim privātā laukā penalty, bet iestatīšanu veiksim caur īpašību Penalty.

private int penalty = 20;

[Export(PropertyHint.Range, "1,50,1")]
public int Penalty
{
    get { return penalty; }
    set { penalty = Math.Max(1, value); }
}

Kad kods lasa obstacle.Penalty, izpildās get. Kad piešķir obstacle.Penalty = -5, izpildās set, un value tajā ir −5. Math.Max(1, -5) atdod 1, tāpēc saglabājas 1. Sods nevar kļūt negatīvs un nejauši atjaunot enerģiju.

"1,50,1" dod redaktoram norādi: diapazons no 1 līdz 50 ar soli 1. Tā ir ievades ērtība; mūsu set atsevišķi nodrošina minimumu arī piešķīrumiem C# kodā. Šajā piemērā maksimālā vērtība kodā netiek ierobežota.

4. Kura vērtība darbosies spēlē?

Koda sākuma vērtība ir penalty = 20. Ja konkrētam mezglam Inspector iestati 12 un saglabā scēnu, palaižot šo mezglu izmantos tā saglabāto vērtību 12. Citam tās pašas klases mezglam var būt 25.

Scēnas mezgla Name palīdz atrast mezglu kodā. ObstacleName ir teksts, kuru izdrukājam cilvēkam. Tiem nav jābūt vienādiem. Izmainot vienu mezglu, pārējie divi saglabā savus iestatījumus.

5. Kā novērot, ka dati tiešām nonākuši kodā?

Failā Obstacle.cs pievieno šo metodi. Katrs šķērslis, nonākot gatavā scēnā, izdrukās savu nosaukumu un sodu:

public override void _Ready()
{
    GD.Print(ObstacleName, ": sods ", Penalty);
}

Izveido scēnu ObstacleDemo.tscn ar sakni Node un trim Obstacle bērniem. Palaid ar F6. Skaties uz trim izdrukām, nevis tikai Inspector: tā pārbaudi vērtības, kuras saņem darbojošā programma.

Pašpārbaude: Kāpēc pēc penalty = 30 ierakstīšanas kodā vienam mezglam joprojām ir 12?

Scēnā šim mezglam jau saglabāts atsevišķs iestatījums. Maini tā Penalty Inspector panelī vai izmanto atgriešanos pie noklusējuma vērtības. Koda sākuma vērtība nepārraksta katru agrāk saglabāto izvēli.

1. uzdevums

Pievieno savu mezgla tipu

Kur strādāt: Izveido Scripts/Obstacle.cs ar Obstacle klasi un Godot redaktorā saglabā scēnu Scenes/ObstacleDemo.tscn.

Atbalsts: skaidrojums un piemērs.

  1. Izveido Obstacle.cs ar using Godot;, [GlobalClass] un public partial class Obstacle : Node.
  2. Saglabā, nospied Build un ar Add Node atrodi Obstacle. Faila un klases nosaukumam jāsakrīt, arī lielajiem burtiem.
  3. Izveido ObstacleDemo.tscn ar sakni Node un pievieno vienu Obstacle.

Gatavs, kad: tavs mezgla tips ir atrodams un pievienojams scēnai.

2. uzdevums

Pievieno nosaukumu un soda iestatījumu

Kur strādāt: Visus laukus, īpašības un _Ready() metodi pievieno Scripts/Obstacle.cs klases iekšienē. Pagaidu piešķīrumu Penalty = -5; raksti šīs metodes sākumā.

Atbalsts: skaidrojums un piemērs.

  1. Pievieno ObstacleName īpašību ar [Export].
  2. Pievieno privāto penalty lauku un Penalty īpašību ar get, set un diapazona norādi.
  3. Nospied Build, atlasi Obstacle un Inspector atrodi Obstacle Name un Penalty.
  4. Pievieno _Ready izdruku. Uz vienu pārbaudes palaišanu pirms tās ieraksti Penalty = -5;: jāizdrukā sods 1. Pēc pārbaudes šo piešķīrumu izdzēs.

Gatavs, kad: sodu var mainīt Inspector, bet negatīvu piešķīrumu kods pārvērš par 1.

3. uzdevums

Salīdzini trīs viena tipa mezglus

Kur strādāt: Trīs mezglus un to Inspector vērtības maini Scenes/ObstacleDemo.tscn; visi izmanto vienu Scripts/Obstacle.cs. Novērojumus raksti README.md.

Atbalsts: skaidrojums un piemērs.

  1. Scēnā izveido trīs Obstacle mezglus un nosauc tos kā teorijas tabulā.
  2. Iestati katram savu Obstacle Name un Penalty. Saglabā scēnu.
  3. Palaid un salīdzini trīs izdrukas ar iestatījumiem.
  4. Maini tikai PrinterQueue sodu, palaid vēlreiz un pieraksti, kuras izdrukas mainījās.

Gatavs, kad: trīs objekti lieto vienu skriptu un katrs saglabā savus datus.

Papildu uzdevums — Pievieno apraksta tekstu

Kur strādāt: Īpašību Description pievieno Scripts/Obstacle.cs, un šī faila metodē _Ready() papildini izdruku. Aprakstu vērtības ievadi Scenes/ObstacleDemo.tscn Inspector panelī.

Izveido vēl vienu eksportētu string īpašību Description. Katram šķērslim uzraksti īsu aprakstu un pievieno to izdrukai. Pārbaudi, vai jaunā īpašība parādās pēc Build.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Obstacle.cs

using Godot;
using System;

[GlobalClass]
public partial class Obstacle : Node
{
    private int penalty = 20;

    [Export]
    public string ObstacleName { get; set; } = "Rinda pie printera";

    [Export(PropertyHint.Range, "1,50,1")]
    public int Penalty
    {
        get { return penalty; }
        set { penalty = Math.Max(1, value); }
    }

    public override void _Ready()
    {
        GD.Print(ObstacleName, ": sods ", Penalty);
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Obstacle.cs un ObstacleDemo.tscn ar trim iestatītiem šķēršļiem.
  • Inspector un Output salīdzinājums pirms un pēc viena šķēršļa maiņas.
  • README: ko dara [Export], ko dara set un kura vērtība tiek izmantota pēc scēnas saglabāšanas.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Obstacle neparādās: pārbaudi faila nosaukumu, [GlobalClass], partial un Build kļūdas.
  • Inspector lauka nav: pārbaudi [Export] un to, vai atlasīts pareizais mezgls.
  • Visiem sods ir 1: izdzēs pagaidu Penalty = -5 pārbaudi no _Ready.
  • Mainīju kodu, bet skaitlis palika: pārbaudi konkrētā mezgla scēnā saglabāto Inspector vērtību.
