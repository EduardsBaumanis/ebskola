Stundas uzdevums: Izveido šķēršļa klasi un iestati trīs dažādus šķēršļus Inspector panelī.

SR 2.4.7. UI (lietotāja saskarne) SR 2.4.18. Objektorientētā programmēšana

Teorija: C# īpašības un redaktora atribūti Godot vidē

Viena klase vairākiem mezgliem un atribūti [GlobalClass] un [Export]

Ja vairāki scēnas objekti darbojas pēc vienādiem noteikumiem un atšķiras tikai ar nosaukumu vai skaitlisku parametru, nav jāveido atsevišķs skripts katram vienumam — vienu C# klasi pievieno vairākiem neatkarīgiem mezgliem (ja mezglam nav vajadzīgas koordinātas vai sadursmes, tas manto tieši no Node).

AtribūtsKo tas nodrošinaKo tas nedara automātiski
[GlobalClass] virs klasesĻauj atrast partial klasi pēc nosaukuma Add Node logā (ja faila un klases nosaukumi sakrīt).Neizveido un nepievieno mezglu scēnai izstrādātāja vietā.
[Export] virs lauka vai īpašībasParāda vērtību Inspector panelī un saglabā to kopā ar konkrēto mezglu scēnā.Neizpilda aprēķinus pats par sevi — to izmanto programmas kods.

Parasts public padara datus pieejamus citam C# kodam, bet bez [Export] tie neparādās Inspector panelī. Pēc atribūtu pievienošanas fails jāsaglabā un jānospiež Build:

using Godot;

[GlobalClass]
public partial class Termostats : Node
{
    [Export]
    public string TelpasNosaukums { get; set; } = "Kabinets";

    // Bez [Export] lauks ir pieejams C# kodā, bet ne Inspector panelī:
    public bool IrIeslegts = true;
}

C# īpašības (get, set un value) un diapazona norāde

Atšķirībā no parasta lauka, īpašība (property) apvieno vērtības nolasīšanu (get) un piešķiršanu (set). Ja papildu pārbaude nav vajadzīga, lieto īso pierakstu [Export] public string Virsraksts { get; set; } = "Noklusējums";, kur glabāšanas vietu C# izveido automātiski. Ja jāaizsargā derīgo vērtību robežas — līdzīgi kā digitālam termostatam, kas neļauj iestatīt temperatūru zem drošā minimuma —, datus glabā private laukā un piešķiršanu kontrolē caur set:

private int intensitate = 20;

[Export(PropertyHint.Range, "1,50,1")]
public int Intensitate
{
    get { return intensitate; }
    set { intensitate = Math.Max(1, value); }
}

Nolasot objekts.Intensitate, izpildās get. Piešķirot jaunu skaitli, izpildās set, kur iebūvētais atslēgvārds value satur jaunpiešķirto vērtību, bet Math.Max(1, value) neļauj saglabāt skaitli, kas mazāks par 1. Norāde PropertyHint.Range ("min,max,solis") sniedz ērtu ievades ierobežojumu Inspector panelī, savukārt set nosacījums nosargā minimumu arī piešķīrumiem tieši C# kodā.

Scēnā saglabāto Inspector vērtību prioritāte un mezgla nosaukums

Kodā ierakstītā sākumvērtība kalpo kā noklusējums jauniem mezgliem. Ja konkrētam mezglam Inspector panelī iestata citu skaitli un saglabā scēnu, palaižot programmu, tieši šī scēnā saglabātā vērtība ir noteicošā (vēlāka noklusējuma maiņa C# failā nepārraksta jau saglabātu mezgla iestatījumu, kamēr to neatjauno Inspector panelī; arī pārējie tās pašas klases mezgli saglabā katrs savus datus).

Tāpat jāatšķir mezgla tehniskais Name Scene kokā (pēc kura mezglu atrod kodā, piemēram, ar GetNode) no eksportētas teksta īpašības, ko izvada lasāmai saziņai ar lietotāju — tiem nav jāsakrīt, un patieso izpildes laika vērtību drošāk pārbaudīt ar GD.Print metodē _Ready():

// Katrs Termostats mezgls izdrukā savu Scene vārdu un Inspector datus:
public override void _Ready()
{
    GD.Print("[", Name, "] ", TelpasNosaukums, ": ", Intensitate);
}

// Vadības skriptā mezglu atrod pēc tā tehniskā Name scēnas kokā:
Termostats pirmais = GetNode<Termostats>("Termostats1");

1. uzdevums

Pievieno savu mezgla tipu

Kur strādāt: Izveido Scripts/Obstacle.cs ar Obstacle klasi un Godot redaktorā saglabā scēnu Scenes/ObstacleDemo.tscn.

  1. Izveido Obstacle.cs ar using Godot;, [GlobalClass] un public partial class Obstacle : Node (šajā projektā šķērslis ir notikums, kas samazina enerģiju, tāpēc kustība un sadursmju formas nav vajadzīgas).
  2. Saglabā, nospied Build un ar Add Node atrodi Obstacle. Faila un klases nosaukumam precīzi jāsakrīt, ieskaitot lielos burtus.
  3. Izveido ObstacleDemo.tscn ar sakni Node un pievieno vienu Obstacle bērna mezglu.

Gatavs, kad: tavs mezgla tips ir atrodams un pievienojams scēnai.

2. uzdevums

Pievieno nosaukumu un soda iestatījumu

Kur strādāt: Visus laukus, īpašības un _Ready() metodi pievieno Scripts/Obstacle.cs klases iekšienē. Pagaidu piešķīrumu Penalty = -5; raksti šīs metodes sākumā.

  1. Pievieno ObstacleName īpašību ar [Export] pēc parauga zemāk.
  2. Pievieno using System;, privāto penalty lauku un Penalty īpašību ar get, set (minimums 1, lai sods nekļūtu negatīvs) un diapazona norādi "1,50,1".
  3. Nospied Build, atlasi Obstacle mezglu un Inspector panelī atrodi Obstacle Name un Penalty.
  4. Pievieno _Ready() izdruku. Uz vienu pārbaudes palaišanu pirms tās ieraksti Penalty = -5; — Output jāizdrukā sods 1. Pēc pārbaudes šo piešķīrumu izdzēs.
private int penalty = 20;

[Export]
public string ObstacleName { get; set; } = "Rinda pie printera";

[Export(PropertyHint.Range, "1,50,1")]
public int Penalty
{
    get { return penalty; }
    set { penalty = Math.Max(1, value); }
}

public override void _Ready()
{
    GD.Print(ObstacleName, ": sods ", Penalty);
}

Gatavs, kad: sodu var mainīt Inspector, bet negatīvu piešķīrumu kods pārvērš par 1.

Salīdzini trīs viena tipa mezglus

Kur strādāt: Trīs mezglus un to Inspector vērtības maini Scenes/ObstacleDemo.tscn; visi izmanto vienu Scripts/Obstacle.cs. Novērojumus raksti README.md.

  1. Scēnā ObstacleDemo.tscn izveido trīs Obstacle bērna mezglus un nosauc tos pēc tabulas zemāk (mezgla Name palīdz atrast mezglu kodā, bet ObstacleName ir cilvēkam izdrukājamais teksts).
  2. Inspector panelī iestati katram savu Obstacle Name un Penalty pēc tabulas. Saglabā scēnu.
  3. Palaid ar F6 un salīdzini trīs Output izdrukas ar iestatījumiem.
  4. Maini tikai PrinterQueue sodu Inspector panelī, palaid vēlreiz un README pieraksti, kuras izdrukas mainījās (un kāpēc scēnā saglabāta vērtība ir noteicošā pār koda sākuma penalty = 20).

Papildu uzdevums — Pievieno apraksta tekstu

Kur strādāt: Īpašību Description pievieno Scripts/Obstacle.cs, un šī faila metodē _Ready() papildini izdruku. Aprakstu vērtības ievadi Scenes/ObstacleDemo.tscn Inspector panelī.

Izveido vēl vienu eksportētu string īpašību Description. Katram šķērslim uzraksti īsu aprakstu un pievieno to izdrukai. Pārbaudi, vai jaunā īpašība parādās pēc Build.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Obstacle.cs

using Godot;
using System;

[GlobalClass]
public partial class Obstacle : Node
{
    private int penalty = 20;

    [Export]
    public string ObstacleName { get; set; } = "Rinda pie printera";

    [Export(PropertyHint.Range, "1,50,1")]
    public int Penalty
    {
        get { return penalty; }
        set { penalty = Math.Max(1, value); }
    }

    public override void _Ready()
    {
        GD.Print(ObstacleName, ": sods ", Penalty);
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Obstacle.cs un ObstacleDemo.tscn ar trim iestatītiem šķēršļiem.
  • Inspector un Output salīdzinājums pirms un pēc viena šķēršļa maiņas.
  • README: ko dara [Export], ko dara set un kura vērtība tiek izmantota pēc scēnas saglabāšanas.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Obstacle neparādās: pārbaudi faila nosaukumu, [GlobalClass], partial un Build kļūdas.
  • Inspector lauka nav: pārbaudi [Export] un to, vai atlasīts pareizais mezgls.
  • Visiem sods ir 1: izdzēs pagaidu Penalty = -5 pārbaudi no _Ready.
  • Mainīju kodu, bet skaitlis palika: pārbaudi konkrētā mezgla scēnā saglabāto Inspector vērtību.
