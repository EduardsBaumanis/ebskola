Atkārtojuma tests: 3.1 C# klases un objekti

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Ar ko C# klase atšķiras no objekta?

Kā līguma veidlapa un atvērtais konts: katram objektam ir savi lauku dati. Atkārto: 3.1 — Teorija: C# klases, objekti un datu iekapsulēšana ↗

2. Ko izdrukā šī rinda? 
Participant anna = new Participant();
anna.Energy = 100;
Participant janis = new Participant();
janis.Energy = 80;
anna.Energy -= 30;
GD.Print("Jānis: ", janis.Energy);

Abi ir atsevišķi objekti. Annas enerģijas maiņa Jāni neietekmē. Atkārto: 3.1 — 1. uzdevums — Dalībnieka klase un divi objekti ↗

3. Klasei ir tikai konstruktors Participant(string name, int energy). Kas notiek ar new Participant()?

Tiklīdz ir konstruktors ar parametriem, tukšais izsaukums vairs nav derīgs, ja vien nav uzrakstīts arī konstruktors bez parametriem. Atkārto: 3.1 — Teorija: C# klases, objekti un datu iekapsulēšana ↗

4. Anna sāk ar 100 enerģijas. Pēc ApplyPenalty(30) un ApplyPenalty(100) — kāda ir viņas enerģija un ko atgriež IsActive()? 
public void ApplyPenalty(int amount)
{
    if (amount < 0) return;
    Energy -= amount;
    if (Energy < 0) Energy = 0;
}
public bool IsActive()
{
    return Energy > 0;
}

100 → 70 → −30, bet pārbaude if (Energy < 0) to nomaina uz 0. 0 > 0 ir false. Atkārto: 3.1 — 2. uzdevums — Konstruktors, ApplyPenalty() un IsActive() ↗

5. Lauks ir private int energy;. Kas notiek, ja citā failā raksta anna.energy = 9999;?

private lauku drīkst mainīt tikai pašas klases kods. Nolasīt to var caur publisku metodi GetEnergy(). Atkārto: 3.1 — 3. uzdevums — Pasargā enerģiju ar private ↗
