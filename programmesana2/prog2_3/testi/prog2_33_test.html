Atkārtojuma tests: 3.2 Mantošana: kopīgais kods un atšķirīgas lomas

Pieci jautājumi par iepriekšējo nodarbību. Katram jautājumam izvēlies vienu atbildi. Pēc iesniegšanas redzēsi pareizās atbildes, un rezultāts tiks nosūtīts skolotājam.

Par tevi

Jautājumi

1. Ko nozīmē : base(name, 150) rindā public Captain(string name) : base(name, 150) { }?

Bāzes klasei nav konstruktora bez parametriem, tāpēc atvasinātajai klasei tas jāizsauc ar : base(...). Atkārto: 3.2 — Teorija: mantošana, metožu pārrakstīšana un polimorfisms ↗

2. Tu noņem virtual no Participant.ApplyPenalty. Kāpēc tad Captain metode ar override nebūvējas?

virtual bāzes klasē atļauj pārrakstīt, override atvasinātajā klasē to izdara. Atkārto: 3.2 — 2. uzdevums — Pārraksti kapteiņa reakciju ar virtual un override ↗

3. Jauns kapteinis (150 enerģijas) saņem ApplyPenalty(6). Cik enerģijas paliek? 
public override void ApplyPenalty(int amount)
{
    if (amount <= 0) return;
    int reduced = Math.Max(1, amount - stability);   // stability = 10
    base.ApplyPenalty(reduced);
}

6 − 10 = −4, bet Math.Max(1, −4) ir 1, tāpēc kapteinis zaudē vismaz 1 punktu. Atkārto: 3.2 — 2. uzdevums — Pārraksti kapteiņa reakciju ar virtual un override ↗

4. Sarakstā ir Participant (100), Captain (150) un Presenter (80), kas pie soda pieskaita 5. Visiem izsauc ApplyPenalty(20). Cik paliek prezentētājam?

Prezentētājs zaudē 20 + 5 = 25: 80 → 55. Cikls ar foreach katram izsauc tā paša tipa versiju — tas ir polimorfisms. Atkārto: 3.2 — 3. uzdevums — Lomas vienā sarakstā ↗

5. Kāpēc Captain.ApplyPenalty raksta base.ApplyPenalty(reduced), nevis ApplyPenalty(reduced)?

base. izsauc bāzes klases versiju, kas samazina enerģiju. Bez tā kapteiņa metode atkal izsauktu kapteiņa metodi. Atkārto: 3.2 — Teorija: mantošana, metožu pārrakstīšana un polimorfisms ↗
