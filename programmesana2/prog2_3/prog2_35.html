3.5 Dalībnieka dati un pagaidu bonusi

Stundas uzdevums: Sakārto dalībnieka skaitļus vienā struktūrā un aprēķini fokusu no pievienotajiem bonusiem.

SR 2.4.16. Saliktas datu struktūras SR 2.4.18. Objektorientētā programmēšana

Pirms sāc: turpini 3.3. Participant versiju ar signālu un Setup. Šodien mainīsies datu glabāšana, bet lomu ApplyPenalty metodes paliks saderīgas.

Darba secība: izlasi skaidrojumu pie attiecīgā uzdevuma, paredzi piemēra rezultātu un tad pārbaudi to. Pēc C# izmaiņām saglabā failus, Godot nospied Build un palaid scēnu ar F6. Rezultātus skaties Output panelī.

Teorija ar piemēriem

1. Kāpēc skaitļus apvienot?

Dalībniekam vajag pašreizējo enerģiju, maksimālo enerģiju un fokusu. Enerģija nosaka, vai dalībnieks vēl piedalās. Maksimums pasaka, cik daudz enerģijas drīkst atjaunot. Fokuss apzīmē dalībnieka koncentrēšanās spēju; šajā stundā to attēlojam ar skaitli, kuram pieskaitām bonusus.

Šos saistītos skaitļus apvienosim Stats struktūrā. Atslēgvārds struct ļauj aprakstīt savu datu tipu. Laukus, kurus lietosim ārpus struktūras, skaidri rakstām ar public; C# struktūras lauki nav publiski pēc noklusējuma.

public struct Stats
{
    public int Energy;
    public int MaxEnergy;
    public int Focus;
}

Šai sākuma versijai new Stats() izveido trīs nulles. Tas vēl nenozīmē spēlei gatavu dalībnieku: ar nulles enerģiju tas jau būtu neaktīvs. Pilnajā versijā pievienosim konstruktoru un lietosim new Stats(100, 10), lai enerģija un maksimums būtu 100, bet fokuss — 10.

2. struct piešķīrums kopē vērtības

Mūsu Stats satur tikai veselus skaitļus. Piešķirot vienu Stats mainīgo otram, iegūstam atsevišķu šo skaitļu kopiju:

Stats original = new Stats(100, 10);
Stats copy = original;
copy.Energy = 40;
GD.Print(original.Energy); // 100
GD.Print(copy.Energy);     // 40

Ar class objektiem piešķīrums darbojas citādi: Participant second = anna; neizveido otru dalībnieku. Abi mainīgie norāda uz to pašu Annu. Ja second.ApplyPenalty(20) maina enerģiju, izmaiņu redz arī caur anna.

Tātad Stats kopija ir piemērota skaitļu nolasīšanai vai salīdzināšanai, bet Participant ir konkrētais dalībnieks, kura izmaiņas vēlamies redzēt visā programmā.

3. Kā dalībnieks izmanto Stats?

Participant iekšienē glabāsim private Stats stats = new Stats(100, 10);. Te ir atšķirība no mantošanas: kapteinis ir dalībnieks, bet dalībniekam ir dati. Klasi veidot no šādām daļām sauc par kompozīciju.

Iepriekšējo energy lauku izņem. Setup, ApplyPenalty, GetEnergy un IsActive tagad lieto stats.Energy. Tas ir tas pats enerģijas noteikums, tikai dati glabājas citā vietā. Saglabā arī Finished signālu.

Stats metodē Heal atjaunosim enerģiju, nepārsniedzot maksimumu. Math.Min izvēlas mazāko no diviem skaitļiem:

public void Heal(int amount)
{
    if (amount <= 0) return;
    Energy = Math.Min(MaxEnergy, Energy + amount);
}

Participant klasē pievieno savu Heal metodi, kas izsauc stats.Heal(amount), ja dalībnieks vēl ir aktīvs. Tādējādi ārējais kods raksta anna.Heal(50) un maina īstos datus. Šī turnīra noteikums: izstājušos dalībnieku neatjauno.

GetStats() atdod Stats kopiju. Tās maiņa nemaina dalībnieku. Tāpēc atjaunošanai nelieto anna.GetStats().Heal(50): tas mainītu tikai pagaidu kopiju. Skaitļu lasīšanai GetStats ir piemērots.

4. Kopējo fokusu aprēķina no pašreizējiem bonusiem

Bonusu apraksta maza struktūra Buff ar nosaukumu un pielikumu fokusam. Participant glabā bonusu sarakstu List<Buff>. Sarakstu turam dalībnieka klasē; Stats šajā piemērā paliek tikai skaitļu grupa.

public struct Buff
{
    public string Name;
    public int FocusBonus;
}

Participant metode sāk ar pamata fokusu un pa vienam pieskaita sarakstā esošos bonusus:

public int GetTotalFocus()
{
    int total = stats.Focus;
    foreach (Buff buff in buffs)
    {
        total += buff.FocusBonus;
    }
    return total;
}

Pamata stats.Focus paliek 10. Ja katru reizi bonusu pieskaitītu tieši šim laukam, atkārtota metodes izsaukšana varētu kļūdaini uzkrāt vienu bonusu vairākas reizes. Pagaidu mainīgais total katrā izsaukumā sāk aprēķinu no jauna.

Pieraksts new Buff { Name = "Atbalsts", FocusBonus = 5 } izveido vērtību un piešķir tās laukus. RemoveBuffAt(0) mūsu Participant metodē noņem saraksta pirmo bonusu; saraksta vietu numerācija sākas ar 0.

Pašpārbaude: Kāds būs fokuss, ja GetTotalFocus() izsauks trīs reizes?

Ja saraksts nemainās un tajā ir +5 un +3, katru reizi rezultāts ir 18. Metode nolasa datus un aprēķina summu, bet nemaina pamata fokusu.

1. uzdevums

Pārbaudi struktūras sākuma vērtības un kopiju

Atbalsts: skaidrojums un piemērs.

  1. Izveido Stats.cs ar trim publiskiem int laukiem. Jaunā StatsDemo scēnā un skriptā izdrukā new Stats() laukus: tie ir 0.
  2. Pievieno konstruktoru no pilnā piemēra un izveido new Stats(100, 10).
  3. Izpildi kopijas piemēru: maini tikai copy.Energy.
  4. README pieraksti abas izdrukas un skaidrojumu, kāpēc oriģināls nemainījās.

Gatavs, kad: vari atšķirt struktūras kopiju no otra mainīgā, kas norāda uz to pašu klases objektu.

2. uzdevums

Pārvieto datus un pārbaudi atjaunošanu

Atbalsts: skaidrojums un piemērs.

  1. Participant.cs aizstāj atsevišķo energy ar stats. Pielāgo Setup, ApplyPenalty, GetEnergy un IsActive; izmanto pilno failu salīdzināšanai.
  2. Stats pievieno Heal; Participant pievieno GetStats un Heal.
  3. Ar parastu Participant: Setup 100, sods 30, atjaunošana 50. Izdrukā: jābūt 100.
  4. Paņem Stats kopiju, maini tās Energy uz 1 un pārbaudi, ka dalībniekam joprojām ir 100.

Gatavs, kad: dalībnieka enerģiju maina tā metode, un maksimums netiek pārsniegts.

3. uzdevums

Pievieno un noņem bonusus

Atbalsts: skaidrojums un piemērs.

  1. Izveido Buff.cs, Participant pievieno bonusu sarakstu un AddBuff, RemoveBuffAt, GetTotalFocus metodes.
  2. Pievieno +5 un +3 bonusus. Izdrukā kopējo fokusu divas reizes: abās jābūt 18.
  3. Noņem pirmo bonusu ar RemoveBuffAt(0). Jāpaliek 13.
  4. README pieraksti tabulu ar paredzētajiem un iegūtajiem skaitļiem.

Gatavs, kad: rezultāti ir 18, 18 un 13; pamata fokuss paliek 10.

Papildu uzdevums — Bonuss beidzas pēc divām kārtām

Buff pievieno public int TurnsLeft; un jaunam bonusam iestati 2. Pēc kārtas samazini atlikušo skaitu. Tā kā Buff ir struktūra, no saraksta paņemto kopiju pēc maiņas ieraksti atpakaļ. Ja dzēs elementus, ej no beigām uz sākumu:

for (int i = buffs.Count - 1; i >= 0; i--)
{
    Buff buff = buffs[i];
    buff.TurnsLeft--;
    if (buff.TurnsLeft <= 0) buffs.RemoveAt(i);
    else buffs[i] = buff;
}

Šo ciklu liec jaunā Participant metodē. Izsauc to pēc katras kārtas un novēro kopējo fokusu. Divu kārtu bonuss pazūd pēc otrā izsaukuma.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Stats.cs

using System;

public struct Stats
{
    public int Energy;
    public int MaxEnergy;
    public int Focus;

    public Stats(int energy, int focus)
    {
        Energy = energy;
        MaxEnergy = energy;
        Focus = focus;
    }

    public void Heal(int amount)
    {
        if (amount <= 0) return;
        Energy = Math.Min(MaxEnergy, Energy + amount);
    }
}

Participant.cs

using Godot;
using System;
using System.Collections.Generic;

public partial class Participant : Node
{
    [Signal]
    public delegate void FinishedEventHandler(string participantName);

    public string ParticipantName = "Dalībnieks";
    private Stats stats = new Stats(100, 10);
    private List<Buff> buffs = new List<Buff>();

    public void Setup(string name, int initialEnergy)
    {
        ParticipantName = name;
        stats = new Stats(Math.Max(0, initialEnergy), 10);
        buffs.Clear();
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (!IsActive() || amount <= 0) return;
        stats.Energy = Math.Max(0, stats.Energy - amount);
        if (stats.Energy == 0)
            EmitSignal(SignalName.Finished, ParticipantName);
    }

    public int GetEnergy()
    {
        return stats.Energy;
    }

    public bool IsActive()
    {
        return stats.Energy > 0;
    }

    public Stats GetStats()
    {
        return stats;
    }

    public void Heal(int amount)
    {
        if (IsActive()) stats.Heal(amount);
    }

    public void AddBuff(Buff buff)
    {
        buffs.Add(buff);
    }

    public void RemoveBuffAt(int index)
    {
        buffs.RemoveAt(index);
    }

    public int GetTotalFocus()
    {
        int total = stats.Focus;
        foreach (Buff buff in buffs)
        {
            total += buff.FocusBonus;
        }
        return total;
    }
}

StatsDemo.cs

using Godot;

public partial class StatsDemo : Node
{
    public override void _Ready()
    {
        Participant anna = new Participant();
        AddChild(anna);
        anna.Setup("Anna", 100);
        anna.ApplyPenalty(30);
        anna.Heal(50);
        GD.Print("Enerģija: ", anna.GetEnergy());

        Stats copy = anna.GetStats();
        copy.Energy = 1;
        GD.Print("Kopija: ", copy.Energy, "; Anna: ", anna.GetEnergy());

        anna.AddBuff(new Buff { Name = "Atbalsts", FocusBonus = 5 });
        anna.AddBuff(new Buff { Name = "Atpūta", FocusBonus = 3 });
        GD.Print("Fokuss ar diviem bonusiem: ", anna.GetTotalFocus());
        anna.RemoveBuffAt(0);
        GD.Print("Fokuss pēc pirmā noņemšanas: ", anna.GetTotalFocus());
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Stats.cs, Buff.cs, atjauninātais Participant.cs un StatsDemo pārbaudes scēna.
  • Izdrukas: kopija pret oriģinālu, atjaunošana līdz maksimumam, bonusa pievienošana un noņemšana.
  • README ar paredzētajiem un iegūtajiem rezultātiem un skaidrojumu par kopējo fokusu.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Enerģija un maksimums ir 0: pārbaudi, vai izmanto konstruktoru ar norādītiem datiem, piemēram, new Stats(100, 10).
  • Atjaunošana nedarbojas: izsauc anna.Heal(...), nevis atjauno no GetStats saņemto kopiju.
  • Fokuss aug katrā izsaukumā: summē vietējā total mainīgajā, nevis pārraksti stats.Focus.
  • Bonusa noņemšana dod kļūdu: indeksam jābūt esošai saraksta vietai. Tukšam sarakstam pirmās vietas nav.
