Teorija: datu struktūras (struct), vērtību kopēšana un kompozīcija

Struktūra (struct) saistītu datu grupēšanai

Ja vairāki skaitliski rādītāji (piemēram, pašreizējais apjoms, maksimālā ietilpība un bāzes koeficients) loģiski pieder kopā, tos ērti apvienot vieglā lietotāja definētā datu tipā ar atslēgvārdu struct (struktūra). Jāievēro, ka C# struktūras lauki pēc noklusējuma nav publiski — laukiem, kurus lasīs vai mainīs ārpus struktūras, priekšā skaidri raksta public.

Izsaukums new Struktura() bez argumentiem visus skaitliskos laukus aizpilda ar nullēm. Pievienojot struktūrai konstruktoru ar parametriem, jau izveidošanas brīdī var piešķirt jēgpilnas sākuma vērtības, savukārt nelielām struktūrām publiskos laukus var aizpildīt arī ar inicializatora pierakstu new Pielikums { Nosaukums = "...", Vertiba = 5 }:

public struct Merijums
{
    public int Apjoms;
    public int MaxApjoms;
    public int Baze;

    public Merijums(int apjoms, int baze)
    {
        Apjoms = apjoms;
        MaxApjoms = apjoms;
        Baze = baze;
    }
}

public struct Pielikums
{
    public string Nosaukums;
    public int Vertiba;
}

// Tukšs izsaukums aizpilda skaitļus ar 0, inicializators — ar norādīto:
Merijums tukss = new Merijums(); // Apjoms = 0, MaxApjoms = 0, Baze = 0
Pielikums p = new Pielikums { Nosaukums = "Filtrs", Vertiba = 5 };

Vērtību kopēšana (struct) pret atsauci uz objektu (class)

Atšķirību starp struct un class var salīdzināt ar papīra fotokopiju un koplietota tiešsaistes dokumenta saiti. Struktūra, kas satur skaitļus, ir vērtību tips (value type) — piešķirot to citam mainīgajam, visas vērtības tiek nokopētas jaunā, neatkarīgā vietā:

Merijums originals = new Merijums(100, 10);
Merijums kopija = originals;
kopija.Apjoms = 40;
// originals.Apjoms joprojām ir 100, bet kopija.Apjoms ir 40.

Tāpat arī metode, kuras atgriežamais tips ir struct, izsaucējam atdod neatkarīgu datu kopiju (tās izmainīšana neietekmē oriģinālo objektu). Turpretī class ir atsauces tips (reference type): pieraksts Klase otrs = pirmais; neizveido jaunu objektu, bet liek abiem mainīgajiem norādīt uz vienu un to pašu eksemplāru atmiņā, tāpēc caur vienu mainīgo veiktās izmaiņas redzamas arī caur otru:

Konts pirmais = new Konts("Līga", 100);
Konts otrs = pirmais; // Abi mainīgie norāda uz vienu un to pašu objektu
otrs.Atlikums = 40;
// Arī pirmais.Atlikums tagad ir 40.

Kompozīcija, robežas ierobežošana (Math.Min) un dinamisku modifikatoru summēšana

Ja klase savā iekšienē glabā private struktūru vai sarakstu, veidojas kompozīcija — attiecība „objektam ir dati” (pretstatā mantošanas attiecībai „objekts ir bāzes tips”). Lai iekšējo struktūru droši atjauninātu, izmaiņas veic caur pašas klases metodi, bet augšējo griestu nepārsniegšanai izmanto Math.Min(maksimums, tekosais + pielikums), kas izvēlas mazāko no diviem skaitļiem.

Ja gala rādītājs jāaprēķina no bāzes vērtības un mainīga saraksta List<T> ar pagaidu modifikatoriem (saraksta indeksi sākas ar 0, un RemoveAt(index) izņem attiecīgo elementu), aprēķinu katrā izsaukumā sāk lokālā mainīgajā (int kopsumma = baze;) un ciklā foreach pieskaita aktīvos pielikumus. Tas darbojas kā pirkumu grozs, kur preces pamatcenai katrā apskatē pieskaita spēkā esošos atlaižu vai bonusu kuponus: ja pielikumu pieskaitītu tieši glabātajam bāzes laukam, atkārtoti metodes izsaukumi vienu un to pašu vērtību kļūdaini uzkrātu arvien no jauna:

private Merijums dati = new Merijums(100, 10);
private List<Pielikums> pielikumi = new List<Pielikums>();

public void Papildinat(int daudzums)
{
    if (daudzums <= 0) return;
    dati.Apjoms = Math.Min(dati.MaxApjoms, dati.Apjoms + daudzums);
}

public void NonemtPielikumu(int indekss) { pielikumi.RemoveAt(indekss); }

public int AprekinatKopapjomu()
{
    int kopsumma = dati.Baze; // Sāk no bāzes lokālā mainīgajā
    foreach (Pielikums p in pielikumi)
    {
        kopsumma += p.Vertiba;
    }
    return kopsumma;          // dati.Baze paliek nemainīgs (10)
}

Pārvieto datus un pārbaudi atjaunošanu

Kur strādāt: Heal metodi pievieno Scripts/Stats.cs; dalībnieka datu glabāšanu un metodes maini Scripts/Participant.cs. Setup, sodu, atjaunošanu un kopijas pārbaudi izsauc Scripts/StatsDemo.cs metodē _Ready().

  1. Participant.cs izņem iepriekšējo energy lauku un aizstāj to ar private Stats stats = new Stats(100, 10);. Pielāgo Setup, ApplyPenalty, GetEnergy un IsActive darbam ar stats.Energy, saglabājot Finished signālu (izmanto pilno failu salīdzināšanai).
  2. Stats struktūrā pievieno Heal metodi pēc parauga zemāk, bet Participant klasē pievieno GetStats() un Heal(int amount) (dalībnieku atjauno tikai tad, ja IsActive() ir patiess; nelieto anna.GetStats().Heal(50), jo tas mainītu tikai pagaidu kopiju).
  3. Ar parastu Participant mezglu: Setup("Anna", 100), sods 30, atjaunošana 50. Salīdzini ar tabulu zemāk un izdrukā: jābūt 100.
  4. Paņem Stats kopiju ar anna.GetStats(), maini tās Energy uz 1 un pārbaudi, ka dalībniecei joprojām ir 100.

Pievieno un noņem bonusus

Kur strādāt: Izveido Scripts/Buff.cs struktūrai. Sarakstu un bonusu metodes pievieno Scripts/Participant.cs; bonusu pievienošanu, izņemšanu un izdrukas pārbaudi Scripts/StatsDemo.cs metodē _Ready().

  1. Izveido Buff.cs, bet Participant klasē pievieno List<Buff> buffs sarakstu un AddBuff, RemoveBuffAt, GetTotalFocus metodes pēc parauga zemāk (summē lokālajā mainīgajā total, lai pamata stats.Focus paliktu 10).
  2. Pievieno +5 ("Atbalsts") un +3 ("Atpūta") bonusus ar new Buff { Name = "Atbalsts", FocusBonus = 5 }. Izdrukā kopējo fokusu divas reizes pēc kārtas: abās jābūt 18.
  3. Noņem pirmo bonusu ar RemoveBuffAt(0). Izdrukā: jāpaliek 13.
  4. Salīdzini ar tabulu zemāk un README pieraksti tabulu ar paredzētajiem un iegūtajiem skaitļiem.
public struct Buff
{
    public string Name;
    public int FocusBonus;
}

public int GetTotalFocus()
{
    int total = stats.Focus;
    foreach (Buff buff in buffs)
    {
        total += buff.FocusBonus;
    }
    return total;
}

Papildu uzdevums — Bonuss beidzas pēc divām kārtām

Kur strādāt: TurnsLeft lauku pievieno Scripts/Buff.cs. Ciklu ievieto jaunā AdvanceBuffs() metodē failā Scripts/Participant.cs; bonusam vērtību 2 piešķir un metodi divreiz izmēģini Scripts/StatsDemo.cs metodē _Ready().

Buff pievieno public int TurnsLeft; un jaunam bonusam iestati 2. Pēc kārtas samazini atlikušo skaitu. Tā kā Buff ir struktūra, no saraksta paņemto kopiju pēc maiņas ieraksti atpakaļ. Ja dzēs elementus, ej no beigām uz sākumu:

for (int i = buffs.Count - 1; i >= 0; i--)
{
    Buff buff = buffs[i];
    buff.TurnsLeft--;
    if (buff.TurnsLeft <= 0) buffs.RemoveAt(i);
    else buffs[i] = buff;
}

Šo ciklu liec jaunā Participant metodē. Izsauc to pēc katras kārtas un novēro kopējo fokusu. Divu kārtu bonuss pazūd pēc otrā izsaukuma.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Stats.cs

using System;

public struct Stats
{
    public int Energy;
    public int MaxEnergy;
    public int Focus;

    public Stats(int energy, int focus)
    {
        Energy = energy;
        MaxEnergy = energy;
        Focus = focus;
    }

    public void Heal(int amount)
    {
        if (amount <= 0) return;
        Energy = Math.Min(MaxEnergy, Energy + amount);
    }
}

Participant.cs

using Godot;
using System;
using System.Collections.Generic;

public partial class Participant : Node
{
    [Signal]
    public delegate void FinishedEventHandler(string participantName);

    public string ParticipantName = "Dalībnieks";
    private Stats stats = new Stats(100, 10);
    private List<Buff> buffs = new List<Buff>();

    public void Setup(string name, int initialEnergy)
    {
        ParticipantName = name;
        stats = new Stats(Math.Max(0, initialEnergy), 10);
        buffs.Clear();
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (!IsActive() || amount <= 0) return;
        stats.Energy = Math.Max(0, stats.Energy - amount);
        if (stats.Energy == 0)
            EmitSignal(SignalName.Finished, ParticipantName);
    }

    public int GetEnergy()
    {
        return stats.Energy;
    }

    public bool IsActive()
    {
        return stats.Energy > 0;
    }

    public Stats GetStats()
    {
        return stats;
    }

    public void Heal(int amount)
    {
        if (IsActive()) stats.Heal(amount);
    }

    public void AddBuff(Buff buff)
    {
        buffs.Add(buff);
    }

    public void RemoveBuffAt(int index)
    {
        buffs.RemoveAt(index);
    }

    public int GetTotalFocus()
    {
        int total = stats.Focus;
        foreach (Buff buff in buffs)
        {
            total += buff.FocusBonus;
        }
        return total;
    }
}

StatsDemo.cs

using Godot;

public partial class StatsDemo : Node
{
    public override void _Ready()
    {
        Participant anna = new Participant();
        AddChild(anna);
        anna.Setup("Anna", 100);
        anna.ApplyPenalty(30);
        anna.Heal(50);
        GD.Print("Enerģija: ", anna.GetEnergy());

        Stats copy = anna.GetStats();
        copy.Energy = 1;
        GD.Print("Kopija: ", copy.Energy, "; Anna: ", anna.GetEnergy());

        anna.AddBuff(new Buff { Name = "Atbalsts", FocusBonus = 5 });
        anna.AddBuff(new Buff { Name = "Atpūta", FocusBonus = 3 });
        GD.Print("Fokuss ar diviem bonusiem: ", anna.GetTotalFocus());
        anna.RemoveBuffAt(0);
        GD.Print("Fokuss pēc pirmā noņemšanas: ", anna.GetTotalFocus());
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Stats.cs, Buff.cs, atjauninātais Participant.cs un StatsDemo pārbaudes scēna.
  • Izdrukas: kopija pret oriģinālu, atjaunošana līdz maksimumam, bonusa pievienošana un noņemšana.
  • README ar paredzētajiem un iegūtajiem rezultātiem un skaidrojumu par kopējo fokusu.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Enerģija un maksimums ir 0: pārbaudi, vai izmanto konstruktoru ar norādītiem datiem, piemēram, new Stats(100, 10).
  • Atjaunošana nedarbojas: izsauc anna.Heal(...), nevis atjauno no GetStats saņemto kopiju.
  • Fokuss aug katrā izsaukumā: summē vietējā total mainīgajā, nevis pārraksti stats.Focus.
  • Bonusa noņemšana dod kļūdu: indeksam jābūt esošai saraksta vietai. Tukšam sarakstam pirmās vietas nav.
