3.6 Noslēguma project (projekts): Klases turnīra simulator (simulators)

Stundas uzdevums: Apvienot OOP (objektorientētā programmēšana), signal (signālus), struct (struktūra) un C# script (skriptus) pilnvērtīgā rundām balstītā klases turnīra simulation (simulācijā).

80 min plāns: Ievads un kritēriju pārruna (~10 min) · 1. uzdevums (~20 min) - saliec komandu un šķēršļus · 2. uzdevums (~25 min) - uzraksti vienas kārtas logic (loģiku) · 3. uzdevums (~20 min) - pievieno turnīra loop (ciklu) un rezultātu · Iesniegšana (~5 min).

Pirms sāc: šis ir 3. tēmas noslēguma project (projekts). Izmanto visu apgūto: class (klases), inheritance (mantošanu), signal (signālus), Inspector (īpašību panelis) property (īpašības) un struct (struktūra). Sāc ar vienu kārtu, tikai tad taisi loop (ciklu).

Teorija: Simulator (simulatora) apraksts

Rundām balstīta klases turnīra simulation (simulācija) ar trim spēlētāja dalībniekiem (Captain, Presenter, TimeKeeper) pret nejauši ģenerētiem šķēršļiem (PrinterQueue, WifiDrop, MissingMarker).

Turnīra plūsma:

  1. Turnīra sākumā izvēlies 3 dalībnieku komandu.
  2. Šķēršļi tiek ģenerēti.
  3. Katras kārtas: spēlētājs izvēlas darbību (izvēlēties gājienu, prezentācijas bonusu, atjaunot enerģiju).
  4. Pēc tam šķēršļi samazina komandas enerģiju.
  5. Raundi turpinās, līdz viena puse pabeigusi visus gājienus.

Class hierarchy (klašu hierarhija): Participant (base (bāzes klase)) → Captain, Presenter, TimeKeeper; Obstacle (base (bāzes klase)) → PrinterQueue, WifiDrop, MissingMarker.

Kā šo izmantot project (projektā)

Atceries: ar redzamu efektu editor (redaktorā) nepietiek. Paskaidro, kura C# class (klase) glabā state (stāvokli), kura method (metode) to maina un kā Godot node (mezgls) structure (struktūra) izmanto šo code (kodu).

Pārbaudi: katrai būtiskai turnīra lomai ir C# class (klase) vienā .cs file (failā), ar constructor (konstruktoriem), method (metodēm), signal (signāliem) vai inheritance (mantošanu).

Praktiskie uzdevumi

1. uzdevums -

Saliec komandu un šķēršļus

Beigās tev būs trīs dalībnieki un trīs šķēršļi, gatavi turnīram.

  1. Izveido C# class (klasi) TournamentManager, kas manto no Node (mezgls).
  2. Pievieno tai private List<Participant> party = new(); un private List<Obstacle> obstacles = new();.
  3. Pievieno komandai pa vienam Captain, Presenter un TimeKeeper object (objektam).
  4. Pievieno šķēršļu list (sarakstam) trīs dažādus Obstacle mezglus.
  5. Izdrukā _Ready() method (metodē) visu dalībnieku un šķēršļu nosaukumus.
  6. Būvē un palaid, lai pārbaudītu abus list (sarakstus).
  7. Pārliecinies, ka neviens list (saraksts) nav tukšs.

Gatavs, kad: Output (izvade) panel (panelī) izdrukājas trīs dalībnieki un trīs šķēršļi ar saviem nosaukumiem.

2. uzdevums -

Uzraksti vienas kārtas logic (loģiku)

Beigās viena turnīra kārta samazinās enerģiju pareizajiem object (objektiem).

  1. Uzraksti method (metodi) private void PlayTurn().
  2. Izvēlies tajā nejaušu šķērsli ar (int)GD.RandRange(0, obstacles.Count - 1).
  3. Izvēlies nejaušu dalībnieku no komandas.
  4. Izsauc dalībniekam ApplyPenalty ar šķēršļa spēku.
  5. Izdrukā, kurš šķērslis kuram dalībniekam iedarbojās un cik enerģijas palika.
  6. Izsauc method (metodi) trīs reizes un pārbaudi output (izdrukas).
  7. Pārbaudi, ka katra loma sodu izcieš atšķirīgi.

Gatavs, kad: katrā kārtā izdrukājas cits šķērslis un dalībnieks, un kapteinis zaudē mazāk nekā pārējie.

3. uzdevums -

Pievieno turnīra loop (ciklu) un rezultātu

Beigās turnīrs noskaidros uzvarētāju pats.

  1. Uzraksti loop (ciklu), kas izsauc PlayTurn(), kamēr aktīvi vismaz divi dalībnieki.
  2. Pieslēdzies katra dalībnieka signal (signālam) Finished no 3.3 stundas.
  3. Izdrukā paziņojumu, kad kāds dalībnieks izstājas.
  4. Saskaiti kārtu skaitu ar field (lauku) private int currentTurn = 0;.
  5. Izdrukā beigās uzvarētāja vārdu un kopējo kārtu skaitu.
  6. Palaid simulation (simulāciju) trīs reizes un pieraksti rezultātus.
  7. Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi).

Gatavs, kad: trīs palaišanas reizēs uzvar dažādi dalībnieki, un loop (cikls) vienmēr beidzas, nevis griežas bezgalīgi.

Papildu uzdevums - Parādi turnīru uz screen (ekrāna)

Ja pamatdarbs ir gatavs, pārcel output (izdrukas) no Output (izvade) uz spēles window (logu).

  1. Pievieno scene (scēnai) Label (teksta etiķete) node (mezglu) katram dalībniekam.
  2. Atjaunini tajos enerģijas value (vērtību) pēc katras kārtas.
  3. Pievieno vienu Label (teksta etiķete) event (notikumu) žurnālam.
  4. Pievieno button (pogu), kas izpilda vienu kārtu.
  5. Izspēlē turnīru, spiežot button (pogu), nevis palaižot loop (ciklu).

Gatavs, kad: turnīru var izspēlēt ar button (pogu), un enerģijas value (vērtības) uz screen (ekrāna) mainās pēc katras kārtas.

Code sample (koda piemērs) (paplašināts)

using Godot;
using System.Collections.Generic;

public partial class TournamentManager : Node
{
    [Signal] public delegate void TournamentWonEventHandler();

    private readonly List<Participant> party = new();
    private readonly List<Obstacle> obstacles = new();
    private int currentTurn = 0;

    public void StartTournament()
    {
        foreach (Obstacle obstacle in obstacles)
        {
            obstacle.Finished += OnObstacleFinished;
        }
        NextTurn();
    }

    public void ExecuteFocus(Participant participant, Obstacle target)
    {
        int penalty = participant.GetStats().GetTotalFocus();
        target.ApplyPenalty(penalty);
        if (obstacles.Count == 0) EmitSignal(SignalName.TournamentWon);
        else NextTurn();
    }

    private void OnObstacleFinished()
    {
        // Atrod un noņem pabeigto šķērsli
        obstacles.RemoveAll(obstacle => !obstacle.IsActive());
    }

    private void NextTurn()
    {
        currentTurn++;
    }
}
