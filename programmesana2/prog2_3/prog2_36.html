Modulāras sistēmas dekompozīcija un mezglu dinamiska izveide

Apjomīgākās programmās visus noteikumus neraksta vienā garā skriptā, bet pielieto dekompozīciju — pienākumu sadali pa atsevišķām klasēm un datu struktūrām. Līdzīgi kā pasākuma tehniskajā komandā katram speciālistam ir sava atbildība, objektorientētā sistēmā datu struktūras glabā skaitļus, bāzes un atvasinātās klases caur polimorfismu (virtual un override) izpilda specifiskos noteikumus, Inspector konfigurēti mezgli glabā vides parametrus, bet centrālais vadītājs organizē soļus un klausās signālus (+=).

Veidojot Godot mezglus dinamiski C# kodā ar new, jāatšķir divas dažādas darbības: AddChild(mezgls) pievieno objektu Godot Scene kokam, savukārt saraksts.Add(mezgls) saglabā atsauci C# sarakstā List<T> ērtai apstrādei ciklos:

private List<Vienums> visiVienumi = new List<Vienums>();

public override void _Ready()
{
    Vienums pirmais = new Vienums();
    AddChild(pirmais);               // Pievieno mezglu Godot Scene kokam
    pirmais.Setup("Modulis A", 50);  // Iestata objekta sākuma datus
    pirmais.Pabeigts += KadPabeigts; // Pieslēdz notikuma signālu
    visiVienumi.Add(pirmais);        // Saglabā atsauci C# sarakstā cikliem
}

Aktīvo objektu atlasīšana un nejauša izvēle (GD.RandRange)

Daudzsoļu procesos objekti, kas savu darbību jau beiguši, bieži paliek kopējā sarakstā vēstures vai pārskata vajadzībām. Ja nākamo kandidātu izvēlētos no visa saraksta, programma varētu atkārtoti trāpīt uz neaktīvu objektu, nemainot kopējo stāvokli. Tāpēc pirms katra soļa ar palīgmetodi atlasa atsevišķu List<T> tikai ar tiem elementiem, kuriem pārbaudes metode atgriež true.

Sarakstam ar Count elementiem derīgie indeksi ir no 0 līdz Count - 1. Kad saraksts nav tukšs, nejaušu elementu izvēlas ar abpusēji ieskaitošu intervālu:

private List<Vienums> GetAktivos()
{
    List<Vienums> aktivie = new List<Vienums>();
    foreach (Vienums v in visiVienumi)
    {
        if (v.IrAktivs()) aktivie.Add(v);
    }
    return aktivie;
}

// Kad aktīvo saraksts nav tukšs, izvēlas nejaušu elementu:
List<Vienums> elementi = GetAktivos();
int indekss = (int)GD.RandRange(0, elementi.Count - 1);
Vienums izveletais = elementi[indekss];

Jēdziens „nejauši” nenozīmē „katrā reizē cits” — gluži kā metot spēļu kauliņu, viens skaitlis var uzkrist trīs reizes pēc kārtas, arī vairākās programmas palaišanās var atkārtoties viens un tas pats iznākums. Tāpēc aprēķinu formulas vispirms pārbauda ar fiksētiem, zināmiem indeksiem (piemēram, 0), un tikai pēc tam ieslēdz GD.RandRange.

Nosacījuma cikls while, izbeigšanās garantija un drošības skaitītājs

Cikls while pirms katra soļa pārbauda loģisko nosacījumu un atkārto darbību, kamēr tas ir patiess. Lai cikls garantēti beigtos, nosacījumā jāpārbauda mainīgais aktīvo objektu skaits (nevis nemainīgais sākuma saraksta garums), un katram cikla solim sistēma neatgriezeniski jāpietuvina gala stāvoklim - piemēram, katrā solī vismaz par 1 vienību samazinot ierobežotu pozitīvu resursu bez tā papildināšanas ciklā.

int solis = 0;
while (GetAktivos().Count > 1 && solis < 1000)
{
    solis++;
    IzpilditSoli();
}
if (solis >= 1000)
    GD.Print("Sasniegts drošības limits - pārbaudi samazināšanu!");

Loģiskais „un” (&&) pieprasa, lai izpildītos abi nosacījumi vienlaikus. Papildu robeža (piemēram, solis < 1000) kalpo kā drošības bremze pret kļūdainu bezgalīgu ciklu: ja sasniegts skaitītāja griestu limits, programma neuzkaras, bet apstājas un izvada diagnostikas brīdinājumu.

using Godot;
using System;
using System.Collections.Generic;

public partial class Participant : Node
{
    [Signal]
    public delegate void FinishedEventHandler(string participantName);

    public string ParticipantName = "Dalībnieks";
    private Stats stats = new Stats(100, 10);
    private List<Buff> buffs = new List<Buff>();

    public void Setup(string name, int initialEnergy)
    {
        ParticipantName = name;
        stats = new Stats(Math.Max(0, initialEnergy), 10);
        buffs.Clear();
    }

    public virtual void ApplyPenalty(int amount)
    {
        if (!IsActive() || amount <= 0) return;
        stats.Energy = Math.Max(0, stats.Energy - amount);
        if (stats.Energy == 0)
            EmitSignal(SignalName.Finished, ParticipantName);
    }

    public int GetEnergy()
    {
        return stats.Energy;
    }

    public bool IsActive()
    {
        return stats.Energy > 0;
    }

    public Stats GetStats()
    {
        return stats;
    }

    public void Heal(int amount)
    {
        if (IsActive()) stats.Heal(amount);
    }

    public void AddBuff(Buff buff)
    {
        buffs.Add(buff);
    }

    public void RemoveBuffAt(int index)
    {
        buffs.RemoveAt(index);
    }

    public int GetTotalFocus()
    {
        int total = stats.Focus;
        foreach (Buff buff in buffs)
        {
            total += buff.FocusBonus;
        }
        return total;
    }
}

using Godot;
using System.Collections.Generic;

public partial class TournamentManager : Node
{
    private List<Participant> party = new List<Participant>();
    private List<Obstacle> obstacles = new List<Obstacle>();
    private int currentTurn = 0;

    public override void _Ready()
    {
        Captain captain = new Captain();
        AddChild(captain);
        captain.Setup("Anna", 150);
        party.Add(captain);

        Presenter presenter = new Presenter();
        AddChild(presenter);
        presenter.Setup("Jānis", 80);
        party.Add(presenter);

        TimeKeeper timeKeeper = new TimeKeeper();
        AddChild(timeKeeper);
        timeKeeper.Setup("Ieva", 100);
        party.Add(timeKeeper);

        obstacles.Add(GetNode<Obstacle>("PrinterQueue"));
        obstacles.Add(GetNode<Obstacle>("WifiDrop"));
        obstacles.Add(GetNode<Obstacle>("MissingMarker"));

        foreach (Participant p in party)
        {
            p.Finished += OnParticipantFinished;
            GD.Print(p.ParticipantName, ": sākumā ", p.GetEnergy());
        }
        foreach (Obstacle obstacle in obstacles)
            GD.Print(obstacle.ObstacleName, ": sods ", obstacle.Penalty);

        RunTournament();
    }

    private List<Participant> GetActiveParticipants()
    {
        List<Participant> active = new List<Participant>();
        foreach (Participant p in party)
        {
            if (p.IsActive()) active.Add(p);
        }
        return active;
    }

    private void PlayTurn()
    {
        List<Participant> active = GetActiveParticipants();
        if (active.Count < 2 || obstacles.Count == 0) return;

        int participantIndex = (int)GD.RandRange(0, active.Count - 1);
        int obstacleIndex = (int)GD.RandRange(0, obstacles.Count - 1);
        Participant target = active[participantIndex];
        Obstacle obstacle = obstacles[obstacleIndex];

        currentTurn++;
        int before = target.GetEnergy();
        GD.Print("Kārta ", currentTurn, ": ", obstacle.ObstacleName,
            " -> ", target.ParticipantName);
        target.ApplyPenalty(obstacle.Penalty);
        GD.Print("Enerģija: ", before, " -> ", target.GetEnergy());
    }

    private void RunTournament()
    {
        if (obstacles.Count == 0 || GetActiveParticipants().Count < 2)
        {
            GD.Print("Vajag vismaz divus aktīvus dalībniekus un vienu šķērsli.");
            return;
        }

        while (GetActiveParticipants().Count > 1 && currentTurn < 1000)
            PlayTurn();

        List<Participant> active = GetActiveParticipants();
        if (active.Count == 1)
            GD.Print("Uzvarētājs: ", active[0].ParticipantName,
                "; kārtas: ", currentTurn);
        else
            GD.Print("Turnīrs apturēts. Pārbaudi enerģijas samazināšanu.");
    }

    private void OnParticipantFinished(string participantName)
    {
        GD.Print(participantName, " izstājās");
    }
}

Vērtēšanas kritēriji (SLA)

Snieguma līmeņu apraksts (SLA) attiecas uz 3. tēmas noslēguma projektu: klases turnīra simulatoru, tā Godot projektu, Output izdruku, README.md un GitHub versiju. Katru kritēriju pārbauda ar konkrētu darbību - palaid scēnu, apskati Output paneli vai atver norādīto failu.

“Apguvis” apraksta pilnīgi izpildītas pamatprasības; “Apguvis padziļināti” - arī prasmi ar sava projekta piemēru pamatot, kāpēc kods darbojas tieši tā. Dotais kods ir atļauts atbalsts; vērtē, vai projekts darbojas un vai vari to izskaidrot. Papildu uzdevums ar pogu nav vajadzīgs nevienam līmenim.

Šaurā ekrānā tabulu ritini horizontāli, lai apskatītu visus līmeņus.

3. tēmas noslēguma projekts - klases turnīra simulators
Kritērijs Sācis apgūt (1–3) Turpina apgūt (4–6) Apguvis (7–8) Apguvis padziļināti (9–10)
Klases, objekti un datu aizsardzība
1. uzdevums · Pārbaudes		 Projekts nebūvējas vai Output neizdrukā dalībnieku un šķēršļu sākuma datus. Projekts būvējas, bet daļa sākuma datu nesakrīt (nav 150, 80, 100 vai 20, 12, 8), trūkst kāda dalībnieka vai šķēršļa, vai enerģiju var tieši mainīt no citas klases. Output rāda trīs dalībniekus ar enerģiju 150, 80, 100 un trīs Inspector panelī iestatītus šķēršļus ar sodiem 20, 12, 8. Dalībniekus izveido kods ar new, AddChild un Setup. Enerģija glabājas privātā Stats laukā, to nolasa ar GetEnergy(), un tā nekļūst negatīva. Izpildīts “Apguvis”; README ar sava projekta piemēru paskaidro klases un objekta atšķirību, kāpēc dalībnieka dati ir private un kā Penalty īpašības set neļauj sodu zem 1.
Mantošana un lomu atšķirīgā reakcija
1. uzdevums · 2. uzdevums		 Lomu klašu nav vai visi dalībnieki uz vienādu sodu reaģē vienādi. Lomas ir izveidotas, bet kādas lomas aprēķins nesakrīt ar tabulu, lomas apstrādā ar atsevišķiem if vai metode izsauc pati sevi. Captain, Presenter un TimeKeeper manto no Participant un pārraksta ApplyPenalty ar override, izsaucot base.ApplyPenalty(...). Fiksētās kārtas dod 150 → 140, 80 → 63 un 100 → 82. Visi dalībnieki ir vienā List<Participant>, un PlayTurn izsauc ApplyPenalty bez lomas pārbaudes. Izpildīts “Apguvis”; README katrai lomai pierakstīts paredzētais un iegūtais rezultāts un paskaidrots, kāpēc viens izsaukums target.ApplyPenalty(...) dod atšķirīgus rezultātus (virtual un override) un kas notiktu bez base..
Signāli un izstāšanās paziņojumi
2. uzdevums · 3. uzdevums · Pārbaudes		 Finished signāla nav vai izstāšanās paziņojums neparādās. Paziņojums parādās tikai daļai izstājušos dalībnieku, vienam dalībniekam atkārtojas vai signāls pieslēgts pēc pirmās kārtas. Finished visiem dalībniekiem pieslēgts ar += pirms turnīra. Pilnā turnīrā Output ir tieši divi izstāšanās paziņojumi - katram izstājušajam vienu reizi -, un viņa enerģija apstājas pie 0. Izpildīts “Apguvis”; README paskaidro, kura klase signālu raida un kura to saņem, kāpēc pieslēgšana jāveic pirms kārtām un kāpēc sods jau izstājušamies dalībniekam nerada otru paziņojumu.
Turnīra vadība: nejauša izvēle un cikla beigas
2. uzdevums · 3. uzdevums · Pārbaudes		 Turnīrs nesākas, uzkaras vai beidzas bez uzvarētāja. Turnīrs notiek, bet izstājies dalībnieks tiek izvēlēts vēlreiz, rodas indeksa kļūda, cikls apstājas tikai pie drošības limita vai neizdrukā uzvarētāju un kārtu skaitu. Katrā kārtā Output rāda kārtas numuru, šķērsli, dalībnieku un enerģiju pirms un pēc soda. Izvēle notiek tikai no aktīvajiem ar GD.RandRange(0, Count - 1). Trīs palaišanās katrs turnīrs beidzas ar vienu uzvarētāju un kārtu skaitu; rezultāti pierakstīti README. Izpildīts “Apguvis”; README pamato, kāpēc while nosacījumā lieto aktīvo dalībnieku skaitu, nevis party.Count, kāpēc turnīrs garantēti beidzas (sākumā kopā 330 punktu, katrā kārtā zūd vismaz 1) un kāpēc atkārtots nejaušs iznākums nav kļūda.

Ja kaut kas nestrādā

  • Neatrod šķērsli: GetNode nosaukumiem precīzi jāsakrīt ar saknes bērnu mezgliem.
  • Turnīrs nebeidzas: pārliecinies, ka sods ir pozitīvs, lomas patērē vismaz 1 punktu un izvēle notiek tikai no aktīvajiem.
  • Paziņojumu nav: pārbaudi, vai Participant saglabāts Finished signāls un pieslēgums veikts pirms turnīra.
  • Scēnā redzams tukšs logs: pamata projekta rezultāts ir Output panelī. Spēles saskarni veido papildu uzdevumā.
