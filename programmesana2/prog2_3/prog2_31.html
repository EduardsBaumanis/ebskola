Sasniedzamais rezultāts: Izveido dalībnieku ar vārdu un enerģiju. Pārbaudi, kā tā dati mainās pēc soda.

SR 2.4.18. Objektorientētās programmēšanas pamati SR 2.4.15. Modulāras programmas

Teorija: C# klases, objekti un datu iekapsulēšana

Klase (class) un objekts (new)

Ja programmā jāapstrādā vairākas līdzīgas vienības, atsevišķu mainīgo veidošana katrai no tām ātri kļūst nepārskatāma. Klase (class) ir vienots apraksts jeb veidne, kas nosaka, kādus datus glabā viena vienība un kādas darbības ar to var veikt. Savukārt objekts (object jeb eksemplārs) ir konkrēts, patstāvīgs vienums, ko pēc šīs veidnes izveido atmiņā ar atslēgvārdu new — gluži kā bankas konta līguma veidlapa vēl nav naudas maciņš, bet katram klientam atvērtais konts glabā savu neatkarīgu atlikumu, un pirkums vienā kartē nemaina cita klienta kontu.

Līdzīgi kā Python vārdnīca grupē saistītus datus zem atslēgām, arī C# klase apvieno viena objekta īpašības. Tomēr C# ir statiski tipizēta valoda: klasē datu nosaukumus un tipus (piemēram, string tekstam, int veselam skaitlim, bool loģiskai vērtībai) definē jau iepriekš un papildina ar metodēm:

public class Konts
{
    public string Ipashnieks = "";
    public int Atlikums;
    public bool IrAktivs = true;
}

// Divi neatkarīgi objekti pēc vienas klases veidnes:
Konts pirmais = new Konts();
pirmais.Ipashnieks = "Līga";
pirmais.Atlikums = 50;

Konts otrais = new Konts();
otrais.Ipashnieks = "Māris";
otrais.Atlikums = 120;

pirmais.Atlikums -= 15; // Mainās tikai pirmais (35); otrais paliek 120.

Lauki (field) un konstruktors (constructor)

Mainīgo, kas deklarēts tieši klases iekšienē, sauc par lauku (field); tam var piešķirt arī noklusējuma sākumvērtību, un konkrēta objekta laukam piekļūst ar punkta pierakstu (objekts.Lauks). Lai izveidošanas brīdī neaizmirstu norādīt būtiskākos sākuma datus, klasē definē konstruktoru (constructor) — īpašu metodi ar precīzi tādu pašu nosaukumu kā klasei un bez atgriežamā tipa:

public class Konts
{
    public string Ipashnieks;
    public int Atlikums;

    public Konts(string ipashnieks, int sakumaAtlikums)
    {
        Ipashnieks = ipashnieks;
        Atlikums = sakumaAtlikums;
    }
}

Izsaukums new Konts("Līga", 50) nodod argumentus konstruktora parametriem, un piešķiršanas rindas tos saglabā jaunā objekta laukos. Tiklīdz klasei ir pievienots konstruktors ar parametriem, tukšais izsaukums new Konts() bez argumentiem vairs nav derīgs, ja vien nav atsevišķi aprakstīts arī konstruktors bez parametriem.

Metodes, piekļuve (public pret private) un parasta klase Godot vidē

Metode (method) ir klasē aprakstīta funkcija, kas darbojas ar konkrētā objekta datiem: void metode izpilda darbību, neatgriežot vērtību, savukārt metode ar tipu int vai bool aprēķina un ar return atdod rezultātu (true vai false).

Ja lauks ir atzīmēts ar public, jebkura cita klase var tajā tieši ierakstīt kļūdainu skaitli (piemēram, negatīvu daudzumu) un apiet noteikumus. Paslēpjot lauku ar private, tam drīkst piekļūt tikai pašas klases kods - kā bankomātā, kur lietotājs nevar brīvi pārrakstīt konta atlikumu, bet drīkst tikai nolasīt to ar nolasīšanas metodi (piemēram, Get...()) vai mainīt caur pārbaudītu darbības metodi. Ja konstruktora vai metodes parametrs saucas tāpat kā lauks, pieraksts this.lauks = lauks; skaidri nošķir objekta lauku kreisajā pusē no saņemtā parametra labajā pusē.

Godot projektā ne katrai C# klasei jābūt scēnas mezglam: tīras datu un loģikas klases raksta bez : Node un partial, nepievienojot tās scēnas kokam. Savukārt scēnas mezglam piesaistītais skripts saglabā using Godot;, partial un : Node, lai dzinējs varētu izsaukt _Ready() un tajā veidot vai pārbaudīt parastus C# objektus:

// Parasta C# datu un loģikas klase (bez : Node un partial):
public class Konts
{
    public string Ipashnieks;
    private int atlikums;

    public Konts(string ipashnieks, int atlikums)
    {
        Ipashnieks = ipashnieks;
        this.atlikums = atlikums;
        if (this.atlikums < 0) this.atlikums = 0;
    }

    public void Norekini(int summa)
    {
        if (summa < 0) return;
        atlikums -= summa;
        if (atlikums < 0) atlikums = 0;
    }

    public int GetAtlikums() { return atlikums; }
    public bool IrPozitivs() { return atlikums > 0; }
}

// Godot scēnas mezgla skriptā (using Godot;, partial un : Node):
public override void _Ready()
{
    Konts konts = new Konts("Līga", 50);
    konts.Norekini(20);
    GD.Print(konts.Ipashnieks, ": ", konts.GetAtlikums()); // 30
}

Izveido projektu, dalībnieka klasi un divus objektus

Kur strādāt: Izveido 3. tēmas Godot 4 (.NET) projektu TournamentSim ar mapēm Scenes/ un Scripts/. Šajā uzdevumā veido divus C# failus: datu klasi Scripts/Participant.cs (ko mezglam nepievieno) un scēnas skriptu Scripts/LessonDemo.cs (ko piesaista Scenes/LessonDemo.tscn saknei LessonDemo).

Scēnas un failu uzbūve:

Scenes/LessonDemo.tscn:
LessonDemo (Node - piesaistīts Scripts/LessonDemo.cs)

Scripts/ mape:
 ├── Participant.cs (parasta C# klase bez : Node un bez partial)
 └── LessonDemo.cs  (Godot scēnas skripts ar : Node un _Ready())
  1. Izveido Godot 4 (.NET) projektu TournamentSim un FileSystem panelī izveido mapes Scenes/ un Scripts/.
  2. Izveido scēnu ar saknes mezglu Node (Other Node -> Node), pārdēvē to par LessonDemo un saglabā kā res://Scenes/LessonDemo.tscn.
  3. Pievieno mezglam LessonDemo skriptu res://Scripts/LessonDemo.cs (tam jāsaglabā using Godot; un public partial class LessonDemo : Node).
  4. Izveido FileSystem panelī (ar labo peles pogu uz mapes Scripts/ -> Create New -> Script...) otru failu res://Scripts/Participant.cs — šo failu scēnas mezglam nepievieno, jo tā ir parasta C# datu klase.
  5. Ieraksti failā Scripts/Participant.cs sākuma klasi Participant ar trim publiskiem laukiem: Name, Energy un Level (skat. paraugu zemāk).
  6. Ieraksti failā Scripts/LessonDemo.cs metodē _Ready() divu neatkarīgu objektu (anna un janis) izveidi ar new Participant(), piešķir tiem dažādus vārdus un enerģijas un izdrukā ar GD.Print(...).
  7. Samazini failā Scripts/LessonDemo.cs tikai anna.Energy par 30 punktiem, izdrukā abus dalībniekus vēlreiz, nospied Build + F5 un README.md pieraksti, kāpēc Jāņa enerģija nemainījās.
// 1. Fails: Scripts/Participant.cs (1. uzdevuma sākuma versija)
public class Participant
{
    public string Name = "";
    public int Energy;
    public int Level = 1;
}

// 2. Fails: Scripts/LessonDemo.cs (metodē _Ready())
public override void _Ready()
{
    Participant anna = new Participant();
    anna.Name = "Anna";
    anna.Energy = 100;

    Participant janis = new Participant();
    janis.Name = "Jānis";
    janis.Energy = 80;

    GD.Print(anna.Name, ": ", anna.Energy, ", līmenis ", anna.Level);
    GD.Print(janis.Name, ": ", janis.Energy, ", līmenis ", janis.Level);

    anna.Energy -= 30; // Mainām tikai Annas objekta enerģiju
    GD.Print("Pēc izmaiņas -> Anna: ", anna.Energy, ", Jānis: ", janis.Energy);
}

Gatavs, kad: Output panelī redzami divi neatkarīgi Participant objekti un viena objekta enerģijas maiņa neietekmē otru.

2. uzdevums

Pievieno konstruktoru un darbības metodes ApplyPenalty() un IsActive()

Kur strādāt: Konstruktoru Participant(string name, int energy) un metodes ApplyPenalty(int amount) un IsActive() pievieno failā Scripts/Participant.cs. Objektu izveidi un sodu pārbaudes atjauno failā Scripts/LessonDemo.cs metodē _Ready().

  1. Atver failu Scripts/Participant.cs un klases Participant iekšienē pievieno konstruktoru public Participant(string name, int energy), kas piešķir Name = name; un Energy = energy;.
  2. Pievieno turpat failā Scripts/Participant.cs metodi public void ApplyPenalty(int amount), kas atņem pozitīvu sodu un neļauj enerģijai nokrist zem 0.
  3. Pievieno turpat failā Scripts/Participant.cs metodi public bool IsActive(), kas ar return Energy > 0; atgriež true, kamēr dalībniekam vēl ir enerģija.
  4. Atver failu Scripts/LessonDemo.cs un metodē _Ready() nomaini objektu izveidi uz konstruktora izsaukumiem: Participant anna = new Participant("Anna", 100); un Participant janis = new Participant("Jānis", 80);.
  5. Izsauc metodē _Ready() (failā Scripts/LessonDemo.cs) Annai pēc kārtas anna.ApplyPenalty(30); un anna.ApplyPenalty(100);, pēc katra soļa izdrukājot Annas enerģiju un anna.IsActive().
  6. Salīdzini Output izdruku ar enerģijas maiņas tabulu zemāk un pieraksti rezultātus failā README.md.
// Pievieno failā Scripts/Participant.cs klases Participant iekšienē:
public Participant(string name, int energy)
{
    Name = name;
    Energy = energy;
}

public void ApplyPenalty(int amount)
{
    if (amount < 0) return; // Negatīvu sodu nepiemērojam.
    Energy -= amount;
    if (Energy < 0) Energy = 0;
}

public bool IsActive()
{
    return Energy > 0;
}

3. uzdevums

Pasargā enerģiju ar private un pievieno GetEnergy()

Kur strādāt: Lauku private int energy; un metodi GetEnergy() veido failā Scripts/Participant.cs. Nolasīšanu ar anna.GetEnergy() un piekļuves pārbaudi veic failā Scripts/LessonDemo.cs metodē _Ready().

  1. Atver failu Scripts/Participant.cs un aizstāj publisko lauku public int Energy; ar privātu lauku private int energy;, lai neviens ārējs skripts nevarētu patvaļīgi ierakstīt anna.Energy = -500;.
  2. Atjauno failā Scripts/Participant.cs konstruktoru (izmantojot this.energy = energy; if (this.energy < 0) this.energy = 0;) un metodes ApplyPenalty() un IsActive(), lai tās strādātu ar privāto lauku energy.
  3. Pievieno failā Scripts/Participant.cs publisku nolasīšanas metodi public int GetEnergy() { return energy; }.
  4. Atver failu Scripts/LessonDemo.cs un metodē _Ready() visās GD.Print(...) rindās nomaini .Energy uz izsaukumu .GetEnergy().
  5. Izmēģini failā Scripts/LessonDemo.cs pierakstīt pagaidu rindu anna.energy = 9999; un nospied Build — izlasi kompilatora kļūdu ('Participant.energy' is inaccessible due to its protection level), pieraksti tās skaidrojumu README.md un pēc tam šo pagaidu rindu izdzēs.
  6. Pārbaudi ar Build un F5, ka abi faili atbilst pilnajam paraugam zemāk un bez kļūdām izvada rezultātus.

Gatavs, kad: enerģijas lauks energy ir private, to nolasa ar GetEnergy(), un projekts būvējas bez kļūdām.

Papildu uzdevums - Trīs dalībnieku saraksts List<Participant>

Kur strādāt: Faila Scripts/LessonDemo.cs sākumā pievieno using System.Collections.Generic;, bet sarakstu un foreach ciklu raksti metodes _Ready() beigās.

Ja pamatdarbs ir gatavs, apvieno vairākus dalībniekus vienā sarakstā (šo pieeju plašāk izmantosim 3.2. stundā).

  1. Pievieno faila Scripts/LessonDemo.cs pirmajā rindā using System.Collections.Generic;.
  2. Izveido metodē _Ready() sarakstu List<Participant> komanda = new List<Participant>(); un ar komanda.Add(...) pievieno trīs dalībniekus.
  3. Izdrukā ar foreach (Participant p in komanda) katra dalībnieka vārdu (p.Name) un enerģiju (p.GetEnergy()).

Gatavs, kad: viens foreach cikls izdrukā visu trīs sarakstā esošo dalībnieku datus.

Pilnie faili salīdzināšanai — gatavs 3.1. stundas risinājums

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

1. fails: Scripts/Participant.cs (parasta C# klase, mezglam nepievieno)

public class Participant
{
    public string Name;
    public int Level = 1;
    private int energy;

    public Participant(string name, int energy)
    {
        Name = name;
        this.energy = energy;
        if (this.energy < 0) this.energy = 0;

    public void ApplyPenalty(int amount)
    {
        if (amount < 0) return;
        energy -= amount;
        if (energy < 0) energy = 0;

    public int GetEnergy()

    }

    public bool IsActive()
    {
        return energy > 0;
    }
}

Ko sagatavo

Stundas mērķis: Izveidota dalībnieka klase Scripts/Participant.cs ar konstruktoru, privātu enerģijas lauku un metodēm ApplyPenalty(), GetEnergy() un IsActive(), kā arī pārbaudīti divi neatkarīgi objekti skriptā Scripts/LessonDemo.cs.

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Failus Scripts/Participant.cs, Scripts/LessonDemo.cs un scēnu Scenes/LessonDemo.tscn.
  • Output paneļa izdruku (ekrānuzņēmumu vai tekstu README.md) ar abu dalībnieku datiem un enerģijas maiņu (100 → 70 → 0).
  • README.md: paredzētie un iegūtie skaitļi, kā arī skaidrojums par atšķirību starp klasi un objektu un kāpēc lauks energy ir private.

Kā iesniedz: Saglabā failus, veic git commit un git push. Skolotāja norādītajā vietā iesniedz GitHub krātuves saiti.

Ja kaut kas nestrādā

  • Nav izdrukas: pārbaudi, vai LessonDemo.cs ir pievienots palaistās scēnas saknei un rindas ir _Ready() iekšienē.
  • Nav piemērota konstruktora: pēc konstruktora pievienošanas norādi vārdu un enerģiju abos new izsaukumos.
  • Energy vai energy nav atrasts: C# atšķir lielos un mazos burtus. Pēc pārdēvēšanas atjauno konstruktoru, metodes un izdrukas.
