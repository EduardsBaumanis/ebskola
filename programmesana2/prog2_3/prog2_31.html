3.1 C# klases un objekti

Stundas uzdevums: Izveido dalībnieku ar vārdu un enerģiju. Pārbaudi, kā tā dati mainās pēc soda.

SR 2.4.18. Objektorientētās programmēšanas pamati SR 2.4.15. Modulāras programmas

Pirms sāc: šajā tēmā veidosi klases turnīru. Sākumā rezultātus redzēsi teksta izdrukās, lai varētu izsekot katrai izmaiņai.

Darba secība: izlasi skaidrojumu pie attiecīgā uzdevuma, paredzi piemēra rezultātu un tad pārbaudi to. Pēc C# izmaiņām saglabā failus, Godot nospied Build un palaid scēnu ar F6. Rezultātus skaties Output panelī.

Failu ceļi: ceļi ir norādīti no tava Godot projekta mapes, kur atrodas project.godot; piemēram, Scripts/Player.cs Godot panelī ir res://Scripts/Player.cs. Ja norādītais fails jau ir izveidots, atver un papildini to.

Jaunus C# failus veido mapē Scripts, scēnas — norādītajā ceļā; trūkstošās mapes izveido. Ja tavā projektā skripts glabājas citur, rediģē esošo failu. using direktīvas raksti faila sākumā, laukus un metodes — klases iekšienē. Esošu _Ready() vai _PhysicsProcess() papildini, neveido otru tāda paša nosaukuma metodi.

Teorija ar piemēriem

1. Kāpēc dalībniekam vajadzīga klase?

Turnīrā piedalās Anna un Jānis. Katram ir vārds, enerģija un līmenis. Ja katram cilvēkam veidotu atsevišķus mainīgos, pie desmit dalībniekiem būtu grūti saprast, kuri dati pieder kopā. Klase apraksta, kādus datus glabā viens dalībnieks un kādas darbības ar to var veikt. C# to pieraksta ar class.

Objekts ir viens konkrēts dalībnieks, kuru izveido pēc šī apraksta. Participant ir klase, bet anna un janis var norādīt uz diviem atsevišķiem šīs klases objektiem. Mainot Annas enerģiju, Jāņa enerģija nemainās.

Python vārdnīca {"vards": "Anna", "energija": 100} arī grupē datus. C# klasē datu nosaukumus un tipus aprakstām iepriekš: string glabā tekstu, int — veselu skaitli. Klase nav vārdnīca, bet šis salīdzinājums palīdz ieraudzīt, kuri dati pieder vienam dalībniekam.

2. Lauks glabā vienu objekta vērtību

Mainīgo klases iekšienē sauc par lauku. Vispirms failā Participant.cs izveido vienkāršu versiju:

public class Participant
{
    public string Name = "";
    public int Energy;
    public int Level = 1;
}

Pārbaudes koda rindas liec metodes _Ready() iekšienē failā LessonDemo.cs. Zemāk ir norādīts, kā to pievienot scēnai.

Participant anna = new Participant();
anna.Name = "Anna";
anna.Energy = 100;
GD.Print(anna.Name, ": ", anna.Energy, ", līmenis ", anna.Level);

new Participant() izveido objektu. Punkts vārdā anna.Energy nozīmē “šīs Annas enerģija”. Izdrukā būs Anna: 100, līmenis 1. Tikai klases apraksta uzrakstīšana vēl neizveido nevienu dalībnieku.

3. Konstruktors nosaka sākuma datus

Lai neaizmirstu piešķirt vārdu un enerģiju, tos var prasīt objekta izveidošanas brīdī. Tam lieto konstruktoru: īpašu koda daļu ar tādu pašu nosaukumu kā klasei un bez atgriežamā tipa.

public Participant(string name, int energy)
{
    Name = name;
    Energy = energy;
}

Tagad objektu izveido ar new Participant("Anna", 100). Vērtība "Anna" nonāk parametrā name, bet 100 — parametrā energy. Parametri ir šajā izsaukumā saņemtie dati; piešķiršanas rindas tos saglabā objekta laukos. Pēc šī konstruktora pievienošanas vecais new Participant() jāaizstāj ar izsaukumu, kurā ir abi dati.

4. Metode apraksta darbību

Metode ir klasē aprakstīta funkcija. anna.ApplyPenalty(30) liek tieši Annai zaudēt 30 enerģijas punktus. Metode ar void veic darbību, neatdodot rezultāta vērtību; metode ar bool atdod true vai false.

public void ApplyPenalty(int amount)
{
    if (amount < 0) return; // Negatīvu sodu nepiemērojam.
    Energy -= amount;
    if (Energy < 0) Energy = 0;
}

public bool IsActive()
{
    return Energy > 0;
}

5. Kāpēc enerģiju mainīt caur metodi?

Ja lauks ir public, citā klasē var uzrakstīt arī anna.Energy = -500 un apiet noteikumu. Trešajā uzdevumā aizstāj to ar private int energy;. private nozīmē, ka lauku var izmantot tikai pašas klases kods. Enerģiju no ārpuses nolasa ar GetEnergy(), bet samazina ar ApplyPenalty().

Mainot lauka nosaukumu, atjauno arī konstruktoru un metodes. Pierakstā this.energy = energy; kreisā puse ir objekta lauks, bet labā — konstruktora saņemtais parametrs. Pilnajā piemērā zem uzdevumiem redzama šī gala versija.

6. Kur šis kods darbojas Godot?

Izveido Godot .NET projektu un scēnu ar saknes mezglu Node, nosauc to LessonDemo. Pievieno tam C# skriptu LessonDemo.cs. Participant.cs glabā tajā pašā projektā, bet nepievieno mezglam: šajā stundā tā ir parasta C# klase.

Godot izsauc LessonDemo._Ready(), kad scēna ir gatava. Tur ievieto izmēģinājuma rindas. Šajā Godot skriptā saglabā using Godot;, partial un : Node; to lietojumu sīkāk aplūkosim 3.3. stundā.

Pašpārbaude: Annas enerģija kļūst 0. Kas notiek ar Jāni?

Ja abi izveidoti ar atsevišķiem new Participant(...) izsaukumiem, Jāņa enerģija paliek tāda pati. Katrs objekts glabā savus datus.

1. uzdevums

Izveido dalībnieka datus

Kur strādāt: Izveido Scripts/Participant.cs dalībnieka klasei un Scripts/LessonDemo.cs pārbaudēm. LessonDemo skriptu piesaisti Scenes/LessonDemo.tscn Node saknei; objektu izveidi un izdrukas raksti tā metodē _Ready().

Atbalsts: skaidrojums un piemērs.

  1. Sagatavo LessonDemo scēnu un skriptu.
  2. Failā Participant.cs ieraksti vienkāršo klasi ar publiskiem Name, Energy un Level laukiem.
  3. Metodē _Ready() izveido Annu un Jāni ar diviem atsevišķiem new Participant() izsaukumiem. Piešķir vārdus un dažādas enerģijas.
  4. Izdrukā abu datus. Maini tikai Annas enerģiju un izdrukā vēlreiz. README pieraksti, kas mainījās.

Gatavs, kad: vari parādīt vienu klasi un divus objektus ar atsevišķiem datiem.

2. uzdevums

Pievieno sākuma datus un darbības

Kur strādāt: Konstruktoru, ApplyPenalty() un IsActive() pievieno Scripts/Participant.cs klases iekšienē. Objektu izveidi un sodu pārbaudes maini Scripts/LessonDemo.cs metodē _Ready().

Atbalsts: skaidrojums un piemērs.

  1. Pievieno konstruktoru ar diviem parametriem. Atjauno abus objekta izveidošanas izsaukumus.
  2. Pievieno ApplyPenalty un IsActive pēc teorijas piemēra.
  3. Annai ar 100 punktiem piemēro 30 un pēc tam 100 punktu sodu. Pirms palaišanas pieraksti gaidāmos rezultātus.
  4. Salīdzini izdruku ar enerģijas maiņas tabulu.

Gatavs, kad: enerģija mainās 100 → 70 → 0, un aktīvais stāvoklis beigās ir false.

3. uzdevums

Pasargā enerģiju no nejaušas maiņas

Kur strādāt: Lauku un metodes maini Scripts/Participant.cs. Nolasīšanu ar GetEnergy() un pagaidu rindu anna.energy = 9999; raksti Scripts/LessonDemo.cs metodē _Ready().

Atbalsts: skaidrojums un piemērs.

  1. Publisko Energy aizstāj ar private int energy; un visās šīs klases metodēs lieto jauno nosaukumu. Konstruktorā izmanto this.energy.
  2. Pievieno GetEnergy(), kas ar return atdod enerģiju. Ārpus klases enerģiju nolasi ar šo metodi.
  3. Izmēģini anna.energy = 9999; un nospied Build. Pieraksti kļūdas iemeslu, pēc tam šo rindu izdzēs.
  4. Salīdzini ar pilnajiem failiem un pārbaudi, ka projekts atkal būvējas.

Gatavs, kad: vari paskaidrot, kāpēc enerģiju var nolasīt, bet nevar tieši pārrakstīt no citas klases.

Papildu uzdevums — Trīs dalībnieku saraksts

Kur strādāt: Faila Scripts/LessonDemo.cs sākumā pievieno using System.Collections.Generic;, bet sarakstu un ciklu — metodes _Ready() iekšienē.

Ar using System.Collections.Generic; pievieno List<Participant> sarakstu. Ievieto tajā trīs dalībniekus un ar foreach izdrukā katra vārdu un enerģiju. Saraksta piemērs būs arī 3.2. stundā.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Aizstāj iepriekšējo tās pašas klases versiju; divas vienādi nosauktas klases vienā projektā neveido.

Participant.cs

public class Participant
{
    public string Name;
    public int Level = 1;
    private int energy;

    public Participant(string name, int energy)
    {
        Name = name;
        this.energy = energy;
        if (this.energy < 0) this.energy = 0;
    }

    public void ApplyPenalty(int amount)
    {
        if (amount < 0) return;
        energy -= amount;
        if (energy < 0) energy = 0;
    }

    public int GetEnergy()
    {
        return energy;
    }

    public bool IsActive()
    {
        return energy > 0;
    }
}

LessonDemo.cs

using Godot;

public partial class LessonDemo : Node
{
    public override void _Ready()
    {
        Participant anna = new Participant("Anna", 100);
        Participant janis = new Participant("Jānis", 80);
        anna.ApplyPenalty(30);
        GD.Print(anna.Name, ": ", anna.GetEnergy());
        GD.Print(janis.Name, ": ", janis.GetEnergy());
        anna.ApplyPenalty(100);
        GD.Print("Anna: ", anna.GetEnergy(), ", aktīva: ", anna.IsActive());
    }
}

Ko sagatavo

GitHub krātuvē saglabā projektu un šādus pierādījumus:

  • Participant.cs un LessonDemo.cs.
  • Izdrukas ar abu dalībnieku datiem un enerģijas maiņu.
  • README: paredzētie un iegūtie skaitļi, skaidrojums par klasi, objektu un private.

Saglabā failus, veic commit ar izmaiņu aprakstu un push. Skolotāja norādītajā vietā iesniedz krātuves saiti.

Ja kaut kas nestrādā

  • Nav izdrukas: pārbaudi, vai LessonDemo.cs ir pievienots palaistās scēnas saknei un rindas ir _Ready() iekšienē.
  • Nav piemērota konstruktora: pēc konstruktora pievienošanas norādi vārdu un enerģiju abos new izsaukumos.
  • Energy vai energy nav atrasts: C# atšķir lielos un mazos burtus. Pēc pārdēvēšanas atjauno konstruktoru, metodes un izdrukas.
