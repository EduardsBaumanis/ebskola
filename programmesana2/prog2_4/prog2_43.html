Teorija: galīga stāvokļu mašīna (State Machine) un pāreju loģika

Stāvokļu mašīnas princips, enum un switch izvēle

Ja autonoma objekta uzvedību mēģina aprakstīt ar daudziem atsevišķiem bool karodziņiem un sazarotām if-else virknēm, noteikumi ātri sāk pretrunot cits citam. Galīga stāvokļu mašīna (Finite State Machine) ir uzvedības projektēšanas paraugs (design pattern), kur objekts katrā laika brīdī atrodas tieši vienā diskrētā stāvoklī — līdzīgi kā robots putekļsūcējs vienlaikus neveic gan telpas tīrīšanu, gan uzlādi dokstacijā, bet darbojas vienā skaidrā režīmā.

Pieļaujamos režīmus C# kodā apraksta ar enum (uzskaitījuma tipu), pašreizējo stāvokli glabā private laukā, bet cikliskajā metodē _PhysicsProcess(double delta) ar switch struktūru izpilda tikai aktīvajam case atbilstošās darbības (noslēdzot katru zaru ar break;):

public enum IericesStavoklis { Gaidisana, Marsruts, Sekosana, Darbiba, Izslegts }

private IericesStavoklis stavoklis = IericesStavoklis.Gaidisana;

public override void _PhysicsProcess(double delta)
{
    switch (stavoklis)
    {
        case IericesStavoklis.Gaidisana:
            if (VaiMerkisUztverts()) stavoklis = IericesStavoklis.Sekosana;
            break;
        case IericesStavoklis.Sekosana:
            VirzitiesPretiMerkim();
            if (!VaiMerkisUztverts()) stavoklis = IericesStavoklis.Marsruts;
            break;
        case IericesStavoklis.Izslegts:
            break; // Gala stāvoklis — izejošu pāreju nav.
    }
}

Pārejas noteikumi, sliekšņu atstarpe un gala stāvoklis

Noteikumus, kas pārslēdz objektu no viena režīma citā (piemēram, pēc laika atskaites vai attāluma Position.DistanceTo(merkis.Position), iepriekš pārliecinoties, ka merkis != null), sauc par stāvokļu pārejām (transitions). Pārslēgšanu parasti izdala atsevišķā palīgmetodē, lai vienuviet fiksētu maiņu vai atiestatītu laika skaitītāju.

Ja režīma ieslēgšanai un izslēgšanai izmanto vienu un to pašu attāluma robežu, sīkas svārstības uz šīs līnijas liek objektam raustīties starp diviem stāvokļiem katrā kadrā. Tāpēc ievieš sliekšņu atstarpi jeb histerēzi (vai minimālo stāvokļa noturēšanas laiku) — gluži kā telpas apkures termostats ieslēdz sildītāju pie 19 °C, bet izslēdz tikai sasniedzot 21 °C, lai pie 20 °C relejs nepārtraukti neklikšķētu. Savukārt režīmu, no kura nav nevienas izejošas pārejas, sauc par gala stāvokli (terminal state):

private Node2D merkis;
private double rezimaLaiks = 0.0;

private void MainitStavokli(IericesStavoklis jaunais)
{
    if (stavoklis == IericesStavoklis.Izslegts || stavoklis == jaunais) return;
    GD.Print(stavoklis, " -> ", jaunais);
    stavoklis = jaunais;
    rezimaLaiks = 0.0; // Katrā pārejā atiestata režīma laika skaitītāju
}

private void ParbauditParejas(double delta)
{
    rezimaLaiks += delta;
    if (merkis == null || stavoklis == IericesStavoklis.Izslegts) return;

    float attalums = Position.DistanceTo(merkis.Position);
    // Sliekšņu atstarpe: ieslēdz pie < 300, atslēdz tikai pie > 400
    if (stavoklis == IericesStavoklis.Marsruts && attalums < 300.0f)
        MainitStavokli(IericesStavoklis.Sekosana);
    else if (stavoklis == IericesStavoklis.Sekosana && attalums > 400.0f)
        MainitStavokli(IericesStavoklis.Marsruts);
}

Izveido ienaidnieka scēnu un stāvokļu enum ar switch

Kur strādāt: Izveido ienaidnieka scēnu Scenes/Enemy.tscn un spēles laukuma scēnu Scenes/Arena.tscn. Papildini Scripts/Enemy.cs (piesaistīts Scenes/Enemy.tscn saknei): EnemyState uzskaitījumu raksti pirms klases Enemy, lauku state — klases iekšienē, bet switch (state) — metodē _PhysicsProcess(double delta).

Beigās scēnā būs redzams ienaidnieks, kurš zina savu pašreizējo stāvokli.

Kur strādāt: Izveido spēlētāja scēnu Scenes/Player.tscn ar skriptu Scripts/Player.cs un ievieto spēlētāju Scenes/Arena.tscn. Pāreju metodi ChangeState() un attāluma pārbaudi pievieno failā Scripts/Enemy.cs.

3. uzdevums

Pievieno gala stāvokli Dead un iztestē visas pārejas

Kur strādāt: Dzīvības punktus Hp, metodi TakeDamage(int amount) un gala stāvokļa Dead aizsardzību pievieno failā Scripts/Enemy.cs. Pāreju tabulu un secinājumus saglabā README.md.

Beigās uzveikts ienaidnieks pāries gala stāvoklī Dead un vairs nereaģēs uz spēlētāju.

  1. Failā Scripts/Enemy.cs klases laukos pievieno [Export] public int Hp = 30; un publisku īpašību public bool IsAlive => state != EnemyState.Dead;.
  2. Tajā pašā failā Scripts/Enemy.cs metodes ChangeState(EnemyState newState) pašā pirmajā rindā ieraksti sarga nosacījumu if (state == EnemyState.Dead || state == newState) return;, lai no Dead stāvokļa nebūtu iespējams izkļūt.
  3. Klasei Enemy failā Scripts/Enemy.cs pievieno publisku metodi public void TakeDamage(int amount) pēc parauga zemāk: tā samazina Hp un, kad Hp <= 0, izsauc ChangeState(EnemyState.Dead), aptur kustību un padara ienaidnieku puspaurspīdīgu.
  4. Lai iztestētu pāreju uz Dead jau šajā stundā (pirms 4.5. stundas lādiņiem), metodes _PhysicsProcess(double delta) sākumā pievieno pārbaudi: if (Input.IsKeyPressed(Key.K)) TakeDamage(30);. Palaid Scenes/Arena.tscn ar F6, pieej ienaidniekam, nospied taustiņu K un pārliecinies, ka pēc Dead sasniegšanas ienaidnieks vairs nekustas un nemaina stāvokli.
  5. Failā README.md aizpildi pāreju tabulu visiem pieciem stāvokļiem (skatīt paraugu zemāk) un pieraksti, kurš stāvoklis ir gala stāvoklis (terminal state) un kāpēc.
// Scripts/Enemy.cs — bojājumu saņemšana un pāreja uz Dead:
public void TakeDamage(int amount)
{
    if (!IsAlive || amount <= 0) return;
    Hp -= amount;
    if (Hp <= 0)
    {
        Hp = 0;
        ChangeState(EnemyState.Dead);
        Velocity = Vector2.Zero;
        Modulate = new Color(0.5f, 0.5f, 0.5f, 0.6f);
    }
}

Papildu uzdevums — Pievieno stāvokļa taimeri (stateTime)

Kur strādāt: Lauku stateTime pievieno failā Scripts/Enemy.cs: laiku pieskaiti metodē _PhysicsProcess(double delta), bet minimālā laika pārbaudi un atiestatīšanu raksti metodē ChangeState(EnemyState newState).

Ja pamatdarbs ir gatavs, pievieno papildu aizsardzību pret pārāk biežu stāvokļu maiņu.

  1. Failā Scripts/Enemy.cs pievieno klases lauku private double stateTime = 0.0;.
  2. Metodē _PhysicsProcess(double delta) pašā sākumā palielini to katrā kadrā: stateTime += delta;.
  3. Metodē ChangeState(EnemyState newState) neļauj mainīt parastos stāvokļus (izņemot pāreju uz EnemyState.Dead), ja stateTime < 0.3, un veiksmīgas pārejas beigās atiestati stateTime = 0.0;.
  4. Palaid Scenes/Arena.tscn un pārbaudi, ka ienaidnieks uz sliekšņa robežas nemaina stāvokli biežāk kā reizi 0.3 sekundēs.

Gatavs, kad: stāvot uz sliekšņa robežas, ienaidnieks nemaina stāvokli vairākas reizes sekundē.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Abus skriptus piesaisti attiecīgi Scenes/Player.tscn un Scenes/Enemy.tscn saknes mezgliem.

Scripts/Player.cs

using Godot;

public partial class Player : CharacterBody2D
{
    [Export] public float Speed = 240.0f;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 input = new Vector2(
            Input.GetAxis("move_left", "move_right"),
            Input.GetAxis("move_up", "move_down")
        );

        if (input != Vector2.Zero)
            input = input.Normalized();

        Velocity = input * Speed;
        MoveAndSlide();
    }
}

Scripts/Enemy.cs

using Godot;

public enum EnemyState
{
    Idle,   // gaida
    Patrol, // patrulē
    Chase,  // dzenas pakaļ
    Attack, // uzbrūk
    Dead    // gala stāvoklis
}

public partial class Enemy : CharacterBody2D
{
    public string EnemyName = "Pretinieks";
    [Export] public float Speed = 140.0f;
    [Export] public int Hp = 30;

    protected EnemyState state = EnemyState.Patrol;
    protected Node2D player;

    public bool IsAlive => state != EnemyState.Dead;

    public override void _Ready()
    {
        player = GetParent()?.GetNodeOrNull<Node2D>("Player");
        GD.Print("Sākuma stāvoklis: ", state);
    }

    protected void ChangeState(EnemyState newState)
    {
        if (state == EnemyState.Dead || state == newState) return;
        GD.Print("Stāvokļa maiņa: ", state, " -> ", newState);
        state = newState;
    }

    public void TakeDamage(int amount)
    {
        if (!IsAlive || amount <= 0) return;
        Hp -= amount;
        GD.Print("Ienaidnieks saņēma ", amount, " bojājumus. HP: ", Hp);
        if (Hp <= 0)
        {
            Hp = 0;
            ChangeState(EnemyState.Dead);
            Velocity = Vector2.Zero;
            Modulate = new Color(0.5f, 0.5f, 0.5f, 0.6f);
        }
    }

    public override void _PhysicsProcess(double delta)
    {
        if (Input.IsKeyPressed(Key.K))
            TakeDamage(30);

        if (player == null || !IsAlive) return;

        float dist = GlobalPosition.DistanceTo(player.GlobalPosition);

        switch (state)
        {
            case EnemyState.Idle:
            case EnemyState.Patrol:
                Velocity = Vector2.Zero;
                if (dist < 300.0f) ChangeState(EnemyState.Chase);
                break;

            case EnemyState.Chase:
                Vector2 dir = (player.GlobalPosition - GlobalPosition).Normalized();
                Velocity = dir * Speed;
                MoveAndSlide();

                if (dist < 60.0f) ChangeState(EnemyState.Attack);
                else if (dist > 400.0f) ChangeState(EnemyState.Patrol);
                break;

            case EnemyState.Attack:
                Velocity = Vector2.Zero;
                if (dist >= 80.0f) ChangeState(EnemyState.Chase);
                break;

            case EnemyState.Dead:
                break; // Gala stāvoklis — izejošu pāreju nav.
        }
    }
}

Ko sagatavo

Stundas mērķis: Tavam ienaidniekam ir strādājoša state machine ar pieciem stāvokļiem, pārejas notiek pēc attāluma līdz spēlētājam, un Dead ir gala stāvoklis, no kura nevar izkļūt.

  • Faili Scripts/Enemy.cs, Scripts/Player.cs un scēnas Scenes/Enemy.tscn, Scenes/Player.tscn un Scenes/Arena.tscn.
  • README.md ievietota video saite vai ekrānuzņēmums ar Output paneli, kurā redzamas pārejas Patrol -> Chase -> Attack -> Dead.
  • README.md tabula ar pārbaudītajām stāvokļu pārejām un skaidrojums, kāpēc atgriešanās slieksnis (400) ir lielāks par dzīšanās slieksni (300).

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • State paliek IDLE: Pārbaudi, vai pārejas nosacījumi tiek izpildīti.
  • Crash, kad player == null: Lieto null check pirms piekļūšanas.
  • Animation neattēlojas: AnimationPlayer (animāciju atskaņotājs) ne pareizi pievienots vai animācija nosaukums nepareizs.
