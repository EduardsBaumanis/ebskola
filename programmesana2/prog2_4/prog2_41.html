4.1 List (saraksts) un Array (masīvs)

Stundas uzdevums: Saprast atšķirību starp C# List<T> un Godot Array, izvēlēties piemēroto data structure (datu struktūru).

SR 2.4.16. Saliktas data structure SR 2.4.13. Data type (datu tipi)

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - izveido ienaidnieku sarakstu ar List<T> · 2. uzdevums (~25 min) - pievieno un izņem elementus droši · 3. uzdevums (~20 min) - salīdzini List<T> ar Godot Array · Iesniegšana (~5 min).

Esošu _Ready() vai _PhysicsProcess() papildini, neveido otru tāda paša nosaukuma metodi.

Teorija: dinamiskie saraksti C# un Godot vidē

Tipdrošs C# saraksts (List<T>) un Godot Array

Kad programmā jāglabā mainīgs skaits viena veida datu, fiksēta garuma masīva vietā izmanto dinamisku sarakstu. Godot .NET vidē ir pieejamas divas sarakstu saimes — to atšķirību var salīdzināt ar specializētu dokumentu mapi, kurā ievieto tikai viena formāta veidlapas, un universālu sūtījumu kasti, kurā var salikt dažādus priekšmetus nodošanai kurjeram:

Type (tips)Īpašības un pielietojumsDeklarācijas piemērs
List<T>Iekšējais C# dinamiskais saraksts (System.Collections.Generic); type-safe (tipdrošs) un ātrs aprēķiniem C# kodā.List<Ieraksts> ieraksti = new();
Godot.Collections.ArrayUniversāls Variant saraksts saziņai ar Godot dzinēju; vienā sarakstā pieļauj dažādus datu tipus.Godot.Collections.Array dati = new();
Godot.Collections.Array<T>Tipdrošs Godot saraksts, ko var eksportēt redaktora Inspector panelī un nodot Godot API metodēm.Godot.Collections.Array<Node2D> mezgli = new();

Tipdrošums (type safety) nozīmē, ka kompilators jau būvēšanas (Build) laikā neļauj List<int> sarakstā nejauši ievietot tekstu, savukārt netipizēts Godot.Collections.Array šādu sajaukumu atļauj, bet prasa uzmanību pie nolasīšanas.

Pamatdarbības, indeksu robežas un droša elementu dzēšana

Gan List<T>, gan Godot Array elementu pievienošanai lieto Add(...), kopējo skaitu nolasa ar īpašību Count, bet elementu noteiktā pozīcijā izņem ar RemoveAt(index). Numerācija vienmēr sākas ar 0, tāpēc pēdējais derīgais indekss ir Count - 1 (pirms piekļuves pēc indeksa pārbauda index >= 0 && index < saraksts.Count, lai neizraisītu ArgumentOutOfRangeException):

using System.Collections.Generic;

List<string> pieturas = new();
pieturas.Add("Stacija");
pieturas.Add("Centrs");
pieturas.Add("Bibliotēka");

pieturas.RemoveAt(2); // Izņem 3. elementu (indekss 2); Count kļūst 2.

Šķērsojot List<T> ar foreach ciklu, pašu sarakstu cikla iekšienē nedrīkst mainīt (ne pievienot, ne dzēst elementus) — tas ir kā izņemt pakāpienu no kāpnēm brīdī, kad kāds pa tām kāpj, jo visu nākamo elementu indeksi nobīdās un C# aptur izpildi ar InvalidOperationException. Lai elementus izņemtu droši, dzēšamos vienumus vispirms savāc atsevišķā pagaidu sarakstā un izdzēš pēc foreach beigām (vai izmanto metodi RemoveAll(...)).

Kā šo izmantot projektā

Atceries: ar redzamu efektu redaktorā nepietiek. Paskaidro, kura C# class (klase) glabā stāvokli, kura method (metode) to maina un kā Godot node (mezgls) struktūra izmanto šo kodu.

Pārbaudi: C# kodā pamatoti izvēlēti List, Dictionary (vārdnīca) vai HashSet (jaucējkopa), AI (mākslīgais intelekts) stāvokļi ir skaidri, un sarežģītākas sistēmas var profilēt vai atkļūdot.

Praktiskie uzdevumi

1. uzdevums -

Izveido ienaidnieku sarakstu ar List

Kur strādāt: Izveido Scripts/EnemyListDemo.cs un piesaisti to Node saknei scēnā Scenes/EnemyListDemo.tscn. using liec faila sākumā, enemies lauku — klasē, bet Add un izdrukas — _Ready(). Ienaidnieka klasi glabā Scripts/Enemy.cs; ja tās vēl nav, izveido to kā public partial class Enemy : CharacterBody2D.

Beigās viens variable (mainīgais) glabās visus ienaidniekus.

  1. Pievieno faila sākumā using System.Collections.Generic;.
  2. Pievieno class lauku private List<Enemy> enemies = new();.
  3. Pievieno trīs ienaidniekus ar enemies.Add(enemy);.
  4. Izdrukā to skaitu ar enemies.Count.
  5. Uzraksti loop (ciklu) foreach (Enemy enemy in enemies) { ... }, kas izdrukā katra nosaukumu.
  6. Pievieno ceturto ienaidnieku un palaid vēlreiz.
  7. Pārbaudi, vai loop bija jāmaina.
List<Enemy> enemies = new();
enemies.Add(new Enemy());
foreach (Enemy enemy in enemies)
{
    GD.Print(enemy.Name);
}

Gatavs, kad: loop izdrukā visus ienaidniekus, un pievienojot ceturto, kods nav jāmaina.

2. uzdevums -

Pievieno un izņem elementus droši

Kur strādāt: Visus saraksta maiņas izmēģinājumus raksti Scripts/EnemyListDemo.cs metodē _Ready(), pēc ienaidnieku pievienošanas. Pēc katras kļūdas pārbaudes aizstāj kļūdaino fragmentu ar drošo variantu.

Beigās tu zināsi, kāpēc sarakstu nedrīkst mainīt loop laikā.

  1. Izņem otro elementu ar enemies.RemoveAt(1);.
  2. Izdrukā saraksta izmēru pirms un pēc izņemšanas.
  3. Mēģini piekļūt elementam enemies[10] un pieraksti, kas notiek.
  4. Nomaini to uz if (index >= 0 && index < enemies.Count) pārbaudi un salīdzini rezultātu.
  5. Uzraksti loop, kas loop iekšpusē mēģina izdzēst elementu, un palaid to.
  6. Pārraksti to tā, lai dzēšamos vispirms savāktu otrā sarakstā.
  7. Pieraksti, kāpēc pirmais variants ir bīstams.
List<Enemy> toRemove = new();
foreach (Enemy enemy in enemies)
{
    if (enemy == enemies[0]) toRemove.Add(enemy);
}
foreach (Enemy enemy in toRemove)
{
    enemies.Remove(enemy);
}

Gatavs, kad: saraksta izmērs pēc dzēšanas ir par vienu mazāks, un droši dzēst izdodas tikai pēc loop.

3. uzdevums -

Salīdzini List ar Godot Array

Kur strādāt: Godot Array un List salīdzinājumu pievieno Scripts/EnemyListDemo.cs metodē _Ready(). Pēc kļūdas izpētes neatbilstošā tipa pievienošanu izdzēs; secinājumus raksti README.md.

Beigās tu zināsi, kuru sarakstu kurā vietā lietot.

  1. Izveido Godot.Collections.Array bullets = new(); un pievieno tam dažas vērtības.
  2. Izdrukā tā izmēru ar bullets.Count.
  3. Mēģini ielikt Array sarakstā gan skaitli, gan tekstu.
  4. Mēģini to pašu ar List<int> un izlasi compiler error (kompilatora kļūdu).
  5. Pieraksti, kurš saraksts pieļauj dažādus type.
  6. Pieraksti, kurš saraksts ir vajadzīgs, lai datus nodotu Godot editoram.
  7. Izvēlies savam ienaidnieku sarakstam pareizo variantu un pamato izvēli.
Godot.Collections.Array bullets = new();
bullets.Add(1);
bullets.Add("paraugs");
GD.Print(bullets.Count);
bullets.RemoveAt(bullets.Count - 1);

Gatavs, kad: tu vari pateikt, ka List<T> ir type-safe un ērts iekšējam C# kodam, bet Array vajadzīgs saziņai ar Godot datiem.

Papildu uzdevums - Atrodi tuvāko ienaidnieku

Kur strādāt: Tuvākā ienaidnieka meklēšanas metodi pievieno Scripts/EnemyListDemo.cs klasei, ārpus _Ready(). Ienaidnieku redzamos eksemplārus un pozīcijas izveido Scenes/EnemyListDemo.tscn un iekļauj tos šī skripta enemies sarakstā.

Ja pamatdarbs ir gatavs, izmanto sarakstu reālam aprēķinam.

  1. Uzraksti method, kas saņem spēlētāja pozīciju.
  2. Izej loop cauri visiem ienaidniekiem.
  3. Izrēķini katram attālumu ar Position.DistanceTo(...).
  4. Saglabā variable to, kuram attālums ir mazākais.
  5. Izdrukā tuvākā ienaidnieka nosaukumu un attālumu.

Gatavs, kad: method atgriež tieši to ienaidnieku, kurš ekrānā ir vistuvāk spēlētājam.

Ko sagatavo

Stundas mērķis: Tu proti C# izveidot List<T> sarakstu, droši pievienot un izņemt elementus un izskaidrot, ar ko tas atšķiras no Godot Array.

GitHub krātuvē jābūt:

  1. C# fails ar ienaidnieku sarakstu un loop.
  2. Ekrānuzņēmums ar Output paneli, kurā redzams saraksta izmērs pirms un pēc dzēšanas.
  3. README.md: kāpēc sarakstu nedrīkst mainīt loop laikā un kad lieto Array, nevis List<T>.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Biežākās kļūdas

  • ArgumentOutOfRangeException (arguments ir ārpus pieļaujamā diapazona): sarakstā nav elementa ar tādu index (indeksu) - pārbaudi index < enemies.Count.
  • NullReferenceException (tukšas atsauces kļūda): sarakstā ielikta tukša reference (atsauce) vai node nav atrasts.
  • Collection was modified (kolekcija tika mainīta): pievienojot vai dzēšot no List<T> foreach (katra elementa cikls) laikā, loop apstājas ar kļūdu.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

using Godot;
using System.Collections.Generic;

public partial class Game : Node2D
{
    [Export] public PackedScene EnemyScene;
    private readonly List<Enemy> enemies = new();
    private double spawnTimer = 0.0;

    private void SpawnEnemy()
    {
        Enemy enemy = EnemyScene.Instantiate<Enemy>();
        AddChild(enemy);
        enemy.Position = new Vector2((float)GD.RandRange(0.0, 1280.0), 0);
        enemies.Add(enemy);
    }

    public override void _PhysicsProcess(double delta)
    {
        spawnTimer += delta;
        if (spawnTimer >= 2.0)
        {
            SpawnEnemy();
            spawnTimer = 0.0;
        }

        // Noņem mirušos
        enemies.RemoveAll(enemy => !enemy.IsAlive());
    }
}
Spēle spawno 1 ienaidnieku ik pa 2 sec, mirstīgi tiek noņemti no vector (vektora) un scēnas.
