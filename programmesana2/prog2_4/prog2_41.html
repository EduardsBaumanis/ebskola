4.1 List (saraksts) un Array (masīvs)

Sasniedzamais rezultāts: Saprast atšķirību starp C# List<T> un Godot Array, izvēlēties piemēroto data structure (datu struktūru).

SR 2.4.16. Saliktas data structure SR 2.4.13. Data type (datu tipi)

Teorija: dinamiskie saraksti C# un Godot vidē

Tipdrošs C# saraksts (List<T>) un Godot Array

Kad programmā jāglabā mainīgs skaits viena veida datu, fiksēta garuma masīva vietā izmanto dinamisku sarakstu. Godot .NET vidē ir pieejamas divas sarakstu saimes — to atšķirību var salīdzināt ar specializētu dokumentu mapi, kurā ievieto tikai viena formāta veidlapas, un universālu sūtījumu kasti, kurā var salikt dažādus priekšmetus nodošanai kurjeram:

Type (tips)Īpašības un pielietojumsDeklarācijas piemērs
List<T>Iekšējais C# dinamiskais saraksts (System.Collections.Generic); type-safe (tipdrošs) un ātrs aprēķiniem C# kodā.List<Ieraksts> ieraksti = new();
Godot.Collections.ArrayUniversāls Variant saraksts saziņai ar Godot dzinēju; vienā sarakstā pieļauj dažādus datu tipus.Godot.Collections.Array dati = new();
Godot.Collections.Array<T>Tipdrošs Godot saraksts, ko var eksportēt redaktora Inspector panelī un nodot Godot API metodēm.Godot.Collections.Array<Node2D> mezgli = new();

Tipdrošums (type safety) nozīmē, ka kompilators jau būvēšanas (Build) laikā neļauj List<int> sarakstā nejauši ievietot tekstu, savukārt netipizēts Godot.Collections.Array šādu sajaukumu atļauj, bet prasa uzmanību pie nolasīšanas:

using Godot;
using System.Collections.Generic;

// 1. Tipdrošs C# saraksts iekšējiem aprēķiniem:
List<int> merijumi = new();
merijumi.Add(24);
// merijumi.Add("kļūda"); // Build kļūda — teksts nav int!

// 2. Tipdrošs Godot saraksts redaktora Inspector panelim:
[Export] public Godot.Collections.Array<Node2D> Sensori = new();

// 3. Universāls Variant saraksts dažādu tipu datiem:
Godot.Collections.Array sutijums = new();
sutijums.Add(105);
sutijums.Add("Trausls");

Pamatdarbības, indeksu robežas un droša elementu dzēšana

Gan List<T>, gan Godot Array elementu pievienošanai lieto Add(...), kopējo skaitu nolasa ar īpašību Count, bet elementu noteiktā pozīcijā izņem ar RemoveAt(index). Numerācija vienmēr sākas ar 0, tāpēc pēdējais derīgais indekss ir Count - 1 (pirms piekļuves pēc indeksa pārbauda index >= 0 && index < saraksts.Count, lai neizraisītu ArgumentOutOfRangeException):

using System.Collections.Generic;

List<string> pieturas = new();
pieturas.Add("Stacija");
pieturas.Add("Centrs");
pieturas.Add("Bibliotēka");

pieturas.RemoveAt(2); // Izņem 3. elementu (indekss 2); Count kļūst 2.
int indekss = 1;
if (indekss >= 0 && indekss < pieturas.Count)
    GD.Print(pieturas[indekss]); // Droša piekļuve: "Centrs"

Šķērsojot List<T> ar foreach ciklu, pašu sarakstu cikla iekšienē nedrīkst mainīt (ne pievienot, ne dzēst elementus) — tas ir kā izņemt pakāpienu no kāpnēm brīdī, kad kāds pa tām kāpj, jo visu nākamo elementu indeksi nobīdās un C# aptur izpildi ar InvalidOperationException. Lai elementus izņemtu droši, dzēšamos vienumus vispirms savāc atsevišķā pagaidu sarakstā un izdzēš pēc foreach beigām (vai izmanto metodi RemoveAll(...)):

// Droša dzēšana divos posmos — nemaina sarakstu foreach laikā:
List<string> dzesamie = new();
foreach (string pietura in pieturas)
{
    if (pietura == "Stacija") dzesamie.Add(pietura);
}
foreach (string pietura in dzesamie)
{
    pieturas.Remove(pietura);
}

1. uzdevums

Izveido ienaidnieku sarakstu ar List

Kur strādāt: Izveido Godot .NET projektu TopDownShooter ar mapēm Scenes/ un Scripts/. Izveido Scripts/Enemy.cs ienaidnieka klasei un Scripts/EnemyListDemo.cs saraksta pārbaudēm. Scēnā Scenes/EnemyListDemo.tscn saknes mezglam Node (EnemyListDemo) piesaisti Scripts/EnemyListDemo.cs.

Beigās viens List<Enemy> saraksts glabās visus ienaidniekus un vienāds foreach cikls apstrādās jebkuru to skaitu.

  1. Izveido jaunu Godot .NET projektu TopDownShooter (režīms Compatibility, loga izmērs 1280 × 720) un FileSystem panelī zem res:// izveido divas mapes: Scenes un Scripts.
  2. Mapē Scripts izveido failu Scripts/Enemy.cs un ieraksti tajā sākuma klasi public partial class Enemy : CharacterBody2D ar publiskiem laukiem EnemyName un Hp pēc parauga zemāk (šo pašu klasi papildināsi 4.3.–4.6. stundā).
  3. Izveido jaunu scēnu ar saknes mezglu Node, pārdēvē to par EnemyListDemo un saglabā kā Scenes/EnemyListDemo.tscn. Ar Attach Script pievieno saknei C# skriptu Scripts/EnemyListDemo.cs.
  4. Faila Scripts/EnemyListDemo.cs pašā sākumā (zem using Godot;) pievieno using System.Collections.Generic;, bet klases EnemyListDemo iekšienē (pirms _Ready()) pievieno lauku private List<Enemy> enemies = new();.
  5. Faila Scripts/EnemyListDemo.cs metodē _Ready() izveido trīs Enemy objektus ("Skauts", "Sargs", "Snaiperis"), pievieno tos sarakstam ar enemies.Add(...);, izdrukā kopējo skaitu enemies.Count un ar ciklu foreach (Enemy enemy in enemies) izdrukā katra enemy.EnemyName.
  6. Saglabā abus failus, nospied Build un palaid scēnu ar F6. Pēc tam faila Scripts/EnemyListDemo.cs metodē _Ready() pirms foreach cikla pievieno ceturto ienaidnieku ("Smagais"), palaid vēlreiz un pārliecinies, ka pats foreach cikls nebija jāmaina.
// 1. Scripts/Enemy.cs sākuma versija:
using Godot;

public partial class Enemy : CharacterBody2D
{
    public string EnemyName = "Pretinieks";
    public int Hp = 30;
}

// 2. Scripts/EnemyListDemo.cs metodē _Ready():
enemies.Add(new Enemy { EnemyName = "Skauts" });
enemies.Add(new Enemy { EnemyName = "Sargs" });
enemies.Add(new Enemy { EnemyName = "Snaiperis" });

GD.Print("Sākuma skaits: ", enemies.Count);
foreach (Enemy enemy in enemies)
{
    GD.Print("Ienaidnieks: ", enemy.EnemyName);
}

Gatavs, kad: Output panelī foreach cikls izdrukā visus ienaidniekus, un, pievienojot ceturto, cikla kods nav jāmaina.

2. uzdevums

Pievieno un izņem elementus droši

Kur strādāt: Visus saraksta izņemšanas un drošas dzēšanas soļus raksti faila Scripts/EnemyListDemo.cs metodē _Ready() zem 1. uzdevuma koda. Novērojumus pieraksti README.md.

Beigās tu pratīsi droši pārbaudīt indeksa robežas un izņemt elementus, neizraisot kļūdu cikla laikā.

  1. Faila Scripts/EnemyListDemo.cs metodē _Ready() (zem 1. uzdevuma cikla) izņem otro ienaidnieku ar enemies.RemoveAt(1); (indekss 1 ir otrais elements, jo numerācija sākas ar 0) un izdrukā jauno enemies.Count.
  2. Tajā pašā metodē _Ready() uz brīdi izmēģini tiešu piekļuvi neesošam indeksam GD.Print(enemies[10].EnemyName); un palaid ar F6. Cilnē Debugger → Errors izlasi kļūdu (ArgumentOutOfRangeException) un pieraksti to README.md.
  3. Failā Scripts/EnemyListDemo.cs aizstāj kļūdaino rindu ar drošu robežu pārbaudi: int index = 10; if (index >= 0 && index < enemies.Count) GD.Print(enemies[index].EnemyName);.
  4. Zem tās uz brīdi izmēģini dzēšanu tieši foreach cikla iekšienē: foreach (Enemy enemy in enemies) { if (enemy.EnemyName == "Skauts") enemies.Remove(enemy); } un palaid ar F6, lai redzētu kļūdu InvalidOperationException: Collection was modified.
  5. Aizstāj kļūdaino ciklu failā Scripts/EnemyListDemo.cs ar drošu divu posmu dzēšanu pēc parauga zemāk (vispirms savāc dzēšamos toRemove sarakstā un izdzēs tos pēc pirmā cikla beigām), palaid ar F6 un README.md pieraksti, kāpēc sarakstu nedrīkst mainīt foreach laikā.
// Scripts/EnemyListDemo.cs metodē _Ready() — droša dzēšana divos posmos:
enemies.RemoveAt(1);
GD.Print("Skaits pēc RemoveAt(1): ", enemies.Count);

int index = 10;
if (index >= 0 && index < enemies.Count)
    GD.Print(enemies[index].EnemyName);
else
    GD.Print("Indekss ", index, " ir ārpus robežām (Count = ", enemies.Count, ")");

List<Enemy> toRemove = new();
foreach (Enemy enemy in enemies)
{
    if (enemy.EnemyName == "Skauts")
        toRemove.Add(enemy);
}
foreach (Enemy enemy in toRemove)
{
    enemies.Remove(enemy);
}
GD.Print("Skaits pēc drošas dzēšanas: ", enemies.Count);

Gatavs, kad: saraksta izmērs pēc dzēšanas samazinās bez kļūdām, un README.md ir pierakstīts, kāpēc dzēšanu veic pēc foreach cikla.

3. uzdevums

Salīdzini List ar Godot Array

Kur strādāt: Sarakstu salīdzinājumu pievieno faila Scripts/EnemyListDemo.cs klasei un metodei _Ready(). Secinājumus pieraksti README.md.

Beigās tu zināsi, kad lietot C# List<T> un kad — Godot.Collections.Array.

  1. Faila Scripts/EnemyListDemo.cs metodes _Ready() beigās izveido Godot universālo sarakstu Godot.Collections.Array bullets = new();.
  2. Tajā pašā bullets sarakstā pievieno gan veselu skaitli, gan tekstu (bullets.Add(12); bullets.Add("plazma");) un izdrukā bullets.Count.
  3. Zem tā metodē _Ready() izveido tipdrošu C# sarakstu List<int> ammoCounts = new();, pievieno ammoCounts.Add(12); un uz brīdi pamēģini pievienot tekstu ammoCounts.Add("plazma");. Nospied Build, izlasi kompilatora kļūdu un pēc tam rindu ar "plazma" izdzēs.
  4. Faila Scripts/EnemyListDemo.cs klases laukos (virs _Ready()) pievieno eksportētu Godot sarakstu [Export] public Godot.Collections.Array<string> WaveNames = new();, nospied Build, atlasi EnemyListDemo mezglu un pārliecinies, ka Wave Names parādās Inspector panelī.
  5. Failā README.md pieraksti: kurš saraksts pieļauj dažādus datu tipus vienā kolekcijā, kurš ir vajadzīgs datu nodošanai Godot Inspector panelim un kāpēc ienaidnieku sarakstam C# kodā izvēlamies List<Enemy>.
// Scripts/EnemyListDemo.cs metodē _Ready():
Godot.Collections.Array bullets = new();
bullets.Add(12);
bullets.Add("plazma");
GD.Print("Godot Array skaits: ", bullets.Count);

List<int> ammoCounts = new();
ammoCounts.Add(12);
// ammoCounts.Add("plazma"); // Kompilācijas kļūda: string nav int!
GD.Print("List<int> skaits: ", ammoCounts.Count);

Gatavs, kad: EnemyListDemo.cs būvējas bez kļūdām, un README.md ir pamatots, kāpēc List<T> lieto iekšējam C# kodam, bet Godot.Collections.Array — saziņai ar Godot redaktoru.

Papildu uzdevums — Atrodi tuvāko ienaidnieku

Kur strādāt: Metodi FindClosestEnemy(Vector2 playerPos) pievieno faila Scripts/EnemyListDemo.cs klasei ārpus _Ready(), bet ienaidnieku pozīcijas un metodes izsaukumu raksti _Ready() beigās.

Ja pamatdarbs ir gatavs, izmanto List<Enemy> sarakstu tuvākā mērķa atrašanai šaušanas spēlei.

  1. Faila Scripts/EnemyListDemo.cs klasei (ārpus _Ready()) pievieno metodi private Enemy FindClosestEnemy(Vector2 playerPos).
  2. Metodes iekšienē izveido divus mainīgos: Enemy closest = null; un float minDistance = float.MaxValue;.
  3. Ar foreach (Enemy enemy in enemies) aprēķini attālumu float dist = playerPos.DistanceTo(enemy.Position); un, ja dist < minDistance, saglabā gan jauno mazāko attālumu, gan closest = enemy;.
  4. Metodē _Ready() piešķir saraksta ienaidniekiem dažādas Position koordinātas, izsauc FindClosestEnemy(new Vector2(200, 360)) un izdrukā atrastā tuvākā ienaidnieka EnemyName.

Gatavs, kad: metode atgriež un izdrukā tieši to ienaidnieku, kura pozīcija ir vistuvāk spēlētājam.

Pilnie faili salīdzināšanai

Katru piemēru liec norādītajā failā. Divas vienādi nosauktas klases vienā projektā neveido.

Scripts/Enemy.cs

using Godot;

public partial class Enemy : CharacterBody2D
{
    public string EnemyName = "Pretinieks";
    public int Hp = 30;
}

Scripts/EnemyListDemo.cs

using Godot;
using System.Collections.Generic;

public partial class EnemyListDemo : Node
{
    [Export] public Godot.Collections.Array<string> WaveNames = new();
    private List<Enemy> enemies = new();

    public override void _Ready()
    {
        // 1. uzdevums: pievieno ienaidniekus List<Enemy> sarakstam
        enemies.Add(new Enemy { EnemyName = "Skauts", Position = new Vector2(500, 300) });
        enemies.Add(new Enemy { EnemyName = "Sargs", Position = new Vector2(350, 360) });
        enemies.Add(new Enemy { EnemyName = "Snaiperis", Position = new Vector2(900, 200) });
        enemies.Add(new Enemy { EnemyName = "Smagais", Position = new Vector2(700, 500) });

        GD.Print("Sākuma skaits: ", enemies.Count);
        foreach (Enemy enemy in enemies)
        {
            GD.Print("Ienaidnieks: ", enemy.EnemyName);
        }

        // 2. uzdevums: izņemšana pēc indeksa, robežu pārbaude un droša dzēšana
        enemies.RemoveAt(1); // Izņem "Sargs" (indekss 1)
        GD.Print("Skaits pēc RemoveAt(1): ", enemies.Count);

        int index = 10;
        if (index >= 0 && index < enemies.Count)
            GD.Print(enemies[index].EnemyName);
        else
            GD.Print("Indekss ", index, " ir ārpus robežām (Count = ", enemies.Count, ")");

        List<Enemy> toRemove = new();
        foreach (Enemy enemy in enemies)
        {
            if (enemy.EnemyName == "Skauts")
                toRemove.Add(enemy);
        }
        foreach (Enemy enemy in toRemove)
        {
            enemies.Remove(enemy);
        }
        GD.Print("Skaits pēc drošas dzēšanas: ", enemies.Count);

        // 3. uzdevums: Godot Array un C# List<int> salīdzinājums
        Godot.Collections.Array bullets = new();
        bullets.Add(12);
        bullets.Add("plazma");
        GD.Print("Godot Array skaits: ", bullets.Count);

        List<int> ammoCounts = new();
        ammoCounts.Add(12);
        GD.Print("Tipdroša List<int> skaits: ", ammoCounts.Count);
    }
}

Ko sagatavo

Stundas mērķis: Tu proti C# izveidot List<T> sarakstu, droši pievienot un izņemt elementus un izskaidrot, ar ko tas atšķiras no Godot Array.

GitHub krātuvē jābūt:

  • Faili Scripts/Enemy.cs, Scripts/EnemyListDemo.cs un scēna Scenes/EnemyListDemo.tscn.
  • Ekrānuzņēmums ar Output paneli, kurā redzams saraksta izmērs pirms un pēc dzēšanas.
  • README.md: kāpēc sarakstu nedrīkst mainīt foreach cikla laikā un kad lieto Godot.Collections.Array, nevis List<T>.

Kā iesniedz: Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • ArgumentOutOfRangeException (arguments ir ārpus pieļaujamā diapazona): sarakstā nav elementa ar tādu index (indeksu) - pārbaudi index < enemies.Count.
  • NullReferenceException (tukšas atsauces kļūda): sarakstā ielikta tukša reference (atsauce) vai node nav atrasts.
  • Collection was modified (kolekcija tika mainīta): pievienojot vai dzēšot no List<T> foreach (katra elementa cikls) laikā, loop apstājas ar kļūdu.
