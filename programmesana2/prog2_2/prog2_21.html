2.1 Process un fizikas cikli

Stundas uzdevums: Saprast atšķirību starp _process un _physics_process metodēm un izveidot pirmo kustīgu objektu.

SR 2.4.14. Vadības struktūras SR 2.4.15. Modulāras programmas

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - liec objektam kustēties ar delta · 2. uzdevums (~25 min) - salīdzini _process un _physics_process · 3. uzdevums (~20 min) - pārbaudi, kas notiek bez delta · Iesniegšana (~5 min).

Pirms sāc: atver savu Godot projektu ar sagatavotu C++ vidi. Šodien galvenais jautājums ir viens: kāpēc ātrums vienmēr jāreizina ar delta.

Teorija: _process un _physics_process

Godot piedāvā divas galvenās per-frame metodes:

  • _process(double delta) - izsaukts katrā renderēšanas kadrā (~60 FPS). Lieto vizuāliem efektiem.
  • _physics_process(double delta) - fiksēts laiks (60 Hz noklusējumā). Lieto fizikai un kustībām.

Delta ir laiks (sekundēs), kas pagājis kopš pēdējā kadra. Reizinot ātrumu ar delta, kustība būs vienmērīga neatkarīgi no FPS.

void Player::_physics_process(double delta) {
    // Slikti - bez delta:
    // position.x += 5;       // ātrums atkarīgs no FPS

    // Labi - ar delta:
    Vector2 pos = get_position();
    pos.x += 200.0f * delta;  // 200 pikseļi/sekundē
    set_position(pos);
}

Kā šo izmantot projektā

Atceries: ar redzamu efektu editorā nepietiek. Paskaidro, kura C++ klase glabā stāvokli, kura metode to maina un kā Godot node struktūra izmanto šo kodu.

Pārbaudi: spēlētājs, objekti un sadursmes darbojas ar C++ klasēm, kas lieto _physics_process, Input, CharacterBody2D, Area2D vai move_and_slide.

Praktiskie uzdevumi

1. uzdevums - Liec objektam kustēties ar delta

Beigās tavs objekts pats vienmērīgi pārvietosies pa ekrānu.

  1. Izveido C++ klasi Mover, kas manto no Node2D.
  2. Pievieno laukus Vector2 velocity; un double speed = 200.0;.
  3. Pieteic metodi void _physics_process(double delta) override;.
  4. Ieraksti tajā set_position(get_position() + velocity * delta);.
  5. Iestati konstruktorā velocity = Vector2(speed, 0);.
  6. Kompilē ar scons platform=windows un pievieno mezglu scēnai.
  7. Palaid spēli un vēro, kā objekts virzās pa labi.

Gatavs, kad: objekts pārvietojas vienmērīgi pa labi un neizlec pa gabaliem.

2. uzdevums - Salīdzini _process un _physics_process

Beigās tu zināsi, kuru metodi kurai lietai izvēlēties.

  1. Pievieno klasei arī void _process(double delta) override;.
  2. Izdrukā abās metodēs UtilityFunctions::print(delta);.
  3. Palaid spēli uz dažām sekundēm un aptur to.
  4. Salīdzini Output panelī abu metožu izdrukātās vērtības.
  5. Pieraksti, kurai metodei delta ir vienmēr vienāds un kurai mainās.
  6. Pieraksti, kura metode ir piemērota kustībai un fizikai.
  7. Izdzēs izdrukas, lai Output panelis netiktu piesārņots.

Gatavs, kad: tu vari pateikt, ka _physics_process delta ir stabils, bet _process delta svārstās.

3. uzdevums - Pārbaudi, kas notiek bez delta

Beigās tu sapratīsi, kāpēc bez delta spēle uz cita datora strādā citādi.

  1. Nomaini kustības rindu uz set_position(get_position() + velocity); - bez delta.
  2. Kompilē un palaid spēli.
  3. Pieraksti, cik ātri objekts tagad aizlido no ekrāna.
  4. Atver Project Settings -> Physics -> Common un nomaini Physics Ticks per Second uz 30.
  5. Palaid vēlreiz un pieraksti, vai ātrums mainījās.
  6. Ieliec delta atpakaļ un atkārto abus mērījumus.
  7. Pieraksti secinājumu: ar delta ātrums nemainījās, bez tā - mainījās.

Gatavs, kad: bez delta objekta ātrums mainās, mainot fizikas biežumu, bet ar delta paliek vienāds.

Papildu uzdevums - Liec objektam kustēties pa apli

Ja pamatdarbs ir gatavs, izmanto delta arī leņķim.

  1. Pievieno lauku double angle = 0.0;.
  2. Palielini to katrā kadrā ar angle += 2.0 * delta;.
  3. Izrēķini pozīciju ar Vector2(cos(angle), sin(angle)) * 150.
  4. Pieskaiti tai ekrāna centru (640, 360).
  5. Palaid un pārbaudi, ka objekts riņķo vienmērīgi.

Gatavs, kad: objekts brauc pa apli ap ekrāna centru ar vienmērīgu ātrumu.

Ko iesniedz skolotājam

Stundas mērķis: Tev ir C++ klase, kas pārvieto objektu, izmantojot delta, un tu ar mērījumu vari pierādīt, kāpēc bez delta spēles ātrums mainās atkarībā no datora.

Iesniedzamais:

  1. Fails mover.cpp tavā GitHub krātuvē.
  2. Ekrānuzņēmums ar Output paneli, kurā redzamas abu metožu delta vērtības.
  3. Burtnīcā: ar ko _process atšķiras no _physics_process un kāpēc ātrums jāreizina ar delta.

Kā iesniedz: Veic commit un push, tad iesniedz krātuves saiti, ekrānuzņēmumu un burtnīcas fotogrāfiju skolotāja norādītajā vietā.

Biežākās kļūdas

  • Objekts kustās ļoti ātri: Aizmirsts reizināt ar delta.
  • Kustība rāva: Lieto _physics_process, ne _process.
  • Crash startējoties: Pārliecinies, ka set_position tiek izsaukts pēc node ir scēnā (_ready vai vēlāk).

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

#include "mover.hpp"
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/variant/utility_functions.hpp>

using namespace godot;

void Mover::_bind_methods() {}

void Mover::_physics_process(double delta) {
    Vector2 pos = get_position();
    pos += velocity * delta;

    if (pos.x < 0 || pos.x > 1280) velocity.x = -velocity.x;
    if (pos.y < 0 || pos.y > 720)  velocity.y = -velocity.y;

    set_position(pos);
}
