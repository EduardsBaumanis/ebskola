2.3 Vadības struktūras spēles loģikā

Stundas uzdevums: Papildināt spēlētāju ar punktu un atslēgas loģiku, pārbaudot if, switch un foreach.

SR 2.4.14. Vadības struktūras SR 2.4.13. Mainīgie

80 min plāns: Ievads (~10 min) · nosacījumi (~20 min) · priekšmetu loģika (~25 min) · cikla pārbaude (~20 min) · saglabāšana (~5 min).

Pirms sāc: turpini 2.2 projekta Player.cs. Šodien priekšmetus pārbaudīsim ar kodu; nākamajā stundā tos savāksim spēlē. Kustības metode paliek tajā pašā klasē.

Darba ritms: pēc katra uzdevuma saglabā, nospied Build un pārbaudi rezultātu. Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Teorija: if, switch un foreach

C# nosacījumu raksta apaļajās iekavās, darbību bloku — figūriekavās. Python elif vietā lieto else if. enum dod priekšmetu veidiem nosaukumus, bet switch izvēlas attiecīgo darbību.

C# automātiski nepāriet uz nākamo netukšo case. Ja piemērā pēc punktu pieskaitīšanas izņem break;, rodas kompilācijas kļūda; to atjauno pirms palaišanas. Skati Microsoft skaidrojumu par switch.

foreach apstrādā katru masīva elementu vienu reizi. Eksperimentu izsaucam _Ready(), ne katrā fizikas solī; citādi punkti pieaugtu nepārtraukti. Spēles gaidīšanai nelieto bezgalīgu while ciklu.

1. uzdevums -

Pārbaudi trīs nosacījuma zarus

  1. Player klases iekšpusē pievieno zemāk doto pagaidu _Ready() metodi. Tā darbojas vienu reizi, kad Player nonāk scēnā.
  2. Pārbaudi health vērtības 100, 20 un 0, katru reizi būvējot un palaižot spēli no jauna. Pieraksti rezultātus.
  3. README.md uzraksti tā paša nosacījuma Python versiju un trīs sintakses atšķirības. Šis ir nosacījumu eksperiments; dzīvību sistēma pamatspēlei nav vajadzīga.
  4. Pēc pārbaudes noņem šo pagaidu _Ready(), lai to nesajauktu ar 3. uzdevuma pārbaudi.
public override void _Ready()
{
    int health = 100;
    if (health <= 0)
        GD.Print("Spēle beigusies");
    else if (health < 30)
        GD.Print("Uzmanību!");
    else
        GD.Print("Viss kārtībā");
}

Gatavs, kad: 100 dod “Viss kārtībā”, 20 — brīdinājumu un 0 — “Spēle beigusies”.

2. uzdevums -

Pievieno spēlētājam punktus un atslēgu

  1. Virs Player klases (pēc using Godot;) deklarē public enum PickupType { Coin, Gem, Key }. Projektā šo enum deklarē tikai vienu reizi.
  2. Player klases iekšpusē pievieno Score, HasKey un IsActive īpašības un publisko metodi OnPickup no pilnā faila zemāk. Saglabā esošo kustības metodi.
  3. Paskaidro katru switch zaru: Coin dod 1 punktu, Gem — 5, Key iestata HasKey = true. private set ļauj citiem skriptiem nolasīt punktus, bet mainīt tos drīkst Player klase.
  4. Uz laiku izņem viena netukša case beigu break;, nospied Build un izlasi kompilācijas kļūdu. Atjauno break un atkārto Build.
2.3 Player.cs — pilns fails salīdzināšanai

Lejupielādēt Player.cs. Aizstāj tikai atbilstošā faila saturu; neveido otru tāda paša nosaukuma klasi.

using Godot;

public enum PickupType { Coin, Gem, Key }

public partial class Player : CharacterBody2D
{
    [Export] public float Speed = 300.0f;

    public int Score { get; private set; } = 0;
    public bool HasKey { get; private set; } = false;
    public bool IsActive { get; set; } = true;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 direction = Vector2.Zero;
        if (Input.IsActionPressed("move_left")) direction.X -= 1;
        if (Input.IsActionPressed("move_right")) direction.X += 1;
        if (Input.IsActionPressed("move_up")) direction.Y -= 1;
        if (Input.IsActionPressed("move_down")) direction.Y += 1;

        Velocity = direction.Normalized() * Speed;
        MoveAndSlide();
    }

    public void OnPickup(PickupType type)
    {
        if (!IsActive) return;

        switch (type)
        {
            case PickupType.Coin:
                Score += 1;
                break;
            case PickupType.Gem:
                Score += 5;
                break;
            case PickupType.Key:
                HasKey = true;
                break;
        }

        GD.Print($"Punkti: {Score}; atslēga: {HasKey}");
    }
}

Gatavs, kad: projekts kompilējas, saglabāta kustība un priekšmetu loģika ir vienā Player.cs.

3. uzdevums -

Izmēģini savākšanu ar foreach

  1. Player klasē uz laiku pievieno zemāk doto _Ready() metodi.
  2. Palaid F5. Pēc trim priekšmetiem rezultātam jābūt 2 punktiem un atslēgai. Tas pārbauda gan punktu pieskaitīšanu, gan if/else.
  3. Masīvam pievieno PickupType.Gem, palaid no jauna; rezultātam jābūt 7 punktiem, atslēga joprojām ir. Cikls nav jāmaina.
  4. Uzņem izdrukas ekrānuzņēmumu un izdzēs visu pagaidu _Ready() pārbaudi. Pēc nākamās palaišanas Score jābūt 0 un HasKey — false; turpmāk punktus iegūs tikai spēlējot.
public override void _Ready()
{
    PickupType[] items = { PickupType.Coin, PickupType.Coin, PickupType.Key };
    foreach (PickupType item in items)
        OnPickup(item);

    if (HasKey)
        GD.Print("Atslēga ir — finišu varēs atvērt.");
    else
        GD.Print("Vēl jāatrod atslēga.");
}

Gatavs, kad: cikls ir pārbaudīts ar 3 un 4 elementiem, bet pārbaudes priekšmeti vairs netiek piešķirti, sākot spēli.

Papildu uzdevums — sasaisti priekšmetus ar stāstu

README.md apraksti, ko tavā pasaulē nozīmēs Coin, Gem un Key: piemēram, sēklas, reta puķe un meža vārtu atslēga. Koda enum nosaukumus pagaidām saglabā; izskatu un spēlētājam redzamos nosaukumus var mainīt.
