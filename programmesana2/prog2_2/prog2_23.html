2.3 Punkti un atslēga

Stundas uzdevums: Pievieno punktus un atslēgu. Rezultātus pārbaudi Godot Output (izdrukām) panel (panelī).

SR 2.4.14. Control structure (vadības struktūras) SR 2.4.13. Variable (mainīgie)

80 min plāns: Ievads (~10 min) · condition (nosacījumi) (~20 min) · priekšmetu logic (loģika) (~25 min) · loop (cikla) pārbaude (~20 min) · save (saglabāšana) (~5 min).

Pirms sāc: turpini 2.2 project (projekta) Player.cs. Šodien priekšmetus pārbaudīsim ar code (kodu); nākamajā stundā tos savāksim spēlē. Kustības code (kods) paliek tajā pašā file (failā).

Pēc izmaiņām: saglabā file (failus). Ja mainīji C# code (kodu), Godot augšējā labajā stūrī nospied Build (būvēt projektu) (āmura icon (ikona)). Tad palaid spēli. Pirms nākamā uzdevuma izlabo pirmo parādīto kļūdu.

Rezultātu skaties Output (izdrukām) panel (panelī)

Šodien rediģēsi Player.cs, bet rezultātu lasīsi Godot window (loga) apakšā: atver Output (izdrukām). Priekšmetus spēles laukumā pievienosim nākamajā stundā.

Code (kodā) if (nosacījuma pārbaude) nozīmē “ja”, else (pretējais gadījums) — “citādi”. Ar switch (izvēle pēc vērtības) izvēlamies, ko dod katrs priekšmets. Ar foreach (katra elementa cikls) pārbaudām priekšmetus pa vienam.

_Ready() darbojas vienu reizi spēles sākumā. Tur ievietosim īsas pārbaudes un pēc tam tās izdzēsīsim.

1. uzdevums -

Palaid spēli un izlasi trīs dažādas ziņas

  1. FileSystem (failu sistēma) → Scripts (skripti) atver Player.cs. Pirms file (faila) pēdējās } pievieno zemāk doto pagaidu _Ready() daļu.
  2. Atstāj health = 100. Saglabā, Godot nospied Build (būvēt projektu) un F5. Apakšā atver Output (izdrukām): tur jābūt ziņai “Viss kārtībā”.
  3. Apturi ar F8. Maini health uz 20, saglabā, nospied Build (būvēt projektu) un palaid vēlreiz. Atkārto ar 0. README.md katram skaitlim pieraksti parādīto ziņu.
  4. Pēc pārbaudes izdzēs visu tikko pievienoto _Ready() daļu. Kustības code (kodu) saglabā.
public override void _Ready()
{
    int health = 100;
    if (health <= 0)
        GD.Print("Spēle beigusies");
    else if (health < 30)
        GD.Print("Uzmanību!");
    else
        GD.Print("Viss kārtībā");
}

Gatavs, kad: 100 dod “Viss kārtībā”, 20 — brīdinājumu un 0 — “Spēle beigusies”.

2. uzdevums -

Pievieno spēlētājam punktus un atslēgu

  1. Atver zemāk esošo pilno Player.cs un ar to aizstāj esošā file (faila) saturu. Tajā ir saglabāta kustība un pievienota punktu skaitīšana.
  2. Atrodi Score — punktu skaitu — un HasKey — vai atslēga jau iegūta. true (patiess) nozīmē “jā”, false (aplams) — “nē”.
  3. Atrodi OnPickup. Zem katra case (izvēles gadījums) redzams rezultāts: Coin dod 1 punktu, Gem — 5, Key piešķir atslēgu. PickupType file (faila) sākumā ir šo trīs priekšmetu nosaukumu list (saraksts).
  4. Saglabā, nospied Build (būvēt projektu) un palaid ar F5. Pārbaudi, ka varonis vēl kustas. Punktu ziņas parādīsies nākamajā uzdevumā.
2.3 Player.cs — pilns file (fails) salīdzināšanai

Lejupielādēt Player.cs. Atver esošo tāda paša nosaukuma file (failu) un aizstāj tā saturu ar šo code (kodu).

using Godot;

public enum PickupType { Coin, Gem, Key }

public partial class Player : CharacterBody2D
{
    [Export] public float Speed = 300.0f;

    public int Score { get; private set; } = 0;
    public bool HasKey { get; private set; } = false;
    public bool IsActive { get; set; } = true;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 direction = Vector2.Zero;
        if (Input.IsActionPressed("move_left")) direction.X -= 1;
        if (Input.IsActionPressed("move_right")) direction.X += 1;
        if (Input.IsActionPressed("move_up")) direction.Y -= 1;
        if (Input.IsActionPressed("move_down")) direction.Y += 1;

        Velocity = direction.Normalized() * Speed;
        MoveAndSlide();
    }

    public void OnPickup(PickupType type)
    {
        if (!IsActive) return;

        switch (type)
        {
            case PickupType.Coin:
                Score += 1;
                break;
            case PickupType.Gem:
                Score += 5;
                break;
            case PickupType.Key:
                HasKey = true;
                break;
        }

        GD.Print($"Punkti: {Score}; atslēga: {HasKey}");
    }
}

Gatavs, kad: Build (būvēt projektu) neparāda kļūdas un varonis joprojām kustas.

3. uzdevums -

Pārbaudi punktus Output (izdrukām) panel (panelī)

  1. Player.cs pirms pēdējās } uz laiku pievieno zemāk doto _Ready() daļu. Tā izmēģinās divas monētas un atslēgu.
  2. Saglabā, nospied Build (būvēt projektu) un F5. Atver Output (izdrukām): pēdējā punktu ziņā jābūt 2 punktiem un atslēga: True.
  3. Apturi spēli. Rindā PickupType[] items pirms }; pievieno , PickupType.Gem. Saglabā, nospied Build (būvēt projektu) un palaid atkal. Tagad jābūt 7 punktiem un atslēgai.
  4. Uzņem Output (izdrukām) screenshot (ekrānuzņēmumu). Izdzēs visu pagaidu _Ready() daļu. Saglabā, nospied Build (būvēt projektu) un palaid atkal: pārbaudes ziņām vairs nav jāparādās. Nākamajā stundā punktus iegūsi, savācot priekšmetus spēlē.
public override void _Ready()
{
    PickupType[] items = { PickupType.Coin, PickupType.Coin, PickupType.Key };
    foreach (PickupType item in items)
        OnPickup(item);

    if (HasKey)
        GD.Print("Atslēga ir — finišu varēs atvērt.");
    else
        GD.Print("Vēl jāatrod atslēga.");
}

Gatavs, kad: Output (izdrukām) esi redzējis 2 un 7 punktus, pēc tam izdzēsis pagaidu pārbaudi.

Papildu uzdevums — sasaisti priekšmetus ar stāstu

README.md apraksti, ko tavā pasaulē nozīmēs Coin, Gem un Key: piemēram, random seed (sēklas), reta puķe un meža vārtu atslēga. Nosaukumus Coin, Gem un Key code (kodā) pagaidām saglabā; izskatu un spēlētājam redzamos nosaukumus var mainīt.

Ko sagatavo

Stundas mērķis: code (kods) pareizi pieskaita punktus un atceras iegūto atslēgu.

GitHub repository (krātuvē) jābūt:

  1. Player.cs ar kustību un punktu skaitīšanu, bez pagaidu _Ready() pārbaudes.

Kā iesniedz: saglabā izmaiņas Git un nosūti tās uz GitHub tāpat kā 1. tēmā (commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi)). Skolotāja norādītajā vietā iesniedz GitHub repository (krātuves) link (saiti); README.md un pārbaudes pierādījumiem jābūt repository (krātuvē).
