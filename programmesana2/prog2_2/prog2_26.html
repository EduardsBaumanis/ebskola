2.6 Noslēguma projekts: Platformas spēle

Stundas uzdevums: Pabeigt izspēlējamu platformas spēli ar uzvaru, zaudējumu, atkārtotu spēli un savu dizainu un stāstu.

SR 2.4.1. Problēmas dekompozīcija SR 2.4.7. UI SR 2.4.14. Vadības struktūras SR 2.4.15. Modulāras programmas

80 min plāns: Kritēriji un spēles cikls (~10 min) · finišs un HUD (~25 min) · savs dizains un stāsts (~20 min) · spēles pārbaude pārī (~20 min) · iesniegšana (~5 min).

Pirms sāc: atver Level1.tscn no 2.5: Player lec, savāc punktus un atslēgu. Turpini šo pašu līmeni. Šīs stundas pamatdarbs ir viens pabeigts līmenis ar tavu dizainu un stāstu.

Darba ritms: pēc katra uzdevuma saglabā, nospied Build un pārbaudi rezultātu. Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Kas ir funkcionāla platformas spēle?

Spēlētājs redz vadību un mērķi, sāk līmeni, pārvar platformas, savāc priekšmetus un nonāk līdz skaidram iznākumam. Sasniedzot finišu ar atslēgu, parādās uzvara. Pieskaroties bīstamajai zonai vai izkrītot no laukuma — zaudējums. Ar R var sākt jaunu mēģinājumu ar atjaunotiem priekšmetiem un 0 punktiem.

Pamatprasības: viens līmenis, trīs sasniedzamas platformas, pieci punktu priekšmeti un atslēga, redzami punkti un atslēgas stāvoklis, bīstama zona, finišs, uzvara, zaudējums un atkārtota spēle. Ienaidnieki, dzīvību skaitītājs, taimeris un papildu līmeņi ir izvēles paplašinājumi.

Atbildības: Player.cs — kustība un savāktie priekšmeti; Pickup.cs — saskare un savākšana; Level.cs — mērķis, HUD, uzvara, zaudējums un restartēšana. Level skriptu piesaista līmeņa saknei; vienam līmenim Autoload nav vajadzīgs.

1. uzdevums -

Pabeidz spēles ciklu: finišs, zaudējums un R

  1. Atver esošo Level1. Pievieno saknes bērnu Area2D ar precīzu nosaukumu Finish, Position = (850,590). Pievieno CollisionShape2D ar RectangleShape2D Size = (48,100) un zaļu Polygon2D Visual: (-24,-50), (24,-50), (24,50), (-24,50).
  2. Pievieno otru saknes bērnu Area2D ar nosaukumu Hazard, Position = (440,625). Formas Size = (80,30); sarkanā Visual punkti (-40,-15), (40,-15), (40,15), (-40,15). Šo zonu var pārlēkt.
  3. Abām zonām iestati Layer tikai 3, Mask tikai 2, Monitoring = On. Tām ir savas CollisionShape2D formas. Kods signālus pieslēgs automātiski.
  4. Level1 saknei pievieno CanvasLayer ar nosaukumu HUD. Tam pievieno trīs Label bērnus: Instructions, Status, Message. Inspector Layout → Transform iestati Position attiecīgi (20,16), (20,48), (20,80), katram Size = (1240,48), Autowrap Mode = Word Smart un fonta izmēru 20.
  5. Level1 saknei pievieno res://Scripts/Level.cs ar pilno kodu zemāk. Player instances nosaukumam un HUD bērnu nosaukumiem precīzi jāsakrīt ar koku. Pārbaudi, ka Input Map ir restart → R.
  6. Build un F5. Izmēģini finišu bez atslēgas (parādās norāde), tad ar atslēgu (uzvara). Atsevišķā mēģinājumā pieskaries Hazard un citā izkrīti aiz grīdas malas (zaudējums). Pēc katra nospied R: līmenis pilnībā atjaunojas.

2.6 Level.cs — pilns fails salīdzināšanai

Lejupielādēt Level.cs. Aizstāj tikai atbilstošā faila saturu; neveido otru tāda paša nosaukuma klasi.

using Godot;

public partial class Level : Node2D
{
    [Export] public string GameTitle = "Bākas gaisma";
    [Export] public string Mission = "Atrodi dzelteno atslēgu un sasniedz zaļo bāku. Izvairies no sarkanās bedres!";
    [Export] public string WinText = "Bāka atkal spīd. Kuģi var atrast mājas!";
    [Export] public string LoseText = "Ceļojums pārtrūka. Mēģini vēlreiz!";
    [Export] public string LockedText = "Vispirms atrodi dzelteno atslēgu augšējā platformā.";

    private Player player;
    private Label status;
    private Label message;
    public bool GameEnded { get; private set; } = false;

    public override void _Ready()
    {
        player = GetNode<Player>("Player");
        status = GetNode<Label>("HUD/Status");
        message = GetNode<Label>("HUD/Message");
        GetNode<Label>("HUD/Instructions").Text =
            $"{GameTitle} | A/D vai ←/→: kustība | Space: lēciens | R: sākt no jauna";
        message.Text = Mission;
        GetNode<Area2D>("Finish").BodyEntered += OnFinishEntered;
        GetNode<Area2D>("Hazard").BodyEntered += OnHazardEntered;
        UpdateHud();
    }

    public override void _Process(double delta)
    {
        if (Input.IsActionJustPressed("restart"))
        {
            GetTree().ReloadCurrentScene();
            return;
        }

        if (!GameEnded && player.GlobalPosition.Y > 800)
            EndGame(false);

        UpdateHud();
    }

    private void UpdateHud()
    {
        string keyStatus = player.HasKey ? "ir" : "nav";
        status.Text = $"Punkti: {player.Score} | Atslēga: {keyStatus}";
    }

    private void OnFinishEntered(Node2D body)
    {
        if (body != player || GameEnded) return;

        if (player.HasKey)
            EndGame(true);
        else
            message.Text = LockedText;
    }

    private void OnHazardEntered(Node2D body)
    {
        if (body == player) EndGame(false);
    }

    private void EndGame(bool won)
    {
        if (GameEnded) return;
        GameEnded = true;
        player.IsActive = false;
        player.Velocity = Vector2.Zero;
        message.Text = (won ? WinText : LoseText) + " | Nospied R, lai spēlētu vēlreiz.";
        UpdateHud();
    }
}

Gatavs, kad: spēlei ir sākums, uzvara, divi zaudējuma veidi un atkārtota spēle. Pēc iznākuma varonis nekustas un jaunus punktus iegūt nevar.

Atbalsts: pilns piemēra projekts

Lejupielādēt piemēru (ZIP)

Ja esi iestrēdzis, izpako atsevišķā mapē, Godot .NET Project Manager izvēlies Import → project.godot, tad Build un F5. Piemēra .csproj ir sagatavots Godot 4.7.2 .NET un .NET 8. Ja skolā lieto citu Godot 4 .NET versiju, izveido tajā tukšu C# projektu un pārnes piemēra Scenes, Scripts un Input Map; saglabā savas versijas ģenerēto .csproj.

Salīdzini konkrēto nestrādājošo daļu ar savu projektu un izlabo to. Lejupielādētajā piemērā ir 2.5 pamatlēciens; savus ieviestos lēciena uzlabojumus saglabā. Piemēra gatavība neaizstāj tavas dizaina un stāsta izvēles. Piemēra palaišana un pārbaudes.

2. uzdevums -

Padari projektu par savu spēli

  1. Izvēlies nosaukumu un uzraksti trīs īsus teikumus: kas ir varonis, ko viņš vēlas un kāpēc tas ir svarīgi. Piemēram: “Mazs robots meklē enerģijas kodolu. Tam jāatjauno bāka. Bez gaismas kuģi nevar atrast mājas.” Izvēlies savu ideju.
  2. Pēc Build atlasi Level1 sakni. Inspector laukos Game Title, Mission, Win Text, Lose Text un Locked Text ieraksti sava stāsta nosaukumu, mērķi un iznākumus. Tie parādās pašā spēlē.
  3. Izmaini vismaz trīs vizuālus elementus: varoni, platformas vai fonu, savācamos, bīstamo zonu vai finišu. Vari zīmēt savus attēlus, veidot Polygon2D figūras vai izmantot atļautus resursus, README.md norādot autoru un licenci.
  4. Ja izmanto attēlu: importē PNG mapē Art, attiecīgajai scēnas saknei pievieno Sprite2D, Texture laukā ievelc attēlu, pielāgo tā Scale un paslēp veco Visual. Fizikas saknes Scale atstāj (1,1), CollisionShape2D pielāgo redzamajam izmēram. Saglabā saknes tipu, nosaukumu un skriptu.
  5. Sasaisti mehānikas ar stāstu: ko simbolizē punkti, atslēga, briesmas un finišs? Ja atslēga tagad ir enerģijas kodols, Level.cs UpdateHud redzamo vārdu “Atslēga” un spēles norādes nomaini atbilstoši. HasKey un PickupType.Key var palikt kā tehniskie nosaukumi.
  6. Pārveido vismaz vienas platformas vai priekšmeta novietojumu atbilstoši savai iecerei un vēlreiz izspēlē visu ceļu. Saglabā salasāmu tekstu un viegli atšķiramu atlīdzību un apdraudējumu.

Gatavs, kad: spēlē redzams tavs nosaukums un stāsta mērķis, vismaz trīs vizuālas izmaiņas un savs pārbaudīts izkārtojuma risinājums. Izvēles vari pamatot.

3. uzdevums -

Dod klasesbiedram izspēlēt un novērs atrastās kļūdas

  1. Dod klasesbiedram spēli bez mutiskiem norādījumiem. Viņam vadība un mērķis jāatrod spēles logā. Pieraksti vienu neskaidrību un vienu veiksmīgu dizaina izvēli.
  2. Veic visus zemāk norādītos testus. README.md pieraksti sagaidāmo un faktisko rezultātu, kā arī veikto labojumu, ja pārbaude neizdodas.
  3. Pēc dizaina izmaiņām pārbaudi sadursmju formas, atslēgas sasniedzamību, teksta salasāmību un finiša atpazīstamību. Salabo vismaz vienu atrasto problēmu vai īsteno testētāja ieteikumu.
  4. Saglabā visu projektu un pārbaudi to no atsevišķas kopijas bez .godot mapes: Import, Build, F5. Tas atklāj trūkstošus attēlus vai nepareizus ceļus.
  5. Ieraksti īsu demonstrāciju: mērķis un tavs dizains, priekšmeta savākšana, zaudējums un R, pēc tam atslēgas savākšana un uzvara. Saglabā Git un iesniedz krātuves saiti.

Papildu uzdevums — izvēlies vienu paplašinājumu pēc pamatspēles pabeigšanas

Vari pievienot animētu varoni, skaņas, 2.5 stundas lēciena toleranci vai vēl vienu līmeni. Izvēlies to, kas palīdz tavam stāstam, un pārbaudi, ka pamatspēle joprojām darbojas.

Otram līmenim saglabā Level1 kopiju kā Level2.tscn, saglabājot Level skriptam vajadzīgos mezglu nosaukumus, un izveido jaunu maršrutu. Vispirms izspēlē katru līmeni atsevišķi. Pārejai jānorāda precīzs scēnas ceļš, un tā jāizpilda ārpus fizikas signāla, piemēram, pēc uzvaras ar atsevišķu taustiņu _Process metodē. Izlem, vai punkti ir katram līmenim atsevišķi; kopējam rezultātam būs vajadzīga atsevišķa stāvokļa glabāšana. Šis paplašinājums nav pamatdarba iesniegšanas prasība.

6. stundas apkopojums: tava spēle, tavs dizains un stāsts

Vienādas programmēšanas prasmes var radīt ļoti atšķirīgas spēles. Tu pats izvēlies varoni, pasauli, krāsas, priekšmetu nozīmi, platformu izkārtojumu un piedzīvojuma noslēgumu. Piemēra bāka un atslēga ir sākumpunkts; tavs projekts var stāstīt pavisam citu stāstu.

Apkopojumā parādi, kā tava ideja ir redzama pašā spēlē: sākuma mērķī, vizuālajā noformējumā, līmeņa ceļā un uzvaras tekstā. Paskaidro vismaz trīs dizaina izvēles un to, kā tās palīdz spēlētājam saprast pasauli vai uzdevumu.

Pašvērtējums: vai svešs spēlētājs saprot mērķi? Vai var iziet līmeni un mēģināt vēlreiz? Kura dizaina vai stāsta izvēle padara projektu par tavu? Ko mainīji pēc klasesbiedra pārbaudes?

Ko sagatavo

Stundas mērķis: ir funkcionāla platformas spēle ar personisku dizainu un stāstu, kuru var patstāvīgi izspēlēt cits cilvēks.

GitHub krātuvē jābūt:

  1. Pilns projekts ar scēnām, Player.cs, Pickup.cs, Level.cs un izmantotajiem attēliem.
  2. README.md: nosaukums, stāsta trīs teikumi, vadība, uzvaras/zaudējuma nosacījumi un palaišanas norādes ar Godot .NET versiju.
  3. Trīs pamatotas vizuālā dizaina izvēles, sava līmeņa izkārtojuma apraksts un izmantoto ārējo resursu avoti/licences.
  4. Aizpildītas pamatpārbaudes, klasesbiedra atsauksme, veiktais uzlabojums un demonstrācijas video vai saite uz to.

Saglabā visu projektu: project.godot, .csproj, scēnas, skriptus un izmantotos attēlus. .gitignore ieraksti .godot/, bin/ un obj/ katru savā rindā.

Kā iesniedz: veic commit un push. Skolotāja norādītajā vietā iesniedz GitHub krātuves saiti; README.md un pārbaudes pierādījumiem jābūt krātuvē.
