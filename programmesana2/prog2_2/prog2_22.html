2.2 Input apstrāde un Input Map

Stundas uzdevums: Konfigurēt Input Map un izveidot WASD/bultiņu vadāmu spēlētāju.

SR 2.4.14. Vadības struktūras SR 2.4.7. UI

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - izveido Input Map darbības · 2. uzdevums (~25 min) - vadi objektu ar taustiņiem · 3. uzdevums (~20 min) - normalizē diagonālo kustību · Iesniegšana (~5 min).

Pirms sāc: atver savu projektu ar Mover klasi no 2.1 stundas. Šodien objektu vadīsi tu pats, nevis tas kustēsies pats.

Teorija: Input pārvaldība Godot

Godot piedāvā divus veidus apstrādāt input:

  • Polling (aptauja) - Input::is_action_pressed("move_right") katrā kadrā pārbauda stāvokli.
  • Events (notikumi) - _input(Ref<InputEvent> event) reaģē uz konkrētu notikumu.

Spēļu kustībai parasti lieto polling (jo notiek katrā kadrā).

#include <godot_cpp/classes/input.hpp>

void Player::_physics_process(double delta) {
    Input *input = Input::get_singleton();
    Vector2 movement = Vector2(0, 0);

    if (input->is_action_pressed("move_right")) movement.x += 1;
    if (input->is_action_pressed("move_left"))  movement.x -= 1;
    if (input->is_action_pressed("move_up"))    movement.y -= 1;
    if (input->is_action_pressed("move_down"))  movement.y += 1;

    movement = movement.normalized();  // diagonāles ātrums = taisns ātrums
    velocity = movement * speed;
    move_and_slide();
}

Input Map definē abstraktas darbības (move_right) un saista tās ar konkrētiem taustiņiem. Project Settings → Input Map.

Kā šo izmantot projektā

Atceries: ar redzamu efektu editorā nepietiek. Paskaidro, kura C++ klase glabā stāvokli, kura metode to maina un kā Godot node struktūra izmanto šo kodu.

Pārbaudi: spēlētājs, objekti un sadursmes darbojas ar C++ klasēm, kas lieto _physics_process, Input, CharacterBody2D, Area2D vai move_and_slide.

Praktiskie uzdevumi

1. uzdevums - Izveido Input Map darbības

Beigās taustiņi būs pieteikti ar saprotamiem nosaukumiem, nevis kodiem.

  1. Atver Project -> Project Settings -> Input Map.
  2. Ieraksti jaunas darbības nosaukumu move_right un nospied Add.
  3. Nospied pluszīmi pie darbības un piesaisti taustiņu D.
  4. Izveido tāpat move_left, move_up un move_down.
  5. Piesaisti katrai arī atbilstošo bultiņu taustiņu, lai būtu divi varianti.
  6. Aizver iestatījumus un saglabā projektu.
  7. Pieraksti, kāpēc labāk lietot nosaukumu, nevis taustiņa kodu.

Gatavs, kad: Input Map sarakstā ir četras darbības, un katrai piesaistīti divi taustiņi.

2. uzdevums - Vadi objektu ar taustiņiem

Beigās objekts kustēsies tikai tad, kad tu turi taustiņu.

  1. Iekļauj C++ failā #include <godot_cpp/classes/input.hpp>.
  2. Paņem metodē Input *input = Input::get_singleton();.
  3. Izveido vektoru Vector2 dir(0, 0);.
  4. Pievieno if (input->is_action_pressed("move_right")) dir.x += 1;.
  5. Pievieno tādas pašas rindas pārējiem trim virzieniem.
  6. Pārvieto objektu ar set_position(get_position() + dir * speed * delta);.
  7. Kompilē, palaid un izmēģini visus četrus virzienus.

Gatavs, kad: objekts kustas visos četros virzienos un apstājas, tiklīdz atlaid taustiņu.

3. uzdevums - Normalizē diagonālo kustību

Beigās pa diagonāli objekts vairs nekustēsies ātrāk nekā taisni.

  1. Nospied vienlaikus divus taustiņus, piemēram D un S.
  2. Pieraksti README.md failā, vai objekts pa diagonāli kustas ātrāk.
  3. Izrēķini README.md failā vektora (1, 1) garumu.
  4. Pievieno kodā rindu dir = dir.normalized(); pirms pārvietošanas.
  5. Kompilē un pārbaudi diagonālo kustību vēlreiz.
  6. Pārbaudi, ka objekts joprojām stāv uz vietas, ja neviens taustiņš nav nospiests.
  7. Pieraksti README.md failā, ko dara normalized().

Gatavs, kad: pirms labojuma diagonālā kustība ir ~1.4 reizes ātrāka, pēc tā - vienāda ar taisno.

Papildu uzdevums - Pievieno skriešanas taustiņu

Ja pamatdarbs ir gatavs, ļauj objektam paātrināties.

  1. Izveido Input Map darbību run ar taustiņu Shift.
  2. Pievieno kodā mainīgo double current_speed = speed;.
  3. Reizini to ar 2, ja run ir nospiests.
  4. Kompilē un pārbaudi abus ātrumus.
  5. Pārliecinies, ka diagonālā kustība joprojām ir normalizēta.

Gatavs, kad: turot Shift, objekts kustas divreiz ātrāk visos virzienos.

Ko iesniedz skolotājam

Stundas mērķis: Tev ir izveidotas četras Input Map darbības, un C++ klase pārvieto objektu pēc taustiņiem tā, ka diagonālā kustība nav ātrāka par taisno.

Iesniedzamais:

  1. Ekrānuzņēmums ar Input Map sarakstu, kurā redzamas visas darbības.
  2. Fails ar tavu kustības kodu GitHub krātuvē.
  3. README.md: vektora (1, 1) garuma aprēķins un viens teikums, ko dara normalized().

Kā iesniedz: Veic commit un push, tad iesniedz krātuves saiti un ekrānuzņēmumu skolotāja norādītajā vietā.

Biežākās kļūdas

  • Spēlētājs nekustas: Input Map nav saglabāta vai darbība nepareizi nosaukta.
  • Diagonālais ātrums dubults: Aizmirsts .normalized().
  • Spēlētājs iet cauri sienām: Lieto move_and_slide(), ne set_position.
