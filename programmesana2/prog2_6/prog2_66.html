Teorija: datu modeļa un saskarnes nošķiršana pabeigtā lietotnē

Loģiskā datu modeļa un vizuālā attēlojuma atdalīšana

Interaktīvās režģa lietotnēs patieso sistēmas stāvokli neglabā ekrāna attēlu koordinātās, bet atsevišķā C# datu modelī (piemēram, int[,] rezgis). Tas darbojas gluži kā elektroniskā izklājlapa (Excel): ekrānā redzamā diagramma ir tikai tabulas skaitļu vizuāls atspoguļojums — lai mainītu rezultātu, pārbauda un izmaina skaitli šūnā, un attēlojums pārzīmējas pēc tā.

Katra lietotāja darbība iziet vienotu pārbaudes un atjaunošanas ciklu: ievades uztveršana → darbības atļautības pārbaude robežās → masīva datu maiņa → mērķa kritērija pārbaude → vizuālo mezglu, pāreju un skaņas atjaunošana:

private int[,] rezgis = new int[4, 4];
private int[,] merkaParaugs = new int[4, 4];

public bool MainitSunu(int x, int y, int jaunaVertiba)
{
    // 1. Pārbauda, vai koordinātas ir masīva robežās:
    if (x < 0 || x >= rezgis.GetLength(0) || y < 0 || y >= rezgis.GetLength(1))
        return false;

    // 2. Atjauno loģisko datu modeli un pārzīmē saskarni:
    rezgis[x, y] = jaunaVertiba;
    AtjaunotSkatu(x, y);

    // 3. Pārbauda, vai sasniegts meklētais gala stāvoklis:
    if (VaiMekletaisStavoklisSasniegts(rezgis, merkaParaugs))
        PazinotParPabeigsanu();

    return true;
}

private bool VaiMekletaisStavoklisSasniegts(int[,] dati, int[,] paraugs)
{
    for (int x = 0; x < dati.GetLength(0); x++)
        for (int y = 0; y < dati.GetLength(1); y++)
            if (dati[x, y] != paraugs[x, y]) return false;

    return true; // Visas šūnas sakrīt ar mērķa stāvokli.
}

Programmatūras izstrādes cikls: no prototipa līdz dokumentētam laidienam

Apjomīgāka projekta izstrādi plāno ar problēmas dekompozīciju un iteratīvu prototipēšanu, sadalot darbu trīs secīgos slāņos:

  • Minimālais kodola prototips: vispirms vienā datu struktūrā pilnībā izstrādā un notestē galveno loģiku un robežnosacījumus nelielam datu apjomam, nevis paralēli iesāk vairākas nepabeigtas funkcijas.
  • Saskarnes un atgriezeniskās saites slānis: pārbaudītajam kodolam caur skaidrām metodēm un signāliem piesaista Control navigācijas skatus, Tween pārejas, AudioServer skaņas kopnes un user:// rezultātu saglabāšanu.
  • Kvalitātes pārbaude un dokumentēšana: pirms nodošanas pārbauda kompilēto darbvirsmas būvējumu ārpus izstrādes vides, apraksta uzbūvi un vadību README.md dokumentācijā un norāda izmantoto ārējo resursu licences.

Šāda slāņu atdalīšana C# kodā ļauj datu kodolu uzturēt un testēt neatkarīgi no ekrāna vadīklām:

// 1. slānis — tīrs C# datu kodols (neatkarīgs no ekrāna mezgliem un skaņas):
public class RezgjaModelis
{
    public int DarbibuSkaits { get; private set; }
    public bool LietotIzmainu(int x, int y) { DarbibuSkaits++; return true; }
}

// 2. slānis — Godot saskarnes mezgls, kas savieno kodolu ar skatu un audio:
public partial class DarbaSkats : Control
{
    private readonly RezgjaModelis modelis = new();

    private void KadNospiestaSuna(int x, int y)
    {
        if (!modelis.LietotIzmainu(x, y)) return;
        statusaUzraksts.Text = $"Darbības: {modelis.DarbibuSkaits}";
        klikskaAtskanotajs.Play();
    }
}

1. uzdevums

Izvēlies puzli un uztaisi laukumu

Kur strādāt: Plānu raksti README.md. Izveido Scenes/Puzzle.tscn ar Node2D sakni un piesaisti tai Scripts/PuzzleBoard.cs; šajā skriptā glabā grid, attēlo laukumu un apstrādā ievadi.

Beigās tev būs spēles laukums, ko var apskatīt un ar ko darboties.

  1. Izvēlies vienu variantu: Sokoban, Match-3, Tetris klons vai 4x4 mozaīka.
  2. Izveido README.md failā īsu laukuma plānu: kā izskatīsies laukums un kas ir uzvara.
  3. Izveido režģi ar int[,] grid = new int[Width, Height];.
  4. Attēlo režģi uz ekrāna ar TileMap (flīžu karte) vai ColorRect node.
  5. Pievieno vadību, kas maina režģa saturu.
  6. Palaid un pārbaudi, ka ekrāns atbilst režģa saturam.
  7. Pārliecinies, ka nevar izdarīt neatļautu gājienu.

Atjautības spēles žanru varianti izvēlei: (1) Sokoban — bīdi kastes uz mērķa vietām; (2) Match-3 — savieno 3+ vienādas krāsas figūras; (3) Tetris klons — krītošo bloku rindu aizpildīšana; (4) Sliding mozaīka — 4×4 bīdāmo lauciņu sakārtošana (vai cita līdzvērtīga režģa puzle).

Gatavs, kad: ekrānā redzamais laukums vienmēr atbilst režģa datiem, un neatļauts gājiens netiek pieņemts.

2. uzdevums

Uzraksti uzvaras noteikumu un līmeņus

Kur strādāt: IsSolved, gājienu skaitīšanu, līmeņa maiņu un restartu pievieno Scripts/PuzzleBoard.cs. Līmeņus glabā šajā failā vai izveido Data/levels.json un tajā pašā skriptā nolasi to; HUD un pogas veido Scenes/Puzzle.tscn.

Beigās spēli varēs pabeigt un pāriet uz nākamo līmeni.

  1. Uzraksti method private bool IsSolved(), kas pārbauda uzvaras nosacījumu.
  2. Izsauc to pēc katra gājiena.
  3. Parādi uzvaras paziņojumu, kad tas atgriež true (patiess).
  4. Izveido vismaz trīs līmeņus - vai nu failā, vai kodā.
  5. Ielādē nākamo līmeni pēc uzvaras.
  6. Pievieno gājienu skaitītāju un pogu Sākt no jauna.
  7. Izej visus trīs līmeņus pēc kārtas.

Gatavs, kad: visus trīs līmeņus var atrisināt, uzvara tiek atpazīta pareizi, un restarta poga strādā.

3. uzdevums

Pievieno izvēlni, skaņu un eksportē

Kur strādāt: Izmanto Scenes/Menu.tscn un Scripts/MainMenu.cs; Sākt pogai norādi res://Scenes/Puzzle.tscn. Skaņu un uzvaras animāciju izsauc Scripts/PuzzleBoard.cs, rezultātu saglabāšanu pievieno Scripts/SaveManager.cs; eksportu glabā build/.

Beigās tava spēle būs pabeigts, izdodams produkts.

  1. Pievieno sākuma izvēlni no 6.1 stundas.
  2. Pievieno skaņas efektu gājienam un uzvarai no 6.3 stundas.
  3. Pievieno animāciju uzvaras brīdim no 6.2 stundas.
  4. Saglabā labāko rezultātu ar 5.3 stundas SaveManager.
  5. Eksportē spēli kā darbvirsmas build pēc 6.5 stundas soļiem.
  6. Publicē ZIP arhīvu itch.io lapā un pārbaudi lejupielādi citā datorā.
  7. Veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi) ar visu projektu.

Pilna noslēguma projekta orientieri: sākuma izvēlne, iestatījumi un augstākie rezultāti (highscore + progress ar saglabāšanas sistēmu), vairāki secīgi līmeņi (sākot ar 3 līmeņiem pamatprasībā un paplašināmā variantā līdz 10 līmeņiem Sokoban vai endless režīmam Match-3 / Tetris), fona mūzika un skaņas efekti (SFX), Tween vai animāciju efekti, kā arī eksportēts darbvirsmas būvējums, kas publicēts lejupielādējamā itch.io lapā.

Gatavs, kad: spēle sākas ar izvēlni, skan skaņas, labākais rezultāts saglabājas, un publiskā lejupielādes saite strādā.

Papildu uzdevums - Pievieno padoma pogu

Kur strādāt: Padoma meklēšanas metodi, atlikušo padomu skaitu un pogas apstrādātāju pievieno Scripts/PuzzleBoard.cs. Pogu un skaitītāja tekstu izveido Scenes/Puzzle.tscn.

Ja pamatdarbs ir gatavs, palīdzi spēlētājam, kurš iestrēdzis.

  1. Uzraksti method, kas atrod vienu derīgu nākamo gājienu.
  2. Pievieno pogu Padoms, kas to izceļ uz ekrāna.
  3. Ierobežo padomu skaitu vienā līmenī.
  4. Parādi, cik padomu vēl atlicis.
  5. Pārbaudi, ka pēc padomu beigām poga vairs nedarbojas.

Gatavs, kad: padoma poga izceļ derīgu gājienu un pēc noteikta reižu skaita pārstāj darboties.

Paplašināts koda piemērs 
using Godot;
using System;
using System.Collections.Generic;

// Match-3 spēles core
public partial class Match3Board : Node2D
{
    private const int Width = 8;
    private const int Height = 8;
    private readonly int[,] grid = new int[Width, Height];
    private readonly Random rng = new();

    public void Initialize()
    {
        for (int x = 0; x < Width; x++)
            for (int y = 0; y < Height; y++)
                grid[x, y] = rng.Next(0, 5);  // 5 colors
    }

    public List<Vector2I> FindMatches()
    {
        List<Vector2I> matches = new();
        for (int x = 0; x < Width; x++)
        {
            for (int y = 0; y < Height - 2; y++)
            {
                if (grid[x, y] == grid[x, y + 1] && grid[x, y + 1] == grid[x, y + 2])
                {
                    matches.Add(new Vector2I(x, y));
                    matches.Add(new Vector2I(x, y + 1));
                    matches.Add(new Vector2I(x, y + 2));
                }
            }
        }
        // similarly for horizontal
        return matches;
    }

    public void ClearAndDrop(List<Vector2I> matches)
    {
        // mark cleared, gravity, refill
    }
}

Ko sagatavo

Stundas mērķis: Tev ir pabeigta un publicēta puzles spēle: strādājošs laukums, pareizi atpazīta uzvara, vismaz trīs atrisināmi līmeņi, sākuma izvēlne, skaņa, saglabāts labākais rezultāts un publiska lejupielādes saite.

GitHub krātuvē jābūt:

  • README.md ievietota publiskā lejupielādes saite uz spēli, kas strādā skolotāja datorā.
  • Viss pirmkods ar C# skriptiem, scēnām un projekta failiem.
  • README.md ievietota video saite, kurā izej vismaz vienu līmeni no sākuma izvēlnes līdz uzvarai.
  • Īss apraksts (5-8 teikumi): kuru puzli izvēlējies, kā darbojas uzvaras pārbaude, kas bija visgrūtāk un kā to atrisināji.

Kā iesniedz: Veic commit un push. Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • Build arhīvā trūkst failu: ZIP liec visu eksportēto mapi, ne tikai palaižamo failu.
  • Save fails neielādējas pēc eksportēšanas: Pārbaudi, vai tiek lietots user://, nevis projekta mape.
  • Vadība nav skaidra: Pievieno spēles lapā īsu taustiņu aprakstu un pārbaudi ar klasesbiedru.
