6.5 Eksports un publicēšana

Sasniedzamais rezultāts: Eksportēt Godot C# spēli darbvirsmas platformai un publicēt lejupielādējamu versiju internetā.

SR 2.4.6. Plāno izstrādes procesu SR 3.1.4. IP tiesības SR 2.3.1. Datorikas nozares attīstība padziļinātos projektos SR 2.3.2. Datorikas virzieni un profesijas SR 2.4.9. Versiju pārvaldība

Teorija: programmatūras būvēšana, eksportēšana un izplatīšana

No pirmkoda līdz patstāvīgam būvējumam (Export Presets un .pck)

Projekts izstrādes vidē ir kā konditorejas virtuve ar visām izejvielām un krāsnīm, turpretim eksportēts būvējums (build) ir gatavs, iepakots produkts, ko lietotājs var darbināt savā datorā bez Godot redaktora un C# kompilatora. Eksportēšanas laikā notiek trīs saistīti procesi:

  • C# kompilācija (dotnet build): visi .cs pirmkoda faili tiek pārbaudīti un kompilēti .NET binārajās bibliotēkās (.dll).
  • Resursu sapakošana (.pck): scēnas, attēli un skaņas no res:// tiek apvienoti vienotā, tikai lasāmā resursu pakotnē.
  • Platformas eksporta profils (Export Preset un Export Templates): gatavā pakotne tiek savienota ar izvēlētās operētājsistēmas izpildfailu (.exe Windows, .x86_64 Linux vai .app macOS vidē). Godot 4 .NET (C#) projektiem izmanto tieši šos darbvirsmas profilus, jo tīmekļa pārlūka eksports C# vidē netiek lietots.

Pēc eksportēšanas mērķa mapē izveidojas savstarpēji saistītu failu komplekts, kurā visi trīs elementi ir nepieciešami lietotnes darbināšanai:

build/
├── Lietotne.exe              # Izpildfails (Linux vidē: Lietotne.x86_64)
├── Lietotne.pck              # Sapakotie res:// resursi (scēnas, audio)
└── data_Lietotne_windows_x86_64/
    └── Lietotne.dll          # Kompilētais C# kods un .NET bibliotēkas

Pārbaude ārpus redaktora, versiju kontrole (.gitignore) un licences

Lai izplatāmā lietotne uzticami darbotos cita cilvēka datorā, ievēro trīs programmatūras inženierijas principus:

  • Pilna arhīva testēšana: izpildfails nevar darboties bez blakus esošā .pck faila un .NET pavadošajām bibliotēkām, tāpēc ZIP arhīvā iekļauj visu būvējuma mapes saturu un pirms publicēšanas to izpako atsevišķā mapē un pārbauda ar aizvērtu redaktoru.
  • Krātuves tīrība (.gitignore): Git versiju kontrole ir paredzēta cilvēka rakstītam pirmkodam un scēnu aprakstiem, nevis desmitiem megabaitu lieliem kompilētiem binārajiem failiem, tāpēc mapi build/ vienmēr iekļauj failā .gitignore.
  • Dokumentācija un autortiesības (IP rights): publiskojot programmu, pievieno skaidru palaišanas un vadības aprakstu, kā arī korekti norāda visu izmantoto trešo pušu resursu (skaņu, attēlu, fontu) autorus atbilstoši to licencei (piemēram, MIT, CC0 vai CC BY).

Minimāls .gitignore un resursu licenču norādes paraugs projekta saknes mapē:

# .gitignore — neiekļauj Git krātuvē ģenerētos un eksportētos failus:
.godot/
.mono/
build/
*.pck
# README.md — Izmantotie resursi un licences
- Saskarnes ikonas: "UI Pack" (autors: Kenney, licence: CC0 1.0)
- Fona ieraksts: "Ambient Loop" (autors: J. Bērziņš, licence: CC BY 4.0)

1. uzdevums

Sagatavo eksporta veidnes, .gitignore un eksportē spēli uz build/

Kur strādāt: Eksporta iestatījumus veido Godot izvēlnēs Editor -> Manage Export Templates un Project -> Export (kas izveido export_presets.cfg). Izveido mapi build/ un papildini projekta saknes failu .gitignore.

Beigās tavā datora mapē build/ būs pilns, patstāvīgi palaižams C# darbvirsmas būvējums, un lielie binārie faili nepiesārņos GitHub krātuvi.

  1. Pārbaudi galveno scēnu: atver Project -> Project Settings -> Application -> Run -> Main Scene un pārliecinies, ka tur ir norādīta res://Scenes/Menu.tscn.
  2. Kompilē C# projektu ar pogu Build Godot augšējā labajā stūrī vai terminālī ar komandu dotnet build un pārliecinies, ka nav kompilācijas kļūdu.
  3. Pārbaudi eksporta veidnes: atver Editor -> Manage Export Templates un, ja veidnes vēl nav uzinstalētas, nospied Download and Install (obligāti .NET versijai).
  4. Atver projekta saknes failu .gitignore un pievieno tam rindas build/ un *.zip, lai eksportētie izpildfaili netiktu sūtīti uz GitHub.
  5. Atver Project -> Export, nospied Add... un izvēlies savu operētājsistēmu (Windows Desktop, Linux vai macOS).
  6. Nospied Export Project..., projekta saknē izveido mapi build/, saglabā failu kā build/PuzzleGame.exe (vai build/PuzzleGame.x86_64 uz Linux) un nospied Save.
  7. Pārbaudi failu pārvaldniekā, ka mapē build/ ir izveidojies gan palaižamais fails, gan resursu pakotne PuzzleGame.pck, gan .NET bibliotēku mape data_PuzzleGame_*/.
# 1. Pārbaudi C# būvējumu terminālī:
dotnet build

# 2. Pievieno .gitignore failam rindas, lai binārie faili nenonāk GitHub:
build/
*.zip

Gatavs, kad: mapē build/ ir visi eksportētie faili (.exe/.x86_64, .pck un data_*/), un build/ ir ierakstīts .gitignore.

2. uzdevums

Pārbaudi build/ un ZIP arhīvu ārpus Godot redaktora

Kur strādāt: Arhivē mapi build/ failā PuzzleGame_Desktop.zip, izpako to atsevišķā testa mapē ārpus projekta un novērojumus ieraksti projekta saknes failā README.md.

Beigās tu būsi drošs, ka cits spēlētājs pēc ZIP arhīva izpakošanas varēs palaist spēli bez Godot redaktora un bez trūkstošām bibliotēkām.

  1. Aizver Godot redaktoru pilnībā, lai tests notiktu tieši tāpat kā spēlētāja datorā.
  2. Iezīmē visus failus un apakšmapes, kas atrodas iekš build/ (izpildfailu, .pck failu un data_PuzzleGame_*/ mapi), un saspied tos vienā arhīvā PuzzleGame_Desktop.zip.
  3. Nokopē un izpako PuzzleGame_Desktop.zip pilnīgi citā mapē (piemēram, uz darbvirsmas mapē TestRun/).
  4. Palaid izpakoto spēles failu un pārbaudi sākuma izvēlni, skaļuma slīdņus, pāreju uz spēles scēnu un iziešanas pogu.
  5. Uzņem ekrānuzņēmumu, kurā redzams darbojošais eksportētās spēles logs un blakus — izpakotās mapes failu saraksts.
  6. Pieraksti failā README.md: (a) kāpēc ZIP arhīvā nedrīkst likt tikai vienu pašu .exe failu bez .pck un data_*/ mapes; (b) kāpēc Godot 4 .NET C# projektam šajā kursā veidojam darbvirsmas būvējumu, nevis tīmekļa (HTML5) eksportu.

Gatavs, kad: no PuzzleGame_Desktop.zip izpakotā spēle bez kļūdām darbojas citā mapē ārpus Godot redaktora.

3. uzdevums

Publicē lejupielādējamu spēli vietnē itch.io

Kur strādāt: Vietnē itch.io augšupielādē PuzzleGame_Desktop.zip. Publisko saiti, vadības aprakstu un izmantoto resursu licences pievieno projekta saknes failam README.md.

Beigās tavai spēlei būs sava publiska lejupielādes lapa internetā ar ekrānuzņēmumiem, vadības aprakstu un korektām resursu licencēm.

  1. Pieslēdzies savam kontam vietnē itch.io un atver Dashboard -> Create new project.
  2. Ieraksti spēles nosaukumu (Title), bet laukā Kind of project izvēlies Downloadable (lejupielādējama programma).
  3. Nospied Upload files, augšupielādē savu PuzzleGame_Desktop.zip arhīvu un atzīmē platformas izvēles rūtiņu (Windows, Linux vai macOS).
  4. Augšupielādē lapas labajā pusē (Screenshots) vismaz divus spēles ekrānuzņēmumus un apraksta laukā (Description) ieraksti spēles mērķi, vadību un izmantoto resursu autorus un licences (piemēram, CC0 vai CC BY 4.0).
  5. Sadaļā Visibility & access izvēlies Public (vai Restricted / Unlisted, ja tā norādījis skolotājs) un nospied Save & view page.
  6. Iekopē izveidotās lapas publisko saiti un licenču sarakstu projekta failā README.md un pārbaudi, ka arhīvu no šīs saites var lejupielādēt.

Gatavs, kad: itch.io lapa ir atverama pēc saites no README.md, un lejupielādētais ZIP arhīvs palaiž spēli.

Papildu uzdevums - Pievieno pirmseksporta pašpārbaudes skriptu Scripts/ExportChecker.cs

Kur strādāt: Izveido skriptu Scripts/ExportChecker.cs un izsauc to no Scripts/MainMenu.cs vai pievieno kā bērna mezglu scēnā Scenes/Menu.tscn.

Ja pamatdarbs ir gatavs, pievieno kodā automātisku pārbaudi, kas konsolē izdrukā, vai visi eksportam vajadzīgie resursi un user:// saglabāšanas mape ir pieejami.

  1. Izveido Scripts/ExportChecker.cs (skat. pilno koda piemēru zemāk), kas pārbauda, vai eksistē res://Scenes/Menu.tscn un res://Scenes/Puzzle.tscn un vai var atvērt user:// mapi rakstīšanai.
  2. Pārbaudi ar OS.HasFeature("editor"), vai spēle pašlaik darbojas redaktorā vai eksportētā būvējumā, un parādi versijas uzrakstu izvēlnes apakšējā stūrī.
  3. Palūdz klasesbiedram lejupielādēt tavu itch.io arhīvu un izspēlēt spēli, balstoties tikai uz lapā uzrakstīto vadības aprakstu.

Gatavs, kad: izvēlnē redzams būvējuma režīms (Editor vai Release), un klasesbiedrs bez mutiskas priekšā teikšanas saprot vadību.

Pilnais koda un dokumentācijas piemērs — gatavs šīs stundas risinājums

1. fails: Scripts/ExportChecker.cs (pirmseksporta un vides pārbaudes komponents)

using Godot;

public partial class ExportChecker : Node
{
    public override void _Ready()
    {
        bool isEditor = OS.HasFeature("editor");
        bool hasMenuScene = ResourceLoader.Exists("res://Scenes/Menu.tscn");
        bool hasPuzzleScene = ResourceLoader.Exists("res://Scenes/Puzzle.tscn");
        bool canWriteUserDir = CheckUserDirWritable();

        GD.Print($"[ExportChecker] Platforma: {OS.GetName()} | Režīms: {(isEditor ? "Editor" : "Exported Build")}");
        GD.Print($"[ExportChecker] Menu.tscn: {hasMenuScene} | Puzzle.tscn: {hasPuzzleScene} | user:// rakstāms: {canWriteUserDir}");

        if (!hasMenuScene || !hasPuzzleScene || !canWriteUserDir)
        {
            GD.PrintErr("[ExportChecker] Uzmanību: kāda no eksporta prasībām nav izpildīta!");
        }
    }

    private bool CheckUserDirWritable()
    {
        const string testPath = "user://export_check.tmp";
        using FileAccess file = FileAccess.Open(testPath, FileAccess.ModeFlags.Write);
        if (file == null)
        {
            return false;
        }
        file.StoreLine("ok");
        return true;
    }
}

2. fails: README.md (paraugs publicētā projekta dokumentācijai un licencēm)

# Atjautības spēle (PuzzleGame) — Godot 4 .NET (C#)

## Lejupielāde (itch.io)
- Publiskā lapa: https://tavs-lietotajvards.itch.io/puzzlegame
- Platforma: Windows / Linux darbvirsmas būvējums (ZIP arhīvs)

## Kā palaist eksportēto spēli
1. Lejupielādē arhīvu `PuzzleGame_Desktop.zip`.
2. Izpako **visu** arhīva saturu vienā mapē (gan `.exe`/`.x86_64`, gan `.pck`, gan `data_PuzzleGame_*/` mapi).
3. Palaid `PuzzleGame.exe` (Windows) vai `PuzzleGame.x86_64` (Linux).

## Tehniskās piezīmes
- Godot 4 .NET (C#) projektiem šajā kursā veidojam darbvirsmas būvējumu, jo Godot 4 C# WebAssembly (HTML5) eksports nav pilnībā atbalstīts visās vidēs.
- Saglabāšanas dati tiek rakstīti `user://` mapē, jo eksportētā būvējumā `res://` ir iepakots `.pck` failā un ir tikai lasāms.

- Saskarnes un spēles kods: paša veidots Godot 4 C# projekts
- Skaņas efekti: ģenerēti programmiski / Kenney UI Audio (licence: CC0 1.0 Public Domain)
Pilna eksporta sagatavošana, user:// rakstāmības pārbaude un README.md dokumentācija ar itch.io saiti un licencēm.

Ko sagatavo

Stundas mērķis: Tava Godot 4 C# spēle ir eksportēta kā darbvirsmas programma mapē build/ (kas pievienota .gitignore), pārbaudīta no izpakota ZIP arhīva ārpus Godot redaktora un publicēta vietnē itch.io.

GitHub krātuvē jābūt:

  • Papildinātam .gitignore failam (ar build/ un *.zip) un README.md ar publisko saiti uz tavu spēli itch.io vietnē.
  • Ekrānuzņēmumam ar Godot Project -> Export logu un darbvirsmas profilu.
  • Ekrānuzņēmumam ar izpakoto spēli, kas darbojas ārpus Godot redaktora.
  • README.md skaidrojumam: kāpēc ZIP arhīvā jāiekļauj visi eksportētie faili (ne tikai .exe), kāpēc Godot 4 C# projektam veidojam darbvirsmas būvējumu un kādas licences ir izmantotajiem resursiem.

Kā iesniedz: Veic git commit un git push. Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • C# kods nav kompilēts: Pirms eksportēšanas nospied Godot Build vai palaid dotnet build.
  • Spēle nepalaižas: Pārliecinies, ka ZIP arhīvā ir visi eksportētie faili, ne tikai .exe.
  • Liels eksportēto failu izmērs: Samazini attēlu un skaņas failu izmērus.
