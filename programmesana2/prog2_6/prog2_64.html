6.4 Debugging (atkļūdošana) un profiling (profilēšana)

Sasniedzamais rezultāts: Apgūt Godot debugger (atkļūdotājs), breakpoints (pārtraukumpunkts), un izmantot to, lai atrastu bugs (kļūdas).

SR 2.4.10. Debugging SR 2.4.19. Algoritmi SR 2.4.5. Datu analīze un vizualizācija

Teorija: programmas atkļūdošana (Debugging) un veiktspējas profilēšana

Diagnostikas izdrukas (Output), pašpārbaudes un #if DEBUG

Kad programma uzvedas neparedzēti, pirmais solis ir padarīt tās iekšējo stāvokli redzamu. Godot Output panelī ziņojumus iedala trīs līmeņos: GD.Print(...) parastai vērtību izsekošanai, GD.PushWarning(...) dzeltenam brīdinājumam par aizdomīgiem datiem un GD.PrintErr(...) sarkanam kļūdas paziņojumam. Savukārt C# direktīva #if DEBUG ... #endif iekļauj diagnostikas izdrukas tikai izstrādes laikā, automātiski izslēdzot tās no gala laidiena:

if (datuAvots == null)
{
    GD.PrintErr("Kļūda: nepieciešamais mezgls nav atrasts!");
    return;
}
if (daudzums == 0)
{
    GD.PushWarning("Brīdinājums: saņemts tukšs datu apjoms.");
}
if (daudzums < 0)
{
    throw new System.InvalidOperationException("Daudzums nedrīkst būt negatīvs!");
}

#if DEBUG
GD.Print("Izsaukta metode: ", nameof(AtjaunotStavokli), ", pozīcija: ", Position);
#endif

Pārtraukumpunkti (Breakpoints), mainīgo steks un Profiler

Diagnostikas izdrukas ir kā atsevišķas iepriekš izliktas fotogrāfijas, turpretim atkļūdotājs (Debugger) ļauj apturēt programmu kā video ierakstu uz pauzes precīzā kadrā. Uzliekot koda rindai pārtraukumpunktu (breakpoint), izpilde tajā apstājas un atklāj pilnu ainu:

  • Stack Variables / Locals un Call Stack: parāda visu lokālo mainīgo un objekta lauku pašreizējās vērtības bez vienas pašas GD.Print rindas, kā arī metožu izsaukumu ķēdi, kas noveda līdz šai vietai; ar pogām Step Into un Step Over kodu var izpildīt soli pa solim.
  • Profiler, Visual Profiler un Network Profiler: mēra nevis pareizību, bet ātrumu — tabulā sakārto funkcijas pēc patērētā procesora laika (piemēram, salīdzinot _Process un _PhysicsProcess slodzi), kā arī vizualizē kadru aiztures un tīkla ziņojumu plūsmu.

Piemēram, klusām loģikas kļūdām (kur programma neavarē, bet atgriež neprecīzu skaitli) pārtraukumpunkts uzreiz atklāj cēloni izsaukumu ķēdē:

public void ApstradatIerakstus(int summa, int skaits)
{
    double vid = AprekinatVidejo(summa, skaits);
    GD.Print("Vidējā vērtība: ", vid);
}

private double AprekinatVidejo(int summa, int skaits)
{
    // <- Breakpoint šajā rindā:
    // Call Stack rāda: ApstradatIerakstus() -> AprekinatVidejo()
    // Locals atklāj: summa = 75, skaits = 20 (veselu skaitļu dalījums = 3!)
    return summa / skaits; // Labojums pēc pārbaudes: (double)summa / skaits
}

1. uzdevums

Atrodi un izlabo loģikas kļūdu ar GD.Print izdrukām

Kur strādāt: Izveido diagnostikas scēnu Scenes/DebugDemo.tscn ar Node sakni DebugDemo un piesaisti tai jaunu skriptu Scripts/DebugDemo.cs. Novērojumus pieraksti README.md.

Beigās tu pratīsi ar strukturētām GD.Print izdrukām pirms un pēc aprēķina precīzi lokalizēt loģikas kļūdu puzles punktu aprēķinā.

  1. Izveido scēnu res://Scenes/DebugDemo.tscn ar Node sakni DebugDemo un piesaisti tai skriptu res://Scripts/DebugDemo.cs (public partial class DebugDemo : Node).
  2. Uzraksti metodē CalculateLevelScore(int basePoints, int movesUsed, int penaltyPerMove) aprēķinu ar apzinātu zīmes kļūdu: int rawScore = basePoints + (movesUsed * penaltyPerMove); (kur par katru gājienu punkti kļūdaini pieaug, nevis samazinās).
  3. Izsauc CalculateLevelScore(1000, 12, 25) no _Ready() un izdrukā ievaddatus pirms aprēķina un rezultātu pēc aprēķina ar GD.Print(...).
  4. Nospied Build, palaid Scenes/DebugDemo.tscn (F6) un apskati Output panelī izdrukātās vērtības (gaidīto 700 vietā parādās 1300).
  5. Salabo aprēķina rindu uz int rawScore = Math.Max(0, basePoints - (movesUsed * penaltyPerMove)); un pārbaudi, ka Output panelī parādās pareizais rezultāts 700.
  6. Pieraksti failā README.md, kura koda rinda saturēja apzināto kļūdu un kā izdrukas pirms un pēc aprēķina palīdzēja to pamanīt.
public int CalculateLevelScore(int basePoints, int movesUsed, int penaltyPerMove)
{
    GD.Print($"[Pirms aprēķina] basePoints={basePoints}, movesUsed={movesUsed}, penalty={penaltyPerMove}");
    int finalScore = Math.Max(0, basePoints - (movesUsed * penaltyPerMove));
    GD.Print($"[Pēc aprēķina] finalScore={finalScore}");
    return finalScore;
}

Gatavs, kad: pēc Output izdrukām ir atrasta un izlabota aprēķina rinda un apraksts pievienots README.md.

2. uzdevums

Apturi izpildi ar Breakpoint un izpēti mainīgo skatu

Kur strādāt: Pārtraukumpunktu (Breakpoint) uzliec failā Scripts/DebugDemo.cs uz aprēķina rindas metodē CalculateLevelScore(). Novērojumus un ekrānuzņēmumu pievieno README.md.

Beigās tu pratīsi apturēt spēles izpildi jebkurā koda rindā un nolasīt visus lokālos mainīgos un izsaukumu steku bez papildu GD.Print rakstīšanas.

  1. Atver failu Scripts/DebugDemo.cs un uzklikšķini pa kreisi no rindas numura pie int finalScore = ..., lai parādītos sarkans pārtraukumpunkts (Breakpoint).
  2. Palaid scēnu Scenes/DebugDemo.tscn atkļūdošanas režīmā un sagaidi, līdz izpilde apstājas uz iezīmētās rindas.
  3. Atver apakšējo paneli Debugger un apskati izsaukumu steku (Stack Frames / Call Stack) un lokālo mainīgo sarakstu (Stack Variables / Locals).
  4. Nospied pogu Step Over (vai Step Into), lai izpildītu vienu koda rindu uz priekšu, un vēro, kā mainīgajam finalScore parādās aprēķinātā vērtība.
  5. Uzņem ekrānuzņēmumu, kurā redzama apturētā koda rinda un Debugger mainīgo panelis, un saglabā to krātuvē.
  6. Pieraksti failā README.md, kādas vērtības redzēji mainīgajiem basePoints, movesUsed un finalScore un kurās situācijās Breakpoint ir ērtāks par GD.Print.

Gatavs, kad: programma apstājas pie Breakpoint, mainīgo vērtības ir nolasītas un ekrānuzņēmums saglabāts krātuvē.

3. uzdevums

Analizē izpildes laiku ar Debugger -> Profiler

Kur strādāt: Izmanto Scenes/DebugDemo.tscn (vai Scenes/Menu.tscn) un Godot apakšējo paneli Debugger -> Profiler. Rezultātus un ekrānuzņēmumu dokumentē README.md.

Beigās tu zināsi, kā ar profilētāju izmērīt kadra laiku (Frame Time) un atrast metodes, kas patērē visvairāk procesora laika.

  1. Atver Godot apakšējā panelī cilni Debugger -> Profiler un nospied pogu Start.
  2. Palaid spēli (F5 vai F6) un ļauj tai darboties vismaz 15–30 sekundes (spied pogas vai ļauj izpildīties kadra ciklam).
  3. Apturi mērīšanu ar Stop, uzklikšķini uz grafika un sakārto sarakstu pēc patērētā laika (Time / Self Time).
  4. Salīdzini kopējo kadra laiku (Frame Time), Process Time un Physics Time.
  5. Uzņem ekrānuzņēmumu ar Profiler tabulu un grafiku un pievieno to krātuvei.
  6. Pieraksti failā README.md trīs rādītājus vai metodes no profilētāja saraksta un vienu konkrētu optimizācijas likumu (piemēram: saglabāt GetNode atsauces laukā _Ready() metodē, nevis meklēt mezglus katrā _Process() kadrā).

Gatavs, kad: krātuvē ir Profiler ekrānuzņēmums un README.md ir aprakstīti trīs profilētāja mērījumi un viena optimizācijas ideja.

Papildu uzdevums - Pievieno mezglu pašpārbaudi ar GetNodeOrNull un GD.PrintErr

Kur strādāt: Papildini Scripts/DebugDemo.cs (vai Scripts/MainMenu.cs) metodi _Ready() ar GetNodeOrNull drošības pārbaudi un GD.PrintErr kļūdas ziņojumu.

Ja pamatdarbs ir gatavs, iemāci savam skriptam pašam skaidri paziņot par trūkstošu scēnas mezglu, nevis avarēt ar NullReferenceException.

  1. Pievieno metodē _Ready() pārbaudi ar Node optionalNode = GetNodeOrNull<Node>("AudioManager");.
  2. Ja atsauce ir null, izdrukā kļūdas ziņojumu ar GD.PrintErr($"[{Name}] Brīdinājums: mezgls 'AudioManager' nav atrasts scēnā!");.
  3. Palaid scēnu un apskati Debugger -> Errors cilni un sarkano GD.PrintErr ierakstu Output konsolē.
  4. Pieraksti README.md, ar ko GD.PrintErr un GD.PushWarning atšķiras no parastā GD.Print.

Gatavs, kad: trūkstoša mezgla gadījumā Output un Debugger -> Errors parāda skaidru sarkanu ziņojumu bez spēles avārijas.

public partial class DebugDemo : Node

        GD.Print($"1. līmeņa rezultāts: {score1}, 2. līmeņa rezultāts: {score2}");
    }

    public int CalculateLevelScore(int basePoints, int movesUsed, int penaltyPerMove)
    {
        if (movesUsed < 0)
        {
            GD.PrintErr($"Nepareizs gājienu skaits: {movesUsed}. Vērtībai jābūt >= 0!");

        // Izlabotā formula (iepriekš kļūdaini bija '+' zīme '-' vietā)

#if DEBUG

Ko sagatavo

Stundas mērķis: Tu proti atrast kļūdu un novērtēt veiktspēju trīs veidos: ar strukturētām GD.Print / GD.PrintErr izdrukām, ar Breakpoint un mainīgo skatu, kā arī ar Debugger -> Profiler.

GitHub krātuvē jābūt:

  • Skriptam Scripts/DebugDemo.cs un scēnai Scenes/DebugDemo.tscn.
  • Ekrānuzņēmumam ar Debugger paneli, kurā izpilde ir apturēta Breakpoint vietā un redzamas mainīgo vērtības.
  • Ekrānuzņēmumam ar Debugger -> Profiler sarakstu un grafiku.
  • README.md atbildēm: kura koda rinda saturēja apzināti ieviesto kļūdu un kā to atradi, kā arī trīs profilētāja rādītājiem un vienai veiktspējas uzlabojuma idejai.

Kā iesniedz: Veic git commit un git push. Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Ja kaut kas nestrādā

  • Breakpoint nestrādā: Palaid projektu no Godot .NET debug režīmā un pārliecinies, ka C# projekts ir uzbūvēts bez kļūdām.
  • Print panelis pārplūst: Pārāk daudz print - lieto conditional vai noņem.
  • Profiler crashes: Pārliecinies par jaunāko Godot versiju.
