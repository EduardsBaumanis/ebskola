6.4 Atkļūdošana un profilēšana

Stundas uzdevums: Apgūt Godot debugger, breakpoints, un izmantot to, lai atrastu bugs.

SR 2.4.10. Atkļūdošana SR 2.4.19. Algoritmi SR 2.4.5. Datu analīze un vizualizācija

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - atrodi kļūdu ar izdrukām · 2. uzdevums (~25 min) - lieto breakpoint un mainīgo skatu · 3. uzdevums (~20 min) - atrodi lēnāko vietu ar profileri · Iesniegšana (~5 min).

Pirms sāc: atver savu spēli. Šodien apzināti salauzīsi kodu un tad mācīsies to atrast - tā ir prasme, ko vajadzēs katrā projektā.

Teorija: Debugger un profileris

Godot piedāvā vairākus rīkus problēmu atrašanai:

  • Output panel - print() un printerr() ziņojumi.
  • Debugger - breakpoints, step through, watch variables.
  • Profiler - funkciju laika analīze.
  • Network Profiler - RPC un networking.
  • Visual Profiler - vizuāls diagrammu uzziņa.
// Debugging C++ kodā
UtilityFunctions::print("Player position: ", get_position());
UtilityFunctions::printerr("Error: enemy is null!");
UtilityFunctions::push_warning("Suspicious value: ", value);

// Asserts
ERR_FAIL_NULL_MSG(player, "Player not found!");
ERR_FAIL_COND_MSG(hp < 0, "Negative HP!");

// Stack trace dump (debug builds)
#ifdef DEBUG_ENABLED
WARN_PRINT("Function called: " + String(__FUNCTION__));
#endif

Kā šo izmantot projektā

Atceries: ar redzamu efektu editorā nepietiek. Paskaidro, kura C++ klase glabā stāvokli, kura metode to maina un kā Godot node struktūra izmanto šo kodu.

Pārbaudi: UI signāli, audio darbības, debug izvade un publicēšanas sagatave ir sasaistīta ar C++ spēles stāvokli.

Praktiskie uzdevumi

1. uzdevums - Atrodi kļūdu ar izdrukām

Beigās tu pratīsi atrast, kurā vietā vērtība kļūst nepareiza.

  1. Ievies savā kodā apzinātu kļūdu, piemēram nomaini + uz -.
  2. Palaid spēli un pieraksti, kas izskatās nepareizi.
  3. Pievieno UtilityFunctions::print("pozicija: ", get_position()); pirms aprēķina.
  4. Pievieno tādu pašu izdruku pēc aprēķina.
  5. Palaid un salīdzini abas vērtības.
  6. Atrodi pēc izdrukām precīzo rindu, kur vērtība kļūst nepareiza.
  7. Salabo kļūdu un izdzēs izdrukas.

Gatavs, kad: tu vari nosaukt konkrētu rindu, kurā vērtība kļuva nepareiza, un kļūda ir izlabota.

2. uzdevums - Lieto breakpoint un mainīgo skatu

Beigās tu pratīsi apturēt spēli un apskatīt visus mainīgos uzreiz.

  1. Atver cilni Debugger.
  2. Uzliec breakpoint uz vienas koda rindas, uzklikšķinot rindas numura kreisajā malā.
  3. Palaid spēli un pagaidi, līdz tā apstājas.
  4. Apskati panelī Stack Variables visu mainīgo vērtības.
  5. Nospied Step Into un vēro, kā izpilde iet pa vienai rindai.
  6. Pieraksti, kāda vērtība bija tavam galvenajam mainīgajam.
  7. Pieraksti, kad breakpoint ir ērtāks par izdrukām.

Gatavs, kad: spēle apstājas norādītajā rindā, un tu vari nolasīt mainīgo vērtības, tās neizdrukājot.

3. uzdevums - Atrodi lēnāko vietu ar profileri

Beigās tu zināsi, kura funkcija patērē visvairāk laika.

  1. Atver Debugger -> Profiler un nospied Start.
  2. Spēlē 30 sekundes ar aktīvu spēli.
  3. Aptur profileri un sakārto sarakstu pēc laika.
  4. Pieraksti trīs funkcijas, kas aizņem visvairāk laika.
  5. Pārbaudi, vai kāda no tām tiek izsaukta biežāk, nekā vajadzētu.
  6. Salīdzini _process un _physics_process kopējo laiku.
  7. Pieraksti vienu ideju, ko varētu uzlabot.

Gatavs, kad: tev ir pierakstītas trīs laikietilpīgākās funkcijas un viena konkrēta uzlabojuma ideja.

Papildu uzdevums - Pievieno pašpārbaudes izdrukas

Ja pamatdarbs ir gatavs, liec kodam pašam brīdināt par kļūdām.

  1. Pievieno pārbaudi, vai svarīgs mezgls tiešām tika atrasts.
  2. Izdrukā UtilityFunctions::printerr("Nav atrasts mezgls!");, ja tas ir nullptr.
  3. Pārsauc mezglu scēnā un palaid spēli.
  4. Pieraksti, ar ko sarkanā printerr izdruka atšķiras no parastās.
  5. Atgriez nosaukumu un pārbaudi, ka brīdinājums pazūd.

Gatavs, kad: pārsaucot mezglu, konsolē parādās sarkans brīdinājums, nevis spēle klusi avarē.

Ko iesniedz skolotājam

Stundas mērķis: Tu proti atrast kļūdu trīs veidos: ar izdrukām, ar breakpoint un mainīgo skatu, un ar profileri atrast laikietilpīgāko funkciju.

Iesniedzamais:

  1. Ekrānuzņēmums ar Debugger paneli, kurā spēle apturēta breakpoint vietā un redzami mainīgie.
  2. Ekrānuzņēmums ar profilera sarakstu, sakārtotu pēc laika.
  3. Burtnīcā: kura rinda saturēja apzināti ievesto kļūdu un kā tu to atradi.
  4. Burtnīcā: trīs laikietilpīgākās funkcijas un viena uzlabojuma ideja.

Kā iesniedz: Iesniedz abus ekrānuzņēmumus un burtnīcas fotogrāfiju skolotāja norādītajā vietā.

Biežākās kļūdas

  • Breakpoint nestrādā: Debug build trūkst - kompilē ar scons target=template_debug.
  • Print panel pārplūst: Pārāk daudz print - lieto conditional vai noņem.
  • Profiler crashes: Pārliecinies par jaunāko Godot versiju.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

// Defensīva programmēšana
void Player::take_damage(int amount) {
    // Validate input
    ERR_FAIL_COND_MSG(amount < 0,
        "Damage amount must be non-negative, got: " + String::num_int64(amount));

    // Log for debugging
    UtilityFunctions::print("Player ", name, " taking ", amount,
                            " damage. Current HP: ", hp);

    // Apply damage
    hp = std::max(0, hp - amount);

    // Sanity check
    if (hp < 0) {
        UtilityFunctions::printerr("CRITICAL: HP went negative! Resetting to 0");
        hp = 0;
    }

    // Conditional debug
    #ifdef DEBUG_ENABLED
    if (hp == 0) {
        UtilityFunctions::print("Player died at position ", get_position());
    }
    #endif

    emit_signal("damaged", amount);
}
Output panelī redzami detalizēti debug ziņojumi; pie nederīgas ievades - error ar context.
