1.2 Scene Tree un Node sistēma

Stundas uzdevums: Saprast, kā Godot organizē objektus Node hierarhijā un izveidot pirmo strādājošu scēnu.

SR 2.4.13. Datu tipi SR 2.4.15. Modulāras programmas

80 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~20 min) - izveido pirmo scēnu ar trim mezgliem · 2. uzdevums (~25 min) - saliec Pong laukuma koku · 3. uzdevums (~20 min) - saglabā paddle kā atsevišķu scēnu · Iesniegšana (~5 min).

Pirms sāc: atver savu Pong projektu no 1.1 stundas. Šodien vēl nerakstīsi kodu - tikai saliksi objektu koku, uz kuru vēlāk atsauksies C# kods.

Fokuss: šodien katrs objekts iegūst vietu kokā un skaidru nosaukumu. Ja apjūc, paskaties tikai uz Scene paneli un pārbaudi, kurš mezgls ir vecāks un kurš ir bērns.

Teorija: Node un Scene koncepti

Godot fundamentālais princips: viss ir Node (Mezgls). Spēles laukums, varonis, poga, skaņa un kamera ir mezgli, kas savienoti hierarhiskā kokā jeb Scene (Skatā). Scēna nav tikai vizuāls izkārtojums; tā ir arī objektu īpašumtiesību un komunikācijas struktūra.

Labs Scene Tree ir kā skaidrs programmas modelis: katram node ir viena atbildība, bērni papildina vecāku, un atkārtoti lietojami objekti tiek saglabāti kā atsevišķas scēnas. Slikts Scene Tree parasti ir milzīgs Main ar nejaušiem bērniem, kur C# kodā grūti atrast vajadzīgos objektus.

Galvenie Node tipi 2D spēlēs:

  • Node2D - bāzes klase 2D objektiem ar pozīciju, rotāciju, mērogu.
  • Sprite2D - rāda 2D attēlu (texture).
  • CollisionShape2D - sadursmes forma.
  • CharacterBody2D - kustīgs objekts ar fiziku (varonis).
  • Area2D - detektē objektus, kas šķērso zonu.
  • Camera2D - kameras skats.
// Pong scēnas struktūra:
// Main (Node2D)
// ├── Background (ColorRect)
// ├── PaddleLeft (CharacterBody2D)
// │   ├── Sprite2D
// │   └── CollisionShape2D
// ├── PaddleRight (CharacterBody2D)
// └── Ball (CharacterBody2D)
//     ├── Sprite2D
//     └── CollisionShape2D

Bērnu nodes pārmanto vecāku transformāciju. Ja Sprite2D ir bērns zem PaddleLeft, tad paddle pārvietošana pārvieto arī sprite. Tas ļauj C# kodā vadīt vienu galveno mezglu, nevis katru vizuālo detaļu atsevišķi.

using Godot;

public partial class Main : Node2D
{
    public override void _Ready()
    {
        CharacterBody2D left = GetNode<CharacterBody2D>("PaddleLeft");
        CharacterBody2D right = GetNode<CharacterBody2D>("PaddleRight");
        Node2D ball = GetNode<Node2D>("Ball");

        GD.Print("Scene ready: ", left.Name, ", ", right.Name, ", ", ball.Name);
    }
}

Praktiskie uzdevumi

1. uzdevums -

Izveido pirmo scēnu ar trim mezgliem

Beigās tev būs scēna ar vecāku mezglu un diviem bērniem.

Ko šis māca: redzēt, ka scēna ir koks, kur bērni pieder vecākam un pārmanto tā novietojumu.

  1. Nospied Scene panelī + Other Node.
  2. Izvēlies tipu Node2D un pārsauc to par Main.
  3. Nospied uz Main ar labo pogu un izvēlies Add Child Node.
  4. Pievieno bērnu CharacterBody2D un pārsauc to par Ball.
  5. Pievieno vēl vienu bērnu Label un pārsauc to par Punkti.
  6. Saglabā scēnu ar Ctrl+S kā main.tscn.
  7. Pārbaudi, ka Scene panelī Ball un Punkti ir nobīdīti pa labi zem Main.

Gatavs, kad: Scene panelī ir koks ar Main augšā un diviem bērniem zem tā, un fails main.tscn ir saglabāts.

2. uzdevums -

Saliec Pong laukuma koku

Beigās tavā scēnā būs visi Pong objekti ar saprotamiem nosaukumiem.

Ko šis māca: izvēlēties mezglu tipus pēc atbildības: kustīgs ķermenis, sadursmes forma un vizuāls elements nav viens un tas pats.

  1. Pievieno zem Main mezglu CharacterBody2D un pārsauc to par PaddleLeft.
  2. Pievieno otru CharacterBody2D un pārsauc to par PaddleRight.
  3. Pievieno PaddleLeft bērnu CollisionShape2D.
  4. Pievieno PaddleRight bērnu CollisionShape2D.
  5. Pievieno Ball bērnu CollisionShape2D.
  6. Izvēlies paddle sadursmēm Inspector panelī Shape -> New RectangleShape2D.
  7. Izvēlies Ball sadursmei Shape -> New CircleShape2D.
  8. Pievieno katram paddle arī bērnu ColorRect, lai to redzētu.
  9. Pievieno Ball bērnu ColorRect, lai bumbu redzētu kā mazu kvadrātu.
  10. Pārbaudi, ka neviens mezgls nesaucas Node2D2, CharacterBody2D2 vai ColorRect3.
  11. Saglabā scēnu.

Gatavs, kad: Scene kokā katram mezglam ir nosaukums, no kura var saprast, kas tas ir, un abiem paddle un Ball ir sadursmes forma.

3. uzdevums -

Saglabā paddle kā atsevišķu scēnu

Beigās vienu paddle varēsi lietot atkārtoti, nekopējot mezglus.

Ko šis māca: saprast atkārtoti lietojamu scēnu principu - vienu objektu labo vienā failā, bet izmanto vairākās vietās.

  1. Nospied uz PaddleLeft ar labo pogu.
  2. Izvēlies Save Branch as Scene un saglabā kā paddle.tscn.
  3. Ievēro, ka mezgla ikonai tagad ir maza filmiņas zīme - tā ir atsevišķa scēna.
  4. Izdzēs PaddleRight no koka.
  5. Ievelc paddle.tscn no FileSystem paneļa uz Main un pārsauc to par PaddleRight.
  6. Atver paddle.tscn, nomaini krāsu un saglabā.
  7. Atgriezies uz main.tscn un pārbaudi abus paddle.

Gatavs, kad: nomainot krāsu vienā paddle.tscn failā, tā mainās abiem paddle uzreiz.

Papildu uzdevums - Sakārto koku pēc atbildības

Ja pamatdarbs ir gatavs, sadali scēnu loģiskās grupās.

Ko šis māca: dalīt projektu mazākās grupās, lai C# kodā vēlāk nav jāmeklē objekti lielā, nejaušā sarakstā.

  1. Pievieno zem Main tukšu Node2D ar nosaukumu Speles.
  2. Pievieno otru tukšu Node2D ar nosaukumu UI.
  3. Pārvelc abus paddle un Ball zem Speles.
  4. Pārvelc Punkti zem UI.
  5. Pieraksti, ka pēc grupēšanas C# ceļi būs, piemēram, Speles/Ball un UI/Punkti.
  6. Pieraksti, kāpēc šāds dalījums vēlāk atvieglos koda rakstīšanu.

Gatavs, kad: koks ir sadalīts divās grupās, un zem Main ir tikai divi tiešie bērni.

Ko sagatavo

Stundas mērķis: Tev ir saglabāta Pong scēna main.tscn, kurā objekti sakārtoti saprotamā Node kokā, un viens paddle ir izveidots kā atkārtoti lietojama scēna paddle.tscn.

GitHub krātuvē jābūt:

  1. Ekrānuzņēmums ar Scene paneli, kurā redzams viss tavs mezglu koks ar nosaukumiem.
  2. Faili main.tscn un paddle.tscn (veic commit un push).
  3. Viens teikums README.md failā: ar ko scēna atšķiras no mezgla.

Kā iesniedz: Veic commit un push. Skolotāja norādītajā vietā ievieto tikai GitHub krātuves saiti; visiem prasītajiem failiem, README.md pierakstiem un pierādījumiem jābūt pašā krātuvē.

Pašpārbaude pirms iesniegšanas

Pārbaudi, vai scēnas koku var saprast arī cilvēks, kurš to redz pirmo reizi.

  • Pārskati nosaukumus: kokā nedrīkst palikt Node2D2, CharacterBody2D2, ColorRect3 vai citi nejauši nosaukumi.
  • Atver paddle.tscn atsevišķi un pārliecinies, ka tajā ir vizuālais mezgls un CollisionShape2D.
  • README.md vienā teikumā paskaidro, ar ko scēna atšķiras no mezgla.

Biežākās kļūdas

  • Bērns nepārvietojas ar vecāku: Pārliecinies, ka Sprite2D un CollisionShape2D ir tieši zem CharacterBody2D.
  • CollisionShape2D rāda dzeltenu trīsstūri: Trūkst Shape resursa.
  • Sprite nav redzams: Texture lauks tukšs.
