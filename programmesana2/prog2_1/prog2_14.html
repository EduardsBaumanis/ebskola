1.4 Pirmais C# script (skripts): variable (mainīgie) un output (izvade)

Stundas uzdevums: Izveidot Paddle C# class (klasi), pārbaudīt data (datu) type (tipus) un atsevišķu scene (scēnas) instance (instanču) property (īpašības).

80 min plāns: Ievads (~10 min) · raketes class (klase) (~20 min) · variable (mainīgie) un instances (instances) (~25 min) · pārbaude un skaidrojums (~20 min) · save (saglabāšana) (~5 min).

Pirms sāc: BuildCheck output (izdruka) no 1.3 darbojas. Tagad rakstīsi C# class (klasi) pašai raketei. Šodien pārbaudīsi tās data (datus); kustības method (metodi) pievienosi 1.5 stundā.

Darba ritms: pēc katra uzdevuma saglabā un pārbaudi rezultātu. Kad project (projektam) pievienots C# script (skripts), pirms palaišanas nospied Build (būvēt projektu). Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Teorija: class (klase) un data (dati), kurus izmantos spēle

using Godot; ļauj izmantot Godot type (tipus). public partial class Paddle : CharacterBody2D deklarē class (klasi), kas atbilst Paddle scene (scēnas) root (saknes) type (tipam). File name (faila nosaukums) ir Paddle.cs, bet šīs class (klases) instances (instances) Main scene (scēnā) drīkst saukties PaddleLeft un PaddleRight.

_Ready() darbojas, kad node (mezgls) ir gatavs scene (scēnā). GD.Print izvada tekstu; $"...{Speed}..." ievieto variable (mainīgā) value (vērtību) string (virknē). [Export] (Inspector pieejamas īpašības atribūts) ļauj mainīt value (vērtību) Inspector (īpašību panelis) pēc Build (būvēt projektu). Inspector (īpašību panelis) saglabāta value (vērtība) ir svarīgāka par code (koda) noklusējumu.

1. uzdevums -

Pievieno Paddle.cs kopīgajai raketes scene (scēnai)

  1. Atver Paddle.tscn, izvēlies tās CharacterBody2D (vadāma 2D tēla mezgls) root (sakni) un Attach Script (pievienot skriptu) → C# → res://Scripts/Paddle.cs. Aizstāj automātiski ģenerēto kustības paraugu ar pilno code (kodu) zemāk.
  2. Pārbaudi Speed (ātrums), InputUp, InputDown un IsActive. { get; set; } ir property (īpašība), kuru cits script (skripts) vēlāk varēs nolasīt un mainīt, lai pēc uzvaras apturētu raketes.
  3. Saglabā un Build (būvēt projektu). Atver Main.tscn un ar F5 pārbaudi Output (izdrukām): jābūt divām rindām, vienai no PaddleLeft, otrai no PaddleRight.
  4. Pārliecinies, ka project (projektā) ir tikai viens Paddle.cs; abas scene (scēnas) instances (instances) izmanto vienu class (klasi), bet katrai ir savas value (vērtības).
1.4 Paddle.cs — pilns file (fails) salīdzināšanai

Lejupielādēt Paddle.cs. Aizstāj tikai atbilstošā file (faila) saturu; neveido otru tāda paša nosaukuma class (klasi).

using Godot;

public partial class Paddle : CharacterBody2D
{
    [Export] public float Speed = 420.0f;
    [Export] public string InputUp = "p1_up";
    [Export] public string InputDown = "p1_down";
    public bool IsActive { get; set; } = true;

    public override void _Ready()
    {
        GD.Print($"{Name}: ātrums {Speed}, vadība {InputUp}/{InputDown}, aktīva {IsActive}");
    }
}

Gatavs, kad: abas raketes izdrukā savu node (mezgla) nosaukumu un data (datus); izskats Main scene (scēnā) ir saglabāts.

2. uzdevums -

Iestati katrai raketei savus data (datus)

  1. Main scene (scēnā) atlasi PaddleLeft. Inspector (īpašību panelis) pēc Build (būvēt projektu) redzami script (skripta) field (lauki): Speed (ātrums) = 420, Input (ievadei) Up = p1_up, Input (ievadei) Down = p1_down.
  2. Atlasi PaddleRight un tikai šai instance (eksemplārei) iestati Input (ievadei) Up = p2_up, Input (ievadei) Down = p2_down. Pati Input Map (ievades darbību karte) tiks izveidota 1.5 stundā.
  3. Uz laiku PaddleRight Speed (ātrums) maini uz 300. Palaid F5: izdrukā kreisajai paliek 420, labajai ir 300. Atjauno labajai 420. Tas apliecina, ka kopīgs script (skripts) nenozīmē kopīgu field (lauka) value (vērtību).
  4. Paddle.cs _Ready beigās pievieno GD.Print($"Pozīcija: {Position}");. Main scene (scēnā) pozīcijām jābūt (60,360) un (1220,360). Pārbaudi ar F5, tad šo papildu output (izdruku) noņem.

Gatavs, kad: abām instance (eksemplārēm) ir atšķirīgi input (ievades) nosaukumi, vienāds ātrums un pareizas position (pozīcijas).

3. uzdevums -

Paskaidro value (vērtības) un saglabā strādājošo version (versiju)

  1. README.md izveido tabulu: field (lauks), type (tips), value (vērtība) kreisajai raketei, value (vērtība) labajai raketei un tā nozīme spēlē.
  2. _Ready sākumā uz laiku ievieto int testScore = 0;, tad testScore += 1; un GD.Print(testScore);. Katrā jaunā F5 palaišanā katra rakete izdrukā 1, nevis turpina iepriekšējo skaitu. Pieraksti, kāpēc. Pēc tam šīs trīs pārbaudes rindas noņem.
  3. Paskaidro atšķirību starp Speed (ātrums) noklusējumu C# code (kodā) un Inspector (īpašību panelis) saglabāto value (vērtību). Ja code (koda) maiņa neparādās, apskati instances (instances) property (īpašības); ar atiestatīšanas icon (ikonu) var atjaunot noklusējumu.
  4. No Main.tscn noņem diagnostikas BuildCheck node (mezglu), jo vide jau pārbaudīta; BuildCheck.cs file (failu) drīkst paturēt. Saglabā, Build (būvēt projektu), F5 un pārliecinies, ka palikušas divas raketes output (izdrukas). Veic Commit (izmaiņu fiksējums) un Push (nosūtīšana uz attālo krātuvi).

Gatavs, kad: project (projekts) paliek bez pagaidu eksperimentiem, un katras raketes data (dati) ir saprotami un pārbaudīti.
