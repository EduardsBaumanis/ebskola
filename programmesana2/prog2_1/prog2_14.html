C# skripta saistība ar mezglu

Direktīva using Godot; faila sākumā pieslēdz dzinēja bibliotēku un ļauj izmantot tā iebūvētos type (tipus). Deklarācija, piemēram, public partial class KustigsObjekts : CharacterBody2D, apraksta C# class (klasi), kuras nosaukumam precīzi jāsakrīt ar faila nosaukumu (KustigsObjekts.cs), atslēgvārdam partial (pa failiem sadalāma klase) jāļauj dzinējam kompilācijas laikā pievienot savu palīgkodu, bet bāzes tipam aiz kola : jāatbilst scēnas mezgla tipam.

Savukārt šīs klases instance (eksemplāriem) citā scēnā var dot atšķirīgus mezglu vārdus — gluži kā viena modeļa viedierīcēm darbojas vienāda programmatūra, taču katrai ierīcei var piešķirt savu nosaukumu:

// Fails: res://Scripts/KustigsObjekts.cs
using Godot;

public partial class KustigsObjekts : CharacterBody2D
{
    // Vienu klasi var izmantot vairāki scēnas eksemplāri ar dažādiem vārdiem
}

Sākuma metode _Ready(), teksta izvade un [Export]

Metodi _Ready() Godot automātiski izsauc vienreiz brīdī, kad node (mezgls) ir sagatavots scēnā. GD.Print izvada tekstu Output panelī, bet teksta interpolācija $"...{Speed}..." (simbols $ pirms pēdiņām) ievieto variable (mainīgā) vērtību tieši string (virknē).

Atribūts [Export] (Inspector pieejamas īpašības atribūts) ļauj mainīt vērtību Inspector panelī pēc veiksmīga Build. Koda noklusējuma vērtība darbojas kā ierīces rūpnīcas iestatījums, bet Inspector panelī saglabātā vērtība — kā konkrētam eksemplāram iestatīts profils: izpildes laikā Inspector saglabātā vērtība ir svarīgāka par koda noklusējumu:

[Export] public float Speed = 250.0f; // Noklusējums kodā (maināms Inspector)
public bool IsActive { get; set; } = true;

public override void _Ready()
{
    // Name atgriež konkrētā eksemplāra mezgla nosaukumu scēnā
    GD.Print($"{Name}: ātrums = {Speed}, aktīvs = {IsActive}");
}

Biežākie datu tipi (data type)

C# ir statiski tipizēta valoda — katram mainīgajam deklarējot norāda tipu kā marķētu konteineru noteikta veida datiem:

TypePiemērs un pielietojums
float (daļskaitlis)Speed = 250.0f — nepārtraukts skaitlis ar komatu (piemēram, ātrums); f norāda float literāli.
string (teksta virkne)ActionName = "move_up" — simbolu virkne pēdiņās (piemēram, nosaukums vai ievades darbības kods).
bool (loģiska vērtība)IsActive = true — loģisks slēdzis ar diviem stāvokļiem (true vai false), piemēram, vai objekts ir aktīvs.
int (vesels skaitlis)Counter = 0 — vesels skaitāms lielums bez komata (piemēram, skaitītājs vai mēģinājumu skaits).
Vector2 (divdimensiju vektors)Position vai Velocity — vērtību pāris ar X un Y komponentēm 2D plaknē.

Mainīgo deklarēšana un pamatdarbības C# kodā:

float atrums = 250.0f;                       // Daļskaitlim pievieno f
string darbibasKods = "move_up";             // Teksta virkne pēdiņās
bool irAktivs = true;                        // Loģiska vērtība (true/false)
int skaititajs = 0;                          // Vesels skaitlis
skaititajs += 1;                             // Palielina vērtību par 1
Vector2 sakumaVieta = new Vector2(640, 360); // 2D koordinātas (X, Y)

Pievieno Paddle.cs kopīgajai raketes scēnai

Kur strādāt: Izveido Scripts/Paddle.cs, aizstāj tā saturu ar doto pilno failu un piesaisti to Scenes/Paddle.tscn saknei.

  1. Atver Paddle.tscn, izvēlies tās CharacterBody2D (vadāma 2D tēla mezgls) sakni un Attach Script → C# → res://Scripts/Paddle.cs. Aizstāj automātiski ģenerēto kustības paraugu ar pilno kodu zemāk — public partial class Paddle : CharacterBody2D deklarē klasi, kas atbilst Paddle scēnas saknes tipam un faila nosaukumam Paddle.cs.
  2. Pārbaudi Speed (ātrums), InputUp, InputDown un IsActive. { get; set; } ir īpašība, kuru cits skripts vēlāk varēs nolasīt un mainīt, lai pēc uzvaras apturētu raketes.
  3. Saglabā un Build. Atver Main.tscn un ar F5 pārbaudi Output: jābūt divām rindām, vienai no PaddleLeft, otrai no PaddleRight.
  4. Pārliecinies, ka projektā ir tikai viens Paddle.cs; šīs class instance Main scēnā drīkst saukties PaddleLeft un PaddleRight — abas izmanto vienu class, bet katrai ir savas vērtības.
1.4 Paddle.cs — pilns fails salīdzināšanai

Lejupielādēt Paddle.cs. Aizstāj tikai atbilstošā faila saturu; neveido otru tāda paša nosaukuma class.

using Godot;

public partial class Paddle : CharacterBody2D
{
    [Export] public float Speed = 420.0f;
    [Export] public string InputUp = "p1_up";
    [Export] public string InputDown = "p1_down";
    public bool IsActive { get; set; } = true;

    public override void _Ready()
    {
        GD.Print($"{Name}: ātrums {Speed}, vadība {InputUp}/{InputDown}, aktīva {IsActive}");
    }
}

Gatavs, kad: abas raketes izdrukā savu node nosaukumu un datus; izskats Main scēnā ir saglabāts.

2. uzdevums -

Iestati katrai raketei savus datus

Kur strādāt: Rakešu vērtības maini Scenes/Main.tscn Inspector panelī; pagaidu izdruku pievieno Scripts/Paddle.cs metodes _Ready() beigās.

  1. Main scēnā atlasi PaddleLeft. Inspector pēc Build redzami skripta lauki: Speed = 420, Input Up = p1_up, Input Down = p1_down.
  2. Atlasi PaddleRight un tikai šai instance iestati Input Up = p2_up, Input Down = p2_down. Pati Input Map tiks izveidota 1.5 stundā.
  3. Uz laiku PaddleRight Speed maini uz 300. Palaid F5: izdrukā kreisajai paliek 420, labajai ir 300. Atjauno labajai 420. Tas apliecina, ka kopīgs skripts nenozīmē kopīgu lauka vērtību.
  4. Paddle.cs _Ready beigās pievieno GD.Print($"Pozīcija: {Position}");. Main scēnā pozīcijām jābūt (60,360) un (1220,360). Pārbaudi ar F5, tad šo papildu izdruku noņem.

Gatavs, kad: abām instance ir atšķirīgi ievades nosaukumi, vienāds ātrums un pareizas pozīcijas.

3. uzdevums -

Paskaidro vērtības un saglabā strādājošo versiju

Kur strādāt: Tabulu un skaidrojumu raksti README.md. Pagaidu skaitīšanas rindas ievieto Scripts/Paddle.cs metodē _Ready(); diagnostikas mezglu noņem no Scenes/Main.tscn.

  1. README.md izveido tabulu: lauks, type, vērtība kreisajai raketei, vērtība labajai raketei un tā nozīme spēlē.
  2. _Ready sākumā uz laiku ievieto int testScore = 0;, tad testScore += 1; un GD.Print(testScore);. Katrā jaunā F5 palaišanā katra rakete izdrukā 1, nevis turpina iepriekšējo skaitu. Pieraksti, kāpēc. Pēc tam šīs trīs pārbaudes rindas noņem.
  3. Paskaidro atšķirību starp Speed noklusējumu C# kodā un Inspector saglabāto vērtību. Ja koda maiņa neparādās, apskati instance īpašības; ar atiestatīšanas ikonu var atjaunot noklusējumu.
  4. No Main.tscn noņem diagnostikas BuildCheck node, jo vide jau pārbaudīta; BuildCheck.cs failu drīkst paturēt. Saglabā, Build, F5 un pārliecinies, ka palikušas divas raketes izdrukas. Veic Commit un Push.

Gatavs, kad: projekts paliek bez pagaidu eksperimentiem, un katras raketes dati ir saprotami un pārbaudīti.
