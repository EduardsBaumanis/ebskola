1.1 Godot instalācija un projekta sagatavošana

Stundas uzdevums: Sagatavot Godot .NET Pong projektu, palaist galveno scēnu un saglabāt sākumpunktu GitHub.

SR 2.4.12. Programmēšanas vide SR 3.1.2. Darba vides riski SR 2.3.1. Datorikas nozares attīstība padziļinātos projektos

Teorija: izstrādes rīki un projekta failu struktūra

Izstrādes vides rīku sadarbība

Mūsdienu programmatūras izstrādē vienas universālas programmas vietā parasti sadarbojas vairāki specializēti rīki — līdzīgi kā video studijā atsevišķi strādā ar kadru kompozīciju, scenārija tekstu un materiālu arhīvu:

  • Godot .NET — vizuālais dzinējs un redaktors ar C# atbalstu, kurā veido ekrāna objektus, fiziku un saskarni.
  • VS Code — pirmkoda redaktors, kurā raksta un rediģē skriptus un projekta dokumentāciju.
  • .NET SDK (programmatūras izstrādes komplekts) — rīku kopums ar kompilatoru, kas pārtulko cilvēkam lasāmo C# kodu datoram izpildāmā formā.
  • Git — lokāla versiju pārvaldības sistēma, kas fiksē izmaiņu vēsturi tavā datorā kā kontrolpunktus, ļaujot droši eksperimentēt un vajadzības gadījumā atgriezties pie iepriekšējās versijas.
  • GitHub — attālināta mākoņkrātuve internetā (līdzīgi mākoņdiskam, bet pielāgota pirmkodam un Git vēsturei), kas glabā projekta kopiju un ļauj strādāt no dažādām ierīcēm.

Projekta mape, failu veidi un ceļš res://

Katrs Godot projekts atrodas savā mapē. Lai failu adreses darbotos vienādi jebkurā datorā neatkarīgi no tā, kurā diskā vai lietotāja mapē projekts saglabāts, Godot izmanto prefiksu res:// (resources) — tas vienmēr apzīmē projekta saknes mapi (kā norāde „no ēkas galvenās ieejas”, nevis pilna pilsētas adrese).

Projekta mapē katram failu veidam ir sava loma: project.godot glabā galvenos projekta iestatījumus, .tscn faili — scēnas (objektu uzbūvi), bet .cs faili — C# class (klases) ar programmas loģiku. Savukārt mape .godot/ ir dzinēja automātiski ģenerēta cache (kešatmiņa) ātrākai ielādei; tāpat kā pārlūkprogrammas pagaidu failus, to jebkurā brīdī var atjaunot automātiski, tāpēc versiju vēsturē to neiekļauj:

ProjektaMape/             ← Godot vidē šī sakne ir res://
├── project.godot         ← res://project.godot (iestatījumi)
├── .gitignore            ← Git ignorējamās mapes (.godot/, bin/, obj/)
├── Scenes/
│   └── GalvenaScena.tscn ← res://Scenes/GalvenaScena.tscn (scēna)
├── Scripts/
│   └── ObjektaLogika.cs  ← res://Scripts/ObjektaLogika.cs (C# klase)
└── .godot/               ← automātiska cache (Git vēsturē neiekļauj)

1. uzdevums

Atver Godot .NET un izveido Pong projektu

Kur strādāt: Izveido Pong projekta mapi; Godot tajā izveidos project.godot. Komandu git --version izpildi VS Code terminālī.

  1. Atver Godot lejupielādi un izvēlies .NET variantu savai operētājsistēmai. Kursa piemērs pārbaudīts ar Godot 4.7.2 .NET; klasē izmantojiet skolotāja izvēlētu vienotu Godot 4 .NET versiju. (C# kompilēšanai vajadzīgo .NET SDK pārbaudīsi un pieslēgsi 1.3. stundā.)
  2. Windows vai Linux izpako visu lejupielādēto arhīvu un palaid tajā esošo Godot executable (izpildfailu); macOS atver lejupielādēto lietotni. Saglabā arī blakus esošo GodotSharp mapi, ja tā ir pievienota.
  3. Project Manager izvēlies New Project, nosaukums Pong, tukša projekta mape, piemēram, Documents/Godot/Pong. Izvēlies Compatibility renderer (renderētāju) un Create & Edit.
  4. Uzstādi vai pārbaudi VS Code un Git. VS Code terminal (terminālī) git --version jāparāda versija. Ja tikko uzstādīji Git, atver VS Code no jauna.

Gatavs, kad: atvērts tieši Pong projekts Godot .NET redaktorā un Git ir pieejams.

2. uzdevums

Izveido un palaid pirmo scēnu

Kur strādāt: Godot redaktorā izveido Scenes/Main.tscn; loga iestatījumus maini Project Settings, kas tos saglabā project.godot.

  1. Atrodi Scene paneli, FileSystem, 2D viewport (skatlogu), Inspector un Output. README.md vēlāk pieraksti katram vienu pielietojumu.
  2. FileSystem panelī ar labo pogu uz res:// izveido mapes Scenes un Scripts. Scene panelī izvēlies 2D Scene; saknes Node2D (2D mezgls) nosauc Main. Saglabā res://Scenes/Main.tscn.
  3. Project → Project Settings → Display → Window: Viewport Width = 1280, Viewport Height = 720, Stretch Mode = canvas_items, Stretch Aspect = keep. Ja kāds lauks nav redzams, ieslēdz Advanced Settings.
  4. Nospied F5, izvēlies Select Current vai norādi Main.tscn kā galveno scēnu. Tukšs spēles logs šodien ir pareizs rezultāts — vēl nav redzamu objektu. Apturi ar F8.
  5. Aizver un atkal atver projektu no Project Manager. Pārbaudi, ka Main.tscn un loga iestatījumi ir saglabāti. F5 palaiž galveno scēnu; F6 — pašlaik redaktorā atvērto scēnu.

Gatavs, kad: F5 atver spēles logu, un pēc projekta atkārtotas atvēršanas var turpināt tajā pašā scēnā.

3. uzdevums

Saglabā sākumpunktu GitHub

Kur strādāt: Projekta saknes mapē, blakus project.godot, izveido vai papildini README.md un .gitignore.

  1. VS Code izvēlies File → Open Folder un atver tieši mapi, kurā atrodas project.godot. Izveido README.md ar projekta nosaukumu, Godot versiju un piecu redaktora paneļu aprakstu.
  2. Izveido .gitignore vai papildini esošo: katru savā rindā ieraksti .godot/, bin/, obj/, *.tmp.
  3. Atver Source Control. Ja krātuves vēl nav, izvēlies Initialize Repository. Pārskati izmaiņas: jābūt project.godot, Scenes/Main.tscn, README.md un .gitignore, bet ne cache saturam.
  4. Pievieno izmaiņas ar Stage All Changes, ievadi ziņu “Pong projekta sākums” un veic Commit. Ja Git prasa autora vārdu un e-pastu, norādi savus vai skolotāja noteiktos Git iestatījumus; tad atkārto Commit.
  5. Izvēlies Publish to GitHub, pieraksties un izveido krātuvi pong-godot ar skolotāja prasīto pieejamību. Ja projektam jau ir GitHub attālā krātuve, izmanto Push/Sync Changes. Pārlūkā pārbaudi, ka faili ir augšupielādēti.

Detalizētās darbības: VS Code versiju pārvaldības pamācība. Saglabāšanas darbības turpmākajās stundās atkārto tajā pašā krātuvē.

Gatavs, kad: GitHub redzams pirmais commit (izmaiņu fiksējums) un Main.tscn; cache nav iekļauta. Privātai krātuvei skolotājam ir piešķirta piekļuve.

Papildu uzdevums — izdomā spēles pasauli

Kur strādāt: Spēles ieceri pievieno projekta saknes failā README.md.

README.md ieraksti vienu teikumu par savu spēles ieceri: kas ir abas komandas un par ko tās sacenšas? Piemēram, zemūdenes sargā pērli vai kosmosa kuģi sacenšas par enerģiju.

Ko sagatavo

Stundas mērķis: ir atverams Pong projekts, galvenā scēna un pirmā versija GitHub.

GitHub krātuvē jābūt:

  • project.godot, Scenes/Main.tscn, .gitignore.
  • README.md: Godot versija un piecu redaktora paneļu pielietojums; palaistā loga ekrānuzņēmums.

Saglabā projekta iestatījumus, izveidotās scēnas un resursus; no 1.3 stundas arī C# skriptus un projekta failus (.csproj u.c.). .gitignore ieraksti .godot/, bin/ un obj/ katru savā rindā.

Kā iesniedz: veic commit un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā iesniedz GitHub krātuves saiti; README.md un pārbaudes pierādījumiem jābūt krātuvē.
