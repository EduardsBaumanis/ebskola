1.3 C# un .NET sagatavošana

Stundas uzdevums: Pārbaudīt .NET SDK (programmatūras izstrādes komplekts), izveidot C# script (skriptu) un iziet pilnu rediģēšanas, compilation (kompilācijas) un palaišanas loop (ciklu).

80 min plāns: Ievads (~10 min) · .NET pārbaude (~20 min) · pirmais Build (būvēt projektu) (~25 min) · editor (redaktors) un kļūdu meklēšana (~20 min) · save (saglabāšana) (~5 min).

Pirms sāc: atver savu 1.2 Pong project (projektu) ar Main, abām raketēm un Ball. Šodien pārbaudīsi darba vidi ar mazu BuildCheck script (skriptu), lai kustības programming (programmēšanā) vēlāk netraucētu installation (instalācijas) kļūdas.

Darba ritms: pēc katra uzdevuma saglabā un pārbaudi rezultātu. Kad project (projektam) pievienots C# script (skripts), pirms palaišanas nospied Build (būvēt projektu). Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Teorija: editor (redaktors), SDK (programmatūras izstrādes komplekts) un compilation (kompilācija)

Godot .NET atver C# project (projektu), bet code (koda) compilation (kompilācijai) nepieciešams atsevišķs .NET SDK (programmatūras izstrādes komplekts). Tikai .NET Runtime (izpildlaiks) nav pietiekams. dotnet --list-sdks parāda uzstādītos SDK (programmatūras izstrādes komplekts); dotnet build kompilē project (projektu) folder (mapē) ar .csproj.

Godot izveido C# project (projekta) file (failus), kad pievieno pirmo C# script (skriptu). Build (būvēt projektu) button (pogas) neesamība vēl tukšā project (projektā) pati par sevi nav kļūda. Pārbaude ir script (skripta) izveide → veiksmīgs Build (būvēt projektu) → output (izdruka) spēles palaišanas laikā. Skati Godot C# vides norādes.

1. uzdevums -

Pārbaudi .NET SDK (programmatūras izstrādes komplekts) un editor (redaktora) version (versiju)

  1. Godot menu (izvēlnē) Help → About pārbaudi, ka lieto .NET variantu. Parastā Godot version (versijā) Attach Script (pievienot skriptu) valodu list (sarakstā) C# nebūs.
  2. Atver VS Code terminal (termināli) un izpildi dotnet --list-sdks un dotnet --version. List (sarakstam) jābūt netukšam. Pieraksti Godot un SDK (programmatūras izstrādes komplekts) version (versiju) README.md.
  3. Ja SDK (programmatūras izstrādes komplekts) nav, instalē to no oficiālās .NET download (lejupielādes). Kursa piemērā izmantots .NET 8 SDK (programmatūras izstrādes komplekts); citas Godot version (versijas) gadījumā ievēro tās SDK (programmatūras izstrādes komplekts) prasības. Atver Godot un terminal (termināli) no jauna.
  4. VS Code atver visu Pong project (projekta) folder (mapi). Pagaidām neizpildi dotnet build (būvējums), ja .csproj vēl nav — to izveidos nākamais uzdevums.

Gatavs, kad: terminal (terminālis) atrod SDK (programmatūras izstrādes komplekts) un Pong ir atvērts Godot .NET editor (redaktorā).

2. uzdevums -

Izveido un palaid BuildCheck.cs

  1. Main.tscn root (saknei) pievieno Node (mezgls) child node (bērnu) ar nosaukumu BuildCheck. Atlasot šo node (mezglu), izvēlies Attach Script (pievienot skriptu), valodu C# un path (ceļu) res://Scripts/BuildCheck.cs.
  2. Aizstāj script (skripta) saturu ar pilno file (failu) zemāk. BuildCheck.cs satur public partial class BuildCheck : Node; class (klases) un file (faila) nosaukumi sakrīt.
  3. Saglabā script (skriptu) un scene (scēnu). Nospied Build (būvēt projektu); ja package (pakotnes) jālejupielādē pirmo reizi, sagaidi procesa beigas. Turpini tikai tad, kad nav compiler error (kompilācijas kļūdu).
  4. Palaid F5 un atver Output (izdrukām). Jāparādās C# build darbojas.. Apturi spēli; project (projekta) folder (mapē) atrodi Pong.csproj un Godot ģenerēto risinājuma file (failu), ja tas ir izveidots.
  5. VS Code terminal (terminālī) no Pong folder (mapes) izpildi dotnet build. Tas pats code (kods) jāspēj kompilēt arī no terminal (termināļa).
1.3 BuildCheck.cs — pilns file (fails) salīdzināšanai

Lejupielādēt BuildCheck.cs. Aizstāj tikai atbilstošā file (faila) saturu; neveido otru tāda paša nosaukuma class (klasi).

using Godot;

public partial class BuildCheck : Node
{
    public override void _Ready()
    {
        GD.Print("C# build darbojas.");
    }
}

Gatavs, kad: abi compilation (kompilācijas) veidi izdodas, un F5 laikā redzama tieši šī script (skripta) output (izdruka).

3. uzdevums -

Pieslēdz code editor (koda redaktoru) un atrodi vienu kļūdu

  1. Godot Editor (redaktors) → Editor Settings (redaktora iestatījumi) → Dotnet → Editor (redaktors) kā External Editor (ārējais redaktors) izvēlies Visual Studio Code. VS Code uzstādi Microsoft C# extension (paplašinājumu). Veicot double-click (dubultklikšķi) uz BuildCheck.cs, jāsākas rediģēšanai.
  2. Nomaini output (izdrukas) tekstu, saglabā, Build (būvēt projektu) un F5. Salīdzini jauno output (izdruku) ar iepriekšējo. Saglabāts file (fails) un veiksmīgi pārkompilēts code (kods) ir divi atsevišķi soļi.
  3. Uz laiku izdzēs semikolu pēc GD.Print un nospied Build (būvēt projektu). Nokopē pirmās kļūdas tekstu ar file (failu) un rindas numuru. Atjauno semikolu, tad atkārto Build (būvēt projektu) un F5.
  4. Pārskati Source Control (versiju pārvaldība): saglabā .cs, .csproj, risinājuma file (failu) (.sln vai .slnx, ja tāds ģenerēts), .tscn un script (skriptu) .uid file (failus), ja tie izveidoti. .godot, bin un obj paliek ignorēti. Veic Commit (izmaiņu fiksējums) un Push (nosūtīšana uz attālo krātuvi).

Gatavs, kad: proti rediģēt, kompilēt, nolasīt kļūdu un atgriezt project (projektu) strādājošā state (stāvoklī).

Papildu uzdevums — izveido savu BUILD.md atgādni

Pieraksti Godot un SDK (programmatūras izstrādes komplekts) version (versiju), project (projekta) atvēršanas path (ceļu), Build (būvēt projektu)/F5 darbības, komandas un atrastās kļūdas risinājumu. Palūdz klasesbiedram pēc pieraksta atrast, kur jālabo script (skripts).
