Teorija: GDExtension un C++ build sistēma

GDExtension ir Godot 4 mehānisms, kas ļauj rakstīt C++ kodu, kas darbojas spēlē. C++ kods tiek kompilēts par koplietojamu bibliotēku (.so Linux, .dll Windows, .dylib macOS), ko Godot ielādē izpildes laikā.

Šajā kursā spēles skripti ir C++ klases. SConstruct ir build konfigurācija, termināļa komandas ir tikai rīku palaišana, bet spēles uzvedību rakstām .hpp un .cpp failos.

Kāpēc C++?

  • Veiktspēja: piemērots intensīvai fizikai, datu apstrādei un AI algoritmiem.
  • Industrijas standarts: C++ sintakse, kompilācija un moduļu dalījums ir bieži sastopami spēļu izstrādē.
  • Kontrole: skaidri tipi, galvenes, implementācijas faili un precīza bibliotēku sasaiste.

Nepieciešamie rīki: C++ kompilators, Python, SCons, Git un godot-cpp bindings. godot-cpp versijai jāatbilst Godot 4 versijai, ko lieto projektā.

# Atkarību instalēšana
# Linux (Debian/Ubuntu):
sudo apt install build-essential scons git python3

# Windows: Visual Studio Community ar "Desktop development with C++"
pip install scons

# macOS:
brew install scons

Praktiskie uzdevumi

1. uzdevums - Uzstādi kompilatoru un SCons

Beigās tavs dators pratīs pārvērst C++ tekstu par programmu.

  1. Uzstādi kompilatoru: Windows - Visual Studio Build Tools ar C++ darbarīkiem; Linux - sudo apt install build-essential; macOS - xcode-select --install.
  2. Pārbaudi terminālī python --version - vajadzīga Python 3.
  3. Izpildi pip install scons.
  4. Izpildi scons --version un pieraksti versijas numuru.
  5. Aizver termināli un atver no jauna, ja komanda netiek atpazīta.
  6. Pieraksti burtnīcā, kuru kompilatoru uzstādīji.

Gatavs, kad: komanda scons --version atbild ar versijas numuru, nevis ar kļūdu par neatpazītu komandu.

2. uzdevums - Lejupielādē godot-cpp un nokompilē to

Beigās tev būs sagatavota bibliotēka, ar kuru C++ var runāt ar Godot.

  1. Izveido projekta mapē apakšmapi gdext.
  2. Izpildi tajā git clone -b 4.2 https://github.com/godotengine/godot-cpp.
  3. Ieej mapē ar cd godot-cpp.
  4. Izpildi scons platform=windows (vai linux, vai macos).
  5. Pagaidi - pirmā kompilēšana var aizņemt 10-20 minūtes. Šajā laikā izlasi teoriju vēlreiz.
  6. Pārbaudi, ka mapē godot-cpp/bin parādījās fails ar paplašinājumu .a vai .lib.
  7. Pieraksti, cik ilgi kompilēšana aizņēma.

Gatavs, kad: mapē godot-cpp/bin ir jauns bibliotēkas fails, un terminālis beigās raksta scons: done building targets.

3. uzdevums - Pieslēdz bibliotēku Godot projektam

Beigās Godot zinās, kur meklēt tavu C++ kodu.

  1. Izveido projekta mapē failu pong.gdextension.
  2. Ieraksti tajā sadaļu [configuration] ar rindu entry_symbol = "pong_library_init".
  3. Pievieno sadaļu [libraries] ar ceļu uz savas platformas bibliotēkas failu.
  4. Saglabā failu un aizver Godot editoru pilnībā.
  5. Atver projektu no jauna un paskaties cilnē Output.
  6. Pieraksti, vai tur parādījās kļūdas ziņojums par bibliotēku.
  7. Pievieno .gitignore failam rindas gdext/godot-cpp/ un *.obj.

Gatavs, kad: Godot atveras bez kļūdas par trūkstošu bibliotēku, un mape godot-cpp nenonāk GitHub.

Papildu uzdevums - Saprot, ko dara katrs solis

Ja pamatdarbs ir gatavs, pieraksti sev atgādni turpmākajām reizēm.

  1. Uzraksti failu BUILD.md projekta mapē.
  2. Pieraksti tajā trīs komandas, ko šodien izpildīji, pareizā secībā.
  3. Pieraksti katrai vienu teikumu, ko tā dara.
  4. Pieraksti vienu kļūdu, ar ko saskāries, un kā to atrisināji.
  5. Veic commit un push.

Gatavs, kad: pēc BUILD.md instrukcijas klasesbiedrs varētu atkārtot uzstādīšanu bez tavas palīdzības.

Ko iesniedz skolotājam

Stundas mērķis: Tavā datorā ir uzstādīts C++ kompilators un SCons, nokompilēta godot-cpp bibliotēka, un Godot projekts atveras bez kļūdas par trūkstošu GDExtension bibliotēku.

Iesniedzamais:

  1. Ekrānuzņēmums ar termināli, kurā redzams scons: done building targets.
  2. Ekrānuzņēmums ar Godot cilni Output pēc projekta atvēršanas.
  3. Fails pong.gdextension tavā GitHub krātuvē.
  4. Ja kaut kas neizdevās - precīzs kļūdas teksts, nokopēts no termināļa.

Kā iesniedz: Veic commit un push, tad iesniedz krātuves saiti un ekrānuzņēmumus. Ja uzstādīšana neizdevās, obligāti iesniedz kļūdas tekstu - to risināsim nākamās stundas sākumā.

Papildu izaicinājumi

Iestati ērtāku C++ rediģēšanu.

  • Atver projektu VS Code ar code ..
  • Instalē C++ paplašinājumu un pievieno include ceļus uz gdext/godot-cpp/include un ģenerētajiem bindings failiem.
  • Pievieno VS Code task, kas palaiž to pašu scons komandu, ko ierakstīji README.

Biežākās kļūdas

  • scons: command not found: SCons nav uzstādīts. pip install --user scons.
  • Linker errors par godot-cpp: Vispirms jākompilē godot-cpp pati. cd godot-cpp && scons.
  • Visual Studio nav atrasts (Windows): Palaiž SCons no Developer Command Prompt.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

// gdext/src/register_types.cpp
#include "register_types.hpp"
#include "hello.hpp"

#include <gdextension_interface.h>
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/core/defs.hpp>
#include <godot_cpp/godot.hpp>

using namespace godot;

void initialize_pong_module(ModuleInitializationLevel level) {
    if (level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }

    ClassDB::register_class<Hello>();
}

void uninitialize_pong_module(ModuleInitializationLevel level) {
    if (level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }
}

extern "C" {
GDExtensionBool GDE_EXPORT pong_library_init(
    GDExtensionInterfaceGetProcAddress get_proc_address,
    GDExtensionClassLibraryPtr library,
    GDExtensionInitialization *initialization) {
    GDExtensionBinding::InitObject init_obj(get_proc_address, library, initialization);
    init_obj.register_initializer(initialize_pong_module);
    init_obj.register_terminator(uninitialize_pong_module);
    init_obj.set_minimum_library_initialization_level(MODULE_INITIALIZATION_LEVEL_SCENE);
    return init_obj.init();
}
}
