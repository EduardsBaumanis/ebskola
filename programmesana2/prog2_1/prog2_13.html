1.3 C# un .NET sagatavošana

Stundas uzdevums: Pārbaudīt .NET SDK, izveidot C# skriptu un iziet pilnu rediģēšanas, kompilācijas un palaišanas ciklu.

SR 2.4.12. Programmēšanas vide SR 2.4.2. Argumentēti izvēlas rīkus SR 2.3.2. Datorikas virzieni un profesijas SR 2.4.8. Koda dokumentēšana un noformēšana SR 2.4.9. Versiju pārvaldība SR 2.4.11. Standartizētas bibliotēkas un API

80 min plāns: Ievads (~10 min) · .NET pārbaude (~20 min) · pirmais Build (~25 min) · redaktors un kļūdu meklēšana (~20 min) · saglabāšana (~5 min).

Pirms sāc: atver savu 1.2 Pong projektu ar Main, abām raketēm un Ball. Šodien pārbaudīsi darba vidi ar mazu BuildCheck skriptu, lai kustības programmēšanā vēlāk netraucētu instalācijas kļūdas.

Darba ritms: pēc katra uzdevuma saglabā un pārbaudi rezultātu. Kad projektam pievienots C# skripts, pirms palaišanas nospied Build. Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Teorija: redaktors, SDK un kompilācija

Godot .NET atver C# projektu, bet koda kompilācijai nepieciešams atsevišķs .NET SDK. Tikai .NET Runtime nav pietiekams. dotnet --list-sdks parāda uzstādītos SDK; dotnet build kompilē projektu mapē ar .csproj.

Godot izveido C# projekta failus, kad pievieno pirmo C# skriptu. Build pogas neesamība vēl tukšā projektā pati par sevi nav kļūda. Pārbaude ir skripta izveide → veiksmīgs Build → izdruka spēles palaišanas laikā. Skati Godot C# vides norādes.

1. uzdevums -

Pārbaudi .NET SDK un redaktora versiju

  1. Godot izvēlnē Help → About pārbaudi, ka lieto .NET variantu. Parastā Godot versijā Attach Script valodu sarakstā C# nebūs.
  2. Atver VS Code termināli un izpildi dotnet --list-sdks un dotnet --version. Sarakstam jābūt netukšam. Pieraksti Godot un SDK versiju README.md.
  3. Ja SDK nav, instalē to no oficiālās .NET lejupielādes. Kursa piemērā izmantots .NET 8 SDK; citas Godot versijas gadījumā ievēro tās SDK prasības. Atver Godot un termināli no jauna.
  4. VS Code atver visu Pong projekta mapi. Pagaidām neizpildi dotnet build, ja .csproj vēl nav — to izveidos nākamais uzdevums.

Gatavs, kad: terminālis atrod SDK un Pong ir atvērts Godot .NET redaktorā.

2. uzdevums -

Izveido un palaid BuildCheck.cs

  1. Main.tscn saknei pievieno Node bērnu ar nosaukumu BuildCheck. Atlasot šo mezglu, izvēlies Attach Script, valodu C# un ceļu res://Scripts/BuildCheck.cs.
  2. Aizstāj skripta saturu ar pilno failu zemāk. BuildCheck.cs satur public partial class BuildCheck : Node; klases un faila nosaukumi sakrīt.
  3. Saglabā skriptu un scēnu. Nospied Build; ja pakotnes jālejupielādē pirmo reizi, sagaidi procesa beigas. Turpini tikai tad, kad nav kompilācijas kļūdu.
  4. Palaid F5 un atver Output. Jāparādās C# build darbojas.. Apturi spēli; projekta mapē atrodi Pong.csproj un Godot ģenerēto risinājuma failu, ja tas ir izveidots.
  5. VS Code terminālī no Pong mapes izpildi dotnet build. Tas pats kods jāspēj kompilēt arī no termināļa.
1.3 BuildCheck.cs — pilns fails salīdzināšanai

Lejupielādēt BuildCheck.cs. Aizstāj tikai atbilstošā faila saturu; neveido otru tāda paša nosaukuma klasi.

using Godot;

public partial class BuildCheck : Node
{
    public override void _Ready()
    {
        GD.Print("C# build darbojas.");
    }
}

Gatavs, kad: abi kompilācijas veidi izdodas, un F5 laikā redzama tieši šī skripta izdruka.

3. uzdevums -

Pieslēdz koda redaktoru un atrodi vienu kļūdu

  1. Godot Editor → Editor Settings → Dotnet → Editor kā External Editor izvēlies Visual Studio Code. VS Code uzstādi Microsoft C# paplašinājumu. Veicot dubultklikšķi uz BuildCheck.cs, jāsākas rediģēšanai.
  2. Nomaini izdrukas tekstu, saglabā, Build un F5. Salīdzini jauno izdruku ar iepriekšējo. Saglabāts fails un veiksmīgi pārkompilēts kods ir divi atsevišķi soļi.
  3. Uz laiku izdzēs semikolu pēc GD.Print un nospied Build. Nokopē pirmās kļūdas tekstu ar failu un rindas numuru. Atjauno semikolu, tad atkārto Build un F5.
  4. Pārskati Source Control: saglabā .cs, .csproj, risinājuma failu (.sln vai .slnx, ja tāds ģenerēts), .tscn un skriptu .uid failus, ja tie izveidoti. .godot, bin un obj paliek ignorēti. Veic Commit un Push.

Gatavs, kad: proti rediģēt, kompilēt, nolasīt kļūdu un atgriezt projektu strādājošā stāvoklī.

Papildu uzdevums — izveido savu BUILD.md atgādni

Pieraksti Godot un SDK versiju, projekta atvēršanas ceļu, Build/F5 darbības, komandas un atrastās kļūdas risinājumu. Palūdz klasesbiedram pēc pieraksta atrast, kur jālabo skripts.
