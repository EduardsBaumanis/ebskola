1.3 C# un .NET sagatavošana

Stundas uzdevums: Pārbaudīt .NET SDK (programmatūras izstrādes komplekts), izveidot C# skriptu un iziet pilnu rediģēšanas, compilation (kompilācijas) un palaišanas loop (ciklu).

SR 2.4.12. Programmēšanas vide SR 2.4.2. Argumentēti izvēlas rīkus SR 2.3.2. Datorikas virzieni un profesijas SR 2.4.8. Koda dokumentēšana un noformēšana SR 2.4.9. Versiju pārvaldība SR 2.4.11. Standartizētas library (bibliotēkas) un API (lietojumprogrammas saskarne)

80 min plāns: Ievads (~10 min) · .NET pārbaude (~20 min) · pirmais Build (~25 min) · redaktors un kļūdu meklēšana (~20 min) · saglabāšana (~5 min).

Pirms sāc: atver savu 1.2 Pong projektu ar Main, abām raketēm un Ball. Šodien pārbaudīsi darba vidi ar mazu BuildCheck skriptu, lai kustības programmēšanā vēlāk netraucētu instalācijas kļūdas.

Darba ritms: pēc katra uzdevuma saglabā un pārbaudi rezultātu. Kad projektam pievienots C# skripts, pirms palaišanas nospied Build. Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Failu ceļi: ceļi ir norādīti no tava Godot projekta mapes, kur atrodas project.godot; piemēram, Scripts/Player.cs Godot panelī ir res://Scripts/Player.cs. Ja norādītais fails jau ir izveidots, atver un papildini to.

Teorija: redaktors, .NET SDK un compilation

Kāpēc ar redaktoru un Runtime vien nepietiek?

Godot .NET spēj atvērt un darbināt C# projektu, taču pirmkoda compilation (kompilācijai) datorā ir nepieciešams atsevišķs .NET SDK (programmatūras izstrādes komplekts). Atšķirību var salīdzināt ar mūzikas atskaņotāju un ierakstu studiju: tikai .NET Runtime (izpildlaiks) prot atskaņot jau gatavu programmu, savukārt .NET SDK ietver arī kompilatoru un būvēšanas rīkus jaunas programmas izveidei no pirmkoda.

Terminālī komanda dotnet --list-sdks parāda datorā uzstādītos izstrādes komplektus, bet dotnet build sakompilē projektu tajā mapē, kurā atrodas C# projekta apraksta fails (.csproj):

# Pārbauda datorā uzstādītos .NET SDK komplektus un aktīvo versiju
dotnet --list-sdks
dotnet --version

# Kompilē C# projektu mapē, kurā atrodas .csproj fails
dotnet build

Kompilācijas cikls un projekta failu ģenerēšana

C# ir kompilējama valoda: saglabāts .cs fails pats par sevi ir tikai teksta dokuments — kā izmainīts rasējums uz papīra, pēc kura iekārta vēl nestrādā. Tikai nospiežot Build, kompilators pārbauda visu skriptu sintaksi un pārvērš pirmkodu binārā modulī, kuru dzinējs ielādē programmas izpildes laikā:

using Godot;

// Faila nosaukumam (Sistema.cs) precīzi jāsakrīt ar klases nosaukumu
public partial class Sistema : Node
{
    public override void _Ready()
    {
        // Build pārbauda sintaksi (piemēram, semikolu rindas beigās)
        GD.Print("Kods veiksmīgi sakompilēts binārā modulī.");
    }
}

Godot automātiski izveido C# projekta failus (.csproj un risinājuma failu) brīdī, kad projektam pievieno pirmo C# skriptu — līdz tam projekts satur tikai scēnas, tāpēc Build rīki redaktorā vēl netiek rādīti. Papildu tehniskās detaļas skati Godot C# vides norādēs.

1. uzdevums -

Pārbaudi .NET SDK un redaktora versiju

Kur strādāt: Komandas izpildi VS Code terminālī, atverot Pong projekta mapi. Versijas pieraksti projekta README.md.

  1. Godot izvēlnē Help → About pārbaudi, ka lieto .NET variantu. Parastā Godot versijā Attach Script valodu sarakstā C# nebūs.
  2. Atver VS Code terminal (termināli) un izpildi dotnet --list-sdks un dotnet --version. Sarakstam jābūt netukšam. Pieraksti Godot un SDK versiju README.md.
  3. Ja SDK nav, instalē to no oficiālās .NET lejupielādes. Kursa piemērā izmantots .NET 8 SDK; citas Godot versijas gadījumā ievēro tās SDK prasības. Atver Godot un terminal no jauna.
  4. VS Code atver visu Pong projekta mapi. Pagaidām neizpildi dotnet build (būvējums), ja .csproj vēl nav — to izveidos nākamais uzdevums (arī Build pogas neesamība tukšā projektā pirms pirmā C# skripta pievienošanas ir normāla).

Gatavs, kad: terminal atrod SDK un Pong ir atvērts Godot .NET redaktorā.

2. uzdevums -

Izveido un palaid BuildCheck.cs

Kur strādāt: Izveido Scripts/BuildCheck.cs, aizstāj tā saturu ar doto pilno failu un piesaisti to Scenes/Main.tscn mezglam BuildCheck.

  1. Main.tscn saknei pievieno Node child node (bērnu) ar nosaukumu BuildCheck. Atlasot šo node (mezglu), izvēlies Attach Script, valodu C# un ceļu res://Scripts/BuildCheck.cs.
  2. Aizstāj skripta saturu ar pilno failu zemāk. BuildCheck.cs satur public partial class BuildCheck : Node; class (klases) un faila nosaukumi sakrīt.
  3. Saglabā skriptu un scēnu. Nospied Build; ja package (pakotnes) jālejupielādē pirmo reizi, sagaidi procesa beigas. Turpini tikai tad, kad nav compiler error (kompilācijas kļūdu).
  4. Palaid F5 un atver Output. Jāparādās C# build darbojas. — tas apliecina pilnu pārbaudes ķēdi (skripta izveide → veiksmīgs Build → izdruka spēles palaišanas laikā). Apturi spēli; projekta mapē atrodi Pong.csproj un Godot ģenerēto risinājuma failu, ja tas ir izveidots.
  5. VS Code terminal no Pong mapes izpildi dotnet build. Tas pats kods jāspēj kompilēt arī no terminal.
1.3 BuildCheck.cs — pilns fails salīdzināšanai

Lejupielādēt BuildCheck.cs. Aizstāj tikai atbilstošā faila saturu; neveido otru tāda paša nosaukuma class.

using Godot;

public partial class BuildCheck : Node
{
    public override void _Ready()
    {
        GD.Print("C# build darbojas.");
    }
}

Gatavs, kad: abi compilation veidi izdodas, un F5 laikā redzama tieši šī skripta izdruka.

3. uzdevums -

Pieslēdz koda redaktoru un atrodi vienu kļūdu

Kur strādāt: Tekstu un pagaidu semikola kļūdu maini Scripts/BuildCheck.cs metodē _Ready().

  1. Godot Editor → Editor Settings → Dotnet → Editor kā External Editor izvēlies Visual Studio Code. VS Code uzstādi Microsoft C# extension (paplašinājumu). Veicot dubultklikšķi uz BuildCheck.cs, jāsākas rediģēšanai.
  2. Nomaini izdrukas tekstu, saglabā, Build un F5. Salīdzini jauno izdruku ar iepriekšējo. Saglabāts fails un veiksmīgi pārkompilēts kods ir divi atsevišķi soļi.
  3. Uz laiku izdzēs semikolu pēc GD.Print un nospied Build. Nokopē pirmās kļūdas tekstu ar failu un rindas numuru. Atjauno semikolu, tad atkārto Build un F5.
  4. Pārskati Source Control: saglabā .cs, .csproj, risinājuma failu (.sln vai .slnx, ja tāds ģenerēts), .tscn un skriptu .uid failus, ja tie izveidoti. .godot, bin un obj paliek ignorēti. Veic Commit un Push.

Gatavs, kad: proti rediģēt, kompilēt, nolasīt kļūdu un atgriezt projektu strādājošā stāvoklī.

Papildu uzdevums — izveido savu BUILD.md atgādni

Kur strādāt: Projekta saknes mapē izveido BUILD.md un ieraksti tajā atgādni.

Pieraksti Godot un SDK versiju, projekta atvēršanas ceļu, Build/F5 darbības, komandas un atrastās kļūdas risinājumu. Palūdz klasesbiedram pēc pieraksta atrast, kur jālabo skripts.
