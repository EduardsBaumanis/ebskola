1.3 C# un .NET sagatavošana

Sasniedzamais rezultāts: Pārbaudīt .NET SDK (programmatūras izstrādes komplekts), izveidot C# skriptu un iziet pilnu rediģēšanas, compilation (kompilācijas) un palaišanas loop (ciklu).

SR 2.4.12. Programmēšanas vide SR 2.4.2. Argumentēti izvēlas rīkus SR 2.3.2. Datorikas virzieni un profesijas SR 2.4.8. Koda dokumentēšana un noformēšana SR 2.4.9. Versiju pārvaldība SR 2.4.11. Standartizētas library (bibliotēkas) un API (lietojumprogrammas saskarne)

Teorija: redaktors, .NET SDK un compilation

Kāpēc ar redaktoru un Runtime vien nepietiek?

Godot .NET spēj atvērt un darbināt C# projektu, taču pirmkoda compilation (kompilācijai) datorā ir nepieciešams atsevišķs .NET SDK (programmatūras izstrādes komplekts). Atšķirību var salīdzināt ar mūzikas atskaņotāju un ierakstu studiju: tikai .NET Runtime (izpildlaiks) prot atskaņot jau gatavu programmu, savukārt .NET SDK ietver arī kompilatoru un būvēšanas rīkus jaunas programmas izveidei no pirmkoda.

Terminālī komanda dotnet --list-sdks parāda datorā uzstādītos izstrādes komplektus, bet dotnet build sakompilē projektu tajā mapē, kurā atrodas C# projekta apraksta fails (.csproj):

# Pārbauda datorā uzstādītos .NET SDK komplektus un aktīvo versiju
dotnet --list-sdks
dotnet --version

# Kompilē C# projektu mapē, kurā atrodas .csproj fails
dotnet build

Kompilācijas cikls un projekta failu ģenerēšana

C# ir kompilējama valoda: saglabāts .cs fails pats par sevi ir tikai teksta dokuments - kā izmainīts rasējums uz papīra, pēc kura iekārta vēl nestrādā. Tikai nospiežot Build, kompilators pārbauda visu skriptu sintaksi un pārvērš pirmkodu binārā modulī, kuru dzinējs ielādē programmas izpildes laikā:

using Godot;

// Faila nosaukumam (Sistema.cs) precīzi jāsakrīt ar klases nosaukumu
public partial class Sistema : Node
{
    public override void _Ready()
    {
        // Build pārbauda sintaksi (piemēram, semikolu rindas beigās)
        GD.Print("Kods veiksmīgi sakompilēts binārā modulī.");
    }
}

Godot automātiski izveido C# projekta failus (.csproj un risinājuma failu) brīdī, kad projektam pievieno pirmo C# skriptu - līdz tam projekts satur tikai scēnas, tāpēc Build rīki redaktorā vēl netiek rādīti. Papildu tehniskās detaļas skati Godot C# vides norādēs.

1. uzdevums

Pārbaudi .NET SDK un redaktora versiju

Kur strādāt: Pārbaudi Godot redaktorā (Help → About), izpildi dotnet komandas VS Code terminālī (atverot Pong projekta saknes mapi), bet atrastās versijas pieraksti failā README.md.

  1. Pārbaudi Godot .NET variantu: Godot redaktorā atver Help → About Godot un pārliecinies, ka versijas nosaukumā ir .NET (parastajā Godot versijā bez .NET pie Attach Script valodu sarakstā nebūs C#).
  2. Pārbaudi .NET SDK no VS Code termināļa: atver Pong projekta saknes mapi programmā VS Code, atver Terminal → New Terminal un secīgi izpildi abas komandas: 
    dotnet --list-sdks
dotnet --version
    Sarakstam jābūt netukšam (kursa piemērā izmantots .NET 8 SDK). Pieraksti savu Godot .NET versiju un .NET SDK versiju failā README.md.
  3. Uzstādi .NET SDK (ja saraksts bija tukšs): lejupielādē un instalē SDK no oficiālās .NET lejupielādes lapas, pēc tam aizver un no jauna atver gan Godot, gan VS Code.
  4. Negaidi vēl pogu Build: kamēr projektā nav izveidots neviens .cs fails, mapē vēl nav Pong.csproj un Godot augšā nerāda pogu Build — tas ir normāli, to izveidosi nākamajā uzdevumā.

Gatavs, kad: terminālī komanda dotnet --list-sdks parāda vismaz vienu SDK, abas versijas ir ierakstītas README.md un Pong ir atvērts Godot .NET redaktorā.

2. uzdevums

Izveido un palaid BuildCheck.cs

Kur strādāt: Scēnā Scenes/Main.tscn pievieno diagnostikas mezglu BuildCheck un tam piesaisti jaunu C# skriptu Scripts/BuildCheck.cs.

Scēnas Scenes/Main.tscn papildinājums 2. uzdevumā:

Main (Node2D, Scenes/Main.tscn)
├── PaddleLeft (Scenes/Paddle.tscn)
├── PaddleRight (Scenes/Paddle.tscn)
├── Ball (Scenes/Ball.tscn)
└── BuildCheck (Node, skripts: Scripts/BuildCheck.cs - pagaidu tests)
  1. Pievieno mezglu BuildCheck scēnā Scenes/Main.tscn: atver Scenes/Main.tscn, Scene panelī atlasi sakni Main, spied +, meklē vienkāršu Node (baltā ikona) un spied Create. Ar F2 pārdēvē to par BuildCheck.
  2. Izveido skriptu Scripts/BuildCheck.cs: ar labo peles pogu klikšķini uz BuildCheck → Attach Script, izvēlies Language: C#, laukā Path norādi res://Scripts/BuildCheck.cs un spied Create. Atver Scripts/BuildCheck.cs un aizstāj tā saturu ar pilno kodu zemāk (klases nosaukumam BuildCheck un bāzes tipam Node jāsakrīt ar failu un mezglu).
  3. Kompilē ar pogu Build: saglabā Scripts/BuildCheck.cs un Scenes/Main.tscn (Ctrl+S). Godot augšējā joslā spied pogu Build (pirmajā reizē sagaidi, kamēr .NET lejupielādē pakotnes) un pārliecinies, ka nav kompilācijas kļūdu.
  4. Palaid ar F5 un pārbaudi Output: nospied Run Project (F5) un redaktora apakšā atver cilni Output — tur jāparādās rindai C# build darbojas. Apturi spēli ar F8 un pārbaudi, ka projekta saknes mapē ir izveidots fails Pong.csproj.
  5. Pārbaudi kompilāciju terminālī: VS Code terminālī (Pong saknes mapē blakus Pong.csproj) izpildi komandu dotnet build — arī tai jābeidzas ar Build succeeded.
1.3 BuildCheck.cs - pilns fails salīdzināšanai

Lejupielādēt BuildCheck.cs. Atver failu Scripts/BuildCheck.cs un aizstāj tā saturu ar šo kodu.

using Godot;

public partial class BuildCheck : Node
{
    public override void _Ready()
    {
        GD.Print("C# build darbojas.");
    }
}

Gatavs, kad: gan Godot Build, gan termināļa dotnet build izdodas bez kļūdām, un pēc F5 panelī Output ir redzama ziņa C# build darbojas.

3. uzdevums

Pieslēdz koda redaktoru un atrodi vienu kļūdu

Kur strādāt: Ārējo redaktoru iestati Godot Editor Settings; teksta un pagaidu semikola izmaiņas veic failā Scripts/BuildCheck.cs metodē _Ready(); pirmās kļūdas tekstu ieraksti README.md.

  1. Pieslēdz VS Code kā C# redaktoru: Godot augšējā izvēlnē atver Editor → Editor Settings → Dotnet → Editor un laukā External Editor izvēlies Visual Studio Code. Programmā VS Code uzstādi Microsoft paplašinājumu C# (Extensions panelī). Tagad, Godot redaktorā uzklikšķinot uz BuildCheck.cs, fails atvērsies VS Code.
  2. Maini izdrukas tekstu failā Scripts/BuildCheck.cs: metodē _Ready() nomaini GD.Print("C# build darbojas."); uz citu tekstu (piemēram, savu sveicienu), saglabā failu (Ctrl+S), Godot spied Build un tad F5 — redzi, ka izdrukas atjaunošanai vajadzīgi abi soļi (saglabāt + Build).
  3. Izraisi un nolasi vienu kompilācijas kļūdu: failā Scripts/BuildCheck.cs uz laiku izdzēs semikolu ; rindas GD.Print(...) beigās, saglabā un Godot spied Build. Apakšējā MSBuild / Errors panelī nokopē pirmās kļūdas tekstu ar faila nosaukumu un rindas numuru un ielīmē to failā README.md. Pēc tam atjauno semikolu ;, saglabā, nospied Build un F5.
  4. Saglabā izmaiņas GitHub: VS Code cilnē Source Control pārbaudi, ka izmaiņās ir Scripts/BuildCheck.cs, Scenes/Main.tscn, Pong.csproj, .sln (vai .slnx) un .uid faili, bet .godot/, bin/ un obj/ paliek ignorēti. Veic Commit un Push / Sync Changes.

Gatavs, kad: proti rediģēt C# failu VS Code, kompilēt ar Build, nolasīt kompilācijas kļūdu un projekts ir atjaunots strādājošā stāvoklī un nosūtīts uz GitHub.

Papildu uzdevums - izveido savu BUILD.md atgādni

Kur strādāt: Projekta saknes mapē (blakus project.godot) izveido failu BUILD.md.

Failā BUILD.md īsi saraksti savu darba kārtību: Godot un .NET SDK versijas, soļus koda rediģēšanai (Ctrl+S → Build → F5), termināļa komandu dotnet build un kā izlabot semikola kļūdu.

Ko sagatavo

Stundas mērķis: vide ir pārbaudīta ar īstu C# compilation un izpildi.

GitHub krātuvē jābūt:

  • Scripts/BuildCheck.cs, atjaunināts Main.tscn un C# projekta faili.
  • README.md: abu rīku versijas, pirmās kļūdas teksts un labojums; Output izdrukas pierādījums.

Saglabā projekta iestatījumus, izveidotās scēnas un resursus; no 1.3 stundas arī C# skriptus un projekta failus (.csproj u.c.). .gitignore ieraksti .godot/, bin/ un obj/ katru savā rindā.

Kā iesniedz: veic commit (izmaiņu fiksējums) un push (nosūtīšana uz attālo krātuvi). Skolotāja norādītajā vietā iesniedz GitHub krātuves saiti; README.md un pārbaudes pierādījumiem jābūt krātuvē.
