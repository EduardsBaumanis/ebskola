1.6 Noslēguma project (projekts): Pong

Stundas uzdevums: Pabeigt Pong punktu, serves, uzvaras un atkārtotas game loop (spēles ciklu) un individualizēt dizainu un stāstu.

SR 2.4.1. Problem decomposition (problēmas dekompozīcija) SR 2.4.7. UI (lietotāja saskarne) SR 2.4.15. Modular program (modulāras programmas) SR 2.4.3. Prototipu izstrāde un testing (testēšana)

80 min plāns: Kritēriji (~10 min) · game loop (spēles cikls) (~25 min) · savs noformējums un stāsts (~20 min) · pārbaude pārī (~20 min) · iesniegšana (~5 min).

Pirms sāc: turpini 1.5 Main.tscn. Abas raketes un bumba jau darbojas, Input Map (ievades darbību karte) ir arī serve un restart (pārstartēšana). Šodien pabeigsi partiju, kuru divi cilvēki var izspēlēt no sākuma līdz uzvarai un sākt vēlreiz.

Darba ritms: pēc katra uzdevuma saglabā un pārbaudi rezultātu. Kad project (projektam) pievienots C# script (skripts), pirms palaišanas nospied Build (būvēt projektu). Kļūdu gadījumā sāc ar pirmo sarkano kļūdu, nevis nākamo uzdevumu.

Kas vēl vajadzīgs pilnai spēlei?

Pamatprasības: divu spēlētāju vadība, atlēkšana no raketēm un sienām, pareizi punkti, uzvara pie 5 punktiem, redzamas norādes un R jaunai partijai. Pirms pirmās un katras nākamās izspēles bumba gaida Space; serves virziens pēc katra punkta mainās.

Paddle.cs atbild par vienas raketes kustību. Ball.cs atbild par lidojumu, atlēkšanu un ExitSide. Game.cs nolasa iziešanas pusi, piešķir punktu, atjaunina tekstu un vada spēles sākumu un beigas. Ar vienu Main scene (scēnu) Autoload (automātiska ielāde) nav vajadzīgs.

1.6 Game.cs — pilns file (fails) salīdzināšanai

Lejupielādēt Game.cs. Aizstāj tikai atbilstošā file (faila) saturu; neveido otru tāda paša nosaukuma class (klasi).

using Godot;

public partial class Game : Node2D
{
    [Export] public string GameTitle = "Zvaigžņu duelis";
    [Export] public string LeftName = "Komēta";
    [Export] public string RightName = "Meteors";
    [Export] public string Mission = "Divas kosmosa komandas sacenšas par enerģijas kodolu.";
    [Export] public string VictoryText = "Enerģijas kodols ir nogādāts mājās!";
    [Export(PropertyHint.Range, "1,20,1")] public int TargetScore = 5;

    public int ScoreLeft { get; private set; } = 0;
    public int ScoreRight { get; private set; } = 0;
    public bool GameOver { get; private set; } = false;

    private Ball ball;
    private Paddle left;
    private Paddle right;
    private Label score;
    private Label message;
    private int serveDirection = 1;

    public override void _Ready()
    {
        ball = GetNode<Ball>("Ball");
        left = GetNode<Paddle>("PaddleLeft");
        right = GetNode<Paddle>("PaddleRight");
        score = GetNode<Label>("HUD/Score");
        message = GetNode<Label>("HUD/Message");
        TargetScore = Mathf.Max(1, TargetScore);
        GetNode<Label>("HUD/Instructions").Text =
            $"{GameTitle} | W/S: {LeftName} | ↑/↓: {RightName} | Space: serve | R: jauna partija";
        PrepareServe();
        message.Text = $"{Mission} Uzvara pie {TargetScore} punktiem. Nospied Space!";
        UpdateScore();
    }

    public override void _Process(double delta)
    {
        if (Input.IsActionJustPressed("restart"))
        {
            GetTree().ReloadCurrentScene();
            return;
        }
        if (GameOver) return;

        if (ball.ExitSide != 0)
        {
            AddPoint(ball.ExitSide > 0);
            return;
        }

        if (!ball.IsMoving && Input.IsActionJustPressed("serve"))
        {
            ball.Serve(serveDirection);
            message.Text = $"Pirmais līdz {TargetScore} punktiem uzvar!";
        }
    }

    private void AddPoint(bool leftScored)
    {
        if (leftScored) ScoreLeft++;
        else ScoreRight++;
        UpdateScore();

        if (ScoreLeft >= TargetScore || ScoreRight >= TargetScore)
        {
            GameOver = true;
            ball.Stop();
            left.IsActive = false;
            right.IsActive = false;
            left.Velocity = Vector2.Zero;
            right.Velocity = Vector2.Zero;
            string winner = ScoreLeft >= TargetScore ? LeftName : RightName;
            message.Text = $"Uzvar {winner}! {VictoryText} Nospied R jaunai partijai.";
        }
        else
        {
            serveDirection = -serveDirection;
            PrepareServe();
        }
    }

    private void PrepareServe()
    {
        ball.ResetBall();
        left.Position = new Vector2(60, 360);
        right.Position = new Vector2(1220, 360);
        left.Velocity = Vector2.Zero;
        right.Velocity = Vector2.Zero;
        message.Text = "Nākamā izspēle: nospied Space!";
    }

    private void UpdateScore()
    {
        score.Text = $"{ScoreLeft} : {ScoreRight}";
    }
}

Gatavs, kad: var pabeigt partiju līdz 5 punktiem un atkārtot to ar R; uzvarētājs un vadība redzami spēlē.

Izpako atsevišķā folder (mapē), atver Godot .NET Project Manager (projektu pārvaldnieks) → Import (importēt) → project.godot, nospied Build (būvēt projektu) un F5. Piemērs sagatavots Godot 4.7.2 .NET un .NET 8 SDK (programmatūras izstrādes komplekts). Ja class (klasē) lieto citu Godot 4 .NET version (versiju), izveido tajā tukšu C# project (projektu) un pārnes piemēra Scenes (scēnas), Scripts (skripti) un Input Map (ievades darbību karte), saglabājot savas version (versijas) ģenerēto .csproj un iestatot 1280 × 720 un Main.tscn kā main scene (galveno scēnu).

Salīdzini kļūdaino daļu ar savu project (projektu), izlabo un paskaidro atšķirību. Pilns piemērs palīdz atrast kļūdas; individuālās dizaina izvēles īsteno pats. Palaišana un piemēra pārbaudes.

2. uzdevums -

Piešķir spēlei savu dizainu un sacensības stāstu

  1. Izdomā spēles nosaukumu un trīs teikumos apraksti, kas sacenšas, ko simbolizē bumba un kāds ir sacensības mērķis. Tas var būt kosmosa duelis, zemūdeņu spēle vai paša izdomāts sporta veids.
  2. Pēc Build (būvēt projektu) atlasi Main. Inspector (īpašību panelis) field (laukos) Game Title, Left Name, Right Name, Mission un Victory Text ievadi savu nosaukumu, abu komandu vārdus, stāsta ievadu un noslēgumu. Tie jāredz pašā spēlē, ne tikai README.md.
  3. Izmaini vismaz trīs vizuālus element (elementus): rakešu noformējumu, bumbu, fonu, sienas, viduslīniju vai rezultāta uzrakstu. Maini Polygon2D (2D daudzstūris) krāsas/figūras vai izmanto paša zīmētus attēlus. Saglabā salasāmu rezultātu un labi saskatāmu bumbu.
  4. Ja lieto PNG (bezzudumu attēlu formāts): izveido Art folder (mapi), importē attēlu un attiecīgajai object (objekta) root (saknei) pievieno Sprite2D (2D attēla mezgls) ar šo Texture (tekstūrā); paslēp veco Visual. Mēro attēlu, saglabājot fizikas root (saknes) Scale (mērogs) (1,1) un sākotnējo collision (sadursmes) izmēru: rakete 24 × 120, bumba 20 × 20. Ārējiem resource (resursiem) norādi autoru un lietošanas permission (atļauju).
  5. Pamato vismaz trīs dizaina izvēles README.md un pārbaudi spēli pēc izmaiņām. Ja maini spēles tempu, abām raketēm saglabā vienādus condition (nosacījumus) un pieraksti izmēģinātos ātrumus. Pamatpartija joprojām beidzas pie 5 punktiem.

Gatavs, kad: spēlei ir savs nosaukums, komandas, sākuma un uzvaras teksts, kā arī vismaz trīs pamatotas vizuālas izmaiņas.

3. uzdevums -

Izspēlē pilnu partiju un pārbaudi arī kļūdu situācijas

  1. Palūdz diviem klasesbiedriem sākt spēli bez mutiskām norādēm. Viņiem no screen (ekrāna) jāsaprot vadība, Space nozīme un uzvaras condition (nosacījums). Pieraksti vienu ieteikumu.
  2. Veic visas zemāk norādītās pārbaudes un README.md atzīmē sagaidāmo un faktisko rezultātu. Pārbaudi gan kreisā, gan labā spēlētāja uzvaru.
  3. Īsteno vienu testētāja ieteikumu vai izlabo atrasto kļūdu. Ja mainīji ātrumu, formu vai tekstu, vēlreiz izspēlē attiecīgo situāciju.
  4. Atver project (projekta) kopiju atsevišķā folder (mapē) bez .godot cache (kešatmiņas): Import (importēt), Build (būvēt projektu), F5. Pārliecinies, ka visi attēli, scene (scēnas) un script (skripti) tiešām ir iesniegtajā project (projektā).
  5. Ieraksti īsu video ar sava dizaina skatu, vadību, atlēkšanu, punktu iegūšanu, uzvaras tekstu un R. Saglabā visu ar Commit (izmaiņu fiksējums) un Push (nosūtīšana uz attālo krātuvi) un iesniedz GitHub repository (krātuves) link (saiti).

6. stundas apkopojums: tavs Pong, tavs dizains un stāsts

Kopīga Pong gameplay mechanic (mehānika) ļauj radīt atšķirīgas spēles. Tu pats izvēlies pasauli, abu komandu identitāti, bumbas nozīmi, krāsu paleti, vizuālos simbolus un uzvaras stāstu. Raketes var attēlot kuģus, dzīvniekus vai izdomātus sportistus, kamēr to vadība paliek saprotama.

Parādi savu ideju pašā spēlē: nosaukumā un sākuma mērķī, object (objektu) izskatā un uzvaras tekstā. Apkopojumā paskaidro vismaz trīs dizaina izvēles un to, kā tās palīdz spēlētājam uztvert spēli. Arī vienkāršas paša veidotas figūras var izteikt oriģinālu ieceri.

Pašvērtējums: vai abi spēlētāji saprot vadību un uzvaras condition (nosacījumu)? Vai var sākt jaunu partiju? Kas project (projektā) atspoguļo manu ieceri? Ko uzlaboju pēc klasesbiedru pārbaudes?
