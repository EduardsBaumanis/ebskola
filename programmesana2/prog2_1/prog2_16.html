Problēmas dekompozīcija un atbildību sadale

Apjomīgākās programmās visu loģiku neraksta vienā failā — sistēmu sadala neatkarīgos moduļos (dekompozīcija). Katra komponenta class (klase) atbild tikai par viena objekta uzvedību (piemēram, kustību vai sadursmju noteikšanu), savukārt atsevišķa vadības klase nolasa komponentu stāvokļus, atjaunina skaitītājus un pārvalda programmas posmus (gaidīšana, aktīva darbība, noslēgums).

To var salīdzināt ar orķestri: katrs mūziķis atskaņo tikai savu partiju, bet diriģents koordinē sākumu, pauzes un finālu. Ja visa lietotne darbojas vienā galvenajā scēnā, šo koordināciju pilnībā veic saknes mezglam piesaistīts skripts, un globāla Autoload (automātiska ielāde) sistēma nav nepieciešama:

// Komponenta klase — atbild tikai par sava objekta lokālo stāvokli
public partial class Sensors : Node2D
{
    public bool IrNostradajis { get; private set; } = false;
    public void Atiestatit() { IrNostradajis = false; }
}

// Vadības klases loģika — nolasa stāvokli un koordinē kopējo procesu
if (sensors.IrNostradajis)
{
    notikumuSkaits++;
    sensors.Atiestatit();
}

Mezglu savienošana (GetNode), notikumu ievade un scēnas pārlāde

Lai vadības klase sazinātos ar scēnas bērnmezgliem, metodē _Ready() saglabā atsauces ar GetNode<Tips>("Ceļš/Līdz/Mezglam"). Ceļam precīzi jāsakrīt ar mezglu nosaukumiem un hierarhiju Scene kokā - gluži kā faila ceļam mapju struktūrā.

Vispārējai stāvokļa uzraudzībai katrā kadrā izmanto metodi _Process(double delta). Vienreizējām komandām (piemēram, procesa palaišanai vai atiestatīšanai) lieto Input.IsActionJustPressed("darbiba"), kas nostrādā tikai vienā kadrā taustiņa nospiešanas brīdī (kā durvju zvana poga, nevis nepārtraukti turēts slēdzis). Savukārt GetTree().ReloadCurrentScene() pilnībā pārlādē pašreizējo scēnu, atgriežot visus skaitītājus un objektus sākuma stāvoklī:

private KustigsObjekts objekts;

public override void _Ready()
{
    // Ceļam precīzi jāsakrīt ar mezgla vārdu un vietu Scene kokā
    objekts = GetNode<KustigsObjekts>("KustigsObjekts");
}

public override void _Process(double delta)
{
    if (Input.IsActionJustPressed("reset_scene"))
    {
        GetTree().ReloadCurrentScene(); // Pilnībā pārlādē aktīvo scēnu
        return;
    }

    if (Input.IsActionJustPressed("start_process"))
        objekts.SaktDarbibu(); // Nostrādā vienreiz nospiešanas kadrā
}

Lietotāja saskarnes slānis (CanvasLayer un Label)

Skaitītājus un teksta norādes ekrānā attēlo ar Label (teksta etiķete) mezgliem, kurus grupē zem CanvasLayer (zīmēšanas slānis). CanvasLayer darbojas kā nekustīga, caurspīdīga stikla plāksne virs 2D telpas (līdzīgi kā kameras ekrāna indikatori viedtālrunī): uzraksti vienmēr paliek fiksētā ekrāna vietā un nepiedalās fiziskās sadursmēs ar 2D objektiem. C# kodā etiķetes saturu atjaunina ar īpašību Text, norādot ceļu caur CanvasLayer mezglu:

// Mezglu koks: Sakne → InfoSlanis (CanvasLayer) → Skaititajs (Label)
private Label skaititajs;
private int skaits = 0;

public override void _Ready()
{
    skaititajs = GetNode<Label>("InfoSlanis/Skaititajs");
    skaititajs.Text = $"Reģistrēti notikumi: {skaits}";
}

1.6 Game.cs - pilns fails salīdzināšanai

Lejupielādēt Game.cs. Atver failu Scripts/Game.cs un aizstāj tā saturu ar šo kodu.

using Godot;

public partial class Game : Node2D
{
    [Export] public string GameTitle = "Zvaigžņu duelis";
    [Export] public string LeftName = "Komēta";
    [Export] public string RightName = "Meteors";
    [Export] public string Mission = "Divas kosmosa komandas sacenšas par enerģijas kodolu.";
    [Export] public string VictoryText = "Enerģijas kodols ir nogādāts mājās!";
    [Export(PropertyHint.Range, "1,20,1")] public int TargetScore = 5;

    public int ScoreLeft { get; private set; } = 0;
    public int ScoreRight { get; private set; } = 0;
    public bool GameOver { get; private set; } = false;

    private Ball ball;
    private Paddle left;
    private Paddle right;
    private Label score;
    private Label message;
    private int serveDirection = 1;

    public override void _Ready()
    {
        ball = GetNode<Ball>("Ball");
        left = GetNode<Paddle>("PaddleLeft");
        right = GetNode<Paddle>("PaddleRight");
        score = GetNode<Label>("HUD/Score");
        message = GetNode<Label>("HUD/Message");
        TargetScore = Mathf.Max(1, TargetScore);
        GetNode<Label>("HUD/Instructions").Text =
            $"{GameTitle} | W/S: {LeftName} | ↑/↓: {RightName} | Space: serve | R: jauna partija";
        PrepareServe();
        message.Text = $"{Mission} Uzvara pie {TargetScore} punktiem. Nospied Space!";
        UpdateScore();
    }

    public override void _Process(double delta)
    {
        if (Input.IsActionJustPressed("restart"))
        {
            GetTree().ReloadCurrentScene();
            return;
        }
        if (GameOver) return;

        if (ball.ExitSide != 0)
        {
            AddPoint(ball.ExitSide > 0);
            return;
        }

        if (!ball.IsMoving && Input.IsActionJustPressed("serve"))
        {
            ball.Serve(serveDirection);
            message.Text = $"Pirmais līdz {TargetScore} punktiem uzvar!";
        }
    }

    private void AddPoint(bool leftScored)
    {
        if (leftScored) ScoreLeft++;
        else ScoreRight++;
        UpdateScore();

        if (ScoreLeft >= TargetScore || ScoreRight >= TargetScore)
        {
            GameOver = true;
            ball.Stop();
            left.IsActive = false;
            right.IsActive = false;
            left.Velocity = Vector2.Zero;
            right.Velocity = Vector2.Zero;
            string winner = ScoreLeft >= TargetScore ? LeftName : RightName;
            message.Text = $"Uzvar {winner}! {VictoryText} Nospied R jaunai partijai.";
        }
        else
        {
            serveDirection = -serveDirection;
            PrepareServe();
        }
    }

    private void PrepareServe()
    {
        ball.ResetBall();
        left.Position = new Vector2(60, 360);
        right.Position = new Vector2(1220, 360);
        left.Velocity = Vector2.Zero;
        right.Velocity = Vector2.Zero;
        message.Text = "Nākamā izspēle: nospied Space!";
    }

    private void UpdateScore()
    {
        score.Text = $"{ScoreLeft} : {ScoreRight}";
    }
}

Gatavs, kad: var pabeigt pilnu Pong partiju līdz 5 punktiem ar servi (Space) un restartu (R), un spēlē redzams gan uzvarētājs, gan vadības norādes.

Piešķir spēlei savu dizainu un sacensības stāstu

Kur strādāt: Spēles tekstus un laukuma dizainu pielāgo scēnā Scenes/Main.tscn; kopīgo rakešu un bumbas izskatu maini scēnās Scenes/Paddle.tscn un Scenes/Ball.tscn; attēlus saglabā mapē Art/, bet stāstu un dizaina pamatojumu raksti failā README.md.

  1. Uzraksti spēles stāstu failā README.md: izvēlies spēles nosaukumu un README.md failā trīs īsos teikumos apraksti, kas sacenšas, ko simbolizē bumba un kāds ir sacensības mērķis (piemēram, divas zemūdenes sargā pērli vai kosmosa komandas sacenšas par enerģijas kodolu).
  2. Nomaini spēles tekstus scēnā Scenes/Main.tscn: atver Main.tscn, Scene panelī atlasi saknes mezglu Main (kam piesaistīts Game.cs) un Inspector panelī nomaini visus piecus tekstus: Game Title, Left Name, Right Name, Mission un Victory Text. Palaid ar F5 un pārliecinies, ka teksti redzami spēles ekrānā.
  3. Pielāgo vismaz trīs vizuālos elementus (Paddle.tscn, Ball.tscn, Main.tscn): maini rakešu (Paddle.tscn → Visual), bumbas (Ball.tscn → Visual), sienu (WallTop/WallBottom → Visual), viduslīnijas (CenterLine) vai rezultāta uzrakstu (HUD/* krāsu un fontu) izskatu, saglabājot labu kontrastu un salasāmu rezultātu.
  4. (Pēc izvēles) Pievieno PNG attēlus ar Sprite2D: ja lieto attēlus, izveido mapi res://Art, iekopē tajā PNG failus, attiecīgajai scēnai pievieno Sprite2D ar izvēlēto Texture un paslēp veco Visual. Maini tikai Sprite2D mērogu, saglabājot fizikas saknes Scale = (1, 1) un sadursmes formas izmēru (rakete 24 × 120, bumba 20 × 20); ārējiem attēliem norādi autoru un licenci failā README.md.
  5. Pamato dizaina izvēles failā README.md: failā README.md pamato vismaz trīs savas dizaina izvēles un pārbaudi spēli pēc izmaiņām ar F5 (abām raketēm saglabā vienādu ātrumu, un pamatpartijai jābeidzas pie Target Score = 5).

Gatavs, kad: spēlē redzams tavs nosaukums, abas komandas, sākuma un uzvaras teksti, kā arī vismaz trīs pamatotas vizuālas izmaiņas.

6. stundas apkopojums: tavs Pong, tavs dizains un stāsts

Kopīga Pong gameplay mehānika ļauj radīt atšķirīgas spēles. Tu pats izvēlies pasauli, abu komandu identitāti, bumbas nozīmi, krāsu paleti, vizuālos simbolus un uzvaras stāstu. Raketes var attēlot kuģus, dzīvniekus vai izdomātus sportistus, kamēr to vadība paliek saprotama.

Parādi savu ideju pašā spēlē: nosaukumā un sākuma mērķī, objektu izskatā un uzvaras tekstā. Apkopojumā paskaidro vismaz trīs dizaina izvēles un to, kā tās palīdz spēlētājam uztvert spēli. Arī vienkāršas paša veidotas figūras var izteikt oriģinālu ieceri.

Pašvērtējums: vai abi spēlētāji saprot vadību un uzvaras nosacījumu? Vai var sākt jaunu partiju? Kas projektā atspoguļo manu ieceri? Ko uzlaboju pēc klasesbiedru pārbaudes?
