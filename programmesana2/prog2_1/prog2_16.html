1.6 Noslēguma projekts: Pong

Stundas uzdevums: Apvienot tēmas prasmes - Godot Scene Tree, C# klases - pilnvērtīgā Pong arkādes spēlē.

SR 2.4.1. Problēmas dekompozīcija SR 2.4.7. UI SR 2.4.15. Modulāras programmas SR 2.4.3. Prototipu izstrāde un testēšana

80 min plāns: Ievads un kritēriju pārruna (~10 min) · 1. uzdevums (~20 min) - liec paddle kustēties · 2. uzdevums (~25 min) - liec bumbai lidot un atlekt · 3. uzdevums (~20 min) - pievieno punktus un uzvaru · Iesniegšana (~5 min).

Pirms sāc: šis ir 1. tēmas noslēguma projekts. Laukums jau ir gatavs no 1.5 stundas - šodien pievienosi kustību. Strādā pa vienam objektam: vispirms paddle, tad bumba, tad punkti.

Fokuss: pēc katra uzdevuma palaid spēli un pārbaudi tikai vienu lietu. Ja reizē labo paddle, bumbu un punktus, kļūdu būs grūtāk atrast.

Teorija: Spēles apraksts un arhitektūra

Pong ir klasiska 1972. gada arkādes spēle. Divi spēlētāji vada vertikālas paddles un atsit bumbu pretiniekam. Pirmais ar 5 punktiem uzvar.

Šis projekts ir labs 1. tēmas noslēgumam, jo tajā ir maz objektu, bet tie pārbauda gandrīz visu pamatu: Scene Tree, atkārtoti lietojamas scēnas, Input Map, C# klases, sadursmes, UI atjaunināšanu un spēles stāvokli. Pong nav izvēlēts tāpēc, ka tas ir vizuāli sarežģīts; tas ir izvēlēts tāpēc, ka kļūdas tajā ir viegli pamanāmas.

Spēles loģika tiek rakstīta C#. Godot editorā drīkst salikt scēnas un iestatīt resursus, bet paddle kustība, bumbas atlēkšana, punktu pieskaitīšana un uzvaras pārbaude jārealizē .cs skriptos.

C# klases:

  • Paddle - spēlētāja vadītā raķete ar Input Map darbībām p1_up, p1_down, p2_up un p2_down.
  • Ball - bumba ar ātrumu, sadursmju apstrādi un reset mehāniku.
  • Game - punktu uzskaite, UI atjaunināšana, uzvaras noteikšana un raunda restartēšana.
using Godot;

public partial class Game : Node
{
    private int scoreLeft = 0;
    private int scoreRight = 0;
    private Ball ball;

    public override void _Ready()
    {
        ball = GetNode<Ball>("Ball");
    }

    public void OnScore(bool leftPlayer)
    {
        if (leftPlayer) scoreLeft++;
        else scoreRight++;

        UpdateScoreLabels();
        ball.ResetBall();
    }

    private void UpdateScoreLabels()
    {
        GetNode<Label>("Punkti").Text = scoreLeft + " : " + scoreRight;
    }
}

Praktiskie uzdevumi

1. uzdevums - Liec paddle kustēties

Beigās abi spēlētāji varēs vadīt savu paddle ar taustiņiem.

Ko šis māca: sasaistīt Input Map darbības ar C# kodu, lai taustiņus var mainīt editorā, nevis meklēt kodā.

  1. Atver Project -> Project Settings -> Input Map.
  2. Izveido darbības p1_up, p1_down, p2_up, p2_down.
  3. Piesaisti tām taustiņus W, S, augšupbulta un lejupbulta.
  4. Izvēlies PaddleLeft un piesaisti tam jaunu C# skriptu Paddle.cs, kas manto no CharacterBody2D.
  5. Pievieno klasē laukus [Export] public string InputUp = "p1_up";, [Export] public string InputDown = "p1_down"; un [Export] public float Speed = 420.0f;.
  6. Piesaisti to pašu Paddle.cs skriptu arī PaddleRight.
  7. Inspector panelī PaddleRight laukiem ieraksti InputUp = p2_up un InputDown = p2_down.
  8. Uzraksti metodē _PhysicsProcess(double delta) ātruma aprēķinu pēc Input.IsActionPressed(InputUp) un Input.IsActionPressed(InputDown).
  9. Izsauc MoveAndSlide(), būvē projektu ar Godot Build pogu un pārbaudi abus paddle.

Gatavs, kad: abi paddle kustas augšup un lejup ar saviem taustiņiem un neiziet ārpus sienām.

2. uzdevums - Liec bumbai lidot un atlekt

Beigās bumba lidos pa laukumu un atlēks no sienām un paddle.

Ko šis māca: izmantot delta un sadursmes rezultātu, lai kustība būtu stabila, nevis atkarīga no datora ātruma.

  1. Izvēlies Ball un piesaisti tam jaunu C# skriptu Ball.cs, kas manto no CharacterBody2D.
  2. Pievieno lauku private Vector2 velocity; un [Export] public float BaseSpeed = 420.0f;.
  3. Uzraksti metodi ResetBall(), kas noliek bumbu centrā un dod nejaušu Y ātrumu.
  4. Izsauc ResetBall() metodē _Ready(), lai bumba sāktu kustēties spēles sākumā.
  5. Izsauc _PhysicsProcess metodē MoveAndCollide(velocity * (float)delta).
  6. Pārbaudi, vai atgrieztā sadursme nav null, un atspoguļo ātrumu ar velocity.Bounce(...).
  7. Būvē projektu un palaid spēli.
  8. Pieraksti, kāpēc ātrums jāreizina ar delta.

Gatavs, kad: bumba lido, atlec no abām sienām un no abiem paddle, un neiestrēgst sienā.

3. uzdevums - Pievieno punktus un uzvaru

Beigās spēle skaitīs punktus un paziņos uzvarētāju.

Ko šis māca: glabāt spēles stāvokli C# laukos un pēc katras izmaiņas atjaunināt redzamo UI tekstu.

  1. Izvēlies Main un piesaisti tam jaunu C# skriptu Game.cs.
  2. Pievieno Game.cs laukus scoreLeft, scoreRight un atsauci uz Ball.
  3. Uzraksti metodi OnScore(bool leftPlayer), kas palielina pareizo punktu skaitu.
  4. Atjaunini Punkti mezgla tekstu pēc katra punkta formā 0 : 0.
  5. Izsauc pēc punkta ResetBall().
  6. Ball.cs pārbaudi: ja bumbas x ir mazāks par 0, punktu saņem labais spēlētājs; ja x ir lielāks par 1280, punktu saņem kreisais.
  7. Pievieno pārbaudi: kad kāds sasniedz 5 punktus, parādi uzvarētāju un aptur bumbu.
  8. Izspēlē vienu pilnu partiju līdz 5 punktiem, tad veic commit un push.

Gatavs, kad: spēle pareizi skaita punktus abiem spēlētājiem un beidzas, kad kāds sasniedz 5.

Papildu uzdevums - Paātrini bumbu pēc katra sitiena

Ja pamatdarbs ir gatavs, padari spēli grūtāku ar laiku.

Ko šis māca: mainīt spēles grūtību kontrolēti: palielini ātrumu, bet saglabā augšējo robežu un reset sākumstāvokli.

  1. Pievieno klasei Ball lauku ar paātrinājuma koeficientu.
  2. Palielini ātrumu par dažiem procentiem pēc katras sadursmes ar paddle.
  3. Ierobežo maksimālo ātrumu, lai bumba neizlido cauri sienai.
  4. Atgriez sākuma ātrumu pēc katra punkta.
  5. Izspēlē partiju un pārbaudi, vai bumba nekad neizlido cauri paddle.

Gatavs, kad: bumba ar katru sitienu kļūst manāmi ātrāka, bet nekad neizlido cauri objektiem.

Pašpārbaude pirms iesniegšanas

Izspēlē īsu testu un pārbaudi, vai katra sistēma strādā atsevišķi.

  • Vadība: W/S kustina kreiso paddle, bultas kustina labo paddle.
  • Ball: pēc palaišanas tā kustas un atlec no sienām un paddle.
  • Punkti: kad bumba iziet ārpus malas, Punkti mainās, un pie 5 punktiem redzams uzvarētājs.

Biežākās kļūdas

  • Ball iziet cauri paddle: ātrums pārāk augsts; lieto MoveAndCollide(), nevis tiešu Position pārbīdi.
  • Punkti netiek atjaunināti: pārliecinies par GetNode<Label>("Punkti") references ceļu. Ja liki punktus zem UI, ceļš ir UI/Punkti.
  • Build neizmainās: nospied Godot Build pogu vai palaid dotnet build no projekta mapes.

Godot ekrānuzņēmumi

Koda piemērs (paplašināts)

using Godot;

public partial class Ball : CharacterBody2D
{
    [Export] public float BaseSpeed = 420.0f;
    private Vector2 velocity;

    public override void _Ready()
    {
        ResetBall();
    }

    public void ResetBall()
    {
        Position = new Vector2(640, 360);
        float ySpeed = (float)GD.RandRange(-180.0, 180.0);
        velocity = new Vector2(BaseSpeed, ySpeed);
    }

    public override void _PhysicsProcess(double delta)
    {
        KinematicCollision2D collision = MoveAndCollide(velocity * (float)delta);
        if (collision != null)
        {
            velocity = velocity.Bounce(collision.GetNormal()) * 1.05f;
        }
    }
}
