# 02 špikeris

1. tēmas špikeris — projekta noteikumi

Pilnos koda failus un precīzas ievietošanas vietas skati attiecīgajās stundās.

1.1 Saglabā projektu

Godot .NET; 1280 × 720; Compatibility; canvas_items ar keep proporcijām. Galvenā scēna res://Scenes/Main.tscn. F5 palaiž projektu, F6 atvērto scēnu. Git saglabā iestatījumus, scēnas, skriptus un resursus; .godot, bin un obj ignorē. Commit ir lokāls, Publish/Push nosūta uz GitHub.

1.2 Scene un instance

Paddle.tscn un Ball.tscn saknes ir CharacterBody2D (vadāma 2D tēla mezgls), bērni — Visual (Polygon2D (2D daudzstūris)) un CollisionShape2D (2D sadursmes forma). Main instance pozīcijas (60,360), (1220,360), (640,360). Scene izmaiņa attiecas uz abām raketēm; instance iestatījums — uz konkrēto raketi.

1.3 C# vide

Vajadzīgs atsevišķs .NET SDK. dotnet --list-sdks pārbauda instalāciju. Pirmais C# skripts izveido projekta failus; tikai tad lieto dotnet build no mapes ar .csproj. Faila un class (klases) nosaukumiem jāsakrīt; class vajag partial (pa failiem sadalāma klase) un atbilstošu Godot bāzes type (tipu).

1.4 Data un Inspector

float (daļskaitlis) — Speed (ātrums); string (teksta virkne) — InputUp/InputDown; bool (loģiska vērtība) — IsActive; int (vesels skaitlis) — punkti; Vector2 (divdimensiju vektors) — pozīcija vai ātrums. Pēc Export maiņas nospied Build. Inspector saglabāta vērtība var pārrakstīt koda noklusējumu.

1.5 Kustība un sadursmes

W/S → p1_up/p1_down; ↑/↓ → p2_up/p2_down. Rakete lieto Velocity un MoveAndSlide bez papildu delta (soļa ilgums). Bumba lieto MoveAndCollide(Velocity × delta) un Bounce. Sienas: Layer 1, Mask nav; raketes: Layer 2, Mask 1; bumba: Layer 3, Mask 1 un 2. Tie ir Inspector ķeksīšu numuri.

1.6 Pilns game loop (spēles cikls)

Bumba pa labi → punkts kreisajam; pa kreisi → labajam. ResetBall nodzēš ExitSide un atgriež bumbu centrā. Space sāk nākamo izspēli. Pie 5 punktiem parādās uzvarētājs un kustība apstājas; R pārlādē scēnu ar 0 : 0. Main laukos pielāgo nosaukumu, komandas un stāsta tekstus; veido savu noformējumu.
