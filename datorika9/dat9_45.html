Teorija ar piemēriem

Kā getBoundingClientRect() un saduras(a, b) pamana divu kvadrātu pārklāšanos

Spēlēs sadursme nozīmē brīdi, kad divi redzami ekrāna taisnstūri daļēji vai pilnībā pārklājas. Lai salīdzinātu abu elementu robežas, sākuma kodā ir iekļauta gatava palīgfunkcija saduras(a, b):

function saduras(a, b) {
  const p = a.getBoundingClientRect();
  const q = b.getBoundingClientRect();
  return p.left < q.right && p.right > q.left &&
         p.top < q.bottom && p.bottom > q.top;
}
  • Četras malas ekrānā: metode getBoundingClientRect() katram elementam izmēra četras robežas pikseļos pārlūka logā — kreiso (left), labo (right), augšējo (top) un apakšējo (bottom).
  • Loģiskais “UN” (&&): lai taisnstūri pārklātos, kopīgai daļai jābūt gan platumā (p.left < q.right && p.right > q.left), gan augstumā (p.top < q.bottom && p.bottom > q.top). Visiem četriem salīdzinājumiem jābūt patiesiem vienlaikus.
  • Atgrieztā atbilde (return): atšķirībā no paradit(), kas maina lapas tekstu, saduras(a, b) ar komandu return atdod loģisku vērtību — true (ir sadursme) vai false (nav sadursmes). Tāpēc to liek tieši if (...) iekavās!

Spēles karodziņš (true / false), vadības bloķēšana un krāsas atjaunošana

Ar vienu pašu clearInterval sadursmes brīdī nepietiek: tas gan apturētu pretinieku, taču spēlētājs ar pogām vai tastatūras bultiņām varētu turpināt staigāt pa laukumu pēc zaudējuma! Tāpēc spēles dzinējā ievieš loģisko stāvokļa mainīgo jeb karodziņu (piemēram, let spelesGaita = false;):

let spelesGaita = false;

function biditVaroni(dx, dy) {
  if (!spelesGaita) { return; }
  // Tālākās kustības rindas izpildās TIKAI tad, ja spelesGaita ir true
}

function parbauditSadursmi() {

    spelesGaita = false;
    clearInterval(kustibasTaimeris);
    varonis.style.backgroundColor = "#d97706";
    document.getElementById("zinojums").textContent = "Šķērslis skarts! Raunds beidzies.";
  }
}
  • Sargs kustības sākumā (if (!spelesGaita) { return; }): izsaukuma zīme ! nozīmē “NAV”. Ja spelesGaita ir false (pirms starta vai pēc sadursmes), return; tūlīt pārtrauc funkciju un neļauj varonim izkustēties. Savukārt sākšanas funkcijā pretēja pārbaude if (spelesGaita) { return; } neļauj nejauši pārstartēt jau notiekošu raundu.
  • Vizuāls signāls (.style.backgroundColor): CSS īpašību background-color JavaScript valodā raksta bez defises kā vienu vārdu — backgroundColor. Pēc sadursmes tā iekrāso kvadrātu brīdinājuma tonī (piemēram, tumši sarkanā "#6b1d1d" vai oranžā "#d97706").
  • Krāsas atiestatīšana ar tukšu tekstu "": uzsākot jaunu raundu vai atiestatot spēli, ar varonis.style.backgroundColor = ""; noņem JavaScript uzlikto krāsu — tad kvadrātam automātiski atgriežas sākotnējā krāsa no <style> CSS noteikuma!

Kurās vietās un kādā secībā jāizsauc parbaudit()?

Sadursme var notikt divos dažādos veidos: 1) spēlētājs stāv uz vietas un pretinieka taimeris uzbrauc viņam virsū, vai 2) pats spēlētājs ar pogu vai taustiņu uzkāpj kustīgajam pretiniekam. Tāpēc sadursmes pārbaudes funkciju obligāti izsauc abās kustību funkcijās — un vienmēr pēc elementu pārzīmēšanas:

// Gan spēlētāja kustības beigās, gan pretinieka taimera soļa beigās:
paradit();
parbauditSadursmi();

Kāpēc vispirms paradit() un tikai tad sadursmes pārbaude? Tāpēc, ka getBoundingClientRect() mēra kvadrātu faktisko atrašanās vietu ekrānā (.style.left un .style.top), nevis mainīgos x un y atmiņā. Ja pārbaudītu pirms paradit(), pārlūks salīdzinātu vēl iepriekšējā soļa vecās koordinātes!

Pašpārbaude: kāpēc pēc sadursmes nepietiek tikai ar krāsas maiņu un clearInterval(taimeris), un ko izdara rinda speletajs.style.backgroundColor = "";?

1) Bez aktiva = false spēlētāja kustības funkcija nezinātu, ka spēle ir beigusies, un ļautu turpināt pārvietot kvadrātu ar pogām un bultiņām (kā arī neļautu no jauna nospiest Sākt). 2) Tukšās pēdiņas "" notīra JavaScript uzlikto sadursmes krāsu, lai atkal darbotos <style> daļā iestatītā spēlētāja sākuma krāsa.

2. uzdevums

Ieprogrammē parbaudit() un izsauc to pēc abām kustībām

Izmanto teoriju: Spēles karodziņš, vadības bloķēšana un krāsa un Kurās vietās izsauc parbaudit()?.

Vide: VS Code → pārlūks

  1. <script> blokā atver tukšo funkciju function parbaudit() { ... } un komentāra vietā uzraksti nosacījumu if (saduras(speletajs, pretinieks)) { ... }.
  2. Šī if bloka iekšpusē vispirms nobloķē spēles gaitu ar aktiva = false; un apturi taimeri ar clearInterval(taimeris);.
  3. Turpat if blokā pievieno spēlētāja sadursmes krāsu (piemēram, speletajs.style.backgroundColor = "#6b1d1d"; vai "#d97706") un ieraksti skaidru beigu paziņojumu elementā document.getElementById("stavoklis").textContent.
  4. Atrodi spēlētāja kustības funkciju kustinat(dx, dy) un tieši pēc rindas paradit(); (komentāra vietā) izsauc parbaudit();.
  5. Atrodi pretinieka soļa funkciju cikls() un arī tās beigās tieši pēc paradit(); izsauc parbaudit();.
  6. Saglabā ar Ctrl+S, pārlūkā nospied Ctrl+R, nospied Sākt un pagaidi, kamēr pretinieks sasniedz spēlētāju: pārbaudi, ka kustība uzreiz apstājas, spēlētājs maina krāsu un parādās tava beigu ziņa!
  7. Uzreiz pēc sadursmes pamēģini nospiest virzienu pogas un tastatūras bultiņas — pārliecinies, ka spēlētāja kvadrāts vairs nedrīkst izkustēties no sadursmes vietas.

Gatavs, kad: sadursme aptur pretinieka taimeri, nobloķē spēlētāja vadību, iekrāso spēlētāju sadursmes krāsā un parāda beigu ziņu.

3. uzdevums

Atjauno sākuma krāsu pie restarta un pārbaudi abus sadursmes veidus

Izmanto teoriju: Krāsas atiestatīšana ar tukšu tekstu "" un Pārklāšanās pārbaudes situācijas.

Vide: pārlūks → VS Code → pārlūks (ar F12 Console)

  1. Pārlūkā uzreiz pēc notikušas sadursmes nospied pogu Sākt — pamani vizuālo nepilnību: jaunais raunds gan sākas, taču spēlētājam paliek pielipusi iepriekšējās sadursmes krāsa!
  2. VS Code <script> blokā atver funkciju sakt() un 3. uzdevuma komentāra vietā pievieno JavaScript uzliktās krāsas notīrīšanu ar tukšām pēdiņām (speletajs.style.backgroundColor = "";).
  3. Tādu pašu krāsas notīrīšanas rindu pievieno arī funkcijā atiestatit() (pie 3. uzdevuma komentāra), lai arī poga Atiestatīt atdotu spēlētājam sākuma CSS krāsu.
  4. Saglabā ar Ctrl+S, pārlūkā nospied Ctrl+R, izspēlē sadursmi un nospied Sākt (vai Atiestatīt) — pārliecinies, ka spēlētājs uzreiz atgūst savu sākuma krāsu!
  5. Pārbaudi izvairīšanos pa Y asi: nospied Sākt, pacel spēlētāju trīs soļus uz augšu (↑) un pagaidi, kamēr pretinieks paslīd apakšā — pārliecinies, ka spēle neapstājas, kad kvadrāti atrodas dažādos augstumos!
  6. Pārbaudi abus sadursmes virzienus: vienā raundā ļauj kustīgajam pretiniekam uzbraukt nekustīgam spēlētājam, bet nākamajā raundā pacelies virs pretinieka ceļa un ar ↓ pats uzkāp kustīgajam pretiniekam — abos gadījumos spēlei tūlīt jāapstājas.
  7. Pārlūkā nospied F12, atver cilni Console, izspēlē izvairīšanos, sadursmi un atiestatīšanu un pārliecinies, ka konsolē nav kļūdu paziņojumu.

Gatavs, kad: sadursme nostrādā gan pretiniekam uzbraucot spēlētājam, gan spēlētājam uzkāpjot pretiniekam, garāmslīdēšana citā augstumā spēli neaptur, Sākt un Atiestatīt pilnībā atjauno sākuma krāsu un pozīcijas, un Console cilnē nav kļūdu.

Papildu uzdevums: Maini pretinieka augstumu katrā jaunā aplī

Sāc, kad visi trīs pamatuzdevumi ir pabeigti.

Izmanto teoriju: paradit() un sadursmes pārbaude pēc kustības.

  1. <script> sākumā zem let pretiniekaX = 270; pievieno mainīgo let pretiniekaY = 160; un funkcijā paradit() pievieno pretinieks.style.top = pretiniekaY + "px"; (kā arī atiestati pretiniekaY = 160; funkcijās sakt() un atiestatit()).
  2. Funkcijā cikls() nosacījuma if (pretiniekaX < 0) { ... } iekšpusē pamīšus maini joslu: ja pretiniekaY === 160, iestati pretiniekaY = 80;, bet pretējā gadījumā (else) atgriez pretiniekaY = 160;.
  3. Izmēģini dažādas pretiniekaAtrums vērtības (no 2 līdz 5), lai spēle būtu dinamiska, bet godīgi izspēlējama.
  4. Saglabā ar Ctrl+S, atjauno pārlūku ar Ctrl+R un pārbaudi, ka pretinieks katrā aplī maina augstumu un sadursmes pārbaude darbojas abās joslās!

Gatavs, kad: pretinieks pārmaiņus šķērso abas joslas, un spēlētājam jāpielāgo sava atrašanās vieta katrā aplī.

Ja kaut kas neizdodas
  • Pretinieks joprojām izbrauc cauri spēlētājam bez apstāšanās? Pārbaudi divas lietas: 1) vai funkcijā parbaudit() tiešām izsauci if (saduras(speletajs, pretinieks)) { ... }; 2) vai pievienoji parbaudit(); izsaukumu gan kustinat(dx, dy), gan cikls() beigās (tieši pēc paradit();).
  • Pēc sadursmes pretinieks apstājas, bet spēlētāju vēl var bīdīt ar pogām vai bultiņām? Pārliecinies, ka sadursmes if blokā ir rinda aktiva = false; (bez pēdiņām ap false!).
  • Spēlētājs pēc sadursmes nemaina krāsu? Pārbaudi rakstību speletajs.style.backgroundColor = "#6b1d1d"; — burtam C vārdā backgroundColor jābūt lielajam, un krāsas kodam jābūt pēdiņās.
  • Nospiežot “Sākt” pēc zaudējuma, jaunais raunds nesākas? Funkcijā sakt() sākumā ir pārbaude if (aktiva) { return; } — tā neļauj sākt jaunu raundu, ja parbaudit() sadursmes brīdī neuzstādīja aktiva = false;.
  • Konsolē (F12 → Console) parādās SyntaxError vai ReferenceError? Salīdzini atverošo un aizverošo figūriekavu { } pārus funkcijā parbaudit() un pārliecinies, ka funkciju un mainīgo vārdos nav garumzīmju.
