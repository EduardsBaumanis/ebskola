Daļa Kuras 2. tēmas prasmes jāparāda?
Krāsas un teksts (2.1.) Saskaņots body, .noteikumi, .laukums un button kontrasts, centrēts h1 (text-align: center;), lasāms font-size un noapaļoti stūri (border-radius).
Spēles laukuma kaste (2.2.) Bloks .laukums ar padding: 20px;, skaidru border, centrēšanu (margin: 20px auto;), box-sizing: border-box; un max-width: 100%; šauram logam.
Attēls mapē atteli/ (2.3., 2.5.) Paša uzzīmēts PNG varonis apakšmapē atteli, piesaistīts ar relatīvo ceļu src="atteli/..." un saturīgu alt aprakstu.
Skaņa mapē skanas/ (2.4., 2.5.) Skaņas fails apakšmapē skanas ar <audio controls src="skanas/..."></audio> (bez autoplay) un skaidrojumu, kad skaņa skan.

Noteikumu atbilstība darbībai un README.md paraugs

Sākuma kodā poga izsauc funkciju savakt(), kas pēc katra klikšķa palielina skaitītāju par vienu (no Punkti: 0 līdz Punkti: 3 un tālāk), bet skaņu atskaņo ar audio joslas pogu ▶. Tāpēc noteikumos apraksti tieši to, ko tava pabeigtā lapa jau dara; ja vēlies pieminēt automātisku uzvaru vai jaunus līmeņus, skaidri norādi tos kā nākotnes ieceri.

Blakus index.html izveido dokumentācijas failu README.md Markdown pierakstā, lai jebkurš lasītājs saprastu projekta uzbūvi un tavas dizaina izvēles:

# Zvaigžņu sargs

Spēles mērķis: palīdzēt kosmosa robotam savākt enerģijas kristālus.

## Mapju struktūra un atvēršana
- `index.html` — galvenā spēles sākumlapa
- `atteli/` — paša zīmēts PNG varonis
- `skanas/` — spēles skaņas efekts

Atvēršana: atver `index.html` interneta pārlūkā no projekta mapes.

## Dizaina izvēles un pārbaude
- Tumši zils fons ar gaišu tekstu rada kosmosa noskaņu un skaidru kontrastu.
- Spēles laukums ir centrēts un pielāgojas arī šauram pārlūka logam.
- Pārbaudīts: attēls, skaņa un punktu skaitītājs (3 klikšķi = 3 punkti) darbojas.
- Klasesbiedra atsauksme un uzlabojums: palielināju pogas fonta izmēru ērtākai pamanīšanai.

Kā pārbaudīt darbu no spēlētāja skatpunkta?

Pirms darba pabeigšanas pārbaudi lapu tā, it kā to pirmo reizi atvērtu cits cilvēks: vai visi relatīvie ceļi ved uz apakšmapēm atteli/ un skanas/ (nevis uz Downloads vai datora pilno ceļu C:\...), vai šaurā logā neparādās horizontālā ritjosla un vai klasesbiedrs bez tavas palīdzības saprot spēles mērķi un darbību.

Pašpārbaude: tavā datorā index.html rāda attēlu un atskaņo skaņu, bet citā datorā abi pazūd — kādi ir divi biežākie iemesli?

1) Kopā ar index.html nav paņemtas apakšmapes atteli un skanas ar tajās esošajiem failiem, vai 2) HTML kodā relatīvā ceļa (atteli/varonis.png) vietā nejauši ierakstīts pilnais datora ceļš (C:\Users\...) vai neprecīzs faila nosaukums.

1. uzdevums

Sagatavo index.html, resursu mapes un savas spēles saturu

Izmanto teoriju: Noslēguma darba struktūra un Noteikumu atbilstība darbībai.

Vide: Windows File Explorer → VS Code → pārlūks

  1. Lejupielādē 26.zip, Windows mapē Downloads atspied to ar Extract All un iekopē index.html, atteli un skanas savā tēmas mapē Desktop/datorika9-tema2 (paturi neskartus iepriekšējo stundu failus 21.html–24.html un mapi 25-mape).
  2. VS Code ar File → Open Folder atver mapi Desktop/datorika9-tema2, iekopē savu 2.3. stundā uzzīmēto varonis.png (vai jaunu Paint zīmējumu 128 × 128 px) apakšmapē atteli, bet savu 2.4. stundas skaņas failu — apakšmapē skanas.
  3. Failā index.html nomaini gan <title>, gan <h1> uz savas spēles nosaukumu un ievada rindkopā uzraksti skaidru spēles mērķi.
  4. Sadaļā <section class="noteikumi"> uzraksti vismaz divas <p> rindkopas, kas paskaidro redzamo lapas darbību (kā spēlētājs vāc punktus ar pogu un ko dara skaņas atskaņotājs; nākotnes ieceres piemini atsevišķi).
  5. Blokā <div class="laukums"> atjauno <img src="atteli/..." alt="..." width="128"> uz savu PNG attēlu ar precīzu alt aprakstu, bet <audio controls src="skanas/..."></audio> (bez autoplay) — uz savu skaņas failu, pielāgojot arī skaņas skaidrojuma <p> un pogas uzrakstu.
  6. Saglabā index.html ar Ctrl+S, atver to no Desktop/datorika9-tema2 pārlūkā (Open with → Edge) un pārliecinies, ka lapā ielādējas tavs attēls un darbojas skaņas josla.

Gatavs, kad: index.html satur tavas spēles nosaukumu, mērķi un patiesus noteikumus, un no apakšmapēm atteli/ un skanas/ veiksmīgi ielādējas tavs PNG attēls un skaņa.

2. uzdevums

Izveido vienotu CSS noformējumu un uzraksti README.md

Izmanto teoriju: 2. tēmas prasmju apkopojums un README.md paraugs.

Vide: VS Code → pārlūks

  1. CSS blokā body { ... } izvēlies savas spēles noskaņai atbilstošu fona krāsu (background-color) un kontrastējošu pamatteksta krāsu (color).
  2. Blokā h1 { ... } iestati virsraksta color, burtu izmēru font-size (piemēram, 36px) un text-align: center;.
  3. Noformē .noteikumi { ... } bloku: izvēlies no lapas fona atšķirīgu background-color, salasāmu color, padding: 16px; un noapaļotus stūrus border-radius: 12px;.
  4. Noformē spēles laukumu .laukums { ... } ar 2.2. stundā apgūto kastes modeli: iestati padding: 20px;, pamanāmu border (biezums, solid vai dashed, krāsa), border-radius: 12px;, centrēšanu margin: 20px auto;, max-width: 100%; un text-align: center;, paturot box-sizing: border-box;.
  5. Noformē button { ... } ar izteiksmīgu akcenta background-color, kontrastējošu color un border-radius: 8px;, saglabā ar Ctrl+S un pārbaudi vizuālo koptēlu pārlūkā ar Ctrl+R.
  6. Mapē Desktop/datorika9-tema2 izveido failu README.md un pēc teorijas parauga apraksti spēles nosaukumu, mērķi, mapju struktūru, atvēršanas norādi un vismaz divas savas CSS dizaina izvēles.

Gatavs, kad: lapai ir vienots, kontrastējošs CSS stils, centrēts .laukums ar atstarpēm un rāmi, un tēmas mapē izveidots README.md ar dizaina pamatojumu.

3. uzdevums

Pārbaudi noslēguma darbu un pilnveido pēc atsauksmes

Izmanto teoriju: Kā pārbaudīt darbu no spēlētāja skatpunkta?.

Vide: pārlūks → VS Code

  1. Pārlūkā pārbaudi teksta lasāmību visās četrās vietās: mērķa rindkopā uz lapas fona, .noteikumi kartītē, .laukums blokā un uz pogas.
  2. Pārbaudi multividi un pogu: pārliecinies, ka PNG varonis redzams ar asām malām, nospied skaņas atskaņošanu ▶ un pauzi, un trīs reizes nospied punktu pogu — skaitītājam jāparāda Punkti: 3.
  3. Pārbaudi šauro skatu: sašaurini pārlūka logu (vai pietuvini ar Ctrl un + līdz 200%), pārliecinies, ka .laukums, attēls, audio josla un poga pilnībā ietilpst logā bez horizontālās ritjoslas, un ar Ctrl+0 atgriez 100% mērogu.
  4. Uzaicini klasesbiedru izlasīt tavu README.md, atvērt index.html, skaļi pateikt spēles mērķi, atskaņot skaņu un iegūt 3 punktus.
  5. Failā README.md pieraksti klasesbiedra atsauksmi un veic vismaz vienu konkrētu uzlabojumu savā CSS vai tekstos (piemēram, uzlabo krāsu kontrastu, palielini atstarpi vai precizē noteikumu teikumu).
  6. Saglabā visus failus ar File → Save All un pārliecinies, ka mapē Desktop/datorika9-tema2 kārtīgi glabājas gan noslēguma darbs (index.html, atteli/, skanas/, README.md), gan visi iepriekšējo stundu darbi (21.html–24.html un 25-mape/).

Gatavs, kad: visas noslēguma lapas daļas darbojas gan pilnā, gan šaurā logā, README.md fiksēta klasesbiedra pārbaude un uzlabojums, un tēmas mapē ir visi 2.1.–2.6. darbi.

Spēles saturs, noteikumi un pogas darbība
1. uzdevums · Teorija		 Failā index.html atstāti nepielāgoti parauga teksti vai punktu poga nedarbojas. Daļa tekstu nomainīta, bet <title> nesaskan ar <h1>, mērķis ir neskaidrs vai noteikumi neatbilst lapā redzamajai darbībai. <title> un <h1> satur savas spēles nosaukumu; skaidri aprakstīts mērķis un vismaz divi noteikumi, kas atbilst redzamajai darbībai, un punktu poga pēc trim klikšķiem parāda Punkti: 3. Izpildīts “Apguvis”; virsraksts, mērķis, noteikumi, skaņas loma un pogas uzraksts veido vienotu spēles stāstu un precīzi nošķir esošo funkcionalitāti no nākotnes iecerēm.
CSS krāsas, kontrasts un teksts (2.1.)
2. uzdevums · 2.1. teorija		 Atstātas sākuma parauga noklusējuma krāsas vai slikta kontrasta dēļ teksts nav salasāms. Mainīta daļa krāsu, bet vismaz vienā zonā (lapā, .noteikumi, .laukums vai pogā) teksts saplūst ar fonu vai poga neizceļas. Pielāgotas body, .noteikumi, .laukums un button krāsas ar skaidru kontrastu visās četrās zonās; h1 ir centrēts (text-align: center;) un blokiem lietots border-radius. Izpildīts “Apguvis”; krāsu palete ir saskaņota ar spēles tēmu, poga kalpo kā pamanāms vizuāls akcents, un CSS pieraksts ir tīrs bez sintakses kļūdām.
Spēles laukuma kastes modelis un šaurs logs (2.2.)
2. uzdevums · 3. uzdevums · 2.2. teorija		 Blokam .laukums nav pamanāma rāmja vai atstarpju, vai saturs iziet ārpus bloka malām. .laukums noformēts daļēji: nav centrēts ar margin: 20px auto;, saturs piekļaujas apmalei vai šaurā logā parādās horizontālā ritjosla. .laukums ir centrēts ar margin: 20px auto;, tam ir padding: 20px;, pielāgots border, box-sizing: border-box; un max-width: 100%; — šaurā logā viss ietilpst ekrānā bez sāniskas ritināšanas. Izpildīts “Apguvis”; gan plašā, gan sašaurinātā ekrānā attēls, audio josla, punktu skaitītājs un poga saglabā līdzsvarotas iekšējās un ārējās atstarpes.
Multivide un relatīvie failu ceļi (2.3.–2.5.)
1. uzdevums · 2.3. · 2.4. · 2.5.		 Attēls un skaņa lapā neielādējas vai apakšmapes atteli/ un skanas/ nav iekļautas krātuvē. Ielādējas tikai viens no resursiem, atstāts tikai parauga varonis.svg, trūkst saturīga alt teksta, lietots C:\... ceļš vai pievienots autoplay. Mapē atteli/ ir paša zīmēts PNG attēls un mapē skanas/ — skaņas datne; abi darbojas ar relatīvajiem ceļiem (atteli/..., skanas/...), attēlam ir saturīgs alt, bet skaņai — controls (bez autoplay) un lomas apraksts. Izpildīts “Apguvis”; visi failu un mapju nosaukumi ievēro labo praksi (mazie latīņu burti bez atstarpēm un garumzīmēm), PNG varonis ir ass paredzētajā izmērā un skaņa ir īsa un tīra.
Dokumentācija (README.md) un pārbaude
2. uzdevums · 3. uzdevums		 README.md nav izveidots vai tajā ir tikai nosaukums bez apraksta un pārbaužu ierakstiem. README.md ir nepilnīgs: trūkst mapju struktūras, atvēršanas norādes, dizaina izvēļu skaidrojuma vai klasesbiedra atsauksmes. README.md ar Markdown virsrakstiem un sarakstiem apraksta mērķi, mapju struktūru, atvēršanu, vismaz divas dizaina izvēles, funkciju pārbaudi un klasesbiedra atsauksmi ar vienu ieviestu uzlabojumu. Izpildīts “Apguvis”; README.md pilnībā atbilst krātuves saturam un skaidri pamato, kā klasesbiedra novērojums tika pārvērsts konkrētā un pārbaudītā uzlabojumā.
Papildu uzdevums: Pogas izcelšana zem peles kursora (:hover) un ZIP pašpārbaude

Sāc, kad visi trīs pamatuzdevumi ir pabeigti. Papildu uzdevums nav nepieciešams nevienam SLA līmenim.

Izmanto teoriju: Arhīva pilnīguma pārbaude.

  1. CSS daļas beigās pievieno noteikumu button:hover { outline: 3px solid #1e293b; } (pielāgojot krāsu savam dizainam), lai poga reaģētu uz peles kursoru.
  2. Saglabā index.html ar Ctrl+S un pārlūkā pārbaudi, ka uzvedot kursoru uz pogas, uzraksts joprojām ir skaidri salasāms.
  3. File Explorer iezīmē index.html, README.md, atteli un skanas un ar Compress to ZIP file izveido rezerves paku noslegums.zip.
  4. Ar Extract All izvelc noslegums.zip atsevišķā pārbaudes mapē iekš Downloads un pārliecinies, ka visa spēles sākumlapa darbojas arī ārpus darba mapes.

Gatavs, kad: poga reaģē uz kursoru un izvilktā rezerves kopija pilnībā darbojas citā mapē.

Ja kaut kas neizdodas
  • Attēls vai skaņa index.html lapā neparādās? VS Code Explorer sarakstā pārbaudi, vai faili tiešām atrodas apakšmapēs atteli/ un skanas/ blakus index.html un vai src vērtība precīzi sakrīt ar faila nosaukumu un paplašinājumu (piemēram, atteli/varonis.png).
  • Punktu poga pēc klikšķa nemaina skaitli? Pārbaudi, vai HTML kodā saglabāts <p id="punkti">Punkti: 0</p>, pogas atribūts onclick="savakt()" un <script>...</script> bloks pirms </body>.
  • Spēles laukums šaurā logā iziet ārpus ekrāna? Pārbaudi, ka CSS blokā .laukums ir gan max-width: 100%;, gan box-sizing: border-box;, un starp skaitļiem un mērvienībām nav atstarpju.
  • Neredzi izmaiņas pārlūkā? VS Code nospied Ctrl+S, tad pārlūkā nospied Ctrl+R un pārliecinies, ka atvērts tieši Desktop/datorika9-tema2/index.html.
