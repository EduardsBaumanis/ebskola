5. Tēma - Noslēguma projekta izstrāde un publicēšana

Tēmas sākums 5.1 Projekta specifikācija un laika plānošana 5.2 Vizuālo resursu un saskarnes (UI) pabeigšana 5.3 Spēles pamatloģikas programmēšana 5.4 Papildfunkciju ieviešana (Power-ups, līmeņi, skaņa) 5.5 Spēles testēšana, atkļūdošana un publicēšana 5.6 Noslēguma projekts: Pilnvērtīga spēle internetā

5.1 Projekta specifikācija un laika plānošana

Stundas uzdevums: Definēt savas spēles tehnisko specifikāciju (MVP) un izveidot detalizētu darbu plānu (Backlog) nākamajām 5 dubultstundām.

1.3.1. Plāno un pamato sava darba gaitu; 1.5.1. Formulē darba uzdevumu un sasniedzamo rezultātu.

70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) - uzraksti savas spēles MVP sarakstu failā roadmap.md · 2. uzdevums (~25 min) - sadali darbu pa piecām atlikušajām stundām un nosūti failu uz GitHub · 3. uzdevums (~20 min) - pārbaudi plānu ar klasesbiedru un saīsini vienu pārāk lielu soli. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: atver savu spēles projekta mapi VS Code un pārliecinies, ka tā jau ir savienota ar GitHub krātuvi (git status nerāda kļūdu).

Teorija: MVP un Agile plānošana

Profesionāļi izmanto MVP (Minimum Viable Product) koncepciju - tas ir vienkāršākais iespējamais produkts, kas strādā.

  • Must-have (Obligāti): Kas spēlei nepieciešams, lai to varētu spēlēt? (Piem., kustība, punkti, sadursme).
  • Nice-to-have (Vēlams): Ko es gribētu pievienot, ja paliks laiks? (Piem., dažādi līmeņi, vairākas skaņas, animācijas).
  • Plānošana: Laiks ir ierobežots resurss (atlikušas 5 dubultstundas). Katra stunda ir jāplāno konkrētam mērķim.

# Roadmap.md piemērs
## 1. nedēļa - Mehānika
- [x] Spēlētāja kustība
- [ ] Sadursmju noteikšana
## 2. nedēļa - Saturs
- [ ] Pretinieki, līmeņi
## 3. nedēļa - Polish
- [ ] Skaņa, animācijas, publicēšana

Praktiskie uzdevumi

1. uzdevums - Uzraksti savas spēles MVP sarakstu

Beigās tavā projekta mapē būs fails roadmap.md ar 3 obligātām un 3 vēlamām spēles daļām.

Nokopējamais paraugs: aizvieto tekstu ar savas spēles nosaukumu un savām daļām.

# Spēle "Kosmosa Izdzīvotājs"
**Mērķis:** Izvairīties no asteroīdiem.

## Must-have (bez šī spēli nevar izspēlēt)
- [ ] Varoņa kustība pa kreisi/labi
- [ ] Asteroīdi, kas krīt no augšas
- [ ] Sadursmes noteikšana

## Nice-to-have (ja paliek laiks)
- [ ] Lāzera skaņas efekts
- [ ] Punktu tabula
- [ ] Uzlabota grafika
  1. Atver savu spēles projekta mapi VS Code.
  2. Izveido jaunu failu ar nosaukumu roadmap.md.
  3. Nokopē augšā doto paraugu un ielīmē to roadmap.md failā.
  4. Nomaini pirmo rindu uz savas spēles nosaukumu.
  5. Uzraksti sadaļā "Must-have" tieši 3 daļas, bez kurām spēli nevar izspēlēt.
  6. Uzraksti sadaļā "Nice-to-have" tieši 3 daļas, ko pievienotu, ja paliek laiks.
  7. Saglabā failu un atver priekšskatījumu ar Ctrl+Shift+V.

Gatavs, kad: priekšskatījumā redzami divi saraksti - 3 obligātās un 3 vēlamās spēles daļas.

2. uzdevums - Sadali darbu pa piecām stundām un nosūti plānu uz GitHub

Beigās tavā GitHub krātuvē būs plāns, kurā katrai atlikušajai stundai ir viens konkrēts darbs.

  1. Atver roadmap.md un zem MVP saraksta uzraksti virsrakstu ## Plāns pa stundām.
  2. Uzraksti piecas rindas ar stundu numuriem: 5.2, 5.3, 5.4, 5.5, 5.6.
  3. Ieraksti pie katras stundas vienu darbu, piemēram: - [ ] 5.2 sākuma ekrāns un punktu panelis.
  4. Pārbaudi, ka katrā stundā ir tikai viens galvenais darbs, nevis trīs.
  5. Saglabā failu un izpildi terminālī git add roadmap.md.
  6. Izpildi git commit -m "Add project roadmap".
  7. Izpildi git push un atver savu krātuvi GitHub.com.

Gatavs, kad: GitHub.com atverot roadmap.md, redzams saraksts ar 5 stundām un ķeksīšu rūtiņām.

3. uzdevums - Saīsini vienu pārāk lielu soli pēc klasesbiedra atsauksmes

Beigās tavā plānā nebūs neviena darba, kas vienā stundā nav paveicams.

  1. Iedod savu roadmap.md klasesbiedram un lūdz izlasīt to divās minūtēs.
  2. Pajautā vienu jautājumu: kurš stundas darbs viņam šķiet par lielu vienai stundai?
  3. Pieraksti viņa atbildi faila beigās zem virsraksta ## Atsauksme.
  4. Saīsini šo vienu darbu - svītro no tā vienu funkciju vai sadali to divās stundās.
  5. Pārvieto vienu svītroto ideju uz sadaļu "Nice-to-have".
  6. Saglabā un izpildi git commit -am "Shrink one task after feedback".
  7. Pieraksti plāna beigās vienu teikumu: kāpēc mazāks plāns ir drošāks par lielu.

Gatavs, kad: plānā ir sadaļa "Atsauksme" un vismaz viens darbs ir kļuvis īsāks nekā sākumā.

Papildu uzdevums - Pievieno plānam risku sarakstu

Beigās tavā plānā būs divi riski un divas konkrētas rīcības, ja tie piepildās.

  1. Atver roadmap.md un pievieno virsrakstu ## Riski.
  2. Uzraksti vienu risku par laiku, piemēram: "sadursmes kods var neizdoties 5.3 stundā".
  3. Uzraksti otru risku par resursiem, piemēram: "nav gatavu attēlu varonim".
  4. Pieraksti pie katra riska vienu rīcību, ko darīsi, ja tas piepildās.
  5. Saglabā un izpildi git commit -am "Add risk list to roadmap".

Gatavs, kad: sadaļā "Riski" ir divi riski un pie katra viena rīcība.

Zelta padomi plānošanai:

  • "Zemāk par zemi": Sākumā ieplāno pavisam vienkāršu spēli. Ja to pabeigsi ātrāk, varēsi pievienot foršas ekstras.
  • Dizains vs Kods: Netērē visu pirmo stundu zīmējot perfektu varoni. Izmanto pagaidu kvadrātu un fokusējies uz to, lai kods strādātu!
  • Vienkāršība ir atslēga: Labāk pabeigta, vienkārša spēle nekā nepabeigta, sarežģīta spēle.

Koda piemērs (plāna nosūtīšana uz GitHub, kad push neizdodas)

# 1. Pārbaudi, kas ir mainīts un kurā zarā strādā
git status

# 2. Pievieno tikai plāna failu
git add roadmap.md

# 3. Saglabā izmaiņas ar saprotamu ziņu
git commit -m "Add project roadmap"

# 4. Nosūti uz GitHub
git push

# Ja push saka "no upstream branch" - norādi zaru vienu reizi:
git push -u origin main

# Ja commit saka "nothing to commit" - fails nav saglabāts vai nav pievienots:
git status        # roadmap.md jābūt zaļā "Changes to be committed" sarakstā
Pēc git push terminālī parādās rindas ar -> main, un GitHub.com krātuves lapā roadmap.md ir redzams sarakstā ar tavu commit ziņu blakus.
