4.6 Noslēguma projekts: Spēles dzinēja prototips

Stundas uzdevums: Apvienot 4. tēmā apgūtās funkcijas, notikumus, DOM manipulāciju, taimerus un sadursmes vienā pārbaudāmā spēles dzinēja prototipā.

SR 2.6.1. Programmas strukturēšana un algoritmi SR 1.3.4. Risinājuma izvērtēšana SR 1.4.2. Testēšana un pilnveide SR 5.2.4. Sadarbība SR 2.6.3. Programmējamas ierīces, roboti un sensori

70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) - savieno "Sākt" un "Beigt" pogas ar spēles stāvokli · 2. uzdevums (~25 min) - savieno kustību, punktus un sadursmi vienā ciklā · 3. uzdevums (~20 min) - izpildi trīs testus un salabo vienu kļūdu. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: atver savu 4.5 stundas projektu ar failiem index.html un script.js, kurā jau ir laukums, spēlētājs, ienaidnieks un sadursmes funkcija.

Teorija: spēles dzinējs ir sakārtots cikls

Šajā prototipā nav jāievieš jauna spēles mehānika. Mērķis ir savienot jau apgūto: starta funkciju, notikumu klausītājus, elementu pārvietošanu, laika kontroli un sadursmju pārbaudi. Ja katra daļa ir atsevišķā funkcijā, kļūdas var atrast ātrāk.

function saktSpeli() {
  clearInterval(taimeris);   // aptur veco ciklu, ja tāds jau darbojas
  punkti = 0;
  speleAktiva = true;
  taimeris = setInterval(atjaunotSpeli, 100);
}

function beigtSpeli() {
  speleAktiva = false;
  clearInterval(taimeris);
}
Šeit izmantots tikai iepriekš apgūtais: funkcijas, mainīgie, taimeris un spēles stāvoklis.

Praktiskie uzdevumi

1. uzdevums - Savieno "Sākt" un "Beigt" pogas ar spēles stāvokli

Beigās divas pogas ieslēgs un izslēgs tavu spēles ciklu, un konsole to parādīs.

Kopējamais paraugs: divas funkcijas, ko ielīmē script.js failā.

function saktSpeli() {
  clearInterval(taimeris);   // aptur veco ciklu, ja tāds jau darbojas
  punkti = 0;
  speleAktiva = true;
  taimeris = setInterval(atjaunotSpeli, 100);
}

function beigtSpeli() {
  speleAktiva = false;
  clearInterval(taimeris);
}
  1. Atver index.html un pievieno pogas <button id="saktPoga">Sākt</button> un <button id="beigtPoga">Beigt</button>.
  2. Atver script.js un pārbaudi, ka faila augšā ir let punkti = 0;, let speleAktiva = false; un let taimeris = null;.
  3. Ielīmē abas parauga funkcijas saktSpeli() un beigtSpeli() faila beigās.
  4. Uzraksti pagaidu funkciju atjaunotSpeli(), kas pagaidām satur tikai console.log("kadrs");.
  5. Piesaisti abas funkcijas pogām ar addEventListener un saglabā failu.
  6. Nospied "Sākt", tad "Beigt" un vēro ierakstus konsolē.

Gatavs, kad: pēc "Beigt" nospiešanas konsolē vairs neparādās neviens jauns "kadrs" ieraksts.

2. uzdevums - Savieno kustību, punktus un sadursmi vienā ciklā

Beigās viena cikla funkcija kustinās ienaidnieku, skaitīs punktus un pārbaudīs sadursmi.

  1. Atver script.js un funkcijā atjaunotSpeli() izsauc savu ienaidnieka kustības kodu no 4.4 stundas.
  2. Pievieno tajā pašā funkcijā punkti = punkti + 1; un pārraksti tekstu elementā #punkti.
  3. Pievieno funkcijas beigās if (parbauditSadursmi()) { beigtSpeli(); }.
  4. Papildini bultiņu taustiņu klausītāju ar rindu if (!speleAktiva) return; pašā sākumā.
  5. Saglabā, nospied "Sākt" un aizvadi spēlētāju ienaidniekam ceļā.
  6. Veic git commit -m "Connect movement, score and collision in game loop".

Gatavs, kad: pēc sadursmes punkti pārstāj augt, ienaidnieks apstājas un bultiņas vairs nekustina spēlētāju.

3. uzdevums - Izpildi trīs testus un salabo vienu kļūdu

Beigās tavs prototips izturēs trīs testus, un tu būsi izlabojis vienu atrastu kļūdu.

  1. Izpildi 1. testu: nospied "Sākt", nospēlē 10 sekundes un pieraksti punktu skaitu.
  2. Izpildi 2. testu: nospied "Sākt" trīs reizes pēc kārtas un pārbaudi, vai ātrums nemainās.
  3. Izpildi 3. testu: pēc sadursmes spied bultiņas un pārbaudi, vai spēlētājs paliek uz vietas.
  4. Pieraksti, kurš tests neizdevās, un salabo tieši to vienu vietu kodā.
  5. Palaid visus trīs testus vēlreiz ar izlaboto kodu.
  6. Pieraksti vienu secinājumu: kura mainīgā vai funkcijas trūkums izraisīja atrasto kļūdu.

Gatavs, kad: visi trīs testi izdodas pēc kārtas un konsolē nav neviena sarkana kļūdas paziņojuma.

Papildu uzdevums - Pievieno trīs dzīvību sistēmu

Beigās ienaidnieka pieskāriens atņems vienu dzīvību, nevis uzreiz beigs spēli.

  1. Pievieno index.html rindu <p id="dzivibas">Dzīvības: 3</p>.
  2. Pievieno script.js faila augšā let dzivibas = 3;.
  3. Nomaini sadursmes blokā beigtSpeli() pret dzivibas = dzivibas - 1; un teksta atjaunošanu.
  4. Izsauc beigtSpeli() tikai tad, kad dzivibas kļūst 0.
  5. Pārvieto spēlētāju atpakaļ uz sākuma pozīciju pēc katras zaudētās dzīvības.
  6. Veic git commit -m "Add lives system to game engine".

Gatavs, kad: pēc trešās sadursmes teksts rāda "Dzīvības: 0" un spēle beidzas.

Biežākās kļūdas (un kā tās labot)

  • Spēle paātrinās pēc vairākiem startiem: pirms jauna setInterval() izsaukuma apturi veco taimeri.
  • Game Over neaptur kustību: pārbaudi, vai visas kustības funkcijas respektē mainīgo speleAktiva.
  • Sadursme nostrādā par agru: pārbaudi objektu platumu, augstumu un pozīcijas vērtības.
  • Klasesbiedrs nevar palaist spēli: pārbaudi failu ceļus un to, vai visi faili ir nosūtīti uz GitHub.

Vērtēšanas kritēriji (SLA)

Kritēriji Sācis apgūt (1-3) Turpina apgūt (4-6) Apguvis (7-8) Apguvis padziļināti (9-10)
1. Funkcionalitāte un spēles loģika Spēle palaižas, bet cikla (start/stop) vadība nedarbojas vai pārlūkprogramma regulāri "uzkaras". Spēli var sākt, taču apstādināšanas (Game Over) loģikā ir nepilnības (piem., objekti turpina kustēties fonā). Spēles cikls (sākums, gaita, beigas) darbojas stabili un bez kļūdām. Visi intervāli tiek korekti apstādināti. Loģika ir nevainojama, patstāvīgi ieviesti papildus stāvokļi (piemēram, pauze vai līmeņu pārslēgšanās), kas darbojas stabili.
2. Koda kvalitāte ("Clean Code") Kods ir grūti lasāms, mainīgo nosaukumi ir nejauši (a, b, x), nav izmantoti komentāri. Kods ir daļēji sakārtots, izmantoti daži jēgpilni nosaukumi, bet palikuši lieki testa kodi (piem., nevajadzīgi console.log). Kods ir strukturēts, mainīgie ir jēgpilni, pievienoti skaidrojoši komentāri pie galvenajām funkcijām. Liekais kods ir izdzēsts. Kods ir modulārs, loģiski sadalīts pa atsevišķām funkcijām, pilnībā ievērojot labās prakses (Clean Code) principus.
3. Atkļūdošana un sadarbība Spēj pamanīt vizuālas kļūdas savā spēlē, bet kļūdu labošanā nepieciešams nepārtraukts skolotāja atbalsts. Izmanto konsoli, lai atrastu vienkāršas sintakses kļūdas. Dalās ar kodu, bet nespēj mērķtiecīgi testēt cita darbu. Patstāvīgi atrod un novērš savas loģikas kļūdas. Veiksmīgi testē klasesbiedra spēli un spēj izskaidrot atrasto kļūdu cēloni. Atrod kļūdas, izskaidro to iemeslus, piedāvā risinājumus un palīdz klasesbiedram tos integrēt.
