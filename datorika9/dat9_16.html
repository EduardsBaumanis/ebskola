Īsā teorija

Kas ir pabeigts spēles pieteikums?

Šīs tēmas projekts ir pārlūkā atverams index.html ar savas spēles ideju un diviem pārslēdzamiem ekrāniem. Izmanto pārbaudāmus noteikumus un abu ekrānu satura prasības. Pogām jāizpilda 1.5. nodarbības pārslēgšanas pārbaude.

Vērtē spēles pieteikumu, teksta saprotamību un gatavo pogu izmantošanu. Punktu rinda paliek Punkti: 0; pašu spēlēšanu pievienosi vēlāk.

README: apraksts un atvēršanas norāde

README.md ir īss projekta apraksts tajā pašā mapē, kur index.html. Markdown pierakstā # veido galveno virsrakstu, ## — sadaļas virsrakstu, bet - — saraksta punktu. Pēc šīm zīmēm liec atstarpi. Rindkopas atdali ar tukšu rindu.

# Zvaigžņu mednieks

Mērķis: savākt 5 zvaigznes, neuzklikšķinot uz akmens.

Spēlētājs: iesācējs, kuram pirms spēles vajadzīgi īsi noteikumi.

## Atvēršana
Lejupielādē projektu no GitHub: Code → Download ZIP.
Izpako ZIP un atver index.html pārlūkā.

## Pārbaudes
- Atveru index.html: redzams sākums, laukums paslēpts.
- Nospiežu “Sākt spēli”: redzams laukums, sākums paslēpts.
- Nospiežu “Atpakaļ”: redzams sākums, laukums paslēpts.

## Atsauksme
Klasesbiedrs atrada vadības norādi, bet nesaprata punktu iegūšanu.
Precizēju pirmo noteikumu: viena zvaigzne dod vienu punktu.
Atkārtotajā pārbaudē klasesbiedrs punktu iegūšanu izskaidroja pareizi.

Pārbaudes ieraksts ir pierādījums

README paraugs rāda pieraksta veidu. Sadaļā Pārbaudes katram no trim soļiem raksti veikto darbību un savā lapā novēroto rezultātu. Ja atrodi kļūdu, norādi to, izlabo lapu un pievieno atkārtotās pārbaudes rezultātu.

Sadaļā Atsauksme īsi apraksti, ko klasesbiedrs saprata vai nesaprata, kādu tekstu precizēji un vai atkārtotā pārbaude izdevās. Ja precizējums nebija vajadzīgs, norādi, ko klasesbiedrs pareizi atrada vai izskaidroja. Piemēra atsauksmi aizstāj ar savā pārbaudē novēroto.

Kādu saiti iesniegt?

Iesniedz GitHub krātuves saiti formā https://github.com/lietotajvards/datorika9-tema1, kur lietotajvards ir tavs GitHub lietotājvārds. Šajā adresē skolotājs redz failus un README. Pašu lapu atver no lejupielādētajiem failiem, kā aprakstīts README.

Pirms nosūtīšanas saglabā abus failus un pārskati to izmaiņas Source Control. Pēc Stage Changes → Commit → Sync Changes GitHub jābūt tai pašai versijai, kuru pārbaudīji datorā. Atgādni skati 1.3. nodarbības teorijā.

Turpini savu projektu

Vide: VS Code

Izmanto teoriju: Pabeigta spēles pieteikuma saturs; noteikumu paraugs.

  1. Atver savu 15.html un ar File → Save As saglabā kopiju kā index.html mapē Desktop/datorika9-tema1. Turpmāk šajā nodarbībā labo index.html.
  2. Ja iepriekšējā darba nav, izmanto pilno rezerves sākuma kodu un saglabā to kā index.html. Aizstāj parauga tekstus un pievieno visu turpmāk prasīto saturu, izmantojot 1.5. nodarbības soļus.
  3. Pārbaudi, ka <title> un <h1> ir viens un tas pats spēles nosaukums, bet rindkopā zem virsraksta — tavs mērķis.
  4. Sadaļā id="sakums" pārbaudi paredzētā spēlētāja aprakstu un trīs <li> noteikumus: darbība un punktu iegūšana, uzvara, zaudējums. Pievieno trūkstošo un saskaņo skaitļus ar mērķi. Saglabā sākšanas pogu un gatavo pārslēgšanas kodu.

Gatavs, kad: index.html sākuma skatā ir tavas spēles nosaukums, mērķis, paredzētais spēlētājs un trīs savstarpēji saderīgi noteikumi.

2. uzdevums

Pabeidz lapu un aprakstu

Vide: VS Code

Izmanto teoriju: Spēles ekrāna saturs; README paraugs un Markdown pieraksts.

  1. Sadaļā id="laukums" pārbaudi rindu Punkti: 0, sava varoņa vai objektu aprakstu un konkrētu vadības norādi. Pievieno trūkstošo. Vadībai un punktu iegūšanai jāsaskan ar sākuma noteikumiem.
  2. Pārbaudi, ka abu pogu teksti skaidri nosauc sākšanu un atgriešanos. Saglabā sadaļu id, hidden, pogu onclick un gatavās funkcijas.
  3. VS Code failu sarakstā ar New File izveido README.md tajā pašā tēmas mapē, kur atrodas index.html. Ja README jau ir, papildini to.
  4. Pēc teorijas parauga ieraksti Markdown virsrakstu ar spēles nosaukumu, mērķi, paredzēto spēlētāju un sadaļu ## Atvēršana. Norādi, kā no GitHub lejupielādēt un izpakot projektu un kuru failu atvērt pārlūkā.
  5. Sagatavo README sadaļas ## Pārbaudes un ## Atsauksme. To faktisko saturu ierakstīsi 3. uzdevumā. Saglabā abus failus ar File → Save All.

Gatavs, kad: abi ekrāni satur prasīto informāciju, bet README.md ir savas spēles apraksts, atvēršanas norāde un vieta pārbaudes pierakstam.

3. uzdevums

Pārbaudi un iesniedz tēmas projektu

Vide: Pārlūks → VS Code → GitHub

Izmanto teoriju: Pārbaudes un atsauksmes pieraksts; projekta iesniegšana.

  1. Pārlūkā atver index.html un izpildi trīs pārbaudes soļus: sākotnējais skats, sākšanas poga, atgriešanās poga. README sadaļā Pārbaudes katram solim ieraksti darbību un faktiski redzēto rezultātu.
  2. Ļauj klasesbiedram bez tava skaidrojuma lapā atrast mērķi, vadību, uzvaras un zaudējuma nosacījumus un pārslēgt abus ekrānus. Palūdz viņam pateikt, kas bija saprotams un kas jāprecizē.
  3. Ja atklāta kļūda vai neskaidrība, izlabo to un atkārto attiecīgo pārbaudi. README sadaļā Atsauksme ieraksti novērojumu, veikto precizējumu un atkārtotās pārbaudes rezultātu. Ja precizējums nebija vajadzīgs, nosauc, ko klasesbiedrs pareizi izskaidroja vai izdarīja.
  4. Salīdzini darbu ar vērtēšanas tabulu un zemāk esošo pārbaudes sarakstu. Saglabā abus failus. Source Control atver to izmaiņas, pārbaudi tās un veic Stage Changes → Commit ar saturīgu ziņu, piemēram, Pabeigts spēles pieteikums un pārbaudes apraksts.
  5. Nosūti versiju ar Sync Changes (pirmajai nosūtīšanai izmanto zemāk esošo atgādni). GitHub pārbaudi, ka projekta saknē ir index.html un README.md, HTML kodā redzams pēdējais labojums un README ir formatētas sadaļas ar faktiskajiem pārbaudes rezultātiem.
  6. Atver GitHub projekta sākumlapu un nokopē tās adresi https://github.com/lietotajvards/datorika9-tema1 ar savu lietotājvārdu. Iesniedz saiti skolotāja norādītajā vietā.

Gatavs, kad: iesniegtā GitHub saite atver projektu ar pārbaudīto index.html, aizpildītu README.md un atbilstošu Commit vēsturi.

Iesniedz 3. uzdevuma rezultātu

Iesniedz GitHub krātuves saiti. Projekta saknē jābūt pabeigtajam index.html un README.md.

Pirms iesniegšanas pārbaudi:

  • index.html ir saskaņots nosaukums, mērķis, paredzētais spēlētājs un trīs noteikumi; izmantoti virsraksti, rindkopas un saraksts.
  • Laukumā ir punktu rinda, varoņa vai objektu apraksts un vadības norāde. Sākotnējais skats un abas pārslēgšanas pogas darbojas.
  • README.md satur spēles nosaukumu, mērķi, paredzēto spēlētāju, atvēršanas norādi, trīs faktiskus pārbaudes ierakstus un klasesbiedra atsauksmi ar secinājumu par precizējumu.
  • Abi gala faili ir GitHub projekta saknē, nosūtīti ar aprakstošu Commit ziņu; skolotājam iesniegta krātuves saite.

Vērtē 3. uzdevumā iesniegto gala darbu pēc SLA tabulas. 1. un 2. uzdevums sagatavo šo rezultātu. Papildu uzdevums nav vērtējuma nosacījums.

Saglabā un nosūti uz GitHub — pogu atgādne

Vide: VS Code / Source Control → GitHub pārlūkā

  1. Ar File → Save All saglabā failus. Atver Source Control ar Ctrl+Shift+G .
  2. Pie Changes nospied + (Stage All Changes). Pārbaudi, ka vajadzīgie faili pārvietojas uz Staged Changes .
  3. Ziņas laukā ieraksti īsu izmaiņu, piemēram, Pabeigts 1.6 darbs . Spied Commit .
  4. Ja šī tēmas mape vēl nav GitHub, spied Publish to GitHub un izveido publisku projektu datorika9-tema1 . Jau publicētam projektam spied Sync Changes . Ja pogas nav, atver … → Push .
  5. Pārlūkā atver savu GitHub projektu un pārbaudi faila pēdējās izmaiņas.

Ja Source Control rāda Initialize Repository , vispirms nospied to. Ja parādās kļūda vai sapludināšanas pieprasījums, izmanto palīdzību un palūdz skolotāja atbalstu.

Spēles ideja un noteikumi
1. uzdevums · Teorija		 Palicis vispārīgs parauga apraksts; nav skaidra mērķa vai vairāku noteikumu. Ir sava ideja un daļa noteikumu, bet trūkst vadības, uzvaras vai zaudējuma nosacījuma, vai skaitļi nesaskan. Aprakstīts paredzētais spēlētājs un viņa vajadzība; mērķis un trīs noteikumi skaidri nosauc darbību, punktus, uzvaru un zaudējumu. Izpildīts “Apguvis”; formulējumi ir savstarpēji saskaņoti, un klasesbiedrs bez autora skaidrojuma pareizi izskaidro mērķi, vadību un abus beigu nosacījumus. Tas fiksēts atsauksmē.
HTML struktūra un saturs
2. uzdevums · HTML · Ekrānu saturs		 Lapa neatveras pareizi vai tajā trūkst lielākās daļas prasītā satura. Lapa atveras, bet trūkst kāda virsraksta, rindkopas, saraksta vai spēles ekrāna informācijas. Nosaukums cilnē un h1 sakrīt; izmantotas rindkopas un trīs li punkti. Abas sadaļas satur prasīto informāciju, arī punktu rindu, objektu vai varoņa aprakstu un vadību. Izpildīts “Apguvis”; visi parauga aizstājējteksti pielāgoti savai idejai, saturs atrodas paredzētajā sadaļā un abos ekrānos konsekventi lietoti vienādi nosaukumi un vadības norādes.
Pogas un ekrānu pārslēgšana
3. uzdevums · Teorija		 Neviena poga nepārslēdz ekrānus vai kādas pogas nav. Darbojas tikai viena pāreja, sākotnēji redzams nepareizais ekrāns vai pēc klikšķa vienlaikus redzamas abas sadaļas. Sākotnēji redzams sākums; abas pogas pārslēdz ekrānus abos virzienos. Katrā brīdī redzama viena no abām sadaļām. Izpildīts “Apguvis”; pogu teksti nepārprotami nosauc darbību, un klasesbiedrs bez palīdzības sāk un atgriežas. Darbība saglabājas arī atkārtotajā pārbaudē.
Pārbaude un uzlabojums
3. uzdevums · Teorija		 Nav faktisku pārbaudes ierakstu vai pārbaudīts tikai tas, vai fails atveras. Pierakstīta daļa pārbaužu; trūkst novēroto rezultātu vai klasesbiedra atsauksmes. README ir visu trīs soļu darbības un novērotie rezultāti, kā arī klasesbiedra atsauksme. Atrastās kļūdas izlabotas un pārbaudītas vēlreiz. Izpildīts “Apguvis”; pieraksts skaidri sasaista novērojumu ar precīzu labojumu un atkārtotās pārbaudes rezultātu. Ja labojums nebija vajadzīgs, to pamato ar konkrētām klasesbiedra atbildēm un darbībām.
README dokumentācija
2. uzdevums · Teorija		 README nav vai tajā palicis nepielāgots paraugs. README ir, bet trūkst apraksta vai atvēršanas soļu; virsrakstu un sarakstu pieraksts ir nepilnīgs. README ir spēles nosaukums, mērķis, paredzētais spēlētājs un sadaļas “Atvēršana”, “Pārbaudes” un “Atsauksme”. Virsraksti un pārbaudes saraksts izmanto Markdown. Izpildīts “Apguvis”; apraksts pilnībā saskan ar HTML lapu, atvēršanas norāde ļauj no GitHub failiem nonākt līdz lapai pārlūkā, un GitHub priekšskatījumā sadaļas un saraksts ir skaidri nodalīti.
Git versija un iesniegšana
3. uzdevums · Teorija		 Darbs ir tikai datorā vai iesniegtā saite neved uz GitHub projektu. GitHub projekts ir, bet trūkst kāda gala faila, nosūtīta veca versija vai Commit ziņa nepasaka izmaiņu. Iesniegta atverama krātuves saite. Saknē ir pārbaudītie index.html un README.md; gala versija nosūtīta ar aprakstošu Commit ziņu. Izpildīts “Apguvis”; pirms Commit pārskatītas abu failu izmaiņas un pēc nosūtīšanas pārbaudīta to atbilstība GitHub. Skolēns failos un vēsturē var parādīt pēdējā Commit aprakstīto izmaiņu.
Papildu uzdevums: Pievieno norādi par nākamo versiju

Sāc, kad 3. uzdevums ir gatavs un iesniegts. Papildu uzdevums nav obligāts. Ja vēlies paturēt obligāto versiju, saglabā kopiju ar citu nosaukumu.

Izmanto teoriju: README sadaļu pieraksts.

  1. README beigās pievieno ## Nākamā versija un vienu konkrētu plānoto darbu, piemēram, “Pievienot punktu skaitītāju, kas pēc klikšķa uz zvaigznes pieskaita 1 punktu.”
  2. Saglabā README, veic Commit ar izmaiņu aprakstu un nosūti uz GitHub. Pārbaudi, ka jaunā sadaļa redzama projekta lapā.

Gatavs, kad: GitHub README redzams konkrēts nākamās versijas uzdevums.
