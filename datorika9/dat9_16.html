1.6 Noslēguma projekts: Spēles projekta pieteikums

Stundas uzdevums: Izveidot un prezentēt spēles projekta pieteikuma lapu, kurā HTML struktūra, idejas pamatojums un prototips parāda, ka projektu var turpināt nākamajās tēmās.

SR 1.3.1. Dizaina risinājuma plānošana un dokumentācija SR 1.5.1. Risinājuma prezentēšana SR 2.6.1. Algoritma un programmas pieraksts SR 5.2.3. Pašvadīta mācīšanās SR 1.1.3. Materiālu, ierīču un programmvadāmu rīku izvēle SR 2.4.4. Prezentācijas plānošana un demonstrēšana SR 7.6. Tehnoloģiju mācību joma

70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) — savāc 1.3–1.5 stundu sadaļas vienā lapā · 2. uzdevums (~25 min) — pievieno tehnisko plānu un vērtēšanas kritērijus · 3. uzdevums (~20 min) — pārbaudi, iesniedz saiti un sagatavo 60 sekunžu stāstījumu. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: atver mapi spele ar failiem index.html un wireframe.png, kā arī savu GitHub repozitoriju pārlūkā.

Teorija: labs pieteikums ir spēles karte

Spēles pieteikums nav tikai skaists virsraksts. Tas ir īss, strukturēts dokuments, kas atbild uz četriem jautājumiem: ko spēlētājs darīs, kāpēc tas būs interesanti, kāda būs pirmā spēlējamā versija un pēc kā varēs izmērīt, ka projekts ir izdevies.

<section>
  <h2>Spēles ideja</h2>
  <p>Spēlētājs vada kosmosa kuģi un izvairās no šķēršļiem.</p>
</section>

<section>
  <h2>Mērķauditorija</h2>
  <p>7.-9. klases spēlētāji, kuriem patīk ātras reakcijas spēles.</p>
</section>
Semantiska struktūra palīdz vēlāk pievienot CSS, JavaScript un vērtēšanas kritērijus.

Šodien pieteikums kļūst par pamatu turpmākajam darbam: 2. tēmā to stilizēsi, 3. un 4. tēmā pievienosi spēles loģiku, bet 5. tēmā publicēsi gatavāku versiju.

Praktiskie uzdevumi

1. uzdevums — Savāc pieteikuma sadaļas vienā lapā

Beigās tavā lapā būs četras sadaļas no 1.3, 1.4 un 1.5 stundas darbiem.

  1. Atver index.html un pārbaudi, vai tajā ir koncepcija, tirgus analīzes tabula un prototipa attēls.
  2. Pieraksti, kura no šīm sadaļām trūkst vai ir tukša.
  3. Pārkopē trūkstošo saturu no savas 1.3, 1.4 vai 1.5 stundas darba.
  4. Sakārto sadaļas secībā: ideja → mērķauditorija → tirgus analīze → prototips.
  5. Pārbaudi, ka katra sadaļa sākas ar <h2> virsrakstu un lapā ir tikai viens <h1>.
  6. Saglabā un atver lapu ar Live Server.

Gatavs, kad: lapā no augšas uz leju redzamas četras sadaļas ar <h2> virsrakstiem un neviena nav tukša.

2. uzdevums — Pievieno tehnisko plānu un vērtēšanas kritērijus

Beigās lapa parādīs, ar kādiem rīkiem spēli būvēsi un pēc kā vērtēsi rezultātu.

  1. Pievieno lapas beigās virsrakstu <h2>Tehniskais plāns</h2>.
  2. Ievieto zem tā <ul> ar pieciem rīkiem: HTML, CSS, JavaScript, Git, VS Code.
  3. Pievieno virsrakstu <h2>Vērtēšanas kritēriji</h2>.
  4. Ievieto zem tā <ol> ar trim izmērāmiem kritērijiem, piemēram: "punktu skaits palielinās par 1".
  5. Pievieno katram lapas <img> tagam alt tekstu, ja tā vēl nav.
  6. Veic git commit -m "Add technical plan and criteria".
  7. Izpildi git push un pārlādē GitHub lapu.

Gatavs, kad: lapā redzams saraksts ar pieciem rīkiem un numurēts saraksts, kurā katrā punktā ir skaitlis vai darbība.

3. uzdevums — Iesniedz pieteikumu un sagatavo 60 sekunžu stāstījumu

Beigās skolotājam būs tava saite, bet tev — trīs domas, ko pateikt bez lasīšanas no ekrāna.

  1. Ielīmē visu savu HTML validator.w3.org lapā un salabo pirmo sarkano kļūdu.
  2. Izpildi git add ., tad git commit -m "Fix HTML validation errors".
  3. Izpildi git push un atver GitHub sadaļu "Commits".
  4. Pārbaudi, ka commit sarakstā ir vismaz četri ieraksti no visas tēmas.
  5. Nokopē repozitorija saiti un iesniedz to skolotājam.
  6. Pieraksti burtnīcā trīs domas: ideja, kam tā domāta, kāds ir nākamais solis.
  7. Pastāsti klasesbiedram par savu spēli 60 sekundēs, neskatoties ekrānā.

Gatavs, kad: skolotājam iesniegtā saite atveras citā datorā un rāda tavu pieteikuma lapu ar attēlu.

Papildu uzdevums — Publicē pieteikumu ar GitHub Pages

Beigās tavu pieteikumu varēs atvērt jebkurš cilvēks pēc interneta adreses.

  1. Atver savu repozitoriju GitHub un ej uz Settings → Pages.
  2. Izvēlies Branch: main, mape / (root), un spied Save.
  3. Pagaidi minūti un pārlādē lapu, līdz parādās publiskā adrese.
  4. Atver šo adresi jaunā cilnē un pārbaudi, vai attēls ir redzams.
  5. Iedod adresi klasesbiedram, lai viņš to atver savā datorā.

Gatavs, kad: klasesbiedra datorā atveras tava lapa ar virsrakstu, tabulu un prototipa attēlu.

Biežākās kļūdas (un kā tās labot)

  • Pieteikums ir pārāk vispārīgs: aizstāj frāzes "interesanta spēle" ar konkrētām darbībām, ko spēlētājs darīs.
  • Nav mērķauditorijas: apraksti vecumu, pieredzi un to, kāpēc tieši šai grupai spēle derēs.
  • Attēls nestrādā: pārbaudi faila nosaukumu, mapes ceļu un lielos/mazos burtus.
  • Prezentācija ir tikai lasīšana no ekrāna: izvēlies 3 galvenās domas un runā ar saviem vārdiem.

Lapā no augšas uz leju: viens liels virsraksts un zem tā sešas sadaļas — ideja, mērķauditorija, tabula ar divām rindām, skices attēls ar parakstu, rīku saraksts un numurēti kritēriji.
Ja attēla vietā parādās ikona ar tekstu "Spēles ekrāna skice", faila nosaukums vai mape nesakrīt — pārbaudi arī lielos un mazos burtus.

Nodošanas pierādījumi

  • Darbojošs index.html fails ar skaidru spēles pieteikuma struktūru.
  • Vismaz viens prototipa attēls vai skice ar korektu alt tekstu.
  • GitHub krātuvē redzami vairāki darba gaitas commit ieraksti.
  • Īsa prezentācija, kurā Tu pamato ideju, mērķauditoriju un nākamo izstrādes soli.

Vērtēšanas kritēriji (SLA)

Kritēriji Sācis apgūt (1-3) Turpina apgūt (4-6) Apguvis (7-8) Apguvis padziļināti (9-10)
HTML un Git lietojums Izveidots index.html fails, bet koda struktūrā ir kļūdas un nav veikta sinhronizācija. Fails ir publicēts GitHub, kods ir funkcionāls, bet trūkst semantisko tagu vai atkāpju. Kods ir tehniski pareizs, strukturēts un regulāri sinhronizēts ar GitHub, izmantojot skaidrus ziņojumus. Kods ir nevainojams, izmantota uzlabota struktūra (piem. section) un demonstrēta patstāvīga kļūdu labošana.
Dizaina plānošana Ideja ir virspusēja, nav aprakstīta mērķauditorija vai tirgus analīze. Ir aprakstīta koncepcija un mērķauditorija, tabula ir aizpildīta, bet trūkst pamatojuma. Skaidri definēta koncepcija, mērķauditorija un vizuālais prototips, kas balstīts izpētē. Dizaina plāns ir detalizēts, pamatots ar tirgus analīzi un ietver skaidrus kvalitātes kritērijus.
