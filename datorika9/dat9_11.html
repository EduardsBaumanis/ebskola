1.1 Izstrādes vide un GitHub integrācija

Stundas uzdevums: Sagatavot VS Code un Git, pieslēgties GitHub un publicēt pirmās projekta izmaiņas no sava datora.

2.3.1. Lieto programmvadāmas ierīces un pielāgo saskarni; 5.2.6. Digitālā pratība.
SR 2.3.2. Datortīklu uzbūves pamatprincipi SR 2.5.2. Tīmekļvietnes, konti un e-pakalpojumi

70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) - atver projekta mapi VS Code un iestati Git autoru · 2. uzdevums (~25 min) - pieslēdzies GitHub no VS Code un publicē index.html savā GitHub repozitorijā · 3. uzdevums (~20 min) - pievieno otro commit un pārbaudi vēsturi GitHub. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: datorā jābūt uzstādītam VS Code un Git; tev jābūt GitHub kontam ar apstiprinātu e-pastu un jāzina sava GitHub lietotājvārda rakstība. Ja programmu instalēšana skolas datorā nav atļauta, lūdz skolotāja palīdzību.

Teorija: Profesionāli rīki

Visual Studio Code (VS Code) ir koda redaktors, nevis teksta apstrādes rīks (kā Word). Tas saprot koda struktūru un palīdz to rakstīt ar krāsu izcelšanu un paplašinājumiem. GitHub ir koda "mākonis", kas glabā visas tavas izmaiņas (versijas). Tas ļauj tev piekļūt savam darbam no jebkura datora un droši iesniegt mājasdarbus skolotājam.

Git glabā izmaiņu vēsturi tavā datorā; tam nav atsevišķa konta, kurā pieteikties. Lai nosūtītu darbu uz GitHub, dosi VS Code piekļuvi savam GitHub kontam, apstiprinot pieslēgšanos pārlūkā. Pieslēgšanās tikai GitHub mājaslapā vēl nepieslēdz VS Code.

Failu sagatavošanu, commit un push veiksi VS Code Source Control sadaļā. Tikai commit autora sākotnējai iestatīšanai izmantosi divas termināļa komandas. Ctrl+S saglabā failu datorā; uz GitHub izmaiņas nosūta Publish to GitHub vai Push.

Svarīgākie jēdzieni:

  • Repository (Repo): Tava projekta mape mākonī.
  • Commit: Izmaiņu "nofotografēšana" un saglabāšana ar komentāru.
  • Push: Saglabāto izmaiņu nosūtīšana no lokālā datora uz GitHub serveri.
  • Source Control: VS Code sadaļa, kur vari saglabāt izmaiņas, publicēt repozitoriju un sinhronizēt darbu ar GitHub.

Praktiskie uzdevumi

1. uzdevums - Izveido projekta mapi un sagatavo Git

Beigās tavā datorā būs mape spele, kas atvērta VS Code, un Git zinās tavu commit autora vārdu. VS Code pieslēgšanos GitHub pabeigsi 2. uzdevumā, publicējot pirmo failu.

  1. Atver Microsoft store un lejuplādē Visual Studio Code.
  2. Atver datorā VS Code. Ja VS Code vai Git vēl nav uzstādīts, izmanto saites sadaļā “Pirms sāc”. Pēc Git instalēšanas aizver un atver VS Code no jauna.
  3. Atver GitHub mājaslapu un pieslēdzies savam kontam. Ja konta nav, izveido to un apstiprini e-pastu.
  4. Izveido uz darbvirsmas mapi ar nosaukumu spele (bez garumzīmēm un atstarpēm).
  5. Atver šo mapi VS Code: File → Open Folder → spele.
  6. Atver Source Control sadaļu kreisajā rīkjoslā (ikona ar sazarojumu) un nospied Initialize Repository. Ja Git nav pieejams, pārbaudi tā instalēšanu kopā ar skolotāju.
  7. Atver VS Code izvēlni Terminal → New Terminal. Terminālim jāatrodas mapē spele. Izpildi zemāk redzamās komandas pa vienai, aizstājot vārdu un e-pastu ar saviem datiem.
git config user.name "Vārds Uzvārds"
git config user.email "tavs@pasts.lv"

Šie iestatījumi attiecas uz šo projektu un norāda commit autoru; tie nav GitHub pieteikšanās dati. E-pasta vietā vari izmantot GitHub Settings → Emails redzamo privāto noreply adresi. Paroli šajās komandās neraksti.

Gatavs, kad: VS Code ir atvērta mape spele, Git krātuve ir inicializēta un abas autora iestatīšanas komandas izpildītas bez kļūdas.

2. uzdevums - Publicē pirmo failu GitHub

Beigās tavs fails index.html būs redzams GitHub lapā jebkurā datorā.

  1. Izveido mapē spele failu index.html ar rindu <h1>Mana spēle</h1> un saglabā (Ctrl+S).
  2. Atver Source Control sadaļu un nospied Initialize Repository, ja VS Code to piedāvā.
  3. Nospied plusa ikonu pie index.html vai Stage All Changes, lai sagatavotu failu saglabāšanai.
  4. Ieraksti commit ziņu Add game page un nospied Commit.
  5. Nospied Publish to GitHub. Ja pogu neredzi, atver View → Command Palette, ieraksti Publish to GitHub un izvēlies šo komandu. Krātuvi GitHub mājaslapā iepriekš neveido — VS Code to izveidos publicēšanas laikā.
  6. Pieslēdz VS Code savam GitHub kontam: ja parādās piekļuves pieprasījums, nospied Allow vai Sign in. Atvērtajā pārlūkā pārbaudi, ka izmantots tavs GitHub konts, pieslēdzies un apstiprini VS Code piekļuvi ar Authorize Visual Studio Code, ja šāda poga tiek piedāvāta. Ja kontam ieslēgta divu faktoru autentifikācija, izpildi arī to.
  7. Atļauj pārlūkam atvērt Visual Studio Code, ja tas jautā, un atgriezies redaktorā. Kontu izvēlnē (Accounts, cilvēciņa ikona) pārbaudi savu GitHub lietotājvārdu. Ja VS Code jau ir pieslēgts tavam kontam, atkārtota pieteikšanās var nebūt vajadzīga. Ja publicēšana tika pārtraukta, vēlreiz izvēlies Publish to GitHub.
  8. Izvēlies repozitorija nosaukumu spele un redzamību Public, ja skolotājs nav norādījis citādi.
  9. Ja tiek piedāvāta failu izvēle, pārliecinies, ka ir atlasīts index.html, un apstiprini publicēšanu. Sagaidi paziņojumu par veiksmīgu publicēšanu un izvēlies Open on GitHub vai pārlūkā atver https://github.com/TAVS-LIETOTAJVARDS/spele, aizstājot lietotājvārdu ar savu.

Publish to GitHub izveido attālo krātuvi, savieno to ar projekta mapi datorā un nosūta pirmo commit. Nākamās izmaiņas sūtīsi ar Push.

Gatavs, kad: savā GitHub repozitorijā spele redzi failu index.html ar rindu <h1>Mana spēle</h1> un commit ziņu Add game page.

3. uzdevums - Pievieno otro commit un izlasi vēsturi

Beigās GitHub sadaļā "Commits" būs divi ieraksti, un tu redzēsi, kas mainījās katrā.

  1. Pievieno failā index.html rindu <p>Vadi spēli ar bultiņu taustiņiem.</p> un saglabā.
  2. Atver Source Control sadaļu un sagatavo index.html izmaiņas ar plusa ikonu.
  3. Ieraksti commit ziņu Add control hint un nospied Commit.
  4. Source Control izvēlnē “…” izvēlies Push, lai nosūtītu izmaiņas uz GitHub. Vari arī izmantot Sync Changes, kas vispirms saņem attālās izmaiņas un tad nosūta tavējās. Ja tiek prasīta pieslēgšanās, izpildi 2. uzdevuma pieslēgšanās soļus. Sagaidi darbības pabeigšanu bez kļūdas.
  5. Atver GitHub repozitoriju un noklikšķini uz saraksta "Commits".
  6. Noklikšķini uz jaunākā commit - zaļā krāsā jābūt tieši tai rindai, ko pievienoji.
  7. Pieraksti vienu secinājumu: ar ko Commit atšķiras no Push.

Gatavs, kad: GitHub "Commits" sarakstā ir divi ieraksti un jaunākajā zaļā krāsā redzama pievienotā <p> rinda.

Papildu uzdevums - Pievieno README ar projekta aprakstu

Beigās tava repozitorija sākumlapā būs redzams spēles nosaukums un īss apraksts.

  1. Izveido mapē spele failu README.md.
  2. Ieraksti pirmajā rindā # Mana spēle ar savu spēles nosaukumu.
  3. Pievieno zem tā divus teikumus par to, ko spēlētājs darīs.
  4. Sagatavo README.md izmaiņas Source Control sadaļā.
  5. Ieraksti commit ziņu Add project README, nospied Commit un pēc tam Sync Changes.
  6. Pārlādē GitHub lapu.

Gatavs, kad: GitHub repozitorija sākumlapā zem failu saraksta redzams tavs spēles nosaukums un apraksts.

Biežākās kļūdas (un kā tās labot):

  • Fails neparādās GitHub: Pārliecinies, vai pēc Commit nospiedi Push vai Sync Changes.
  • Accounts izvēlnē nav Sign in to GitHub: Sāc Publish to GitHub no komandu paletes, kā norādīts 2. uzdevumā; šī darbība vajadzības gadījumā atvērs pieslēgšanos. Settings Sync sinhronizē redaktora iestatījumus, nevis projekta failus.
  • Pārlūks neatgriežas VS Code vai pieteikšanās atcelta: Atļauj atvērt Visual Studio Code un atkārto publicēšanu vai Push. Ja VS Code piedāvā citu pieteikšanās veidu vai koda ievadi, seko tā norādēm.
  • Commit prasa user.name un user.email: Izpildi 1. uzdevuma autora iestatīšanas komandas projekta terminālī un vēlreiz nospied Commit.
  • Push rāda Authentication failed vai Permission denied: Pārbaudi, vai VS Code Accounts izvēlnē un pārlūkā izmantots tavs GitHub konts un krātuve pieder tev. Ja redzams cits konts, izraksties no tā un pieslēdzies savam. Ja saglabājusies cita lietotāja piekļuve datorā, lūdz skolotāja palīdzību. GitHub konta paroli Git HTTPS paroles pieprasījumā neizmanto; atjauno pieslēgšanos pārlūkā.
  • VS Code neatpazīst Git: Pasauc skolotāju, lai pārbaudītu datora uzstādījumus.
  • Krātuve spele jau eksistē: Ja tā ir iepriekš izveidota krātuve, lūdz skolotājam palīdzēt to atvērt ar Clone Repository; ja šis ir jauns projekts, publicējot izvēlies citu nosaukumu, piemēram, spele-2.

VS Code darbību secība bez termināļa

Pēc vienreizējās Git iestatīšanas: Saglabā failu → Stage (+) → Commit → Push → pārbaudi GitHub. Pirmajā reizē Push vietā izmanto Publish to GitHub un apstiprini pieslēgšanos.

  1. Source Control sadaļā apskati izmainītos failus.
  2. Sagatavo vajadzīgos failus ar plusa ikonu.
  3. Ieraksti īsu commit ziņu, piemēram, Add control hint.
  4. Nospied Commit.
  5. Nospied Sync Changes vai Push.
  6. Pārbaudi GitHub repozitorijā, vai faili un "Commits" saraksts ir atjaunoti.
GitHub repozitorija lapā fails index.html ir atjaunots, un "Commits" sarakstā ir jauns ieraksts ar tavu ziņu.

Pirms stundas beigām

Pārlādē savu GitHub krātuvi un atver index.html: tur jābūt gan virsrakstam, gan vadības norādei. Vēsturē jābūt commit ziņām Add game page un Add control hint (un README commit, ja izpildīji papildu uzdevumu). Tukšs Changes saraksts VS Code pats par sevi vēl nenozīmē, ka darbs ir nosūtīts. Iesniedz skolotājam krātuves saiti.

Papildu palīdzība: VS Code pieslēgšanās GitHub un Source Control pamācība.
