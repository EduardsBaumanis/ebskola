4.1 Funkcijas: viena darbība vairākām pogām

Šodien: Izmanto vienu JavaScript funkciju ar parametru vairākām punktu pogām (gan pieskaitīšanai, gan atņemšanai) un ar atsevišķu attēlošanas funkciju atjauno spēles rādītājus lapā.

Teorija ar piemēriem

Kas ir funkcija (function) un kā to izsauc no pogas (onclick)

Spēlēs vairākas pogas bieži veic vienu un to pašu darbību secību — piemēram, izmaina varoņa enerģiju vai punktus, pieskaita gājienu un atjauno skaitļus ekrānā. Lai šīs komandas nebūtu jāpārraksta katrai pogai atsevišķi, tās sagrupē nosauktā blokā jeb funkcijā:

let energija = 10;

function mainitEnergiju(daudzums) {
  energija = energija + daudzums;
  atjaunotEkranu();
}

function atiestatit() {
  energija = 10;
  atjaunotEkranu();
}
Pieraksta daļa Ko tā nozīmē? Piemērs
function nosaukums(...) { ... } Definē (apraksta) funkciju un iemāca pārlūkam jaunu komandu. Pati definīcija, atverot lapu, vēl neko neizpilda. function atiestatit() { ... }
Nosaukuma rakstība Funkcijas vārdā nelieto garumzīmes un atstarpes; vārdu savienojumā otro vārdu sāk ar lielo burtu. saktNoJauna, mainitEnergiju
Izsaukums JavaScript kodā Nosaukums ar apaļajām iekavām () liek pārlūkam tūlīt izpildīt figūriekavās ierakstītās rindas. atjaunotEkranu();
Izsaukums no HTML pogas Atribūts onclick="..." izpilda funkciju katrā klikšķa reizē (iekavas () ir obligātas!). <button onclick="atiestatit()">No sākuma</button>

Atceries no 3. tēmas: spēles stāvokļa mainīgie (piemēram, let energija = 10;) vienmēr jāizveido <script> sākumā ārpus funkcijām. Ja mainīgo ar let izveidotu funkcijas iekšpusē, katrs klikšķis to sāktu skaitīt no sākuma.

Funkcijas parametrs: kā viena funkcija pieskaita un atņem dažādus skaitļus

Mainīgais funkcijas virsraksta iekavās — piemēram, daudzums iekš function mainitEnergiju(daudzums) — ir parametrs jeb vieta ienākošajam skaitlim. Katra poga izsaukuma iekavās padod savu konkrēto skaitli (argumentu):

<button onclick="mainitEnergiju(3)">+3 ogu deva</button>
<button onclick="mainitEnergiju(10)">+10 enerģijas dzēriens</button>
<button onclick="mainitEnergiju(-4)">−4 šķēršļa trieciens</button>
  • Pozitīvs skaitlis (3 vai 10) izteiksmē energija = energija + daudzums; palielina vērtību.
  • Negatīvs skaitlis (-4) tajā pašā saskaitīšanas rindā vērtību samazina (piemēram, 23 + (-4) = 19). Tāpēc soda vai izmaksu pogai nav jāraksta jauna atņemšanas funkcija!
  • Rakstība kodā un tekstā: onclick iekavās skaitli raksta bez pēdiņām un negatīvam skaitlim lieto parasto tastatūras mīnusu jeb defisi - cieši pie cipara (-4). Savukārt pogas redzamajā uzrakstā starp >...< cilvēkam var rakstīt glītu garo mīnusu −4 un paskaidrojošus vārdus.
  • Saskaņa ar uzrakstu: pārlūks rēķina pēc iekavās dotā skaitļa, nevis pēc pogas teksta — ja nomainīsi tikai pogas uzrakstu uz +20, bet atstāsi onclick="mainitEnergiju(10)", kods joprojām pieskaitīs 10!
Spēlētāja darbība Parametra daudzums vērtība Aprēķins atmiņā energija pēc darbības
Lapas atvēršana — Sākuma vērtība 10
Klikšķis uz mainitEnergiju(3) 3 10 + 3 13
Klikšķis uz mainitEnergiju(10) 10 13 + 10 23
Klikšķis uz mainitEnergiju(-4) -4 23 + (-4) 19
Klikšķis uz atiestatit() — Piešķir sākuma vērtību 10 10

Ja spēles noteikumi neļauj skaitlim noslīdēt zem nulles, funkcijā uzreiz pēc aprēķina (pirms ekrāna atjaunošanas) var pievienot pārbaudi if (energija < 0) { energija = 0; }.

Kāpēc ekrāna atjaunošanu izdala atsevišķā funkcijā paradit()?

Mainīgā aprēķins maina skaitli tikai datora atmiņā, bet HTML rindkopas (<p id="...">) ekrānā rāda pēdējo tajās ierakstīto tekstu. Tāpēc spēlēs izveido palīgfunkciju paradit(), kuras vienīgais pienākums ir saskaņot visus redzamos lapas uzrakstus ar mainīgo vērtībām:

let energija = 10;
let gajieni = 0;

function paradit() {
  document.getElementById("energija").textContent = "Enerģija: " + energija;
  document.getElementById("gajieni").textContent = "Gājieni: " + gajieni;
}

Kāds ir ieguvums? Kad spēlei pievieno jaunu rādītāju (piemēram, veikto darbību vai gājienu skaitītāju), document.getElementById(...).textContent rinda jāpieraksta tikai vienā vietā — funkcijā paradit(). Gan izmaiņu funkcija, gan atiestatīšanas funkcija savās beigās izsauc paradit();, tāpēc abi rādītāji vienmēr atjaunojas sinhroni.

Ja pēc pogas nospiešanas nekas nenotiek, pārlūkā (Edge vai Chrome) nospied F12 un atver cilni Console: tur redzēsi precīzu kļūdas vietu (piemēram, is not defined pie drukas kļūdas funkcijas nosaukumā vai Cannot set properties of null pie neprecīza HTML id).

Pašpārbaude: kāpēc jaunas +10 punktu pogas izveidošanai nav jāraksta vēl viena JavaScript funkcija, un kas notiktu, ja funkcijas beigās aizmirstu izsaukt paradit()?

1) Esošā funkcija ar parametru jau prot pieskaitīt jebkuru skaitli — jaunajai pogai atliek onclick iekavās padot skaitli 10. 2) Ja neizsauktu paradit(), mainīgais datora atmiņā gan mainītos, taču teksts pārlūka lapā paliktu sastindzis ar veco vērtību.

1. uzdevums

Izpēti gatavās funkcijas un pielāgo spēles ievadu

Izmanto teoriju: Kas ir funkcija (function) un kā to izsauc no pogas (onclick).

Vide: Windows File Explorer → pārlūks → VS Code

  1. Windows mapē Desktop/datorika9-tema4 atver saglabāto 41.html pārlūkā (ar peles labo pogu izvēlies Open with → Edge) un pārliecinies, ka sākumā kartītē redzams Punkti: 0.
  2. Paredzi rezultātu un trīs reizes pēc kārtas nospied pogu +1 punkts — pārbaudi, kā katrs klikšķis palielina uzrakstu uz Punkti: 1, Punkti: 2 un Punkti: 3.
  3. Nospied pogu Sākt no jauna un pārliecinies, ka funkcija saktNoJauna() noliek skaitītāju atpakaļ uz Punkti: 0.
  4. VS Code failā 41.html salīdzini HTML pogu atribūtus onclick="pieskaitit(1)" un onclick="saktNoJauna()" ar atbilstošajām function definīcijām <script> blokā.
  5. Nomaini gan <title>, gan <h1> uz savas spēles nosaukumu (piemēram, kosmosa vākšanas, sacīkšu vai piedzīvojumu spēlei).
  6. Rindkopā <p id="noteikumi"> ieraksti savas spēles mērķa teikumu un pēc vēlēšanās papildini pirmās pogas redzamo tekstu (piemēram, +1 monēta), atstājot neskartus atribūtus onclick="pieskaitit(1)" un id="punkti".
  7. Saglabā failu ar Ctrl+S, pārlūkā nospied Ctrl+R un pārbaudi, ka redzams jaunais spēles virsraksts un abas sākuma pogas joprojām darbojas.

Gatavs, kad: esi pārbaudījis pieskaitit(1) un saktNoJauna() darbību pārlūkā un pielāgojis lapas virsrakstu un noteikumu ievadu savai spēlei.

2. uzdevums

Pievieno bonusa (+5) un soda (−2) pogas ar to pašu funkciju

Izmanto teoriju: Funkcijas parametrs: kā viena funkcija pieskaita un atņem dažādus skaitļus.

Vide: VS Code → pārlūks

  1. HTML blokā <div class="panelis"> atrodi komentāru <!-- 2. UZDEVUMS: šeit pievieno +5 un −2 punktu pogas --> starp pirmo punktu pogu un pogu Sākt no jauna.
  2. Komentāra vietā pievieno otro pogu, kas atribūtā onclick izsauc to pašu funkciju pieskaitit ar argumentu 5 un uzrakstā skaidri norāda +5 punktu ieguvumu (jaunu function iekš <script> neraksti!).
  3. Paredzi punktu summu pēc klikšķiem uz +1 un +5, saglabā failu ar Ctrl+S, pārlūkā nospied Ctrl+R un pārbaudi, ka pēc abiem klikšķiem parādās Punkti: 6.
  4. Tieši zem otrās pogas pievieno trešo — soda vai šķēršļa pogu, kas atribūtā onclick izsauc to pašu funkciju ar negatīvu skaitli -2 (iekavās raksti parasto tastatūras mīnusu - cieši pie 2 bez pēdiņām, bet pogas uzrakstā norādi −2 punktus).
  5. Atjauno rindkopu <p id="noteikumi"> tā, lai spēlētājam būtu izskaidrotas visas trīs darbības (+1, +5 un −2).
  6. Pirms pārbaudes galvā aprēķini rezultātu secībai +1, +5, −2 no nulles (0 + 1 + 5 - 2), pēc tam saglabā ar Ctrl+S un atjauno pārlūku ar Ctrl+R.
  7. Pārlūkā nospied pogas +1, +5 un −2: pārliecinies, ka lapā parādās Punkti: 4, un pēc pogas Sākt no jauna nospiešanas rezultāts atkal kļūst Punkti: 0.

Gatavs, kad: viena funkcija pieskaitit(skaits) apkalpo visas trīs punktu pogas (+1, +5, −2), un klikšķu secība +1 → +5 → −2 parāda 4 punktus.

3. uzdevums

Papildini paradit() ar darbību skaitītāju un pārbaudi konsoli

Izmanto teoriju: Kāpēc ekrāna atjaunošanu izdala atsevišķā funkcijā paradit()?.

Vide: VS Code → pārlūks (ar F12 Console)

  1. HTML blokā <div class="panelis"> zem <p id="punkti">Punkti: 0</p> (komentāra vietā) pievieno jaunu rindkopu <p id="darbibas">Darbības: 0</p>.
  2. <script> sākumā zem let punkti = 0; izveido mainīgo let darbibas = 0; (ārpus funkcijām, lai skaitītājs saglabātos starp klikšķiem).
  3. Funkcijā pieskaitit(skaits) tieši pirms rindas paradit(); pievieno darbibas = darbibas + 1;, lai katrs punktu pogas klikšķis pieskaitītu vienu darbību.
  4. Funkcijā saktNoJauna() tieši pirms rindas paradit(); pievieno darbibas = 0;, lai atiestatīšana nullētu arī darbību skaitu.
  5. Funkcijā paradit() zem #punkti rindas pievieno document.getElementById("darbibas").textContent = "Darbības: " + darbibas; — šī viena rinda atjaunos skaitītāju gan pēc punktu maiņas, gan pēc sākšanas no jauna.
  6. Paredzi abu skaitītāju vērtības, saglabā ar Ctrl+S, pārlūkā nospied Ctrl+R un pēc kārtas nospied +1, +5, −2: pārbaudi, ka redzams Punkti: 4 un Darbības: 3, bet pēc Sākt no jauna abi rādītāji kļūst 0.
  7. Pārlūkā nospied F12 un atver cilni Console: atkārtoti nospied visas četras pogas un pārliecinies, ka sarakstā nav neviena sarkana kļūdas paziņojuma.

Gatavs, kad: palīgfunkcija paradit() sinhroni atjauno gan punktus, gan veikto darbību skaitu (pēc +1, +5, −2 ir 4 punkti un 3 darbības; pēc Sākt no jauna — abi ir 0), un Console cilnē nav kļūdu.

Papildu uzdevums: Neļauj punktiem kļūt negatīviem

Sāc, kad visi trīs pamatuzdevumi ir pabeigti.

Izmanto teoriju: Negatīva skaitļa pārbaude un Izpildes secība pirms paradit().

  1. <script> blokā atver funkciju pieskaitit(skaits) un atrodi vietu pēc punktu aprēķina, bet pirms izsaukuma paradit();.
  2. Pievieno nosacījumu, kas negatīvu punktu kopsummu nolīdzina uz nulli (salīdzini mainīgo ar 0, izmantojot zīmi <, un nepieciešamības gadījumā piešķir 0).
  3. Saglabā failu ar Ctrl+S, atjauno pārlūku ar Ctrl+R un pie 0 punktiem nospied soda pogu −2 — pārliecinies, ka punkti paliek Punkti: 0, kamēr Darbības pieaug uz 1.
  4. Pārbaudi vēl divas situācijas: nospied +1 un tad −2 (jāpaliek Punkti: 0), pēc tam nospied +5 un −2 (virs nulles atņemšanai joprojām jādod Punkti: 3).

Gatavs, kad: punktu skaits nekad nenoslīd zem 0, bet pozitīvo punktu samazināšana un darbību skaitīšana turpina strādāt.

Ja kaut kas neizdodas
  • Soda poga (−2) nestrādā un F12 → Console rāda SyntaxError: Invalid or unexpected token? Pārbaudi pogas onclick atribūtu: iekavās jāraksta parastais tastatūras mīnuss jeb defise (piemēram, (-4)), nevis garā tipogrāfiskā mīnus zīme −! Garo − drīkst atstāt tikai pogas redzamajā tekstā.
  • Saskaitīšanas vietā skaitļi salīp tekstā (piemēram, Punkti: 015)? Noņem pēdiņas ap skaitli izsaukuma iekavās — padod skaitli kā (5), nevis kā tekstu ("5"). Pēdiņās skaitlis kļūst par tekstu un tiek piekabināts galā.
  • Nospiežot pogu, nekas nemainās un konsolē rāda is not defined vai nekādu reakciju? Pārliecinies, ka onclick="..." nosaukums burtu pa burtam sakrīt ar function nosaukumu (bez garumzīmēm!) un galā ir apaļās iekavas (), piemēram, onclick="saktNoJauna()".
  • Konsolē rāda Cannot set properties of null vai Darbības vienmēr rāda 1? Pārbaudi, vai HTML daļā tiešām pievienoji <p id="darbibas"> ar precīzi tādu pašu id kā getElementById("darbibas"), un vai let darbibas = 0; atrodas skripta augšpusē ārpus funkcijām.
  • Neredzi savas izmaiņas vai kods pārlūkā atveras kā parasts teksts? VS Code nospied Ctrl+S, tad pārlūkā nospied Ctrl+R un pārliecinies, ka atvērts tieši Desktop/datorika9-tema4/41.html (Windows File Explorer ieslēdz View → Show → File name extensions, lai beigās nebūtu .txt).
