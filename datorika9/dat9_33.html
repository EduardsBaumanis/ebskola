3.3 Nosacījumi: kad spēlētājs uzvar?

Šodien: Izveido punktu pārbaudi ar trim atšķirīgiem rezultātiem.

Īsā teorija

if nozīmē “ja”. else nozīmē “citādi”.

>= nozīmē “lielāks vai vienāds”; < nozīmē “mazāks”.

Ar else if pievieno vēl vienu pārbaudi. Pārbaudes notiek no augšas uz leju. 

if (punkti < 0) {
  zina = "Punkti nevar būt negatīvi.";
} else if (punkti >= 10) {
  zina = "Uzvara!";
} else {
  zina = "Turpini spēli!";
}

Sākuma kods un darba vieta

Vide: mācību lapa → VS Code

  3. VS Code nospied Ctrl+N un ielīmē kodu ar Ctrl+V .

1. uzdevums

Izmēģini robežu

Vide: VS Code → pārlūks

  1. Sāc ar 33.html .
  2. Pārlūkā pārbaudi 9 un 10 punktus.
  3. Ievēro, ka pie 10 punktiem ziņa mainās uz Uzvara! .

Gatavs, kad: Atpazīsti, pie kura skaita mainās rezultāts.

2. uzdevums

Pievieno trešo rezultātu

Vide: VS Code

  1. Atrodi visu if ... else bloku.
  2. Aizstāj to ar šīs lapas teorijas piemēru. Saglabā rindu, kas parāda zina .
  3. Pārbaudi, ka visām figūriekavām ir pāris.

Gatavs, kad: Kodā ir negatīvu punktu, uzvaras un turpināšanas gadījums.

3. uzdevums

Maini mērķi un pārbaudi visus gadījumus

Vide: VS Code → pārlūks

  1. Uzvaras robežu nomaini uz 20 .
  2. HTML daļā pievieno norādi, ka uzvarai vajag 20 punktus. Izvēlies savai spēlei piemērotas ziņas.
  3. Pārlūkā pārbaudi -1 , 19 un 20 . Jāparādās trim atbilstošajām ziņām.
  4. Saglabā un nosūti darbu uz GitHub.

Gatavs, kad: Visi trīs pārbaudes gadījumi dod pareizo rezultātu.

Iesniedz 3. uzdevuma rezultātu

Iesniedz pabeigto 33.html skolotāja norādītajā vietā. Šo pašu versiju saglabā arī GitHub.

Stunda ir ieskaitīta, ja 3. uzdevuma rezultāts atbilst visiem šiem punktiem:

  • Kodā ir if, else if un else.
  • Uzvaras robeža kodā un lapas norādē ir 20.
  • −1 dod brīdinājumu, 19 — turpināšanu, 20 — uzvaru.

1. un 2. uzdevums sagatavo šo rezultātu. Papildu uzdevums nav vajadzīgs ieskaitei.

Saglabā un nosūti uz GitHub — pogu atgādne

Vide: VS Code / Source Control → GitHub pārlūkā

  1. Ar File → Save All saglabā failus. Atver Source Control ar Ctrl+Shift+G .
  2. Pie Changes nospied + (Stage All Changes). Pārbaudi, ka vajadzīgie faili pārvietojas uz Staged Changes .
  3. Ziņas laukā ieraksti īsu izmaiņu, piemēram, Pabeigts 3.3 darbs . Spied Commit .
  4. Ja šī tēmas mape vēl nav GitHub, spied Publish to GitHub un izveido publisku projektu datorika9-tema3 . Jau publicētam projektam spied Sync Changes . Ja pogas nav, atver … → Push .
  5. Pārlūkā atver savu GitHub projektu un pārbaudi faila pēdējās izmaiņas.

Ja Source Control rāda Initialize Repository , vispirms nospied to. Ja parādās kļūda vai sapludināšanas pieprasījums, izmanto palīdzību un palūdz skolotāja atbalstu.

Papildu uzdevums: Pievieno lielo uzvaru

Sāc, kad 3. uzdevums ir gatavs un iesniegts. Ja vēlies paturēt obligāto versiju, saglabā kopiju ar citu nosaukumu.

  1. Pirms parastās uzvaras pārbaudes pievieno gadījumu punkti >= 100 .
  2. Parādi īpašu ziņu un pārbaudi 99 un 100 punktus.
Ja kaut kas neizdodas
  • Neredzi izmaiņas? VS Code nospied Ctrl+S. Pārlūkā nospied Ctrl+R. Pārbaudi, ka atvērts tieši 33.html .
  • Kods redzams kā teksts? Saglabā ar galotni .html. Windows ieslēdz View → Show → File name extensions un pārbaudi, ka beigās nav .txt.
  • Poga nestrādā? Pārbaudi, vai neizdzēsi pēdiņu, iekavu vai elementa id. Salīdzini savu laboto vietu ar sākuma kodu.
  • Nesaproti nākamo soli? Atrodi pirmo nepabeigto soli un parādi skolotājam tieši šo vietu.
