GitHub palīdzība

Saglabā failu datorā, saglabā darba versiju un nosūti to uz GitHub.

Trīs dažādas saglabāšanas darbības

  • Ctrl+S saglabā pašreizējo failu datorā.
  • Commit saglabā izvēlēto failu darba versiju datorā.
  • Sync Changes nosūta versijas uz GitHub un saņem tur esošās izmaiņas.

Piemērs: nomainīji spēles nosaukumu

Failu vari uztvert kā pašreizējo darbu, bet Git versiju — kā saglabātu pieturpunktu ar izmaiņas aprakstu. GitHub glabā nosūtītos pieturpunktus, lai darbam varētu piekļūt arī ārpus šī datora.

SolisKas notiek ar labojumu?
Ctrl+S vai Save All.Jaunais nosaukums ir failā datorā; pārlūks to nolasa pēc lapas atjaunošanas.
Stage Changes (+).Izvēlies saglabātās izmaiņas, kuras iekļaut nākamajā versijā.
Commit ar ziņu “Precizēts spēles nosaukums”.Izvēlētās izmaiņas saglabā Git versijā datorā.
Pirmoreiz Publish to GitHub, vēlāk Sync Changes.Pēc veiksmīgas nosūtīšanas versija ir arī GitHub projektā.
Atver failu GitHub.Pārbaudi, vai tur tiešām redzams jaunais nosaukums.

Ja pēc Stage Changes vēl kaut ko izlabo, saglabā un izvēlies jauno izmaiņu vēlreiz, lai arī tā nonāktu versijā. Pieslēgšanās kontam viena pati nenosūta darba failus. Nosūtīšanas darbībai jābeidzas veiksmīgi; kļūdas gadījumā izmanto šīs lapas palīdzību.

Pašpārbaude: vai Sync Changes nosūtīs nesaglabātu tekstu no redaktora?

Nē. Vispirms saglabā failu, izvēlies izmaiņas ar Stage Changes un izveido Commit. Tikai tad nosūti versiju.

Atver savu darbu

Vide: VS Code

  1. Ar File → Open Folder atver attiecīgās tēmas mapi uz Desktop .
  2. Ja šajā datorā mapes nav, atver Source Control → Clone Repository . Ievieto sava GitHub projekta adresi un vietai izvēlies Desktop . Pēc lejupielādes spied Open .
  3. Ja pirms stundas strādāji citā datorā un šajā mapē nav nesaglabātu izmaiņu, lieto Source Control → … → Pull , lai saņemtu savu jaunāko darbu.
  4. Ja mape vēl nekad nav saglabāta GitHub, atver Source Control un spied Initialize Repository .

Pirmoreiz nosūti tēmas mapi

Vide: VS Code → GitHub pārlūkā → VS Code

  1. Ar File → Save All saglabā failus. Atver Source Control .
  2. Pie Changes spied + (Stage All Changes). Ziņas laukā ieraksti, ko paveici, un spied Commit .
  3. Spied Publish to GitHub . Ja šī poga nav redzama, nospied Ctrl+Shift+P un meklē Publish to GitHub . Tas ir VS Code darbību meklētājs.
  4. Pārlūkā pieslēdzies savam GitHub kontam un apstiprini VS Code piekļuvi. Atgriezies VS Code.
  5. Izvēlies Publish to GitHub public repository . Nosauc projektu, piemēram, datorika9-tema2 . Ja ir failu atlase, izvēlies mācību darba failus.
  6. GitHub atver izveidoto projektu un pārbaudi failu sarakstu. Iestatījumu sinhronizēšana ar Accounts viena pati spēles failus nenosūta.

Nosūti nākamās izmaiņas

Vide: VS Code / Source Control → GitHub pārlūkā

  1. File → Save All .
  2. Source Control → Changes → + .
  3. Ziņas laukā īsi ieraksti izmaiņu un spied Commit .
  4. Sync Changes . Ja pogas nav, izmanto … → Push .
  5. GitHub failā pārbaudi, vai redzama pēdējā izmaiņa.

Atver rezultātu pārlūkā

Vide: Windows → pārlūks

  1. Windows atver savu tēmas mapi uz darbvirsmas.
  2. Uz HTML faila nospied peles labo pogu un izvēlies Open with → Edge .
  3. Pēc koda maiņas VS Code saglabā ar Ctrl+S ; pārlūkā atjauno ar Ctrl+R .

Ja ir šķērslis

  • Git nav atrasts: skolotājs palīdz uzstādīt Git; pēc tam aizver un atver VS Code.
  • Prasa user.name vai user.email: skolotājs palīdz sagatavot Git autora iestatījumus. Tie nav tas pats, kas GitHub pieslēgšanās.
  • Nothing to commit: iespējams, viss jau saglabāts. Ja veici labojumu, vispirms saglabā failu ar Ctrl+S un izvēlies pareizo mapi.
  • Nosūtīšana neizdodas: pārbaudi internetu un pieslēgšanos savam GitHub kontam. Ja redzi konfliktu, lūdz skolotāja palīdzību, parādot šo paziņojumu.
  • GitHub rāda vecu failu: pārbaudi, vai pēc Commit nospiedi Sync Changes un sagaidīji nosūtīšanas beigas.
Skolotājam: sagatavošana un avoti
