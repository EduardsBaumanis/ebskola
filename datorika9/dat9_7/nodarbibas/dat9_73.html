E-pasta adreses uzbūve

anna.kalnina  @  skola.example  .lv
└ lietotājvārds  │  └ domēns       └ augstākā līmeņa domēns
                 └ „et” zīme: „pie”
  • Lietotājvārds — konkrētā pastkastīte, piemēram, anna.kalnina.
  • @ — atdala lietotāju no servera; adresē tā ir tieši viena.
  • Domēns — pasta servera nosaukums, piemēram, skola.example.lv. Tajā ir vismaz viens punkts.
  • Augstākā līmeņa domēns — pēdējā daļa aiz punkta: .lv (Latvija), .com, .org.

Adresē nav atstarpju, un parasti nelieto garumzīmes. Viena burta kļūda domēnā aizsūta vēstuli citam serverim — vai krāpniekam, kas reģistrējis līdzīgu vārdu (par to 7.4. nodarbībā).

E-pasta sistēmas, skolas un personālais e-pasts

Pasta vēstules glabājas pasta serverī. Tās var lasīt ar dažādiem klientiem — tas ir klientservera princips no 7.1. nodarbības:

  • tīmekļa pasts — pārlūkā, piemēram, Outlook tīmeklī vai Gmail; nekas nav jāinstalē;
  • e-pasta lietotne — Outlook datorā vai pasta lietotne telefonā; tā rāda to pašu pastkastīti.

Tīkla etiķete un drošība saziņā

  • Pirms sūtīšanas pārbaudi saņēmējus. Reply atbild tikai sūtītājam, Reply All — visiem. Atbilde „Paldies!” 30 cilvēkiem ir lieka, bet privāta atbilde visiem — kļūda.
  • Svešu adreses slēp. E-pasta adrese ir personas dati: rakstot daudziem, liec viņus BCC.
  • Nesūti paroles, personas kodu un citu cilvēku ziņas vai attēlus bez viņu atļaujas.
  • Nesūti dusmās. Uzraksti melnrakstu, pagaidi un izlasi vēlreiz. Nosūtītu ziņu nevar atsaukt — to var pārsūtīt un saglabāt.
  • Nekliedz ar LIELAJIEM BURTIEM un neraksti tikai emocijzīmēs lietišķā vēstulē.
  • Ja kāds tevi aizskar tiešsaistē, neatbildi tajā pašā tonī: saglabā pierādījumus (ekrānuzņēmums) un pastāsti skolotājam vai vecākiem.
Pašpārbaude: tev jāaizsūta skolotājam spēles mape, kas aizņem 60 MB. Ko darīsi?

Pielikums būs par lielu. Sūti saiti: uz publicēto spēli GitHub Pages vai uz mapi mākoņkrātuvē ar tiesībām „tikai skatīt”. Temats un teksts paskaidro, kas aiz saites.

1. uzdevums

Pārbaudi adreses un izlabo pārbaudītāju

Izmanto teoriju: E-pasta adreses uzbūve.

Vide: VS Code → pārlūks

  1. Saglabā sākuma kodu kā 73.html un atver to pārlūkā. Pārbaudi pāris adreses laukā augšā un apskati, kā tās sadalās lietotājvārdā, domēnā un augstākā līmeņa domēnā.
  2. Nospied Pārbaudīt visas. Kopsavilkumā ir Pareizi: 7 no 10. Atrodi trīs rindas ar ✗ un pasaki, kuru teorijas noteikumu pārbaudītājs neievēro.
  3. Funkcijā parbauditAdresi pirmā komentāra vietā pievieno: if (adrese.indexOf("@") !== adrese.lastIndexOf("@")) { return { derigs: false, iemesls: "vairāk nekā viena @ zīme" }; }. Ja pirmā un pēdējā @ vieta atšķiras, @ ir vairāk nekā viena.
  4. Otrā komentāra vietā pievieno: if (!domens.includes(".")) { return { derigs: false, iemesls: "domēnā nav punkta" }; }.
  5. Saglabā, atjauno lapu un vēlreiz nospied Pārbaudīt visas.

Gatavs, kad: kopsavilkums rāda Pareizi: 10 no 10, un anna@@example.com ir „nederīga: vairāk nekā viena @ zīme”.

2. uzdevums

Nosūti lietišķu e-pastu ar saiti uz savu spēli

Izmanto teoriju: Lietišķs e-pasts un Skolas un personālais e-pasts.

Vide: personālais e-pasts pārlūkā → Snipping Tool → VS Code

  1. Atver savu personālo e-pastu pārlūkā — to pašu, ar kuru reģistrēji GitHub kontu — un izveido jaunu vēstuli.
  2. Laukā Kam ieraksti skolotāja norādīto adresi. Temats: 9.x, Vārds Uzvārds — 7.3: saite uz manu spēli ar savu klasi un vārdu.
  3. Uzraksti uzrunu, divus teikumus par savu spēli, ielīmē tās GitHub Pages saiti (nevis pielikumu), noslēgumu un savu vārdu un klasi.
  4. Pirms sūtīšanas pārbaudi: saņēmējs, temats, vai saite atveras. Nospied Send.
  5. Atver mapi Sent (Nosūtītie) un nosūtīto vēstuli. Ar Win+Shift+S uzņem ekrānuzņēmumu, kurā redzams temats un teksts. Snipping Tool logā ar pildspalvu pilnībā aizkrāso abas e-pasta adreses — savu un skolotāja.
  6. Saglabā attēlu kā epasts_73.png mapē datorika9-tema7 un pārbaudi, ka tas parādās lapā sadaļā „Mans lietišķais e-pasts” un ka adreses nav izlasāmas.

Gatavs, kad: skolotājs ir saņēmis vēstuli ar skaidru tematu, uzrunu, divus teikumus, strādājošu saiti un tavu vārdu, un lapā ir tās ekrānuzņēmums bez redzamām adresēm.

3. uzdevums

Atrisini situāciju kartītes un papildini testus

Izmanto teoriju: Kuru saziņas rīku izvēlēties un Tīkla etiķete un drošība saziņā.

Vide: VS Code → pārlūks

  1. Failā 73.html katrā no trim situāciju kartītēm punktu ... vietā ieraksti: kādu rīku izmantosi, kuru lauku vai paņēmienu (piemēram, BCC, saite mākoņkrātuvē, pauze pirms atbildes) un kāpēc — ar atsauci uz teorijas noteikumu.
  2. Masīvā testaAdreses pievieno divas savas izdomātas adreses: vienu derīgu un vienu nederīgu ar citu kļūdu nekā esošajām. Nelieto īstas adreses — lapa būs publiska.
  3. Nospied Pārbaudīt visas. Ja kāda tava adrese saņem ✗, izdomā, kas pārbaudītājam vēl jāpārbauda, un pieraksti to komentārā virs funkcijas.
  4. Saglabā, nosūti uz GitHub (Sync Changes) un pārbaudi, ka projektā ir 73.html un epasts_73.png.

Gatavs, kad: visās trīs kartītēs ir rīks, paņēmiens un pamatojums, testu tabulā ir 12 adreses, un GitHub projektā ir abi faili.

Iesniedz 3. uzdevuma rezultātu

Iesniedz GitHub projekta datorika9-tema7 saiti skolotāja norādītajā vietā. Projektā jābūt 73.html un epasts_73.png.

Stunda ir ieskaitīta, ja 3. uzdevuma rezultāts atbilst visiem šiem punktiem:

  • Pārbaudītājs noraida adreses ar divām @ zīmēm un bez punkta domēnā; desmit doto adrešu tests ir 10 no 10.
  • Skolotājs saņēma lietišķu e-pastu no personālās adreses ar tematu, uzrunu, saiti un vārdu.
  • Ekrānuzņēmumā nav redzamas e-pasta adreses.
  • Trīs kartītēs izvēlēti piemēroti rīki (BCC ielūgumam, saite lielam failam, pauze un privāta saruna konfliktā) ar pamatojumu.
  • Testos ir divas tavas izdomātas adreses.

1. un 2. uzdevums sagatavo šo rezultātu. Papildu uzdevums nav vajadzīgs ieskaitei.

Papildu uzdevums: „Vai tu domāji…?” bieži sajauktiem domēniem

Sāc, kad 3. uzdevums ir gatavs un iesniegts.

Izmanto teoriju: E-pasta adreses uzbūve.

  1. Skripta sākumā izveido objektu ar biežām kļūdām: const labojumi = { "gmial.com": "gmail.com", "gmail.co": "gmail.com", "outlok.com": "outlook.com" };.
  2. Funkcijā paraditVienu derīgai adresei pārbaudi if (labojumi[r.domens]) un pievieno rezultātam tekstu " — Vai tu domāji " + labojumi[r.domens] + "?".
  3. Pārbaudi ar anna@gmial.com un pievieno vēl divas savas biežās kļūdas.

Gatavs, kad: adrese ar sajauktu domēnu ir derīga, bet pārbaudītājs piedāvā pareizo domēnu.

Ja kaut kas neizdodas
  • Pēc izmaiņām tabula ir tukša? Atver F12 → Console. Visbiežāk trūkst iekavas } vai pēdiņas tavā jaunajā rindā.
  • Tagad visas adreses ir nederīgas? Pārbaudi, vai nosacījumā ir !== (nav vienāds) un !domens.includes(".") ar izsaukuma zīmi.
  • Tavs personālais e-pasts neatveras skolas datorā? Pajautā skolotājam: varbūt jāsūta no telefona. Tad ekrānuzņēmumu pārsūti uz datoru un aizkrāso adreses.
  • Snipping Tool nav pildspalvas? Pēc Win+Shift+S noklikšķini uz paziņojuma ekrāna stūrī — atvērsies redaktors ar pildspalvu un apgriešanu. Vari arī apgriezt attēlu tā, lai adreses paliek ārpusē.
  • Vēstule nonāca surogātpastā vai neatnāca? Pārbaudi adresi burtu pa burtam. Ja tā ir pareiza, pasaki skolotājam — vēstule var būt Junk mapē.
