Klients, serveris, pieprasījums un atbilde

5.6. nodarbībā publicēji spēli GitHub Pages. Kad kāds atver tās saiti, notiek saruna starp diviem datoriem:

  • klients — pārlūks spēlētāja datorā vai telefonā — nosūta pieprasījumu: „Lūdzu, failu index.html”;
  • serveris — dators GitHub datu centrā, kurā glabājas tava spēle — nosūta atbildi: statusa kodu un faila saturu.

Tā ir klientservera arhitektūra: viens serveris apkalpo daudzus klientus. Katrai lapai, attēlam un skaņai pārlūks sūta atsevišķu pieprasījumu. Atbildes sākumā ir statusa kods:

Kods Nozīme Kad redzēsi
200Labi — fails atrasts un nosūtīts.Spēle atveras.
301, 308Pārvietots — skaties citā adresē.Pārlūks pats aiziet uz jauno adresi.
404Nav atrasts — tāda faila serverī nav.Kļūda faila nosaukumā vai fails nav nosūtīts uz GitHub.
500Kļūda serverī.Problēma nav tavā datorā.

Ja nav savienojuma, statusa koda nav vispār: pieprasījums līdz serverim nenonāk, un pārlūks ziņo Failed to fetch vai „Nav interneta savienojuma”.

Sākuma kodā šo sarunu veic komanda fetch(adrese): tā nosūta pieprasījumu un ar await gaida atbildi. Tev tā nav jāraksta pašam — tu maini tikai adreses un vēro rezultātus.

IP adrese, domēna vārds un DNS

Tīklā katrai ierīcei ir IP adrese — skaitļu virkne, piemēram, 185.199.108.153. Cilvēkiem vieglāk atcerēties domēna vārdu, piemēram, lietotajs.github.io. Pirms pieprasījuma pārlūks pajautā DNS serverim: „Kāda IP adrese ir šim vārdam?” DNS darbojas kā tālruņu grāmata: vārds → numurs.

Komanda ipconfig (Start → cmd → Enter, tad ipconfig) parāda tava datora adresi lokālajā tīklā:

Wireless LAN adapter Wi-Fi:
   IPv4 Address. . . . . . . . . . . : 192.168.1.23
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.1.1
  • IPv4 Address — tava datora adrese lokālajā tīklā.
  • Default Gateway (noklusējuma vārteja) — maršrutētāja adrese: pa šīm „durvīm” dati iziet no lokālā tīkla uz internetu.

Adreses, kas sākas ar 192.168., 10. vai 172.16.–172.31., ir privātas: tās der tikai lokālajā tīklā un atkārtojas tūkstošos māju un skolu. Tās drīkst ierakstīt darbā. Publisko adresi, ko redz serveri internetā, savā publicētajā darbā neraksti: pēc tās var noteikt tīklu, no kura strādā.

Ierīces ceļā no tava datora līdz serverim

Lokālais tīkls (LAN) savieno ierīces vienā ēkā — klasē, skolā vai mājās. Internets ir tīklu tīkls, kas savieno miljoniem lokālo tīklu. Tava spēle ceļo pa abiem:

Ierīce Kur atrodas Ko dara
Dators vai telefons (klients)uz tava galdaSūta pieprasījumus un rāda atbildes.
Wi-Fi piekļuves punktsklasē pie griestiem vai mājas rūterīSavieno bezvadu ierīces ar tīklu.
Komutators (switch)skolas tīkla skapīSavieno vadu ierīces vienā lokālajā tīklā un sūta datus tieši vajadzīgajai ierīcei.
Maršrutētājs (router) — noklusējuma vārtejalokālā tīkla izejāSūta datus no lokālā tīkla uz citiem tīkliem un atpakaļ.
Modems vai optiskais termināliskur ēkā ienāk ārējais kabelisSavieno ēkas tīklu ar pakalpojumu sniedzēja līniju (optika, kabelis, mobilais tīkls).
Pakalpojumu sniedzēja tīkls un internetsārpus ēkas, citās pilsētās un valstīsDaudzi maršrutētāji, kas pa posmiem nogādā datus līdz mērķim.
DNS serverisparasti pie pakalpojumu sniedzējaPārvērš domēna vārdu IP adresē.
Serverisdatu centrā (GitHub Pages)Glabā spēles failus un atbild uz pieprasījumiem.

Mājās viena kaste — rūteris — bieži ir piekļuves punkts, komutators, maršrutētājs un modems reizē. Skolā tās parasti ir atsevišķas ierīces, un tās pārvalda skolas IT speciālists.

Kā izmērīt, kas notiek tīklā

  • DevTools → Network (F12, cilne Network, tad Ctrl+R) rāda katru pieprasījumu: nosaukumu (Name), statusu (Status), veidu (Type), izmēru (Size) un laiku (Time). Atzīmē Disable cache, lai pārlūks neizmanto jau saglabātus failus.
  • Sarakstā No throttling var izvēlēties lēnāku savienojumu (piemēram, Slow 4G) vai Offline — tad pārlūks uzvedas tā, it kā interneta nebūtu.
  • ping adrese nosūta serverim četrus mazus signālus un rāda, cik milisekundēs atnāk atbilde: time=24ms, beigās Average.
  • tracert -d -h 15 adrese parāda maršrutētājus ceļā līdz serverim — katra rinda ir viens posms (hop). Zvaigznīte * nozīmē, ka šis maršrutētājs neatbild; tā ir normāla parādība.
C:\> ping lietotajs.github.io
Reply from 185.199.108.153: bytes=32 time=24ms TTL=57
...
    Minimum = 23ms, Maximum = 26ms, Average = 24ms
Pašpārbaude: spēle atveras, bet attēls tajā nerādās, un Network cilnē pie tā ir 404. Kur meklēt kļūdu?

Serveris strādā — tas atbildēja ar 404, nevis klusēja. Tātad serverī nav faila ar tādu nosaukumu: pārbaudi, vai nosaukums kodā sakrīt ar faila nosaukumu (arī lielie un mazie burti) un vai attēls ir nosūtīts uz GitHub.

const speleAdrese = "https://pages.github.com/";

// 3. UZDEVUMS: pievieno vēl vienu rindu — savas spēles failu ar kļūdu nosaukumā

  { nosaukums: "Fails, kura nav", adrese: speleAdrese + "nav-tada-faila.html" }

// === STATUSA KODA SKAIDROJUMS ===
function statusaTeksts(kods) {
  if (kods === 200) { return "200 — atrasts"; }
  if (kods === 404) { return "404 — nav atrasts"; }
  return kods + " — cita atbilde";
}

// === SERVERA NOSAUKUMS NO ADRESES ===
function serveris(adrese) {
  try {
    return new URL(adrese).hostname;
  } catch (kluda) {
    return "nepareiza adrese";
  }
}

// === VIENS PIEPRASĪJUMS: nosūta, gaida atbildi un mēra laiku (šo funkciju nemaini) ===
async function pieprasit(fails) {
  const sakums = performance.now();
  try {
    const atbilde = await fetch(fails.adrese, { cache: "no-store" });
    const saturs = await atbilde.blob();
    const laiks = Math.round(performance.now() - sakums);
    return {
      statuss: statusaTeksts(atbilde.status),
      labi: atbilde.ok,
      izmers: (saturs.size / 1024).toFixed(1) + " KB",
      laiks: laiks + " ms"
    };
  } catch (kluda) {
    return { statuss: "Nav atbildes: " + kluda.message, labi: false, izmers: "—", laiks: "—" };
  }
}

// === VISI PIEPRASĪJUMI PĒC KĀRTAS UN REZULTĀTU TABULA ===
async function sutitVisus() {
  const tabula = document.getElementById("rezultati");
  tabula.innerHTML = "";
  for (const fails of faili) {
    const r = await pieprasit(fails);
    const rinda = document.createElement("tr");
    const klase = r.labi ? "ok" : "kluda";
    rinda.innerHTML = "<td>" + fails.nosaukums + "</td><td>" + serveris(fails.adrese) + "</td>" +
      "<td class=\"" + klase + "\">" + r.statuss + "</td><td>" + r.izmers + "</td><td>" + r.laiks + "</td>";
    tabula.appendChild(rinda);
  }
}

document.getElementById("sutit").addEventListener("click", sutitVisus);

1. uzdevums

Apskati, ko tava spēle ielādē no servera

Izmanto teoriju: Klients, serveris, pieprasījums un atbilde un Kā izmērīt.

Vide: pārlūks (DevTools) → VS Code

  1. Atver savu 5.6. nodarbībā publicēto spēli (https://lietotajs.github.io/datorika9-tema5/). Nospied F12, atver cilni Network, atzīmē Disable cache un nospied Ctrl+R.
  2. Sarakstā apskati katru failu: Name, Status, Type un Size. Pieraksti, cik failu spēle ielādē, un kurš ir lielākais.
  3. Izveido mapi Desktop/datorika9-tema7, VS Code atver to un saglabā sākuma kodu kā 71.html.
  4. Skripta sākumā speleAdrese vērtību aizstāj ar savas spēles adresi pēdiņās (ar / beigās). Saglabā ar Ctrl+S.
  5. Atver 71.html pārlūkā (Open with → Edge) un nospied Sūtīt pieprasījumus. Salīdzini spēles lapas statusu un izmēru ar DevTools Network cilnē redzēto.

Gatavs, kad: tu zini, cik failu ielādē tava spēle un kurš ir lielākais, un „Tīkla pētnieks” tavai spēlei rāda 200, attēlam citā serverī — 200, bet failam, kura nav, — 404.

2. uzdevums

Uzzīmē ceļu no sava datora līdz serverim

Izmanto teoriju: IP adrese, domēna vārds un DNS un Ierīces ceļā.

Vide: komandrinda (cmd) → diagrams.net pārlūkā → VS Code

  1. Atver Start, ieraksti cmd un nospied Enter. Ieraksti ipconfig. Atrodi adapteri, kuram ir Default Gateway, un pieraksti tā IPv4 Address un Default Gateway.
  2. Atver https://app.diagrams.net, izvēlies Device (saglabāt datorā) un Create New Diagram → Blank Diagram.
  3. Uzzīmē ceļu no kreisās uz labo pusi: tavs dators → Wi-Fi piekļuves punkts vai komutators → maršrutētājs (vārteja) → pakalpojumu sniedzējs → internets → GitHub Pages serveris. Formas atrodi kreisajā meklēšanas laukā (router, switch, server, cloud) un savieno tās ar līnijām.
  4. Pie katras ierīces uzraksti tās nosaukumu un vienā rindā, ko tā dara. Pie sava datora ieraksti savu IP adresi, pie maršrutētāja — vārtejas adresi. Atsevišķi pievieno DNS serveri ar raustītu līniju un uzrakstu „lietotajs.github.io → IP?”.
  5. File → Export as → PNG un saglabā kā tikls_71.png mapē datorika9-tema7. Ar File → Save as saglabā arī tikls_71.drawio — to izmantosi 7.2. nodarbībā.
  6. Failā 71.html sadaļā „Mani mērījumi” punktu ... vietā ieraksti savu IP adresi un vārteju. Saglabā un atjauno pārlūku: shēmai jāparādās lapā.

Gatavs, kad: 71.html redzama shēma ar vismaz sešām ierīcēm, katrai ir nosaukums un funkcija, un pie datora un maršrutētāja ir tavas IP un vārtejas adreses.

3. uzdevums

Salauz pieprasījumu un izmēri savienojumu

Izmanto teoriju: Statusa kodi un Kā izmērīt, kas notiek tīklā.

Vide: VS Code → pārlūks (DevTools) → komandrinda

  1. Masīvā faili pievieno ceturto rindu ar savas spēles failu, kura nosaukumā ir kļūda, piemēram, { nosaukums: "Kļūda nosaukumā", adrese: speleAdrese + "Index.html" }. Neaizmirsti komatu iepriekšējās rindas beigās.
  2. Pirms pogas nospiešanas sadaļā „Ko es noskaidroju” ieraksti prognozi: kādu statusu saņemsi un kāpēc. Tad saglabā, atjauno lapu, nospied pogu un ieraksti rezultātu.
  3. Atver DevTools → Network, sarakstā No throttling izvēlies Offline un nospied pogu. Ieraksti, ko rāda tabula. Tad izmēģini Slow 4G un salīdzini laikus. Beigās atgriez No throttling.
  4. Komandrindā izpildi ping lietotajs.github.io (ar savu adresi, bez https:// un mapes) un tracert -d -h 15 lietotajs.github.io. Sadaļā „Mani mērījumi” ieraksti vidējo laiku ms un posmu skaitu.
  5. Saglabā visu, nosūti uz GitHub jaunā projektā datorika9-tema7 (atgādne zemāk) un pārbaudi, ka GitHub ir gan 71.html, gan tikls_71.png.

Gatavs, kad: tabulā ir ceturtā rinda ar 404, „Ko es noskaidroju” ir prognoze, rezultāts un Offline ziņojums, un „Mani mērījumi” ir aizpildīti.

Iesniedz 3. uzdevuma rezultātu

Iesniedz GitHub projekta datorika9-tema7 saiti skolotāja norādītajā vietā. Projektā jābūt 71.html un tikls_71.png.

Stunda ir ieskaitīta, ja 3. uzdevuma rezultāts atbilst visiem šiem punktiem:

  • speleAdrese ir tavas publicētās spēles adrese, un tabula rāda 200, 200, 404 un tavu ceturto rindu.
  • Shēmā ir vismaz sešas ierīces no datora līdz serverim ar nosaukumiem un funkcijām, kā arī DNS.
  • Pie shēmas vai sadaļā „Mani mērījumi” ir tava privātā IP adrese un vārteja, ping laiks un tracert posmu skaits.
  • „Ko es noskaidroju” ir prognoze pirms pārbaudes, rezultāts un Offline ziņojums.

1. un 2. uzdevums sagatavo šo rezultātu. Papildu uzdevums nav vajadzīgs ieskaitei.

Saglabā un nosūti uz GitHub — pogu atgādne

Vide: VS Code / Source Control → GitHub pārlūkā

  1. Ar File → Save All saglabā failus. Atver Source Control ar Ctrl+Shift+G.
  2. Pie Changes nospied + (Stage All Changes). Pārbaudi, ka 71.html un tikls_71.png pārvietojas uz Staged Changes.
  3. Ziņas laukā ieraksti Pabeigts 7.1 darbs un spied Commit.
  4. Šī ir jauna tēmas mape, tāpēc spied Publish to GitHub un izveido publisku projektu datorika9-tema7. Nākamajās nodarbībās spied Sync Changes.
  5. Pārlūkā atver savu GitHub projektu un pārbaudi, ka tajā ir abi faili.

Ja Source Control rāda Initialize Repository, vispirms nospied to. Ja parādās kļūda, izmanto palīdzību un palūdz skolotāja atbalstu.

Papildu uzdevums: pajautā DNS un salīdzini divus serverus

Sāc, kad 3. uzdevums ir gatavs un iesniegts.

Izmanto teoriju: IP adrese, domēna vārds un DNS.

  1. Komandrindā izpildi nslookup lietotajs.github.io un nslookup ebskola.lv. Pieraksti, kādas IP adreses atbild DNS.
  2. Izpildi tracert -d -h 15 ebskola.lv un salīdzini posmu skaitu ar savu spēli.
  3. Failā 71.html zem mērījumiem uzraksti divus teikumus: kurš serveris atbild ātrāk un kāpēc ceļš līdz tiem var atšķirties.

Gatavs, kad: lapā ir abu domēnu IP adreses, abu ceļu posmu skaits un pamatots salīdzinājums.

Ja kaut kas neizdodas
  • Visām rindām „Nav atbildes: Failed to fetch”? Pārbaudi, vai adrese sākas ar https:// un vai DevTools nav palicis ieslēgts Offline.
  • Spēles lapai 404? Adresē ir kļūda vai GitHub Pages nav ieslēgts. Atver adresi pārlūkā un salīdzini ar 5.6. nodarbības spēles saiti.
  • ping rāda „Request timed out”? Serveris vai skolas tīkls neatbild uz ping. Izmēģini ping ebskola.lv un ieraksti, ka savai spēlei ping nesaņēmi atbildi.
  • tracert rāda daudz zvaigznīšu *? Daļa maršrutētāju neatbild — tas ir normāli. Skaiti visas rindas līdz pēdējai, kurā redzama adrese.
  • ipconfig rāda vairākus adapterus? Izvēlies to, kuram ir aizpildīts Default Gateway.
  • Shēma lapā nerādās? Failam jābūt tieši tikls_71.png tajā pašā mapē, kur 71.html. Windows ieslēdz View → Show → File name extensions un pārbaudi, ka nav .png.png.
  • diagrams.net prasa Google Drive vai OneDrive? Izvēlies Device — tad konts nav vajadzīgs.
