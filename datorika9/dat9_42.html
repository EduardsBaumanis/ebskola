4.2 Vadi spēlētāju ar pogām un taustiņiem

Sasniedzamais rezultāts: Savieno spēles vadību ar pogu klikšķiem un tastatūras bultiņu taustiņiem abos horizontālajos virzienos, pielāgo kustības soli un pārliecinies, ka spēlētājs paliek laukuma robežās.

Teorija ar piemēriem

Notikumi (click, keydown) un klausītājs addEventListener

4.1. nodarbībā pogas izsauca funkciju ar HTML atribūtu onclick="...". Spēlēs ar tastatūras vadību šāds atribūts neder, jo tastatūras taustiņš nav atsevišķa HTML poga ekrānā. Tāpēc JavaScript kodā izmanto notikumu klausītāju addEventListener, kas gaidīšanas režīmā novēro konkrētu elementu vai visu lapu (document):

document.getElementById("lecPoga").addEventListener("click", function () {
  pacelt(1);
});

document.addEventListener("keydown", function (notikums) {
  // Šī funkcija izpildās katru reizi, kad nospiests jebkurš taustiņš
});
Pieraksta daļa Ko tā dara?
element.addEventListener("click", ...) Gaida peles klikšķi uz konkrētās HTML pogas (atrastas pēc id) un tad izpilda iekšējo funkciju.
document.addEventListener("keydown", ...) Klausās taustiņa nospiešanu visā atvērtajā lapā. Lai pārlūks uztvertu taustiņus, lapai jābūt aktīvai (vienreiz uzklikšķini uz lapas fona).
function (notikums) { ... } Funkcija, kuru pārlūks izsauc notikuma brīdī, automātiski iedodot parametru notikums ar ziņām par notikušo darbību.

Šajā nodarbībā kustība vēl nenotiek pati no sevis pēc laika — kods mierīgi gaida spēlētāja klikšķi vai taustiņa spiedienu un izpilda vienu soli.

Nospiestā taustiņa pārbaude (notikums.key) un preventDefault()

Kad spēlētājs nospiež taustiņu, parametra īpašība notikums.key satur nospiestā taustiņa precīzo nosaukumu tekstā. Vienā un tajā pašā keydown klausītājā ar vairākiem atsevišķiem if blokiem pārbauda visus vajadzīgos spēles taustiņus (piemēram, vertikālai pacelšanai un nolaišanai):

document.addEventListener("keydown", function (notikums) {
  if (notikums.key === "ArrowUp") {
    notikums.preventDefault();
    pacelt(1);
  }
  if (notikums.key === "ArrowDown") {
    notikums.preventDefault();
    pacelt(-1);
  }
});
Taustiņš uz tastatūras Precīza notikums.key vērtība Kam jāpievērš uzmanība?
Labā bultiņa (→) "ArrowRight" Lielie burti A un R, bez atstarpes vidū!
Kreisā bultiņa (←) "ArrowLeft" Lielie burti A un L, bez atstarpes!
Augšējā / apakšējā bultiņa "ArrowUp" / "ArrowDown" Izmantosim kustībai četros virzienos.
Burtu taustiņi A un D "a" un "d" Mazie un lielie burti atšķiras — izslēdz Caps Lock!
  • Kāpēc vajadzīgs notikums.preventDefault()? Bultiņu taustiņu parastais uzdevums pārlūkā ir ritināt garāku lapu uz sāniem vai augšup/lejup. Izsaucot notikums.preventDefault();, šī noklusētā ritināšana tiek atcelta un kustas tikai spēles varonis.
  • Viens klausītājs visiem taustiņiem: jaunu taustiņu vienmēr pievieno kā nākamo if (...) { ... } bloku tā paša document.addEventListener("keydown", ...) iekšpusē (vienu zem otra, neliekot vienu if otra if figūriekavās).

Virziens, soļa lielums un pikseļu mērvienība (+ "px")

Lai kvadrātu varētu brīvi bīdīt spēles laukumā, CSS stilā laukumam #laukums ir uzlikts position: relative, bet spēlētājam #speletajs — position: absolute. Tas nozīmē, ka left mēra attālumu pikseļos no spēles laukuma kreisās iekšējās malas.

JavaScript pusē atrašanās vietu glabā parastā skaitlī x, un katrā solī to izmaina ar reizinājumu x = x + virziens * solis;:

let x = 30;
const solis = 15;

function pabidit(virziens) {
  x = x + virziens * solis;
  elementaBloks.style.left = x + "px";
}
  • Virziens 1 vai -1: padodot 1, pieskaitās +1 * 15 = +15 (kustība pa labi, piemēram, 30 → 45 → 60). Padodot -1, pieskaitās -1 * 15 = -15 (kustība pa kreisi, 60 → 45).
  • Konstante const solis: mainīgais x mainās katrā gājienā (tāpēc raksta let x), turpretim soļa garums spēles gaitā paliek nemainīgs (const solis). Izmainot skaitli pie const solis vienā rindā, uzreiz mainās gan abu pogu, gan abu taustiņu ātrums!
  • Obligātais + "px": aprēķinos x ir tīrs skaitlis (piemēram, 45), bet CSS īpašībai .style.left vajadzīga mērvienība ("45px"). Ja aizmirst + "px", skaitlis tekstā gan mainās, bet kvadrāts uz ekrāna nekustas ne par milimetru!
  • Praktisks ieteikums pārbaudei: pārbaudot vienu soli ar tastatūru, taustiņu īsi nospied un atlaid — turot taustiņu nospiestu, dators automātiski atkārto keydown notikumu vairākas reizes sekundē.

Laukuma kreisā un labā robeža (clientWidth)

Koordināte x norāda spēlētāja kvadrāta kreisās malas atrašanās vietu, nevis centru vai labo malu. Tāpēc pirms kvadrāta pārvietošanas ekrānā kods pārbauda abas laukuma sienas:

const robeza = document.getElementById("laukums").clientWidth - 30;
if (x < 0) { x = 0; }
if (x > robeza) { x = robeza; }
  • Kreisā siena (0): ja spēlētājs pie x = 0 vēlreiz spiež pa kreisi, aprēķins uz mirkli dod negatīvu skaitli, bet if (x < 0) { x = 0; } noliek to atpakaļ tieši pie kreisās malas.
  • Labā siena (clientWidth - 30): īpašība clientWidth nolasa laukuma iekšējo platumu pikseļos (sākuma kodā tie ir 300 px). Ja 30 px platajam kvadrātam atļautu x = 300, tā kreisā mala nostātos uz laukuma labās līnijas un viss kvadrāts pazustu ārpus laukuma! Atņemot kvadrāta platumu (300 - 30 = 270), pie x = 270 kvadrāta labā mala (270 + 30 = 300) precīzi pieskaras sienai.
  • Darbību secība funkcijā: vispirms izrēķina jauno x, tad ar abiem if ierobežo to robežās un tikai pēc tam ieraksta speletajs.style.left = x + "px" un atjauno uzrakstu lapā.
Pašpārbaude: kāpēc pie 300 px plata laukuma spēlētājs apstājas pie X = 270 (nevis 300), un vai piespiešana pie malas nozīmē, ka vadība vairs nestrādā?

1) Koordināte X ir 30 px platā kvadrāta kreisā mala, tāpēc pie X = 270 tā labā mala jau atrodas pie 270 + 30 = 300 px. 2) Vadība joprojām strādā katrā nospiešanas reizē — robežas pārbaude tikai neļauj pārsniegt 270, un, nospiežot pretējo virzienu, kvadrāts uzreiz dodas atpakaļ.

1. uzdevums

Izpēti pogu un taustiņu notikumus un pielāgo spēles izskatu

Izmanto teoriju: Notikumi (click, keydown) un klausītājs addEventListener.

Vide: Windows File Explorer → pārlūks → VS Code

  1. Windows mapē Desktop/datorika9-tema4 atver saglabāto 42.html pārlūkā (Open with → Edge) un pārliecinies, ka laukumā redzams spēlētāja kvadrāts un zem pogām rakstīts X: 20.
  2. Paredzi jauno koordināti un nospied ekrāna pogu Pa labi →, bet pēc tam ← Pa kreisi — pārbaudi, kā X mainās pa 10 pikseļiem (20 → 30 → 20) reizē ar kvadrāta kustību.
  3. Uzklikšķini uz lapas fona un nospied tastatūras labo bultiņu (→) un pēc tam kreiso bultiņu (←): pārliecinies, ka labā bultiņa jau kustina spēlētāju, bet kreisā bultiņa vēl nereaģē.
  4. VS Code atver 42.html un izpēti <script> beigas: salīdzini, kā addEventListener("click", ...) jau ir pieslēgts abām pogām, kamēr keydown klausītājā pagaidām ir aprakstīts tikai "ArrowRight".
  5. Nomaini <title> un <h1> uz savas spēles nosaukumu (piemēram, vārtsarga, sargtorņa vai skrējēja vadībai).
  6. <style> blokā pie #speletajs nomaini background krāsu uz sev tīkamu toni (nemainot width: 30px, height: 30px, left: 20px un position īpašības).
  7. Saglabā failu ar Ctrl+S, pārlūkā nospied Ctrl+R un pārbaudi, ka redzams jaunais virsraksts, jaunā spēlētāja krāsa un sākuma kustība joprojām strādā.

Gatavs, kad: esi pārbaudījis sākuma pogu un labās bultiņas darbību un pielāgojis spēles virsrakstu un spēlētāja krāsu.

3. uzdevums

Palielini kustības soli uz 20 px un pārbaudi abas laukuma robežas

Izmanto teoriju: Virziens, soļa lielums un pikseļu mērvienība (+ "px") un Laukuma kreisā un labā robeža (clientWidth).

Vide: VS Code → pārlūks (ar F12 Console)

  1. <script> sākumā atrodi konstanti const solis = 10; un nomaini tās vērtību no 10 uz 20.
  2. Pirms pārbaudes pārlūkā aprēķini galvā: ja sākumā x ir 20 un solis ir 20, kāda būs X vērtība pēc viena gājiena pa labi un kāda — pēc viena gājiena atpakaļ pa kreisi?
  3. Saglabā ar Ctrl+S, pārlūkā nospied Ctrl+R (lai X atgrieztos uz 20), vienreiz nospied → (jāparādās X: 40) un vienreiz ← (atkal X: 20).
  4. Vēl divas reizes nospied ← vai pogu ← Pa kreisi: pārliecinies, ka pie kreisās malas koordināte apstājas pie X: 0 un kvadrāts nepazūd aiz laukuma kreisās līnijas.
  5. Funkcijā kustinat(virziens) apskati rindu const robeza = document.getElementById("laukums").clientWidth - 30; un izrēķini lielāko atļauto X šim 300 px platajam laukumam.
  6. Ar bultiņu → vai pogu Pa labi → aizvadi spēlētāju līdz pašai labajai malai: pārliecinies, ka koordināte apstājas pie X: 270 (no 260 nākamais solis tiek ierobežots uz 270, nevis 280) un ka pēc tam spiediens pa kreisi uzreiz atbīda kvadrātu uz X: 250.

Gatavs, kad: abas pogas un abas tastatūras bultiņas pārvieto spēlētāju pa 20 px vienā solī (20 → 40 → 20), kvadrāts precīzi apstājas pie X: 0 un X: 270, un Console cilnē nav kļūdu.

Papildu uzdevums: Pievieno vadību arī ar taustiņiem A un D

Sāc, kad visi trīs pamatuzdevumi ir pabeigti.

Izmanto teoriju: Burtu taustiņu nosaukumi īpašībā notikums.key.

  1. <script> blokā tajā pašā keydown klausītājā zem bultiņu pārbaudēm pievieno vēl divus atsevišķus if nosacījumus: mazo burtu "a" kustībai pa kreisi un mazo burtu "d" kustībai pa labi.
  2. Atjauno rindkopu <p id="noteikumi">, lai spēlētājs redzētu, ka kustināšanai var izmantot gan bultiņas (←, →), gan taustiņus A un D.
  3. Saglabā ar Ctrl+S, atjauno pārlūku ar Ctrl+R, pārliecinies, ka uz tastatūras ir izslēgts Caps Lock, un pārbaudi kustību ar A un D.
  4. Pamīšus izmēģini visas trīs vadības iespējas (ekrāna pogas, bultiņas un A / D) un pārliecinies, ka pie abām malām joprojām darbojas robežas 0 un 270.

Gatavs, kad: spēlētāju var vadīt gan ar pogām un bultiņu taustiņiem, gan ar taustiņiem A un D laukuma robežās.

Ja kaut kas neizdodas
  • Kreisā bultiņa nestrādā, lai gan pievienoji if pārbaudi? Pārbaudi trīs lietas: 1) vai pēdiņās ir precīzi "ArrowLeft" ar lielo A un lielo L bez atstarpēm; 2) vai if bloks ievietots pirms keydown klausītāja aizverošās }); un nav nejauši ielikts "ArrowRight" figūriekavu iekšpusē; 3) vai pirms taustiņa spiešanas vienreiz uzklikšķināji uz lapas fona pārlūkā.
  • Konsolē (F12 → Console) parādās ReferenceError: notikums is not defined? Jauno if (notikums.key === ...) bloku esi ierakstījis ārpus document.addEventListener("keydown", function (notikums) { ... });. Pārvieto to šīs funkcijas iekšpusē, kur parametrs notikums ir pieejams.
  • Skaitlis pie X: mainās, bet spēlētāja kvadrāts stāv uz vietas? Pārbaudi, vai nav izdzēsta mērvienība rindā speletajs.style.left = x + "px"; un vai <style> daļā pie #speletajs ir saglabāts position: absolute;.
  • Papildu uzdevumā nereaģē taustiņi A un D? Izslēdz Caps Lock — JavaScript atšķir mazo burtu "a" no lielā burta "A".
  • Neredzi savas izmaiņas vai kods pārlūkā atveras kā teksts? VS Code nospied Ctrl+S, tad pārlūkā nospied Ctrl+R un pārliecinies, ka atvērts tieši Desktop/datorika9-tema4/42.html (nevis 41.html vai fails ar .txt galotni).
