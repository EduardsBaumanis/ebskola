2.5 Datņu sistēmas organizēšana un arhīvi

Stundas uzdevums: Strukturēt projekta failus loģiskā mapju sistēmā, atjaunot failu ceļus kodā un izveidot projekta rezerves kopiju (arhīvu).

2.3.3. Pārvalda datņu sistēmu, veic arhivēšanu; 5.2.6. Digitālā pratība.

70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) — izveido mapes css/, js/, atteli/ · 2. uzdevums (~25 min) — pārvieto failus un salabo ceļus index.html un style.css · 3. uzdevums (~20 min) — pārbaudi, ka nav 404, un izveido ZIP arhīvu. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: atver savu projektu VS Code un pārliecinies, ka viss ir nokomitēts ar git status — tad pārvietošanas kļūdu varēs atsaukt.

Teorija: Ceļi un mapju hierarhija

Tīmekļa projekti vienmēr seko konkrētai struktūrai. Visi faili neatrodas vienā "kaudzē":

  • Saknes mape (Root): Galvenā mape, kurā atrodas `index.html`.
  • Relatīvie ceļi: Norāda, kā no viena faila nokļūt līdz citam. Piemēram, `css/style.css` nozīmē "ieej mapē css un atver style.css". Savukārt `../` nozīmē "izej vienu mapi uz augšu".
  • Arhivēšana (ZIP): Vairāku failu un mapju saspiešana vienā failā. Tas ir noderīgi, lai nosūtītu visu projektu skolotājam e-pastā vai izveidotu drošu rezerves kopiju.

# Mapju struktūra projektam
mans_projekts/
├── index.html
├── css/
│   └── stils.css
├── js/
│   └── spele.js
├── attels/
│   └── varonis.png
└── README.md

# Arhīva izveide piegādei
zip -r mans_projekts.zip mans_projekts/

Praktiskie uzdevumi

1. uzdevums — Izveido mapes css/, js/ un atteli/

Beigās tavā projekta mapē blakus index.html būs trīs tukšas apakšmapes.

cd mans_projekts
mkdir css
mkdir js
mkdir atteli
  1. Atver VS Code terminālī savu projekta mapi ar komandu cd.
  2. Izpildi augšējās komandas pa vienai un spied Enter pēc katras.
  3. Pārbaudi ar komandu ls (Windows: dir), vai visas trīs mapes ir izveidotas.
  4. Atver VS Code kreiso failu koku un pārliecinies, ka mapes redzamas arī tur.

Gatavs, kad: failu kokā blakus index.html redzamas mapes css, js un atteli.

2. uzdevums — Pārvieto failus mapēs un salabo ceļus

Beigās tava lapa izskatīsies tieši tāpat kā pirms pārkārtošanas, bet faili būs sakārtoti mapēs.

  1. Ievelc VS Code failu kokā style.css mapē css.
  2. Ievelc tāpat script.js mapē js un visus attēlus mapē atteli.
  3. Atver index.html un nomaini ceļu uz <link rel="stylesheet" href="css/style.css">.
  4. Nomaini arī skripta ceļu uz <script src="js/script.js"></script>.
  5. Atver css/style.css un nomaini fona attēla ceļu uz url("../atteli/fons.webp").
  6. Saglabā visus failus un pārlādē lapu ar Ctrl+F5.
  7. Veic git commit -m "Reorganize project into css/ js/ atteli/ folders".

Gatavs, kad: lapa pārlūkā izskatās tāpat kā stundas sākumā, lai gan neviens fails vairs nav saknes mapē.

3. uzdevums — Iztīri 404 kļūdas un iesaiņo projektu ZIP arhīvā

Beigās tev būs ZIP arhīvs, kuru var izpakot citā datorā un lapa tur strādās.

  1. Spied F12, atver cilni "Network" un pārlādē lapu ar Ctrl+F5.
  2. Atrodi sarakstā katru sarkano ierakstu ar statusu 404 un pieraksti tā nosaukumu.
  3. Salabo katru šādu ceļu kodā, atceroties, ka CSS failā ceļš sākas ar ../.
  4. Pārlādē lapu vēlreiz, līdz sarakstā vairs nav neviena 404 ieraksta.
  5. Izveido ZIP arhīvu: labais klikšķis uz projekta mapes → "Compress" vai "Send to → Compressed folder".
  6. Izpako arhīvu darbvirsmā jaunā mapē un atver tur index.html pārlūkā.
  7. Pieraksti vienu secinājumu: kāpēc relatīvie ceļi strādā arī pēc projekta pārvietošanas.

Gatavs, kad: izpakotā kopija darbvirsmā izskatās tieši tāpat kā oriģināls un "Network" sarakstā nav neviena 404.

Papildu uzdevums — Pievieno .gitignore un README.md

Beigās tavā GitHub repozitorijā būs īss apraksts un lieki faili tajā vairs nenonāks.

  1. Izveido saknes mapē failu README.md un ieraksti tajā spēles nosaukumu un divus teikumus par to.
  2. Pieraksti README.md failā mapju sarakstu: css/, js/, atteli/.
  3. Izveido failu .gitignore un ieraksti tajā rindas *.zip un .DS_Store.
  4. Izpildi git status un pārbaudi, ka ZIP arhīvs sarakstā vairs neparādās.
  5. Veic git commit -m "Add README and gitignore" un pēc tam git push.
  6. Atver GitHub.com un pārbaudi, vai apraksts parādās zem failu saraksta.

Gatavs, kad: GitHub lapā zem failu saraksta redzams tavs apraksts un repozitorijā nav neviena ZIP faila.

Biežākās kļūdas (un kā tās labot):

  • Pazudis stils (404 kļūda): Ja CSS nedarbojas, pārliecinies, ka ceļš ir tieši `css/style.css`, nevis `style.css` vai `/css/style.css` (ar lieku slīpsvītru sākumā).
  • Strādāšana ZIP arhīvā: Nekad neraksti kodu failā, kas atvērts tieši no ZIP arhīva (neatarhivējot). Izmaiņas nesaglabāsies! Vienmēr vispirms "Extract all".
  • Nepareizi lielo/mazo burtu lietojumi: Tīmekļa serveros `Attels.png` un `attels.png` ir divi dažādi faili. Vienmēr lieto mazos burtus mapju un failu nosaukumos!

Koda piemērs (ceļš CSS failā sākas ar ../, nevis ar mapes nosaukumu)

mans_projekts/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── script.js
└── atteli/
    ├── varonis.png
    └── fons.webp
<!-- index.html: ceļš skaitās no index.html vietas -->
<link rel="stylesheet" href="css/style.css">
<script src="js/script.js"></script>
<img src="atteli/varonis.png" alt="Spēles varonis" width="64">
/* NEPAREIZI: šis ceļš meklē mapi atteli/ iekšā mapē css/ → 404 */
body { background-image: url("atteli/fons.webp"); }

/* PAREIZI: ../ nozīmē "izej no mapes css/ vienu līmeni uz augšu" */
body { background-image: url("../atteli/fons.webp"); }

Ja ceļi ir pareizi, DevTools cilnē "Network" visiem četriem resursiem — style.css, script.js, varonis.png un fons.webp — statuss ir 200. Ja fons pazūd, bet pārējais strādā, kļūda ir tieši trūkstošajā ../ CSS failā.
