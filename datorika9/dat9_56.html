5.6 Noslēguma projekts: Pilnvērtīga spēle internetā

Stundas uzdevums: Publicēt pilnvērtīgu spēles versiju internetā, pārbaudīt tās darbību citās ierīcēs un pamatot savus tehniskos risinājumus īsā projekta aizstāvēšanā.

Vērtēšana un pamatota atgriezeniskā saite SR 2.3.2. Datortīklu uzbūves pamatprincipi SR 2.4.3. Datu attēlošanas veidi SR 2.4.4. Prezentācijas plānošana un demonstrēšana SR 2.4.8. 70 min plāns: Teorija un paraugs (~10 min) · 1. uzdevums (~15 min) - ieslēdz GitHub Pages un atver savu spēles publisko saiti · 2. uzdevums (~25 min) - salabo trūkstošos failus publicētajā versijā un papildini README.md · 3. uzdevums (~20 min) - pārbaudi saiti citā ierīcē un salabo vienu neskaidrību. Papildu uzdevumu sāc tikai tad, ja pārējie trīs ir gatavi.

Pirms sāc: atver savu projekta mapi un GitHub krātuvi; visām 5.5 stundas izmaiņām jau jābūt nosūtītām ar git push.

Teorija: publicēšana nav tikai poga

GitHub Pages padara projektu publisku, bet publicēšana ir tikai viens solis. Gatavai spēlei jābūt atrodamai, ielādējamai un saprotamai arī cilvēkam, kurš nav redzējis tavu kodu. Tāpēc pirms aizstāvēšanas jāpārbauda saite, resursu ceļi, vadības instrukcija un projekta dokumentācija.

Minimālais nodošanas komplekts: publiska spēles saite, GitHub krātuve, README.md ar instrukciju, ekrānšāviņš vai GIF, īss kļūdu/testu apraksts un prezentācijas gatavība.

README.md struktūra
1. Spēles nosaukums
2. Publiskā saite
3. Vadība
4. Izmantotās tehnoloģijas
5. Zināmās kļūdas vai nākamie uzlabojumi
Lietotājs saprot, ko atvērt, kā spēlēt un kā vērtēt tavu darbu.

Praktiskie uzdevumi

1. uzdevums - Ieslēdz GitHub Pages un atver savu spēles saiti

Beigās tava spēle būs pieejama publiskā adresē, ko var atvērt jebkurš cilvēks.

  1. Izpildi projekta mapē git push, lai GitHub būtu tava jaunākā versija.
  2. Atver savu krātuvi GitHub.com un pārbaudi, ka index.html atrodas saknē, ne apakšmapē.
  3. Atver krātuves sadaļu Settings un kreisajā izvēlnē izvēlies Pages.
  4. Izvēlies Source: "Deploy from a branch", zaru main, mapi / (root) un nospied Save.
  5. Uzgaidi divas minūtes un pārlādē Pages lapu, līdz parādās adrese ar zaļu ķeksīti.
  6. Atver šo adresi jaunā cilnē un ieraksti to savos pierakstos.

Gatavs, kad: adrese https://tavsvards.github.io/spele atver tavu spēli, nevis "404 File not found".

2. uzdevums - Salabo trūkstošos failus publicētajā versijā

Beigās publicētajā spēlē ielādēsies visi attēli un skaņas, tāpat kā tavā datorā.

  1. Atver publicēto saiti, nospied F12 un pārej uz cilni "Network".
  2. Pārlādē lapu ar Ctrl+F5 un atrodi rindas ar statusu 404.
  3. Salabo ceļus HTML un CSS: /attelī/fons.png jāraksta kā attelī/fons.png.
  4. Pārbaudi lielos un mazos burtus - serverim Fons.png un fons.png ir divi dažādi faili.
  5. Papildini README.md ar publisko saiti un vadības taustiņiem.
  6. Izpildi git commit -am "Fix asset paths for GitHub Pages" un git push.
  7. Uzgaidi minūti, pārlādē saiti ar Ctrl+F5 un pārbaudi "Network" vēlreiz.

Gatavs, kad: cilnē "Network" nav neviena sarkana 404 ieraksta un spēles fons ir redzams.

3. uzdevums - Pārbaudi saiti citā ierīcē un salabo vienu neskaidrību

Beigās svešs cilvēks no sava telefona varēs izspēlēt tavu spēli bez tava paskaidrojuma.

  1. Nosūti savu Pages saiti klasesbiedram un lūdz atvērt to savā ierīcē.
  2. Vēro klusējot, kā viņš mēģina sākt spēli, un neko nepasaki priekšā.
  3. Pieraksti vienu vietu, kur viņš apstājās vai jautāja.
  4. Salabo tieši šo vietu - pogas tekstu, instrukciju vai elementa izmēru.
  5. Izpildi git commit -am "Final polish before presentation" un git push.
  6. Pārbaudi GitHub commit vēsturi - tur jābūt vismaz 5 saprotamām ziņām.
  7. Pieraksti vienu secinājumu: ko darītu citādi, ja sāktu šo projektu no jauna.

Gatavs, kad: klasesbiedrs savā ierīcē izspēlē vienu pilnu kārtu bez tava paskaidrojuma.

Papildu uzdevums - Papildini README ar attēlu un zināmajām kļūdām

Beigās tavas krātuves pirmajā lapā būs redzams spēles attēls un godīgs kļūdu saraksts.

  1. Uzņem savas spēles ekrānšāviņu un saglabā to mapē kā screenshot.png.
  2. Pievieno README.md rindu ![Spēles ekrānšāviņš](screenshot.png).
  3. Pievieno sadaļu "Zināmās kļūdas" ar divām lietām, ko nepaguvi salabot.
  4. Pievieno sadaļu "Nākamie uzlabojumi" ar divām idejām nākamajai versijai.
  5. Izpildi git add screenshot.png, pēc tam commit un git push.
  6. Sagatavo trīs teikumus prezentācijai: spēles mērķis, grūtākā koda vieta, ko iemācījies.

Gatavs, kad: GitHub krātuves sākumlapā redzams spēles attēls un abas jaunās sadaļas.

Biežākās kļūdas (un kā tās labot)

  • GitHub Pages rāda 404: pārbaudi, vai publicē pareizo zaru un vai galvenais fails saucas index.html.
  • Attēli strādā lokāli, bet nestrādā internetā: pārbaudi failu ceļus un lielos/mazos burtus failu nosaukumos.
  • README nav lietotājam noderīgs: pievieno vadību, mērķi, publisko saiti un zināmās kļūdas.
  • Prezentācijā nav tehniska pamatojuma: sagatavo vienu koda fragmentu, kuru vari izskaidrot soli pa solim.

Nodošanas pierādījumi

  • Publiska GitHub Pages saite, kas atver spēli bez pieteikšanās.
  • GitHub krātuve ar sakārtotiem failiem, README un pēdējo publicēšanas commit.
  • Īss testēšanas pieraksts: kurās ierīcēs vai ekrāna izmēros spēle pārbaudīta.
  • Prezentācijā parādīts gan spēles rezultāts, gan viens konkrēts koda vai dizaina lēmums.

Publicēšana un pieejamība (1.5.1.) Spēle nav publicēta; saite nedarbojas vai nav pieejama. Spēle ir publicēta, bet trūkst resursu (attēlu/skaņu) nepareizu ceļu dēļ. Spēle ir veiksmīgi publicēta GitHub Pages, un visi elementi darbojas korekti. Projekts ir publicēts un papildināts ar kvalitatīvu README dokumentāciju un lietošanas instrukciju.
Komunikācija un prezentācija (5.3.1.) Nespēj paskaidrot sava koda darbību vai nodemonstrēt spēli. Demonstrē spēli, bet paskaidrojumi par tehnisko izpildi ir nepilnīgi. Pārliecinoši demonstrē spēli un prot izskaidrot galvenās koda funkcijas un loģiku. Prezentē projektu profesionāli, analizē izmantotās tehnoloģijas un prot pamatot algoritmu izvēli.
